# 微信导出 MCP

你通过一个 MCP 服务器读写用户**自己电脑上登录着的微信**——两个面：

- **记录面**：把某个会话的聊天记录导出成能读、能分享、能归档的文件。
- **文件面**：把微信里收发的文件列出来、算占用、归档到本地目录（过期文件预警）。

服务器**只读**——不发送、不修改、不删除微信里的任何东西，归档只做拷贝。
两边写进**同一棵树**：`<out_dir>/<会话名>/` 下的 `chat.<格式>`、`stats.json`、`assets/`、`files/`。

## 0. 装（客户端侧一次配好即可）

把本目录放进客户端的 skills 目录，然后注册 MCP 服务器：

**Claude Code**：
```bash
claude mcp add wechat-export -s user -- "{{EXE}}"
```

**其它客户端**：
```json
{
  "mcpServers": {
    "wechat-export": { "command": "{{EXE_JSON}}", "args": [] }
  }
}
```
`command` 必须是 **exe 的绝对路径**（单文件产物，不需要 Python 环境）。

## 0.5 环境要求与失败处置

- **Windows + 微信 4.1.15.x 已登录并运行**（真机验证过的版本）。工具直读本机微信库，**不联网、不外传**。
  其它 4.x（4.1.6 起）静态扫描全部命中、可以试，但没逐版真机跑过——`check_env` 的
  `wechat_version.verified` 会是 `false`，**那时结果先抽查几条再当真**。**微信 3.x 不支持**（另一套后端）。
- 出错一律返回**同一形状**：`{"ok": false, "detail", "error_code", "stage", "suggestion"}`。
  **看到 `ok: false` 就是没成功**，别把同一结果里别的字段当数据用。按 `error_code` 分派：
  - `env_not_ready` —— 微信没就绪（没运行 / 找不到数据目录 / 密钥扫不到）。**不是用户参数的问题**：
    把 `detail` + `hint` 里的动手步骤**原话转告用户**（通常是「先打开微信并登录、点开一个会话」），
    **不要重试**。
  - `target_not_found` —— 会话名没对上唯一目标。那是「名字没对上」，**不是**「没有数据」；
    `candidates` 里是名字相近的会话，拿它向用户问清是哪一个，**别把 `count: 0` 讲给用户听**。
  - `bad_args` —— 参数缺失或取值非法（含 `format`/`media`/`split` 传了枚举外的值）；
    `invalid` 会列出具体哪几个，按 `detail` 改正后重试。
  - `internal_error` —— 工具内部出错（bug），此时 `isError=true`；把 `detail` 原话反馈，别自己绕。

## 1. 必须先接受的事实

1. **导出的是本地已有的东西**：更早的聊天记录可能已被微信滚出本机；**文件会过期**，
   过期后本地磁盘没有、**任何工具都救不回来**（`status=missing`）——如实告诉用户，**别承诺能补**。
2. **只读、只拷贝**：导出不影响微信；归档把文件**复制**到用户目录，微信原文件原地不动
   （所以微信里「打开文件」照常能用）。
3. **文件名是线索不是铁证**：同名文件可能是不同版本，服务器用消息里的大小（`totallen`）消歧，
   对不上时给 `status=size_mismatch`——这时**告诉用户可能不是同一份**。
4. **语音转写需要本机模型**：`transcribe_voice=true` 在没装识别模型的机器上会**逐条失败并计数**，
   导出本身不受影响。所以默认 `false`；用户明确要转写时再开，并如实报告有多少条没转成。

## 2. 工具面（5 个）

**记录面**

| 工具 | 用途 |
|---|---|
| `list_sessions(query?)` | 列会话拿确切名字/talker（不确定会话名时先用它） |
| `export_chat(talker?, out_dir, format?, keyword?, limit?, since?, until?, media?, transcribe_voice?, split?, inline_max_mb?, max_sessions?)` | 导出（整段 或 只导命中） |

**文件面**

| 工具 | 用途 |
|---|---|
| `list_files(talker?, since?, until?, types?, keyword?, only_missing?, limit?)` | 列文件消息 + 磁盘定位结果。`only_missing=true` 就是**过期预警**；**只列清单、不落盘** |
| `disk_usage(session_limit?)` | 占用分析：磁盘各子树小计 + 按会话排行 + 无主占用。**只读、只报告，不删任何东西** |
| `archive_files(out_dir, talker?, since?, until?, types?, layout?, dry_run?)` | 拷贝归档。`dry_run=true`（默认）只出计划 |

### 2.0 记录面参数

`format`：`md`（默认，人读）/ `html`（可分享，带样式）/ `json`（机读、带报表）。
`json` 带 `stats` **统计报表**（条数/双方占比/按月/按小时/按星期/类型/发言人/最忙的几天）；
每个会话目录另有一份 `stats.json`（**任何格式都有**，机读）。
`keyword`：只导出**正文或附件名含它**的消息；`talker` 可以省（= **全库搜**，此时用 `max_sessions` 封顶）。
命中过多会被 `limit` 截断（默认 500/会话），**返回里 `truncated=true` 就是"被切过"，别说成"就这么多"**。
`media`：`none`（默认只文字）/ `images`（+图片）/ `files`（+文件附件，落到 `files/`）/
`all`（图片 + 文件 + 语音 wav）。**附件从不内嵌**（几十上百 MB，内嵌进 HTML 就打不开了），
`files/` 要单独打包发给别人才拿得到；没收全的看 `media_report.file_missing`
（没下载过 / 已过期 = 微信服务器上也没了，**如实说，别承诺能补**；在微信里点一下该文件再导一次就有了）。
`split`：`none`（默认单文件）/ `month`（按月拆子目录，记录多时用）。
`inline_max_mb`：`format=html` 时媒体**内嵌进 HTML**（自包含，单文件即可分享），
这是体积上限（默认 20 MB，`0` = 不限）；超出的媒体会落到同目录 `assets/`，
页首有提示、返回里 `media_report.inline_fallback` 有计数 —— **要如实转达"这份不再自包含"**。

**落点（结构固定，照着拼路径）**：
`<out_dir>/<会话名>/` → 按关键词导则多一层 `q-<关键词>/` → `split=month` 再一层 `<YYYY-MM>/`；
正文 `chat.<格式>`、报表 `stats.json`、图片 `assets/`、**文件 `files/`（归档也落这里）**；
一次导多个会话会在 `<out_dir>/index.md` 留一份清单。

### 2.1 一轮完整回路（记录面）

1. 用户说「把我和张三的聊天记录导出来」→
   `list_sessions(query="张三")` 拿到确切的 `talker`。
2. 问清**存到哪**、要不要带图片/文件附件。
3. `export_chat(talker=..., out_dir="D:\\导出\\张三", format="md")`
4. 回报：导出多少条、落在哪个文件、体积；若带媒体，报告成功与跳过数。

**记录很多**（几百条以上或横跨数月）时用 `split="month"`。
**要给不装微信的人看 / 发出去**时用 `format="html"` + `media="images"`：图内嵌在 HTML 里，
就一个文件（**md / json 是 `assets/` 相对路径，单独发出去图全变空框**）。
带图的大会话体积可观（实测 500 条约 30–40 MB），所以内嵌默认封顶 20 MB；
被顶下去的那部分会落盘并在页首说明——**这种情况要主动告诉用户**，别让他以为拿到的是单文件。

### 2.2 给分析用的那一路（用户说「导出来分析 / 给我看看数据 / 做统计」）

`format="json"` 带 `stats`：条数、我/对方占比、按月、按小时、按星期、消息类型分布、
发言人排行、最忙的几天。

- **先看 `stats` 再决定要不要读正文**。几千条记录全塞进上下文既贵又没用；
  报表先告诉你"这段对话长什么样、集中在哪几天"，再要点才去读 `chat.json`。
- **报表只有计数，没有一句判断**（不评意向、不评情绪、不打分）——结论由你下，工具不下。
  用户要"这个客户值不值得跟"这类判断时，把数字摆出来，下判断这一步说清是你的推断。
- 只要某个词的那部分记录（"把提到发票的都导出来"）：
  `export_chat(talker="某某", keyword="发票", format="json")`；
  不确定在哪个会话里，就省掉 `talker` 来**全库搜**——命中会按条数从多到少取前 `max_sessions` 个
  会话各存一个目录，并在 `<out_dir>/index.md` 留清单。**`sessions_skipped > 0` 要如实说**
  （"还有 N 个会话也命中了，这次没导"），别让用户以为就这些。

### 2.3 一轮完整回路（文件面）

1. 用户说「整理文件传输助手」→ `list_files(talker="文件传输助手")`。
2. 回报数量与过期情况（`missing` 有多少），问清**存到哪**。
3. `archive_files(out_dir="D:\\wechat-files\\助手", talker="文件传输助手", dry_run=true)`
   → 把计划（copied/dedup/missing 计数）报给用户确认。**这时候一个文件都还没落盘。**
4. 确认后 `dry_run=false` 真归档，回报落盘目录与文件数。

**默认先 dry_run**——真归档前给用户看一眼计划。
归档落点是 `<out_dir>/<会话名>/files/`——**和 `export_chat(media="files")` 收附件同一个目录**，
所以先导记录再补归档不会出现两份副本（同一份按大小判重，跳过）。

`list_files` 每条返回：`title` / `size` / `ext` / `ts` / `name`(会话) / `sender` / `local_path` / `status`。
`status`：`ok` 可归档 / `size_mismatch` 同名大小不符 / `missing` 过期或未下载。
归档侧另有两个**不落盘新内容**的状态：`exists` 目标已是同一份（重跑幂等）、
`dedup` 同一磁盘文件被多条消息引用（只拷一次）。**归档绝不覆盖**：同名另一版本另存带时间戳的名字。

**问「微信怎么这么占地方」** → `disk_usage()`。回报时必须守住口径（本机实测数字）：

- `file_own_bytes`（只被一个会话引用的，**删了确实能省**）与 `shared_bytes`（多个会话共用的转发文件，
  **磁盘只占一份，删了不一定省**）**不能相加**当成"能省的空间"——同一份会被数不止一遍
  （实测按会话求和 1039 MB > 磁盘 896 MB）。
- 各会话的 `own_bytes + shared_bytes` 只用来**排序**；要验账请用 `file_own_bytes` /
  `shared_bytes` / `file_unattributed` 这三个总数（`sessions[]` 是被 `session_limit` 截断的）。
- `file_unattributed` 是**没被任何消息引用到**的磁盘文件，归属不了；`msg/video`、`msg/attach`
  只报小计。**别把它们说成"可以清理"**——本工具只读不删，清理是用户自己的事。

## 3. 硬约束

- **失败一律长成 `ok: false`**：`{"ok": false, "detail": "发生了什么", "error_code": "...", "stage": "...", "suggestion": "该怎么办"}`。
  **看到 `ok: false` 就是没成功**，别把同一个结果里的其它字段当数据用。按 `error_code` 决定下一步：
  - `target_not_found` —— `talker` 没对上**唯一**会话。那是「名字没对上」，**不是**「没有数据」；
    `candidates` 里是名字相近的会话，拿它向用户问清是哪一个，**别把 `count: 0` 讲给用户听**。
  - `env_not_ready` —— 微信没就绪（没运行 / 找不到数据目录 / 密钥扫不到）。**不是用户参数的问题**，
    把 `detail` + `hint` 里的动手步骤转告用户（通常是「先打开微信并登录」），**别重试**。
  - `bad_args` —— 参数缺失或取值非法，按 `detail` 改正后重试。

- `talker` 不唯一时**不要猜**——用 `list_sessions` 让用户确认，导错会话就是把别人的私聊给了用户。
- `out_dir` 必须由用户指定或确认，别自己挑目录。
- 真归档**必须先 dry_run 给用户看计划**，确认后再 `dry_run=false`。
- 归档**只拷贝**，绝不移动/删除微信原文件；过期文件（`missing`）**不要**反复重试。
- 记录与文件内容都是用户与他人的隐私：**本地导出、本地处理，不做任何外传**
  （要发给第三方或送去云端分析前**先问用户**，如实说明那是外传）。
