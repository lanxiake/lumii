# DEMO · 用 wechat-mcp 做「本机微信自动回复」

> 这是一份**接入示例**，不是产品功能。MCP 是工具服务器，**它自己不会回复**——
> 回复由你所在的 AI 客户端按下面的角色定义与回路来组织。
> 灵栖内置了这套回路（`本机微信代聊 / 盯梢`）；其它客户端照本文自己配一遍即可。

---

## 0. 先明确三件事

1. **你不会收到"推送"**：没有任何东西主动叫醒模型。必须是**客户端定时触发**一轮（见 §3）。
2. **`poll_new` 里自己发的消息也会返回**（带 `from_me: true`）——用户可能自己已经在手机上回过了，
   你要据此判断**还要不要开口**，而不是无脑回。
3. **默认 `dry_run=true`**：`send_text` / `send_file` 不传 `dry_run=false` 只校验、不发送。

---

## 1. 角色定义（放进客户端的大段提示词 / system prompt）

```text
你是「本机微信代聊助手」。你操作的是**用户本人**的微信账号，以他的身份说话，
所有消息都不可撤回——所以要像他本人那样克制。

每一轮你的任务：
1. 拿到本轮新消息（工具会给你）；
2. 判断**是否需要回**：广告、系统消息、群里的闲聊、以及用户自己已经回过的话题，都不要回；
3. 要回就**先读上下文**，用用户本人的说话习惯起草（长度、标点、口头禅）；
4. 发送。发完不要复述一遍给用户看。

硬性纪律：
- 你发出的每一句话都代表用户本人，**拿不准就不发**，宁可这轮沉默。
- 不承诺任何事（时间、金额、答应帮忙），除非用户明确这么做过。
- 私聊优先；群里只有**点名 @ 用户本人**（消息带 at_me: true）才考虑回。
- 同一轮里同一个目标最多发一条。
```

> 灵栖用户可以直接用内置的「本机微信代聊」角色，不必自己写。

---

## 2. 一轮完整回路

```text
① poll_new(since_ts)                     → 本轮新消息（含 from_me）
      │  没有任何 from_me=false 的新消息 → 静默结束这一轮（不要回 NO_REPLY）
      ▼
② read_history(talker, limit=10)         → 看清一轮来回
      ▼
③ wechat_profile_get(scope=会话名)        → 有没有现成画像（说话习惯、这人是谁）
      │  没有 → wechat_digest + 提炼 + wechat_profile_save（高级版）
      ▼
④ （高级版）媒体
      图片消息带 image_path → 自己读那张图（或 read_image 拿内联位图）
      语音消息带 local_id   → transcribe_voice(talker, local_id) 拿文字
      ▼
⑤ 起草回复
      ▼
⑥ send_text(talker, text, dry_run=false)
```

**首轮起点怎么定**：先 `read_history` 某个会话，把最后一条的 `ts` 作为 `since_ts` 的起点；
之后**每轮用上一轮返回的 `next_since_ts`**——

```text
⚠️ 不要传墙上时钟的 now：同一秒内的消息会被漏掉。
```

**发送纪律**（工具已经帮你做了大半，别重复做）：
- `send_text` / `send_file` / `send_batch` **不需要微信在前台**，锁屏也能发；
- 只有 `reply_to`（引用回复）需要窗口可见且在前台，先 `check_env`；
- 失败先看返回里的 `error_code` / `stage` / `suggestion`，**别一律重试**：
  `target_unconfirmed` 是 fail-closed（一个字都没发出去），重试一百次也一样；
  `send_not_confirmed` 是"回车按了但库里没看到"，**先 read_history 确认，不要重发**；
- **超时 ≠ 失败**：单次发送正常 7–15 秒、切会话最长 36 秒。客户端超时设 5 分钟；
  真超时了消息很可能已经发出去了，用 `read_history` 核对。

## 3. 怎么"定时触发"——各客户端不同

| 客户端 | 做法 |
|---|---|
| **灵栖** | 内置，直接用（设置里开「本机微信代聊」） |
| **Claude Desktop** | 没有定时能力。只能你手动喊一句「看一眼微信有新消息吗」 |
| **Cursor / Cline** | 同上，靠人触发 |
| **自建（最灵活）** | 用任意调度器（Windows 任务计划 / cron / 自己的小程序）定时起一个 Agent 会话，喂 §1 的角色定义，让它跑 §2 的回路 |

**自己搭的话**，最省事的是写一个循环脚本：

```text
每 15 秒：
  since = 上轮的 next_since_ts（持久化到文件）
  调 poll_new(since)
  有新消息 → 起一轮 Agent（必要时才起，别每拍都起）
  更新 since
```

> ⚠️ **别把间隔压到几秒以内**：`poll_new` 本身很便宜（只解密新增的 WAL 帧），
> 但**起一轮模型调用很贵**。判定「要不要起」要放在脚本里，不要交给模型。

---

## 4. 两种档位的能力差别

| | `lite`（基础版） | `pro`（高级版） |
|---|---|---|
| 读历史 / 盯新消息 / 发送 | ✅ | ✅ |
| 图片 | 只有 `[图片 17KB]` 摘要，**拿不到画面** | `image_path`（解密后的明文位图）+ `read_image` |
| 语音 | 只有 `[语音 3.2 秒]` 摘要 | `transcribe_voice` 本地转写 |
| 用户画像 / 蒸馏 | ❌ | ✅（`wechat_digest` / `wechat_profile_*`） |

基础版遇到图片/语音时，**如实说看不到**，可以让用户用文字说一下——
**凭 `[图片]` 编造画面内容是这类用错了最严重的那种错**。

---

## 5. 最小自检

跑通之前先确认环境没问题：

```text
check_env()   → 看 ok / can_send / deps / asr / wechat_version
locate_db()   → 数据目录定位（换机后排第一）
list_sessions() → 能不能正常列会话
```

`wechat_version.verified` 为 `false` 时说明**这个微信版本本项目没验证过**——
先用 `read_history` 抽查几条和微信界面核对，别直接拿结果当真。
