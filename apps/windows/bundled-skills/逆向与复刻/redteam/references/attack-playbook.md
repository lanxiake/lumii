# 攻击面清单（逐类过，不许跳）

**用法**：一类一节，每节都先问「**我这个功能有没有**」。没有就记「不适用 + 为什么」，
不要因为「应该不会有」就跳过——那正是漏洞待的地方。

每类的四段固定：**我有没有** → **怎么验证** → **怎么判成功** → **改哪里**。

---

## 1. XSS（反射 / 存储 / DOM）

### 我有没有

任何「用户输入会被渲染成 HTML」的地方：评论、昵称、简介、富文本、搜索回显、错误页带参数、
`dangerouslySetInnerHTML` / `v-html` / `innerHTML`。

### 怎么验证

- **反射**：把 `?q=<img src=x onerror=alert(1)>` 打到搜索页，看是否原样进 HTML。
- **存储**：提交评论/昵称后，**换一个账号或隐身窗口**打开同一页面。
- **DOM**：在 URL 的 hash / query 里放 `#<img src=x onerror=alert(1)>`，
  再看页面有没有把 `location.hash` 塞进 `innerHTML`。

用 `browser_navigate` 打开带 payload 的 URL、`browser_eval` 读
`document.querySelector('#target').innerHTML` 确认是否被转义。

### 怎么判成功

`alert` 弹出来只说明「能执行」；要判**影响**，看：
- Cookie 是不是 `HttpOnly`（能读 ⇒ 可窃取会话）
- 能不能用 `fetch('/api/me')` 带 cookie 读到敏感数据

### 改哪里

输出编码（按上下文：HTML / 属性 / JS / URL 各自一套），或改用框架的自动转义路径。
**不要用黑名单过滤 `<script>`**——那挡不住 `<img onerror>`。

## 2. CSRF

### 我有没有

任何「靠 cookie 鉴权 + 改状态」的接口：改密码、改邮箱、下单、发消息、删除。
纯 Token（Authorization 头）的接口天然不受影响。

### 怎么验证

1. 以 alice 登录，抓一个改状态的请求，记下它的**全部参数**。
2. 新建一个本地 HTML（放在另一个源，比如 `http://127.0.0.1:8080`），里面自动提交同样参数的表单。
3. 在 alice 还登录着的情况下打开它，回来看状态有没有被改。

```html
<form action="http://localhost:3000/api/profile/email" method="POST">
  <input name="email" value="attacker@evil.test">
</form>
<script>document.forms[0].submit()</script>
```

### 怎么判成功

状态**真的变了**才算。返回 200 但没改，不算。
再看服务端有没有校验 `Origin` / `Referer` / CSRF token。

### 改哪里

CSRF token（每会话/每请求）+ `SameSite=Lax` 起步 + 危险操作二次确认。

## 3. SSRF

### 我有没有

任何「服务端按用户给的 URL 去取东西」的功能：图片导入、webhook、URL 预览、PDF 生成、订阅源。

### 怎么验证

把目标换成内网地址，看服务端行为：

| 输入 | 期望（安全的） | 危险信号 |
|---|---|---|
| `http://127.0.0.1:22` | 拒绝或超时 | 返回 banner 文本 / 连接成功 |
| `http://169.254.169.254/latest/meta-data/` | 拒绝 | 返回云元数据 |
| `http://localhost:3000/api/admin` | 拒绝 | 返回内网接口内容 |
| `file:///etc/passwd` | 拒绝 | 返回文件内容 |

**只打你自己这一台机器上的端口**，不扫内网其它主机。

### 怎么判成功

响应体里出现**只有内网才能拿到的东西**（banner、元数据、内部页面）。

### 改哪里

协议白名单 + 解析后 IP 黑名单（内网段/回环/链路本地）+ 禁跳转或跳转后再校验。

---

## 4. IDOR（越权访问对象）

### 我有没有

任何「URL 或请求体里带对象 id」的接口：`/api/orders/123`、`?userId=7`、`DELETE /files/9`。

### 怎么验证

1. 用 alice 建两条数据，记下 id（比如 101）。
2. 用 bob 登录，把请求里的 id 换成 alice 的 101。
3. 看能不能读到 / 改到 / 删掉。

**三种动作都要试**：读（信息泄露）、改（数据篡改）、删（破坏）。

### 怎么判成功

bob 拿到了 alice 的数据，或改了/删了。**返回 403 不算**。

### 改哪里

每个对象操作都要在**服务端**校验归属，不能靠前端不显示 id。

## 5. 认证与会话

### 我有没有

登录、注册、找回密码、记住我、第三方登录。

### 怎么验证（每项单独做）

| 检查 | 怎么做 | 危险信号 |
|---|---|---|
| 密码强度下限 | 注册 `a` | 注册成功 |
| 用户名枚举 | 登录时对比「存在的用户」与「不存在的用户」的响应差异 | 文案/状态码/耗时明显不同 |
| 暴力破解防护 | 同一账号连错 5-10 次 | 没有锁定/延迟/验证码 |
| 找回密码令牌 | 看令牌长度与是否一次性 | 短、可预测、可复用 |
| 登出是否失效 | 登出后用旧 cookie 请求 | 仍然 200 |
| 会话固定 | 登录前后 session id 是否变 | 不变 |

### 怎么判成功

上表每一项都是一个独立的 Finding，**不要合并成「认证有问题」一句话**。

### 改哪里

服务端强制，不靠前端；令牌用 CSPRNG；登录后轮换 session。

## 6. 注入（SQL / 命令 / 模板）

### 我有没有

搜索框、筛选、排序字段、导出、任何拼 SQL 或拼命令的地方。

### 怎么验证

- **SQL**：在搜索框输入 `'`，看是否报 SQL 错误（这是信息泄露，本身就是一个 Finding）；
  再试 `' OR '1'='1` 看是否返回异常多的结果。
- **命令**：只在**你自己写的**功能上试（如「生成缩略图」「转码」），
  输入 `; sleep 3` 看响应是否明显变慢。
- **模板注入**：输入 `{{7*7}}`、`${7*7}`，看是否被求值。

### 怎么判成功

**报错信息本身就是 Finding**（泄露了表名/路径）。
求值/时间差则证明注入可达。

### 改哪里

参数化查询；命令用数组传参不用 shell 拼接；模板别把用户输入当模板编译。

## 7. 文件上传

### 我有没有

头像、附件、导入。

### 怎么验证

1. 传一个 `.php` / `.jsp` / `.js` 后缀的文件（内容无所谓）。
2. 看返回的 URL：是**同源可执行目录**还是独立存储域？
3. 传一个超大的文件（比如 100 MB）看有没有大小限制。
4. 传一个文件名含 `../` 的（`../../evil.txt`）看落点。

### 怎么判成功

- 能上传可执行脚本且落在 Web 可访问目录 ⇒ 高危
- 能路径穿越写出目录 ⇒ 高危
- 无大小/类型限制 ⇒ 中危（可当存储滥用）

### 改哪里

白名单扩展名 + 服务端嗅探真实类型 + 存到独立域/非执行目录 + 重命名。

## 8. 敏感信息与配置

### 我有没有

任何前端能拿到的配置、错误页、源码映射、API Key。

### 怎么验证

- 打开浏览器 devtools 的 Network/Source，看有没有 `*.map`、`.env`、`config.json`。
- 请求一个不存在的路径，看错误页有没有堆栈/路径/框架版本。
- `grep` 前端产物里的 `key`、`secret`、`token`、`password`。

### 怎么判成功

拿到**真实的**凭据或能定位内部结构的堆栈。
`NEXT_PUBLIC_*` 这类**设计上就公开**的不算——写 Finding 前先确认它不是故意的。

### 改哪里

密钥只放服务端；生产关 sourcemap；错误页给通用文案。

---

## 9. 不适用时的写法

```markdown
## 3. SSRF —— 不适用
本应用没有任何「服务端按用户给的 URL 取资源」的功能；图片走前端直传对象存储。
依据：`app/api/` 下 7 个路由全部只接受 file 流，无 URL 参数。
```

**要有依据**（哪个目录、哪几个文件），不要只写「没有这个功能」。
