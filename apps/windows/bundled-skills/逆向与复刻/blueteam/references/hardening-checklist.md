# 加固清单（按漏洞类别）

用法：拿到 Finding 后查到对应类别，**逐条核对**。每条都要能回答「这一条我改了吗 / 为什么不需要」。

---

## XSS

- [ ] **按上下文编码**：HTML 正文 / 属性值 / URL / JS 字符串各自一套，不是通用「转义」
- [ ] 富文本走**白名单**净化（DOMPurify 一类），黑名单无效
- [ ] 框架的自动转义**不要绕开**：`dangerouslySetInnerHTML` / `v-html` / `|safe` 每次出现都要有理由
- [ ] `innerHTML` 只在内容是**你自己拼的静态串**时使用
- [ ] **CSP**：`default-src 'self'`，禁 `unsafe-inline`（内联脚本改用 nonce/hash）
- [ ] Cookie：`HttpOnly` + `Secure` + `SameSite=Lax`，会话令牌不给 JS 读
- [ ] **全仓找同类**：`grep -rn "dangerouslySetInnerHTML\|innerHTML =\|v-html"`，一次改完

## CSRF

- [ ] 所有改状态的接口校验 CSRF token（每会话或每请求）
- [ ] `SameSite=Lax` 起步；跨站嵌入场景才考虑 `None` + `Secure`
- [ ] 危险操作（改邮箱/改密码/转账/删除）要求二次确认或重新验证密码
- [ ] **不用 GET 改状态**
- [ ] 校验 `Origin` / `Referer` 作为第二道（不是唯一一道）

## SSRF

- [ ] 协议白名单（通常只 `http`/`https`）
- [ ] 解析后的 **IP** 做黑名单：`127/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、`fc00::/7`
- [ ] **禁止自动跳转**，或跳转后重新校验（`redirect: 'manual'`）
- [ ] DNS 重绑定：解析一次后按 IP 连接，别「先校验域名再按域名连」
- [ ] 出站用独立网络策略（容器网络策略/代理），不靠应用层单点

## IDOR / 越权

- [ ] 每个对象操作在**服务端**校验归属（不能只靠前端不显示 id）
- [ ] 列表接口同样要过滤（`WHERE owner_id = :me`），不只是详情接口
- [ ] 批量接口逐项校验，不能只校验第一条
- [ ] id 用不可预测值（UUID）只是降低难度，**不是**替代鉴权
- [ ] 全仓找同类：`grep -rn "findById\|findUnique.*id"`，逐个确认有没有 `owner` 校验

## 认证与会话

- [ ] 密码下限（长度 ≥ 8 + 常见密码黑名单），服务端强制
- [ ] 登录失败不做用户枚举（统一文案 + 统一耗时）
- [ ] 登录限流 + 渐进延迟（5 次后放缓，10 次后锁定）
- [ ] 令牌用 CSPRNG，够长（≥ 128 bit），一次性
- [ ] 登录成功后**轮换** session id
- [ ] 登出真的失效（服务端销毁，不是只清 cookie）
- [ ] 敏感操作重新验证

## 注入

- [ ] SQL 全部参数化（ORM 的 `whereRaw` 一类同样要查）
- [ ] 排序/表名字段用**白名单映射**，不能直接拼
- [ ] 命令用数组传参，不经 shell；必须用 shell 时对每个参数转义
- [ ] 模板不把用户输入当模板源码编译（SSTI）
- [ ] 生产环境**关掉详细错误页**（堆栈泄露表名/路径）

## 文件上传

- [ ] 扩展名白名单 + **服务端嗅探真实类型**（magic bytes，不信 Content-Type）
- [ ] 存到**不可执行**目录或独立域/对象存储
- [ ] 重命名（不用用户提供的文件名）；路径穿越校验
- [ ] 大小上限 + 数量上限
- [ ] 图片二次编码（去掉内嵌脚本与 EXIF）

## 敏感信息

- [ ] 密钥只在服务端；前端只有设计上就公开的（`NEXT_PUBLIC_*` 之类）
- [ ] 生产关 sourcemap
- [ ] `.env` / `.git` / 备份文件不可访问
- [ ] 日志不记录密码、令牌、身份证、完整卡号
- [ ] 响应最小化：不把整条 ORM 实体直接返回（含密码哈希、内部字段）

## 依赖与配置

- [ ] `npm audit` / `pnpm audit` 无高危（或已确认不可达并记录）
- [ ] 锁文件进版本控制
- [ ] 默认凭据全部改掉（数据库、管理后台、示例账号）
- [ ] CORS 不用 `*` 且带凭据；白名单精确

---

## 改完之后

1. **全仓重跑一遍规则**（`semgrep --config security/rules/`），确认无命中；
2. **同一模式找全**：一个洞通常意味着同类还有几处，`grep` 找完再收工；
3. 回到 `security/rules/VERIFY.md` 把「对着修复后的代码跑」那一列填上；
4. 能跑测试就跑（`npm test` / `npm run build`），补丁不能破坏构建。
