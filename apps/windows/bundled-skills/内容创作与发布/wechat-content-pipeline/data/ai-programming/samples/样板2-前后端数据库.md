上周有个读者给我发消息：

> "我让 AI 帮我做了个网站，它写了一堆文件，有的叫 `.html`，有的叫 `.py`，有的好像是数据库的东西……我完全不知道它们之间是什么关系，感觉一团乱麻。"

这个感受我太熟悉了。

用 AI 写代码，它会一口气给你生成十几个文件。你不知道哪个负责什么，改了一个地方报错了也不知道从哪找问题。

**这不是 AI 的问题，是你缺少一张"技术地图"。**

有了这张地图，你就能看懂 AI 在做什么，在它跑偏的时候把它拉回来。没有这张地图，你只能对着一堆代码发呆。

今天我们来把这张地图画出来。

## 理论：用一次"寄快递"，讲清楚三层架构

我用过很多类比来解释前后端，最好用的还是**寄快递**。

<!-- IMAGE:02 type=infographic path=images/02-architecture.png -->

想象你要网购一件衣服：

**你看到的那个购物网页**，可以选颜色、看图片、点"加入购物车"——这是**前端**。

**后台处理你订单的系统**，判断库存够不够、算运费、通知仓库发货——这是**后端**。

**记录所有订单、用户、库存的那本大台账**——这是**数据库**。

三者分工明确：

| 角色 | 类比 | 负责什么 | 技术举例 |
|------|------|---------|---------|
| **前端** | 快递网站的网页 | 你看到的、点击的一切 | Vue、React、HTML |
| **后端** | 快递公司的调度中心 | 处理业务逻辑、连接数据库 | Python、Node.js、Go |
| **数据库** | 仓库里的台账本 | 永久保存所有数据 | MySQL、PostgreSQL |

**三者怎么配合？**

你在前端点"下单"→ 请求发给后端 → 后端查数据库确认库存 → 数据库返回数据 → 后端处理后告诉前端"下单成功" → 前端显示给你看。

**一次点击背后，是这三层的接力。**

---

### 前端：你的程序的"脸"

前端就是用户能看到、能摸到的一切。

- 网页上的按钮、表单、图片、颜色
- 点击之后的动画、弹窗、跳转
- 手机 App 的界面

**前端不存数据，不做判断，只负责展示和收集输入。**

类比：快递网站的网页。它展示商品信息、让你填地址，但它自己不知道仓库还有多少货——这个要问后端。

---

### 后端：你的程序的"大脑"

后端处理所有真正的业务逻辑。

- 验证你的账号密码对不对
- 算出这个订单该收多少钱
- 判断这个用户有没有权限看这个内容
- 调用第三方服务（发短信、支付、地图）

**后端是前端和数据库之间的中间人。** 前端把请求发过来，后端处理完再把结果存进数据库或返回给前端。

类比：快递公司的调度中心。接到你的订单之后，它决定从哪个仓库发货、走哪条路线、通知哪个快递员。

---

### 数据库：你的程序的"记忆"

数据库存储所有需要持久保留的数据。

- 用户注册的信息
- 每一笔交易记录
- 文章、评论、设置

**没有数据库，程序一关闭所有数据就消失了。**

类比：快递公司的台账本。每笔单子、每个地址、每个包裹状态，全记在上面。台账本坏了，公司就不知道谁的货送到哪了。

---

## 为什么选 Python + Vue + MySQL？

学完三层架构，你可能会问：市面上有那么多技术，为什么这个系列选这三个？

<!-- IMAGE:03 type=infographic path=images/03-tech-choice.png -->

选择的逻辑很简单——**对 AI 来说，哪个出错率最低，我们就用哪个**。

**Python（后端）**：AI 训练数据里 Python 代码最多，生成质量最高，报错信息最容易看懂。对零基础读者来说，跑通率最高。

**Vue（前端）**：国内用得最多，移动端有 uniapp 加成，中文文档和社区资源丰富，AI 生成的 Vue 代码 bug 少。

**MySQL（数据库）**：免费、通用、安装资料最多，几乎所有主机和云服务都支持。学会了 MySQL，其他数据库触类旁通。

> 注意：这不是"最好的技术栈"，是**最适合零基础配合 AI 上手的技术栈**。掌握方法论之后，换其他技术会非常轻松。

## 实操：让 AI 帮你画出项目架构图

光说不练不够用。现在我们做一件有意思的事：**用 AI 帮你把一个真实项目的架构图画出来，并逐层解释**。

**打开 Claude Code**（`cd` 进一个文件夹，输入 `claude` 启动），把这段提示词复制进去：

```
我想做一个「个人记账小工具」，功能是：
- 用户可以记录每笔收支（金额、类别、备注）
- 可以查看每月的收支统计
- 数据要永久保存，重启不丢失

请帮我：
1. 画一张这个项目的三层架构图（前端/后端/数据库各负责什么）
2. 列出每一层会用到的技术（用我们系列的 Vue + Python + MySQL）
3. 用大白话解释三层之间数据是怎么流动的

用 Mermaid 格式输出架构图，然后用文字解释。
```

AI 会给你一张架构图 + 逐层文字解释。你不需要看懂每一行代码，只需要**理解三层各管什么、数据怎么流**。

<!-- IMAGE:04 type=screenshot path=images/04-ai-architecture.png -->

看完之后，你对自己要做的项目会有一个清晰的"鸟瞰图"——这是后续用 AI 写代码的地基。

## 避坑：两个最常见的认知误区

**误区 1："前后端分离"听起来很复杂**

很多人一听"前后端分离"就头大，以为是高级技术。其实就是前端和后端**分开部署、通过 API 通信**，不是什么神秘概念。我们系列一开始先做"合在一起"的简单版本，后面再拆分。

**误区 2："数据库要先学 SQL 才能用"**

不用。你只需要知道"数据库是用来存数据的台账本"，具体的 SQL 语句全让 AI 写。第12篇我们会专门讲，到时候你就懂了。

---

## 本篇小结

三句话，可以截图保存：

1. **前端 = 脸**，用户看到的、点到的一切；**后端 = 大脑**，处理所有逻辑；**数据库 = 记忆**，永久保存数据
2. **三层接力**：前端发请求 → 后端处理 → 数据库存取 → 后端返回 → 前端展示
3. **选 Python + Vue + MySQL**，不是最好的，是对零基础 + AI 最友好的
