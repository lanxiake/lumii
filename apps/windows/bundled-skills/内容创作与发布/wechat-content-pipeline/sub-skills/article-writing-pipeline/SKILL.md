# Article Writing Pipeline · 文章创作流水线

## 一、为什么需要这个技能

写一篇能打动读者的文章不是单点工作，而是一条流水线：要先想清楚主题、研究清楚事实、设计清楚结构、写清楚每一段、配清楚每一张图、改清楚每一个平台版本。

过去我们把这些步骤散落在六七个不同的技能里，每次切换都要重新对齐输出格式。这个技能把它们串起来，定义统一的中间产物（research.md / outline.md / draft.md / images/ / platform/{wechat,xhs,douyin}.md），让每一个阶段都为下一个阶段服务，不重复、不遗漏。

## 二、核心理念

**流水线不是顺序，而是约束。** 每个阶段的输出都必须满足下一阶段的输入契约——研究阶段必须输出可被引用的事实卡片，大纲阶段必须输出可被段落填充的层次结构，写作阶段必须输出可被精准配图的语义片段。

**写作的产能瓶颈在判断，不在打字。** AI 能批量生成文字，但什么该留、什么该删、哪个角度更打动读者，需要人来判断。这个流水线把判断点暴露在每个阶段交接处，而不是闷头一口气写完才让用户看。

**配图是压缩工具，不是装饰。** 只有当图能比文字更高效地传递信息时才插图，否则不插。本流水线用 visual-explanation 的三层递进结构（核心观点→机制关系→边界说明）来决定要不要画图、画什么图。

## 四、目录约定

每篇文章建立一个工作目录，建议命名：`articles/YYYYMMDD-topic-slug/`

```
articles/20260529-vibe-coding-intro/
├── user_brief.md           # 阶段0：用户意图与约束
├── research.md             # 阶段1：研究素材
├── outline.md              # 阶段2：大纲
├── draft.md                # 阶段3：正文初稿
├── final.md                # 阶段3：定稿（人工修订后）
├── images/                 # 阶段4：所有图片
│   ├── 01-cover.png
│   ├── 02-flow-diagram.png
│   └── prompts.md          # 每张图的提示词记录
└── platform/               # 阶段5：各平台改编
    ├── wechat.md
    ├── xhs.md
    └── douyin.md
```

这个结构是**强约定**：下游阶段直接按路径读上游产物，不通过参数传递。任何阶段都可以从对应文件重新开始，不需要重跑前面所有步骤。

## 阶段0：意图澄清

**目的**：在动笔前对齐三件事——读者是谁、目标是什么、能写多深。

**触发条件**：用户给出一个新主题且没有明确说"按之前的来"。

**必须澄清的5个维度**（如果用户没说，就直接问）：

| 维度 | 默认值 | 关键问题 |
|------|--------|---------|
| 读者画像 | 完全零基础 | "这篇是给谁看的？刚入行还是已经在用？" |
| 内容类型 | A类干货 | "想做干货教程、个人观点、还是带商业转化的软文？" |
| 平台 | 公众号为主 | "首发哪个平台？要不要同步小红书/抖音？" |
| 篇幅 | 1500-2500字 | "想要一篇深度长文还是几百字快读？" |
| 核心动作 | 让读者读完后理解某个概念 | "读完这篇你希望读者去做什么？" |

**输出**：`user_brief.md`

```markdown
# 用户意图说明

- 主题：{一句话主题}
- 读者：{完整画像描述}
- 内容类型：{A类干货 / B类测评 / C类植入}
- 首发平台：{公众号/小红书/抖音}
- 同步平台：{...}
- 目标篇幅：{字数范围}
- 读完动作：{读者预期行为}
- 系列定位：{是否系列文章，第几篇}
- 已有素材：{用户提供的任何参考链接、数据、截图}
- 红线：{不能提的内容、不能用的措辞}
```

**判断标准**：如果不能用 user_brief.md 推导出"这篇文章绝对不会写什么"，就还没澄清完。

## 阶段1：主题研究

**目的**：把模糊的"我想写X"变成可被引用的事实卡片，避免写作阶段陷入"凭印象编"。

**调用子技能**：`content-research-writer-cn` 的研究模块。

**研究三件事**：

1. **事实层**：和主题相关的数据、新闻、案例。来源必须可追溯（URL 或出版物）。
2. **观点层**：业内主流观点、争议焦点、最新转向。
3. **故事层**：能用作 hook 或具体案例的人物/事件。

**研究方法**：

```
优先级：firecrawl_search > WebFetch > WebSearch
理由：firecrawl_search 返回完整页面内容，便于抽取事实卡片
```

**输出**：`research.md`

```markdown
# 主题研究：{主题}

## 一、关键事实卡片

### 卡片1：{事实标题}
- 数据/陈述：{原文摘录}
- 来源：{URL 或出版物 + 日期}
- 可信度：{高/中/低}
- 用法：{适合做 hook / 论据 / 案例}

### 卡片2：...

## 二、观点谱系

| 观点立场 | 代表人物/媒体 | 核心论据 |
|---------|--------------|---------|
| {立场A} | ... | ... |
| {立场B} | ... | ... |

## 三、可用故事/案例

- 案例1：{一句话概括} — 来源：...
- 案例2：...

## 四、研究空白与风险

- 这个主题里我没找到充分证据的：...
- 容易被误读 / 被反驳的点：...
```

**质量门禁**：至少 5 张事实卡片 + 2 个具体案例 + 标注研究空白。如果达不到，先回到阶段0问用户要素材或者承认主题选小一点。

## 阶段2：大纲设计

**目的**：把研究素材组装成一篇文章的骨架，每个段落必须能回答"为什么读者要继续读"。

**调用子技能**：`blog-post` 的5段式结构。

**5段式结构**：

```
① Hook（钩子）：50-150字
   用最具体的事实/数字/反常识陈述抓住注意力。
   绝不用"在当今这个时代"开头。

② Context（上下文）：200-400字
   建立共同语境：读者大概率知道什么，这篇要解决的是什么具体问题。

③ Main（主体）：占总字数 50-60%
   按"反模式优先"框架：先展示错误做法 → 解释为什么错 → 给出正确做法。
   主体必须分2-4个小标题，每个小标题对应一个事实卡片。

④ Practical（落地）：占总字数 15-20%
   读者读完能立刻照做的最小动作。具体到"打开X、点Y、输入Z"。

⑤ CTA（行动召唤）：100-200字
   单一行动：评论/转发/进群/读下一篇。绝不在 CTA 里塞两个动作。
```

**配图占位规则**：

每张图必须在大纲里就标好位置和用途。决策树：

```
该位置需要图吗？
├─ 文字已经能讲清楚 → 不画
└─ 文字解释起来超过3段
   ├─ 是流程/步骤 → Mermaid 流程图（路径B）
   ├─ 是对比/权衡 → 表格或2×2矩阵（路径C 或 Markdown 表格）
   ├─ 是抽象概念/场景 → AI 插画（路径A，gpt-image-2-pro）
   └─ 是数据 → 条形图或卡片（路径C Canva）
```

**输出**：`outline.md`

```markdown
# 大纲：{主题}

## 标题候选（3个）
1. {数字+反差}：...
2. {提问式}：...
3. {利益承诺式}：...

## 副标题（系列定位）
> 系列：... | 适合读者：... | 阅读时间：...

## ① Hook
- 一句话：...
- 用到的事实卡片：#3
- 配图：[封面图，AI生成，路径A]
  - 提示词草稿：...

## ② Context
- 一句话：...
- 用到的事实卡片：#1, #2

## ③ Main

### 小标题1：{...}
- 反模式：...
- 正确做法：...
- 用到的事实卡片：#4
- 配图：[Mermaid 流程图]

### 小标题2：{...}
- ...

### 小标题3：{...}
- ...

## ④ Practical
- 第一步：...
- 第二步：...
- 第三步：...

## ⑤ CTA
- 单一行动：...
- 文案：...

## 图片清单（汇总）
| 编号 | 类型 | 路径 | 提示词文件 |
|------|------|------|-----------|
| 01 | 封面 | images/01-cover.png | images/prompts.md#cover |
| 02 | Mermaid | 直接嵌入md | - |
| 03 | 概念图 | images/03-concept.png | images/prompts.md#concept |
```

**质量门禁**：大纲中的每个小标题都能用一句话回答"读者读完这一节会带走什么"，否则继续打磨。

## 阶段3：正文写作

**目的**：把大纲的骨架填成血肉。

**调用子技能**：`content-research-writer-cn`（中文写作风格）+ `visual-explanation`（图文配合）。

**写作7条铁律**（从已验证的范文中提炼）：

1. **不用"在当今这个X时代"开头**，用具体数字或反常识陈述。
2. **每段不超过3句话**，超过就分段。手机阅读场景下，长段是劝退器。
3. **类比必须落地**。"AI 像副驾"比"AI 像智能助手"好，因为副驾这个角色读者立刻能套用。
4. **反模式优先**。先写❌错的做法，再写✅对的做法。读者从对比中学得最快。
5. **数据必须有出处**。任何百分比、金额、时间都要么有研究卡片支持，要么删除。
6. **删掉所有"非常"、"极其"、"十分"**。强度词等于没说。
7. **结尾不写总结**，写一个能让读者立刻行动或评论的钩子。

**写作流程**：

```
读 outline.md → 读 research.md → 逐段填充：
  for 每个小节 in outline:
    1. 把对应的事实卡片摆在面前
    2. 写一段、读一段，问自己"这段如果删了文章会缺什么"
       缺 → 留；不缺 → 删
    3. 写完一节 → 标记需要配图的位置 → 进入阶段4
  全文写完后整体读一遍：
    - 第一段能不能换成更具体的开头？
    - 中间有没有连续3段没有具体例子？
    - 结尾的 CTA 是不是单一动作？
```

**输出**：`draft.md`，遵循 outline.md 的图片占位标记。

**关键标记格式**（供阶段4识别）：

```markdown
<!-- IMAGE:01 type=cover prompt-ref=images/prompts.md#cover -->

正文段落...

<!-- IMAGE:02 type=mermaid -->
\`\`\`mermaid
flowchart LR
  A[输入] --> B[处理] --> C[输出]
\`\`\`

正文段落...

<!-- IMAGE:03 type=ai-generated prompt-ref=images/prompts.md#concept -->
```

**质量门禁**：把 draft.md 通读一遍能在 8 分钟内读完，且每个小节都能独立成段被截图分享。

### 实操教学风格（零基础教程必用）

> 来源：标杆公众号《风声的AI编程·Vibe Coding 小白指南》的实测分析。
> 适用：第一章认知篇之后的所有"教读者动手做"的篇目（准备篇、实战篇、进阶篇）。

零基础教程不能只停在"认知"，必须让读者**照着抄就能跑出结果**。在写作铁律之外，再叠加这 6 条：

1. **自述式开头建立信任**：用"我们团队踩了很多坑""我教会了非计算机专业的同事"这类真实经历开头，比讲道理更让小白信服。
2. **明确"适合谁"**：开篇用 2-4 条 bullet 划定读者画像（如"熟练用电脑""零基础纯小白""产品/运营想自己动手"），让读者自我对号入座。
3. **理论 / 实践分块**：先一小段必要理论（用类比讲清），再进入可动手的实践。理论不超过全文 1/3。
4. **接地气类比讲技术架构**：抽象概念一律用生活场景类比。范文用"寄快递小程序"讲前端/后端/数据库——前端=你看到能点的界面，后端=快递公司看不见的工作人员，数据库=记录每个快递的台账本。自己写时也要找一个读者天天接触的场景。
5. **给可复制的提示词/命令**：这是实操文的灵魂。不要只说"让 AI 帮你装环境"，要直接给出能复制粘贴的整段提示词，例如：
   ```
   帮我在当前电脑中安装 python 3+ 版本，并完成环境验证，
   如果遇到问题你帮我解决，最后完成后明确告诉我："python环境安装完成"。
   ```
   读者复制即用，成功率和成就感都飙升。
6. **小试牛刀，立刻给成就感**：在讲完安装/配置后，马上安排一个 5 分钟能跑出可见成果的小练习（范文是"生成一个烟花动效页面显示 hello world"）。让读者在第一篇就有"我真的做出来了"的体验，而不是读完一堆理论。

**配套语气**：口语化、鼓励式。多用"似懂非懂也没关系""太好了""跟着一步步来""下节见"。承认 AI 会出错、承认有的步骤复杂（如"mysql 安装可能最麻烦，善用 AI 帮你"），降低读者的挫败预期。

**配图策略对标**：实操文配图密度要高（范文 14 张），类型包括：技术架构示意图、官网/安装界面截图（标注箭头）、操作步骤截图、成果演示（图或短视频）。每个关键操作步骤配一张图。

### 零基础系列文章 8 段式骨架（硬规范）

当任务是"零基础 AI 编程教程系列"这类既要讲原理又要能动手的文章时，每篇严格按这 8 段写：

```
① 开篇·共鸣          用读者熟悉的困境/疑问切入，"说的就是我"
② 本篇你能学到        3-4 条具体收获，设定预期
③ 理论·够用就好       本篇必须懂的原理/常识，全用生活类比，篇幅 ≤ 全文 1/3
④ 实操·跟着做         可操作步骤；指挥 AI 处必给【可直接复制的提示词】
⑤ 成果·看得见         5-30 分钟能跑出的可见成果(截图/页面/文件)，立刻给成就感
⑥ 避坑·真实经验       本篇最易踩的坑 + 解决思路；承认 AI 会出错，把报错正常化
⑦ 本篇小结           3 条核心要点，可截图保存
⑧ 下一篇预告 + 互动    悬念引导 + 一个能引发评论的具体问题
```

**两条不可妥协**：
1. **可复制提示词**：任何"让 AI 做 X"的地方都要给整段能复制的提示词，不能只说"你让 AI 做"。
2. **看得见的成果**：每篇结束前读者手里要有真实产出，哪怕很小。用 cloakbrowser-scraper 截真实运行结果。

**理论部分的类比库**（沿用标杆，保持全系列一致）：
- 前端 = 你看到、能点的界面 | 后端 = 看不见的幕后工作人员 | 数据库 = 记录一切的台账本（整体用"寄快递小程序"串起来）
- API = 餐厅服务员（你不进厨房，告诉他要什么就行）
- 终端/CLI = 用打字和电脑对话的地方（像微信聊天，对象换成电脑）
- 上下文/记忆 = 给 AI 的一份工作手册（CLAUDE.md），不写它就会"失忆"

### 内容深度标准（让读者"真学到东西"）

光"能看懂"不够，要让读者觉得"有内涵、学到真东西"。每篇按这三条加深度：

1. **适度引入真术语 + 重类比讲透**：每篇挑 1-3 个该领域真术语，用生活类比讲明白，让读者"既懂又显专业"。已用过的：
   - **AI 幻觉（Hallucination）** = 信息不足时 AI 不说"不知道"，而是一本正经地编个看似合理的答案。金句："AI 的自信远超它的可靠性。"
   - **提示词（Prompt）** = 你给 AI 的那段话/指令。
   - **隐性知识→显性指令** = 需求描述的本质：把你脑子里默会的东西，翻译成 AI 能执行的明确指令。
   术语只点到"够用"，不堆砌；引入后必须立刻配类比或示意图。

2. **沉淀方法论 / 选择矩阵**：每篇尽量留下一个可复用的框架，而不只是讲一堆点。已用过：需求描述"做·有·存·用"四步、需求颗粒度 2×2 选择矩阵（功能多少 × 描述清晰度，指出新手该待的象限）。矩阵/框架用 HTML 信息图呈现（见配图）。

3. **动态对比增强说服力**：关键对比（错误做法 vs 正确做法）做成左右分屏的动态 GIF（双路同屏演进、红绿对照），比纯文字代入感强得多。用 cloakbrowser-scraper 的 html_to_gif 制作。

**参考爆款再加自己见解**：动笔前可搜同主题高浏览量文章（如程序员鱼皮、Datawhale 的 Vibe Coding 教程），提炼其术语体系和金句，但必须**叠加差异化见解**（如"做有存用"对零基础比"输入/输出/技术"更友好），不照搬。

### 叙事进阶（对标高浏览量爆款的实测拆解）

拆解过两篇爆款（《一个人翻身最快的方式：用 AI 做小生意》《Codex 必装十大 Skills，我挨个翻车之后…》）后，提炼出 5 条让文章更有"高级感和说服力"的叙事规则：

1. **标题要狠**：要么巨大利益承诺（"翻身最快""值多少钱"），要么反套路真实测评（"我挨个翻车之后重排顺序""别被 AI 忽悠"）。避免平淡的"X 是什么"。
2. **开篇强叙事 / 强背书**：用具体场景切入（"早上 10 点 15 分，朋友群弹了一张图"）或数字背书（"半年跨行 50W"），3 句内抓住人。比直接讲道理强得多。
3. **掺入"我"的真实取舍与翻车**：不当百科全书，要有亲历的踩坑、判断、取舍（"我改到第五版才发现它偷偷删了字段""装了 30 个 Skill 结果启动要 8 秒"）。真实经历 = 信任。
4. **金句收尾**：每篇留一句能被截图转发的话。例："工具的进化，从来不是模型变强，是围绕模型的文化变厚。""机会不眷顾犹豫者，只青睐行动者。"
5. **分级/取舍代替罗列**：讲多个东西时，给出"第一档天天用 / 第四档当目录翻"这种带个人判断的分级，而不是平铺直叙列清单。

**但守住底线**：本系列读者是**完全零基础小白**，叙事可以老练，但术语、类比、节奏仍要照顾小白——爆款 B 的读者是已在用工具的人，我们不能照搬它的术语密度。**学它的叙事手法，不学它的门槛。**

## 阶段4：配图生成

**目的**：让每张图都成为"压缩工具"，而不是装饰。

**调用子技能**：`figure-prompt-builder`（写提示词）+ `openai-image-gen`（生成）+ `visual-explanation`（决定要不要画）。

### 4.1 提示词写作框架

每张 AI 生成的图都要在 `images/prompts.md` 留底，结构如下：

```markdown
# 图片提示词记录

## #cover：封面图
- 类型：AI生成（gpt-image-2-pro）
- 用途：公众号封面 + 文章顶图
- 尺寸：1536x1024
- 完整提示词：
  扁平插画风格的文章封面图。

  主题：{核心主题，一句话}
  画面构成：
    - 左侧：{主元素}
    - 中间：{辅助元素}
    - 右侧1/3区域：留白用于叠加文字标题

  视觉焦点：左侧2/3 区域
  配色：深蓝(#1a3a5c)为背景，橙色(#ff6b35)为强调色，白色辅助
  风格：简洁现代，扁平化，无阴影，图标化元素
  不要：密集文字、真实人脸、复杂背景、3D效果

## #concept：概念说明图
- 类型：AI生成（gpt-image-2-pro）
- 用途：阐释核心概念
- 尺寸：1024x1024
- 完整提示词：
  ...
```

### 4.2 生成方式：通过 LLM-Link 调用 gpt-image-2-pro

**API 配置**：凭证只从技能包根目录的 `config.json` 读取（**不读环境变量**，避免系统残留失效变量干扰）。首次使用复制 `config.example.json` 为 `config.json` 填入 `key`：

```json
{
  "_type": "newapi_channel_conn",
  "key": "sk-...",
  "url": "https://www.llm-link.top",
  "model": "gpt-image-2-pro"
}
```

**调用脚本**：用 `scripts/generate_image.py`（不要用 .sh,见下方踩坑）。脚本自动向上查找 `config.json`，无需传任何环境变量：

```bash
python scripts/generate_image.py \
  --prompt-file articles/<slug>/images/prompts.md \
  --section cover \
  --output articles/<slug>/images/01-cover.png \
  --size 1536x1024
```

**LLM-Link 出图实测踩坑（重要,都已在 .py 里处理）**：

1. **走 chat completions,不是 images/generations**。这个 LLM-Link 部署的 `/v1/images/generations` 端点 60s 硬超时返 504,用不了。`gpt-image-2-pro` 实际包装在 `/v1/chat/completions`：发 `messages`,回复的 `content` 里是 markdown `![image](url)`,解析这个 URL 再下载。
2. **必须用 curl 发请求,不能用 Python urllib**。llm-link.top 前置 WAF 按 TLS 指纹(JA3)识别客户端:curl 放行,Python urllib 被拦(403 / RemoteDisconnected),改 User-Agent 无效(拦截在 TLS 握手层)。脚本已改为 `subprocess` 调系统 `curl`。
3. **504 偶发,要重试**。上游高峰期会 504,脚本内置 3 次重试,通常第 2-3 次成功。
4. **中文必乱**。gpt-image-2-pro 渲染中文文字会乱码——所以提示词里明确"不要出现任何中文/英文文字",文字标题后期叠加;**带中文的信息图/架构图改用 cloakbrowser-scraper 的 HTML 模板截图,不要硬让 AI 生成**(见 4.5)。
5. **环境**：本机 `pip` 被 uv 接管,装包用 `python -m pip`;无 `jq`,所以脚本用 Python 不用 shell。

脚本职责：
- 从 prompts.md 中提取指定 section 的提示词
- 调用 LLM-Link `/v1/images/generations` 接口
- 解析 base64 或 URL 返回，落盘到指定路径
- 失败重试3次，每次间隔 5s
- 不在日志中打印 API key

### 4.3 Mermaid 图直接嵌入

流程图、时序图优先用 Mermaid，不调用图像 API：

```markdown
\`\`\`mermaid
flowchart LR
  A[你的想法] --> B[写清楚需求]
  B --> C[Claude Code 执行]
  C --> D{结果对吗?}
  D -- 对 --> E[完成]
  D -- 不对 --> B
\`\`\`
```

公众号渲染 Mermaid 需要在发布前转成 PNG（用 mermaid-cli 或 mermaid.live），但 draft.md 里保留源代码，便于后续修改。

### 4.4 生成后必须人工审核

每张 AI 图生成后必检 4 项：

- [ ] 文字区域是否真的留出来了（不要让 AI 自己生成中文标题）
- [ ] 配色是否符合品牌色
- [ ] 是否出现真实人脸（避免肖像权问题）
- [ ] 是否有错误的科技元素（比如键盘按键错位、屏幕显示乱码）

不通过则改提示词重新生成，最多 3 轮。3 轮还不行就降级到 Mermaid 或 Canva。

### 4.5 演示素材：信息图 / 终端 / 对话 / 动效（用 cloakbrowser-scraper）

这是把文章从"科普"提升到"专业可操作"的关键，也是对标标杆的核心。**分层产出**：

| 素材类型 | 何时用 | 怎么做 | 工具 |
|---------|--------|--------|------|
| 彩色封面插画 | 每篇 1 张 | gpt-image-2-pro(纯插画,无中文) | `generate_image.py` |
| 黑白手绘信息图 | 讲原理/架构/流程 | HTML 模板改文案 → 截图 | `cloakbrowser-scraper/templates/infographic.html` + `screenshot.py` |
| 终端运行成果 | 命令行程序成果 | HTML 模板 → 截图 | `templates/terminal.html` + `screenshot.py` |
| AI 对话过程 | 展示人机协作 | HTML 模板 → 录 GIF | `templates/ai-chat.html` + `html_to_gif.py` |
| 动效成果(烟花等) | "看得见的成果" | HTML 模板 → 录 GIF | `templates/firework.html` + `html_to_gif.py` |

**配图选型铁律（GPT 生图为主）**：
- **默认优先 gpt-image-2-pro 生图**：封面、插画、概念图、无中文/纯英文信息图，一律先用 AI 生图——最美观高效。
- **只有这三类才退回 HTML 模板截图**：① 文字必须分毫不差的中文信息图/架构图（gpt 反复乱码时）；② 需精确控制布局的结构图（矩阵/带标注界面）；③ 图片难以表达、AI 画不准的。带中文先让 GPT 试，乱了再退 HTML，不要一上来就 HTML。
- **成果尽量做成 GIF/动画**而非静态图,读者能看到真实运行效果(公众号/小红书支持 GIF 自动播放;抖音需转视频)。
- **真实运行结果优先用真实截图**(CloakBrowser 打开真页面截),实在不便再用 HTML 模拟。

具体命令见 `cloakbrowser-scraper` 技能的"演示素材模板库"一节。

## 阶段5：多平台改编

**目的**：同一篇文章在公众号、小红书、抖音上是三种生物，硬搬一定死。

### 5.1 公众号版（`platform/wechat.md`）

- 直接用 final.md
- 加封面图、文末关注引导、系列文章互链
- 段落保持，不需要重写
- 配 1-3 张精选图作为内嵌

### 5.2 小红书版（`platform/xhs.md`）

改写规则：

- 标题改为带数字 + 表情的形式："3个步骤｜零基础也能用 AI 写程序 ✨"
- 全文压到 800-1200 字，删掉所有过渡段
- 第一句必须钩住：用问题或反差陈述
- 配图改为 9:16 或 1:1 卡片图（封面单独做小红书封面）
- 文末加 5-10 个 hashtag

模板：

```markdown
{emoji} {标题数字+利益点}

{开头钩子，1句话}

▎{小标题1}
{正文}

▎{小标题2}
{正文}

▎{小标题3}
{正文}

💡 {核心总结，1句话}

{评论引导问题}

#话题1 #话题2 #话题3
```

### 5.3 抖音口播版（`platform/douyin.md`）

改写规则：

- 全文压到 60-90 秒口播稿（约 200-300 字）
- 钩子必须在前 3 秒说完
- 用"你""我"对话感语言，去掉书面词
- 标记画面提示（B-roll cue）

模板：

```markdown
【0-3s 钩子】
{反差陈述或惊人数据}
[画面：xxx]

【3-15s 痛点】
{读者的具体困境}
[画面：xxx]

【15-50s 方案】
- 第一步：...
- 第二步：...
- 第三步：...
[画面：xxx]

【50-60s 行动】
{评论/关注引导}
[画面：xxx]
```

### 5.4 改编质量自检

每个平台版本生成后，回头问3个问题：

1. 在这个平台滑动信息流时，前 2 秒能停下来吗？
2. 这个平台的读者熟悉的语气是什么？我的版本符合吗？
3. 转换给其他平台的读者，他们会觉得"水"还是"刚好"？

## 五、编排逻辑（Agent 如何使用本技能）

### 完整流程：用户给一句话主题

```
1. 接到主题 → 创建 articles/{date}-{slug}/
2. 启动阶段0：澄清意图 → user_brief.md
   - 至多问 3 个最关键的问题，避免疲劳
   - 用户已有素材直接收下，不重复问
3. 阶段1：研究 → research.md
   - 用 firecrawl_search 收集原始素材
   - 整理成事实卡片
4. 阶段2：大纲 → outline.md
   - 让用户审一次大纲（这是最重要的人工 review 点）
   - 改完再写
5. 阶段3：写作 → draft.md
6. 阶段4：配图 → images/
7. 阶段5：改编 → platform/
8. 最终交付：把 articles/{date}-{slug}/ 路径报告给用户
```

### 部分流程：用户已经有大纲

```
跳到阶段3，从 outline.md 开始填正文。
```

### 部分流程：仅生成配图

```
跳到阶段4，需要 outline.md 或者用户当场提供图片需求清单。
```

### 关键决策点（必须停下来问用户）

- 阶段2 完成后：大纲是否符合用户预期
- 阶段3 完成后：正文初稿是否需要调整方向
- 阶段4 每张 AI 图生成后：是否接受当前生成结果

其他点可以连续推进，不打断用户。

## 六、错误处理与降级

| 故障 | 降级方案 |
|------|---------|
| firecrawl 不可用 | 改用 WebFetch + WebSearch 收集素材 |
| gpt-image-2-pro 调用失败 | 改用 Mermaid 或要求用户在 Canva 自己做 |
| LLM-Link API key 缺失 | 提示用户在技能包根目录 `config.json` 配置，不要硬编码到脚本 |
| 研究素材不足 5 张事实卡片 | 回到阶段0，建议主题缩小或要素材 |
| AI 图连续 3 轮未通过审核 | 自动降级为 Mermaid 或概念性 ASCII 图占位 |

**绝不做的事**：

- 不在脚本里硬编码 API key（统一从技能包根目录 `config.json` 读取，不读环境变量）
- 不在 commit 里包含 articles/{slug}/images/ 中的临时草图（只保留 final 选用的）
- AI 生图中文若反复乱码，该图退回 HTML 截图（不是禁用 AI 生图，而是按图选型）
- 不在没有事实卡片支持的情况下编造数据

## 八、扩展点

### 8.1 新增平台

在 `阶段5` 增加新的改编模板（如知乎、即刻、X）。每个新平台需要回答：
- 标题规则
- 字数范围
- 段落分隔风格
- 配图比例
- 互动话术

### 8.2 新增内容类型

当前覆盖 A类干货 / B类测评 / C类植入。如果要加 D类故事/访谈/复盘，需要：
- 在阶段0 的"内容类型"列表加选项
- 在阶段2 调整大纲结构（故事类不一定 5 段式）
- 在阶段3 增加对应的写作铁律

### 8.3 接入图片质量评估

当前阶段4 是人工审核 4 项。未来可接入视觉模型自动评估：
- 文字区域占比（避免 AI 生成中文乱码）
- 主色调与品牌色 ΔE 距离
- 是否包含人脸（人脸检测）
