# 闲鱼商品图与发布文案

## 什么时候用

- 用户要给一款软件 / 虚拟商品做闲鱼主图、详情图、商品图套装
- 用户要写闲鱼标题、正文、标签，要求「去 AI 味」「避开敏感词」
- 已经有产品截图，但画面太散、字看不清、手机上缩略图认不出

## 一、先记住五条硬规则

1. **3 秒法则**：缩略图状态下，买家 3 秒内要能看懂「是什么 / 值不值 / 可信不可信」。首图只放一个卖点。
2. **AI 只出底图，文字和界面必须用 HTML/CSS 排。**
   直接让生图模型画中文海报，字会糊、会错、会乱码——这条路已经试过，整批报废。
3. **一张图一个卖点。** 功能清单、参数表不要堆在主图上；放不下的卖点拆到下一张。
4. **数字必须真实可追溯。** 用「本机实测 2026-10-14，132 个未读、2.05 秒」这种写法；没有实测就写场景，不要编数字。
5. **浅色、干净、留白。** 白色/浅色半透明卡片 + 一个产品主色（accent），文字不超过画面 20%，主体占 60–80%。

## 二、六张图的分工

| 编号 | 类型 | 要回答的问题 | 画什么 |
| --- | --- | --- | --- |
| 01 | 功能亮点 | 这东西到底干什么 | 核心界面 + 一个箭头/标注 + 一个关键数字 |
| 02 | 使用场景 | 我什么时候用得上 | 真实场景对照（开会转文字、交接打包、见客户前看简报） |
| 03 | 个人成果 1 | 用了有什么结果 | 结果页 / 指标页，数字来自本机实测 |
| 04 | 个人成果 2 | 结果可信吗 | 第二个角度的结果，或「前后对比」 |
| 05 | 公司/团队成果 1 | 团队能不能用 | 流程 + 团队场景。**标「示例」** |
| 06 | 公司/团队成果 2 | 有没有更重的用法 | 第二个团队场景。**标「示例」** |

公司成果没有真实案例时：**删掉这两张，不要编客户、拼假聊天记录。** 演示画面必须能一眼看出是示例。

## 三、制作流程

### 第 1 步：定产品色

每款产品一个主色，全套图统一，不要一张图换一个色：

```js
// accent / soft / 底图文件名
message-assistant  '#2563eb' / '#eff6ff' / '01-blue'
export-archive     '#4f46e5' / '#eef2ff' / '02-indigo'
contact-organizer  '#059669' / '#ecfdf5' / '03-green'
message-retention  '#b45309' / '#fffbeb' / '04-orange'
```

### 第 2 步：生成浅色底图（可选）

用 ComfyUI 出一张 1024×1024 的浅色抽象底，**只当背景，不要任何文字**：

```text
浅色渐变背景，柔和的${色系}光斑，大量留白，极简，细腻颗粒，
电商商品图背景，无文字，无人物，无logo，正方形
```

- Qwen-Image 2.1 Turbo，8 步，1024×1024，约 3.5–4.8 秒/张
- 每款 1 张就够，24 张图共用 4 张底
- 没有 ComfyUI 就跳过：模板自带 CSS 渐变兜底，效果也能用

### 第 3 步：复制模板，排六张图

把 `templates/posters.html` 复制到工作目录，按产品改 `poster(...)` 块。

**命名即契约**：`data-out="<产品>/<编号>"`，渲染脚本按它切图、探针按它定位。

```html
<section class="poster" data-out="demo/01"
  style="--accent:#2563eb;--soft:#eff6ff;background-image:url('./images/_bg/01-blue.png')">
```

结构固定三层，不要自己发明：

```text
.head   kicker + 标签 + 60px 标题 + 24px 副标题
.stage  flex:1 的界面区（窗口 / 对照 / 指标 / 流程）
.foot   实测说明 + Win10/11 徽标
```

### 第 4 步：探针 → 渲染 → 逐张目检

```bash
cd <工作目录>

# 1) 找裁切：只报 scrollHeight/scrollWidth 溢出，不靠肉眼
node <skill>/scripts/check-overflow.mjs posters.html

# 2) 导出：viewport 1120、deviceScaleFactor=2，每张 2048×2048
node <skill>/scripts/render.mjs posters.html images
```

Playwright 默认从**当前目录**的 `node_modules` 解析；解析不到时：

```bash
PLAYWRIGHT_MODULE=/abs/path/node_modules/.pnpm/playwright@x/node_modules/playwright/index.mjs \
  node <skill>/scripts/render.mjs ...
```

渲染脚本会在页面报错 / console error 时退出码 1，不要忽略。

### 第 5 步：目检（必须做，探针查不出「丑」）

- [ ] 手机上缩略到 200px，标题还能读
- [ ] 没有半张脸、没有半行字、没有贴边
- [ ] 一屏只有一个视觉中心，没有两套并列的重点
- [ ] 底部说明和页脚没被裁
- [ ] 图里没有联系方式、二维码、平台名
- [ ] 公司成果两张有「示例」标记

## 四、排版：用「结构」填满，不要放大字号

常见问题是中间一大片空白，看着像半成品。按顺序处理：

1. `stage` 设 `flex:1;min-height:0;display:flex;flex-direction:column`
2. 主卡片 `.win-body` / `.bd` 也设 `flex:1;min-height:0;display:flex;flex-direction:column`
3. 用 `margin-top:auto` 把底部说明钉住
4. 还有空洞就补**真实信息**：回复速度、未接问句、最近往来、高频词、上次成交、更多记录
5. 最后才考虑调整字号或间距

不要用无意义的占位块凑高度——买家看得出来。

## 五、溢出处理

探针报的是 `scrollHeight > clientHeight + 1` 或 `scrollWidth > clientWidth + 1`。

修的时候按这个顺序，且**必须 scope 到单张图**，不要全局改：

```css
[data-out="export-archive/04"] .hit{padding:7px 0}
[data-out="message-retention/04"] .sys{margin:5px 0}
```

1. 删掉与页脚/上一块重复的一行
2. 缩短文案，不缩小到 12px 以下
3. 缩小该图的 padding / margin
4. 仍然残留 2–4px 且画面不可见时，记录并接受；**可见裁切一律不算通过**

## 六、文案与合规（图和正文都要查）

### 不能写

| 不写 | 换成 |
| --- | --- |
| 微信全称、微信号、加微信、喂信、卫星 | WX、VX |
| 插件、外挂、脚本、注入、补丁 | 工具、小助手、后台程序 |
| 自动回复、代聊、机器人、托管 | 帮你起草、后台运行、确认后发送 |
| 防撤回、撤回插件 | 消息留痕、本地留存 |
| 破解、绿色版、激活码 | 不写 |
| 群发、批量加人、加粉、获客、引流 | 不写，功能也不提供 |
| 监控、偷看、采集、抓取、爬 | 整理、盘点、留存 |
| 网盘、电子版、下载链接、压缩包 | 闲鱼聊天窗口发货 |
| 永久、无限、100%、最、第一、唯一 | 不写；有效期写「以拍下规格为准」 |
| 零风险、不封号、包过 | 不写 |

### 其他红线

- 平台会 **OCR 图片里的文字**，图里同样不能有上面这些词
- 不出现手机号、QQ、邮箱、二维码、外链、平台名
- 聊天截图里的人名、头像、手机号一律打码
- 公司成果必须标「示例」，正式上架前换成真实案例并征得同意
- 不承诺「能当法律证据」「公证级别」；只说本机记录、可被修改
- 文案写完搜一遍：`微信|微信号|插件|外挂|破解|永久|100%|零风险|群发|加粉|获客|引流|监控|二维码`

### 去 AI 味

- 短句，一句一个意思；不用排比、不用破折号堆叠
- 写具体动作和数字，不写「赋能」「闭环」「一站式」
- 用卖家口吻：「装不上远程协助」「这个版本不支持，拍前发版本号确认」
- 敢写做不到的事：过期文件救不回来、装之前的撤回查不到

## 七、交付前检查清单

- [ ] 6 张图都是 2048×2048，命名 `01.png`–`06.png` 放在产品目录
- [ ] 探针跑过，没有可见裁切
- [ ] 每张图只有一个卖点，标题在缩略图下可读
- [ ] 数字有实测来源，页脚写清日期或口径
- [ ] 图片和正文都过了一遍敏感词
- [ ] 公司成果两张已标「示例」，或已删除
- [ ] 商品页里的图片说明与实物一致

## 八、常见坑

- **heredoc 吞反斜杠**：写临时脚本时 `replace(/\\/g,'/')` 会变成 `replace(/\/g,'/')`；用 `pathToFileURL()` 代替手写路径。
- **字体没加载就截图**：`await page.evaluate(() => document.fonts.ready)`，再 `networkidle`。
- **全局改 CSS 修单图**：会碰坏其它图；一律 `[data-out="..."]` 前缀。
- **探针通过就当完成**：探针只查裁切，不查空洞、不查错别字、不查缩略图可读性，必须目检。
- **一张图塞两个卖点**：缩略图下两个都看不清，等于没有。
- **让模型在图上写中文**：字必糊。中文只能 HTML 排。
