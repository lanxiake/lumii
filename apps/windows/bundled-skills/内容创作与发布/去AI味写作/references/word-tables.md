# 查表：黑话、术语、语气词

这页是查表用的，不是规则。规则在 SKILL.md 里。

## 高危黑话清单（全篇搜一遍，零命中）

开坑、填坑、断更、催更、塌房、遥遥领先、赢麻了、封神、YYDS、绝绝子、家人们、宝子们、懂的都懂、拉满、直接起飞、天花板、香、顶、绝、泪目、爷青回

**用法**：逐句问"这个词在传递信息，还是在制造气氛？"只制造气氛的，换回中性词。

**注意误伤**：有些词在别的语境里是正常词，别一刀切。比如"顶"在"置顶""顶栏""顶部"里是名词，不是黑话。

## 听着内行、其实不准确（比黑话更容易漏）

| 说法 | 为什么不准确 | 换成 |
|---|---|---|
| 2018 年**开的坑** | 圈内黑话；隐含可能烂尾，做介绍时含混 | 2018 年**开始做** |
| 八年**没断更** | 网文术语，用在开源项目维护上不对 | 到现在整整八年**还在维护** |
| **三十七兆代码** | 那是仓库拉取体积，不是代码本身的量 | **源码包 37 兆** |
| 八年，**一个人**维护 | 开源项目多半有其他贡献者，说满了 | 八年，**基本是一个人**在维护 |
| 三条**路径**／**打法** | 咨询黑话 | 三个**办法** |

这类词的麻烦在于它读着"很专业"，所以不会触发警报。过一遍时要专门盯。

## 安全语气副词（可以放心用）

其实 / 就 / 才 / 压根 / 足足 / 全都 / 直接 / 现在 / 整整

**判据**：它们在传递信息或强调程度，不是在造气氛。

- ✓ "**其实**我们根本不想看" —— "其实"确实在说"这跟你的预期不同"
- ✓ "**足足**二十二个组件" —— "足足"确实在说"比你想的多"
- ✗ "**开坑**" —— 什么都没说，只是听着像个圈内人

**约束：一段里最多一个。** 堆三个就成"网感"了，网感和说明书一样假。

## 元叙述 / 自证话（全删）

- `观众不需要理解任何技术细节`、`观众不需要知道全部` —— 你在跟审稿人交代写作策略
- `（必须说清楚）` —— 自我壮胆
- `注意：` —— 删
- `三个值得说的点：` —— 改"挑三个点说"，或直接进第一条
- `这不是黑它` —— 预防性自我辩护，会诱发读者原本没有的怀疑

**探测法**：念出来，问"这句是在跟读者说，还是在跟老板汇报？"

**一个例外**：真正标记重点的话留着。`但重点是，……`确实在告诉读者"下面这条重要"。判据：去掉这个强调，句子会变弱吗？不会就删，会才留。

## 答题腔对照

| ✗ | ✓ |
|---|---|
| 但它**有三个**代价。**第一**，性能。**第二**，零单元测试。**第三**，许可证带附加条款。 | 当然它**也有几个**明显代价。**首先是**性能开销……**其次**……**最后**…… |
| 所以它**适合谁**？……**哪些人别碰**？ | 所以**什么样的人适合用**？……**这些人就别碰了**：…… |

两条：**别预告总数**（"有三个"把话说满了，读者会开始数）；**分点用"首先／其次／最后"**，不用"第一／第二／第三"——前者是人在捋思路，后者是文档在排版。

## 术语换写表

术语不只藏在名词里，**动词和量词都是重灾区**。

| 类型 | 术语裸奔 | 接人话 |
|---|---|---|
| 名词 | JS 堆内存 | 内存占用 |
| 名词 | 一百一十个**元素** | 一百一十**项设置** |
| 名词 | 类型检查 0 错误 | 类型检查零报错 |
| 动词 | 把它**注入**首页 | **加载到**首页 |
| 动词 | **模拟脚本环境** | 在本地**搭好环境** |
| 动词 | **进行验证** | 自己**跑了一遍** |
| 量词 | 22 **个**组件（读者要的是能干什么） | 22 个组件，视频、音频、弹幕都能单独存 |

**判据**：一个不写代码的人，不但要听懂，还要觉得这是人话。

"加载到"和"注入"都听得懂——但只有前者不会让人出戏。这个区别就是这一节的全部意义。

**可以保留的**：行业里通用的说法。`首屏 DOM 就绪`在开发者社区是标准表述，强行翻译反而绕。
