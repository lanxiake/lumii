# H3 精灵图生成（pet-sprite-h3）

用 **MiniMax H3 视频模型**出动作帧，再归一化成客户端能加载的图集。
**权威外部参考是 `fmmix/sprite_h3`（MIT）**——本项目的方法学全部学自它，别自己调参。

## 一、能力边界（先说清楚做不到的）

| 做得到 | 做不到 |
| --- | --- |
| 单个动作出一张 8 格横排精灵表，**首尾闭合可循环** | 一次出整套动作（一个动作一次生成） |
| 正面 / 侧身两种视角 | 任意视角（侧身要靠"先出一张姿势图"两段式） |
| 任何画布比例、任何角色 | 像素风整数网格对齐（那是后处理的事） |

**H3 是音视频联合模型**：提示词里不写静音，它会自己配环境音（对精灵图毫无意义且拖慢生成）。

## 二、前置条件

1. **ComfyUI 可达**，且装了 `minimax_h3_fl2va_pruned_int8_convrot` 这套模型。
   地址取 `~/.claude.json` 的 `mcpServers['comfyui-remote'].env.COMFYUI_URL`，
   或用环境变量 `COMFYUI_URL` 覆盖。本机 8188 不通，走的是 cpolar 隧道，**请求要带重试**。
2. **Node 环境能解析 `sharp`**（脚本要做像素运算）。从仓库内跑最省事；
   搬走的话先 `npm i sharp`。
3. 客户端在跑（只有「安装」这一步需要——它经 `/pet/asset` 控制口走技能链）。

## 三、流水线

```
立绘 ──stage-frame──▶ staged/<角色>.png ──h3-motion sheet──▶ 精灵表 ──install-pet──▶ 客户端
                          （生成画布上的首帧）      （生成+抠底+抽帧+拼条一次出）
```

侧面视角要**多一段**：管线只有正面立绘，而走动/攀爬/爬行要侧身。

```
正面立绘 ──h3-motion pose（尾帧自由）──▶ 姿势图 ──stage-frame --keep-scale──▶ staged/<角色>-<姿势>.png
                                                                                    │
                                                          再拿它去跑上面那条循环 ◀──┘
```

**为什么非要两段**：管线的首帧同时当首帧和尾帧（FL2VA），用正面立绘直接生成侧身循环，
末帧会被**强制拉回正面**，循环里出现"转过去→被拉回来"的鬼畜。姿势图那一轮**不接尾帧**，
角色才能真正转过去；循环闭合交给下一轮。

## 四、二十三条硬规则（每条都是实测换来的，别推翻）

1. **循环闭合靠 FL2VA，不是靠提示词求。** 把**同一张图**同时接给 `first_frame` 和 `last_frame`。
   只在提示词里写"请回到起始姿势"模型可以不理（实测末尾手臂一直举着）。
   ⚠ **姿势图那一轮反过来——必须不接尾帧**，否则转过去会被钉回来，**而出图看着完全正常**，
   只有量宽高比才发现没转过去。两条路的 `freeEnd` 别接反。

2. **首帧必须先 staging，它是机位标定。** H3 保持首帧里角色的大小、位置、朝向。
   参数照搬 sprite_h3：角色高 = `canvas_h × ratio`、脚底落在 `round(baseline × canvas_h) − 1`、水平居中。

3. **底色用「颜色名 + hex」写进提示词**（如 `cyan (#00CCFF)`），只给 hex 是弱信号。
   抠底后用**精确纯色**重铺一层——源图那层"纯色底"带渐变和噪声（实测四角从 28,220,227 飘到 51,202,216）。
   抠底走 **`ColorToMask` 色键**，不用 BiRefNet：底色是自己铺的精确色、模型也守着它，色键更准且不吃显存。
   ⚠ ComfyUI 的 mask 语义**三套并存**，只能跑一次看 alpha 占比，推不出来。

4. **`--ratio` 不是"留白"旋钮，`--baseline` 才是。** 客户端的 normalize 按帧尺寸分组、
   **组内共用一个倍率**（`scale = canvas.h × 0.94 / 组内最高的包围盒`）——压低 ratio 只会让这一组
   **整体变小**（实测跳起来会比别的动作小 11%）。要给跳跃/立起来留头顶空间，把角色在画面里**下移**
   （抬 `--baseline`），像素高度不变。

5. **姿势图要 `--keep-scale`，不能按 `--ratio` 重摆。** 同一角色的所有动作都从**同一张首帧**生成，
   **本来共用一个尺度**。强行把每张都摆成同样高度 = 把矮姿势放大（实测下落 388 vs 站立 472，放大 21%），
   切动作时肉眼可见地跳。

6. **每个动作的首帧必须是它自己的姿势。** 抽帧沿整段均匀取、**含第 0 帧**，而第 0 帧就是输入图。
   爬行一度从侧身**站立**首帧生成，循环每转一圈都会在格 0 闪一下站姿。

7. **出图闸门（S1/S2/S4/S6/S8）拦下的批次不要放宽判据去凑，重出。**
   最常撞的两条：
   - **S1 角色越出格线**——头顶出框是**信息已经丢了**，后期缩放救不回来 → 抬 baseline 重出。
   - **S8 底色离角色色太近**（安全线 150）——抠底容差会逼近这个距离、穿过描边漏进角色内部。
     让模型画的道具**颜色写死**（实测写 "bright red ball" 后色距从 99 回到 252）。

8. **`Crawl` 那一行必须倒挂，而且是"谁装谁翻"**（2026-09-23）。它只在天花板上播
   （`PetWanderDriver` 里 `onActivity('crawl')` 只有"沿上边缘爬行"一处），所以素材得是
   **脚朝上、头朝下**。Shimeji 那套的作者就是那么画的，**而 H3 出的这一行是正的**
   （`POSES.creep` 写的是"趴在地上"，模型照做）。不在 `install-pet.mjs` 的 `ACTIONS` 里
   标 `invertY: true` 会怎样：**宠物头朝上吊在天花板上**——用户的原话是
   「反了，应该底部朝上，头部朝下」。⚠ 反过来也不行：给本来就倒挂的素材再翻一次，
   同样头朝上（`import-shimeji.mjs` 里记着一次）。**朝向只能由生产侧声明**——
   归一化把内容底边对齐到锚点，装完之后翻与不翻的包围盒**一模一样**，量不出来。

9. **装完必须写 `perchGaps`，不写就是静默用 Shimeji 的数**（2026-09-23）。
   `pet-core` 的攀附几何只有两个数：锚点到**墙面**、到**天花板**的距离 ÷ 画布高。
   兜底值 `0.43 / 0.99` 是 Shimeji 那套素材量出来的，成立前提是"CLIMB 内容贴着格的
   墙侧边、CRAWL 内容贴着格的顶边"——**H3 出的素材按重心对齐、内容在格中央**，
   同一组比例套上去：实测团子**离墙 47px、离天花板 108px**，看着不是"贴着墙爬"
   而是"悬在那儿被电梯带上去"（用户原话「就像坐电梯一样」）。
   `install-pet.mjs` 装完会调 `lib/perch-gaps.mjs` 从**装好的图集**量出来补进清单
   （量装好的而不是源表：倍率是 `canvas.h × 0.94 / 组内最高包围盒`，源表上算等于把
   `computeNormalize` 抄一遍）。团子实测 `{ wall: 0.2478, ceiling: 0.5625 }`。

   ⚠ **`wall` 的口径是「锚点到内容最宽那一侧」，不是「内容右缘」**（2026-09-25 用户实测纠正）。
   「右缘」那个老口径隐含一个从没写下来的假设：**锚点落在身体的一侧**——Shimeji 那只猫就是
   那么画的，所以两个口径数值恰好相同，一直没暴露。**锚点居中的素材立刻穿帮**：月兔
   `anchor [200,442]`、画布宽 400、身体左右对称，于是"哪边宽"完全由**姿势**决定，实测
   （16 帧并集、画布空间）Climb 左边 159 / Crawl 右边 190 / Fall 左边 172，按右缘填
   `0.2746` 的结果是**贴墙或下坠时半边身体压出屏幕**（用户原话「每次都有半边身体在屏幕外面」）。
   两个都必须取到的理由各自独立：
   ① **左右都要**——往左走时渲染器 `setFlip` 镜像，镜像后**另一侧**才变成贴墙那一侧，
      而 `max(左, 右)` 对镜像**不变**；
   ② **三组都要**——贴墙播 Climb、脱手下坠播 Fall、墙角横爬播 Crawl，**三处都发生在屏幕边缘**，
      只有三组取最大值才不会被最宽的那一组切掉。
   取的是**整组 16 帧的并集**，不是首帧（某一帧挥出去的袖子同样会被切）。
   分母仍是 `canvas.h`（引擎按 `gap × modelHeight` 换算，`modelHeight = canvas.h × scale`）。
   `ceiling` 的口径不变（`anchor.y − Crawl 内容顶边`，月兔 0.7121 是对的，别顺手改）。
   月兔最终 `{ wall: 0.4241, ceiling: 0.7121 }`。**以后做任何正面／居中构图的角色都会踩这条。**

10. **抽帧数与源片长是一对，不是一个**（2026-09-24）。`DEFAULT_FRAMES`（源片）与
   `DEFAULT_PICKS`（抽几帧）**必须一起改**。回放时长 = 抽帧数 ÷ 回放帧率，所以：

   ```
   56 帧取 8  → 8 帧 @8fps 播 1.00s，源 2.33s  ⇒ 快放 2.33×   ← 既有动作的手感
   107 帧取 16 → 16 帧 @8fps 播 2.00s，源 4.46s  ⇒ 快放 2.23×   ← 帧数翻倍、手感不变
   107 帧取 8  → 8 帧 @8fps 播 1.00s，源 4.46s  ⇒ 快放 4.46×   ← 只改源片长 = 把动画放快
   ```

   只把源片长抬上去是**把动画放快**，不是变细腻。⚠ 动作 prose 里的完成时刻
   **由 `buildPrompt` 从片长算**（`seconds × 0.9`），写过一次常量 `'2.10'`——片长一改
   那句话就跟画面无关，模型前半段做完动作、剩下两秒无事可做，**而提示词里没有任何
   地方提示这个矛盾**。

11. **回放帧率按动作挑，不都是 8**（2026-09-24）。`install-pet.mjs` 的 `ACTIONS` 里
   每条可以带 `cols` 与 `fps`。判据是**这个动作该演多久**：闪避（`Dodge`）2 秒太拖，
   给 14fps（1.14s）；持续状态的慢循环（`Purr`）给 6fps（2.67s）。
   ⚠ `cols` **必须与出图时抽的帧数一致**，否则切出来的格子横跨两个角色
   （出图闸门报 S1），或者 `names` 数量与网格不符（`pet-creator` 直接抛错）。

12. **图集的列数必须随帧数生长**（2026-09-24）。图集是**一张**贴图，
   `packages/pet-asset` 的 `maxCols` 默认 8 → 高度 = `⌈帧数/8⌉ × 格高`，帧数一多
   就是一条细长竖条：104 帧已是 4480×5824，再加 128 帧是 **12992px**，
   **越过不少 GPU 的 8192 上限**——而超限的后果不是报错，是**整张图集建不出纹理、
   宠物直接不显示**。`install-pet.mjs` 按总帧数算出列数（`ATLAS_MAX_DIM = 8192`，
   两个方向都守），经 `pet-creator` 的 `maxCols` 传给打包器。团子 232 帧实测
   `7280×8064`，与预览值逐位一致。

13. **循环动作用独立姿势图当首帧**（2026-09-24）。FL2VA 把同一张图钉死在首尾两端，
   **首帧是什么姿势，循环每一圈就回到什么**。要一个"整段都闭眼"的呼噜循环，
   拿睁眼的站立立绘当首帧只会得到"闭眼→睁眼→闭眼"——那是眨眼，不是持续状态。
   走两段式（`POSES` + `pose-pick` + `stage-frame --keep-scale`）出一张闭眼姿势。
   ⚠ 这是 `POSES` 的**第二类理由**（第一类是换视角：侧身/贴墙）。

14. **`stage.from` 借用别的动作的机位，别复制文件**（2026-09-24）。要跳的动作
   （`cheer`）需要 `hop` 那张把角色压低（`baseline 0.95`）的首帧，否则
   `displacement` 那句"整个人可以在画面里升起"会让头顶出格线。两张图**姿势完全一样**，
   重出一份只会多一个会各自漂移的副本——用名字显式声明依赖。

15. **拼条的列数写进 `f0000.json`，别让下游猜**（2026-09-24）。格宽 = 表宽 ÷ 列数，
   而**任何约数在几何上都自洽**：对 16 列的表按 8 列切，每"格"横跨两个角色，
   于是**量不出"装不下"**（错的方向是偏乐观），装完才发现被裁。
   同一个角色下 8 列与 16 列的表并存之后，默认值彻底不成立。
   `h3-motion.mjs` 产拼条时写 `writeSheetGrid`，`sheet-canvas.mjs` 优先读它。

16. **新动作进了归一化组，就可能改整组的倍率**（2026-09-24）。
   `scale = canvas.h × 0.94 / 组内最高包围盒`，所以**往组里加一个更高的动作，
   整组会一起变小**（宠物在屏幕上凭空缩水）。加完必须用 `sheet-canvas.mjs`
   跟旧值对照。团子这一轮新组最高的 `cheer` 是 338，旧组最高是 `picked` 的 366，
   倍率逐位未变——**离出事只差 28px**。

17. **一次性（`once`）动作的时长必须 < 2.6 秒**（2026-09-24）。
   编排器播这类动作（打哈欠/伸懒腰/挠头/张望…）前会**先按住自主行为再播**，
   而让位是**定时放开**的——`ONE_SHOT_AMBIENT_HOLD_MS = 2600ms`。动画比它长，
   让位就会在播到一半时解除，环境姿态一被切走，宠物就**一边平移一边演**。
   现有各组 8fps×16 帧 = 2.00s（`Dodge` 14fps 只有 1.14s），余量最小 600ms——
   按硬规则 10 的成对口径调帧数/fps **之前先算一下时长**。
   **要更长的动作，去把 hold 调长**（`PetOrchestrator`），别只把 fps 降下来顶上去：
   那会让动画变卡，两笔账不是一回事。

18. **光点/花瓣/粒子不画进动作帧，只有特效层能出**（2026-09-24 月兔小仙）。
   模型自己在空中画的粒子，**底色跟精确底色对不上**（实测离 `#00FF00` 有 26~80 之远），
   `ColorToMask threshold=30` 抠不掉 → 变成表上的绿渣；而且**只长在中间格**
   （首末格等于机位图本身，所以那两格干净）。位置、时机、密度也全归了模型。
   措辞要用**肯定式列清单**（`no petals, no sparkles, no glowing dots, no dust motes,
   no light streaks, no particles`）——只写 "clean background" 会被理解成"干净的绿幕"，
   粒子照画。这句已焊在 `h3-motion.mjs` 的 `_CLEAN_PLATE`，四个动作共用。
   要特效就走 `slots` 非 base 批次（见 `install-pet --fx-dir`）。

19. **碎块拦两道：机位图一道，抠完底再一道**（2026-09-24）。
   `stage-frame --drop-debris` 拦的是**机位图自带**的渣（实测有效：渣表首格 5 块 → 0 块），
   但**表里中段的渣是视频播放时长出来的**——角色移动后把身后的地方让开，模型把那块
   重新画一遍，画出来的绿跟底色不一样，色键抠不掉。**机位图抠得再干净也拦不住它长**，
   所以第二道必须落在**抠完底之后**：`characters/detached-check.mjs`
   （`h3-motion` 出表时自动跑，`--no-scrub` 可关；也可单独跑，默认只报不改）。
   三档：`≥1500px` **本体级**不动｜`420~1500` **保留并告警**｜`<420` 且离本体 `>6px` 抹掉。
   ⚠ "离本体"**必须用像素距离**：按包围盒间距判时，"花瓣飘在她躯干正前方"的间距是 0，
   实测 102 个非本体块里 96 个会被漏掉。大块（脚下的云、断开的水袖）**永不自动删**，
   只报——误杀一次真部件比漏十块渣贵。

20. **往上飞的动作，机位图那一步就要留顶空**（2026-09-24）。
   `POSES.ascend` 带 `ratio: 0.6`，`buildPrompt` 里 `figureRatio ≤ 0.65` 会换成
   `_POSITION_LOW`（"站在画面下半部、头顶留大片空天"），高度百分比也跟着这句走。
   不给这个数，提示词永远是默认的"70% + 画面正中"：实测踏云机位 16 格里 **12 格头顶
   贴边被切**，而摆位只是照着已经切掉头部的图裁，**改摆位治不好**。
   后果不止难看——**越出格线的批次整批被 S1 闸门拒绝**（报"12 格越出格线，最差 8.91%"），
   那一组根本进不了包。所以装包前后都要核对组清单：缺表的动作组是**静默跳过**
   （只打一行 `⚠ 跳过 X`），装出来少组**不报错**（见第八节）。
   ⚠ **但"留顶空"只解决了一半**——另一半见第 22 条：振幅不设上限的话，留多少空
   都会被吃光（实测升幅 124px 正好吃掉 125px 顶空）。
   
21. **抠底只管透明不透明，颜色要单独修一道**（2026-09-24 月兔小仙走路表）。
   角色压在绿底上的那圈像素，alpha 拿到了、RGB 还带着绿——`ColorToMask` 治不了它。
   走路表实测：距透明区 ≤4px 的不透明像素里 **60% 绿分量高于红蓝、平均高 88**。
   两种修法，只有一种能用：
   · **压绿（clamp）是错的**：绿清掉了，边缘平均色变成 `rgb(113,110,121)` 一条
   **灰边**，离角色本色 `rgb(222,200,218)` 反而从 150 **远到 171**。混合像素里
   压掉绿，剩下的本来就是灰。
   · **换色（recolor）是对的**：从"干净内部像素"（不透明且 `e=g-max(r,b) ≤ 0`）
   多源 BFS 扩散颜色，边缘换成扩散来的颜色。实测边缘绿像素 **45,580 → 93**、
   边缘平均色 `rgb(113,164,121)` → `rgb(169,155,178)`、离本色 **150 → 80**。
   四条必须一起成立的细节：
   · **alpha 一个字节都不动**，且**边缘带以外逐字节不动**（这两条要逐字节核对，
   别靠"应该不会动"推理）。带内半径 3px 是内部与本体的分界——越界就会把角色
   自己的绿元素也染色（走路表内部有 4,706 个 `e>0` 的像素，腾云表有 32,473 个）。
   · **源距闸门 `maxdist=6`**：最近的干净源超过 6px 就别用。实测只跳过 93 个像素，
   正好是飘在远处模型自己撒的碎块——**把它们染成角色色只会更显眼**，那些归
   第 19 条的连通块过滤管。两道各管各的，别互相抢。
   · **半透明那一圈（64≤alpha<250）必须一起进刀口**。它是缩放/抗锯齿把边缘与绿底
   混出来的：实测平均色 `rgb(29,221,31)`、平均 alpha 170、99.8% 的像素 `e>0`，
   按 alpha 加权算**占整圈绿色的一半**（走路表 4.12M / 8.13M）。只修不透明像素的
   话剩余权重几乎不降（降 49.1%，和 clamp 的 49.3% 没差别）——这道工序就白干一半。
   含进来之后走路表 8.13M → 75,612（**降 99.1%**）、腾云表降 99.7%。
   · **扩散只走实体**（alpha≥64），不许跨过透明缝：跨缝会把**另一条丝带**的颜色
   染过来，实测走路表 105 个像素受影响、最大单通道差 169。
   · ⚠⚠ **必须"只借色相、保住自己的明度"**（`keepLuma`，默认开）。换色的取材是"最近的
      干净像素"，而描边只有 3~5px、外侧一旦被绿污染，最近的干净源**已经是里面的浅色
      衣料**——于是**描边被提亮洗淡**：实测描边暗档平均明度 **+37（走路）/+44（待机）
      /+36（点头）**，肉眼就是"边糊了"。修法是拿源色乘 `原明度/源明度`（保色相不保亮度），
      实测位移降到 **0.0**，而绿色降幅一点没损失（97.9%→97.9%、99.9%→99.9%）。
   · ⚠ **`边缘离角色本色的距离` 这个指标本身有偏**：它拿"内部平均色"当参照，
      把描边洗淡反而更靠近那个平均值——所以 `150→80` 那条漂亮曲线里**有一部分就是
      描边被洗淡贡献的**。保明度之后它只到 116，但人眼是对的、指标是错的。
      **判修得对不对要用这三条**：① alpha 加权绿色权重降幅 ② 描边暗档明度位移（要 ≈0）
      ③ 离最近调色板色的距离（别拿"内部平均色"当尺子）。
   落点：`lib/spill-fix.mjs`，由 `characters/detached-check.mjs` 在**碎块过滤之后**
   顺带跑（`h3-motion` 出表时自动调；`--spill off` 可关，`--no-semi` 退回只修不透明）。
   ⚠ **特效层表（`slots` 的光环/粒子表）必须加 `--no-cc`**：碎块判据假设"有一个主体、
   其余小块是渣"，而特效层整张表都是散开的光点，照跑会把整圈删光。
   

22. **画面内的位移必须有上限——真正的位移归客户端**（2026-09-24 腾云连栽两轮）。
    措辞里写 `rises ... by about a quarter of the frame height`，模型**就真升四分之一**：
    实测升幅 124px，而首帧顶空 125px、底空 32px，下降段又正好 32px → **8/16 格越界**，
    整批被 S1 拒（第 20 条）。留空是解不出来的：她占格高 0.65 时，672 的画布只剩
    234px 总余量，而容下 ±124px 需要 278px——**无解，只能压振幅**。
    三条一起改：
    · `motionClassMap.climb` 用 **`riding`** 不用 `displacement`（后者那句"整个人在画面里
      升起"就是长途位移的邀请函）。上升的净位移本来就归客户端
      （`RisingWallClimber` 上升段是代码平移），帧里要的是"云载着她、衣摆往下淌"。
    · prose 里把幅度写成**硬上限**（`about one tenth of the frame height, and never more
      than that`）+ 四个方向都得点名：`her ears never come near the top edge and the
      cloud under her feet never comes near the bottom edge`。
    · ⚠ **别再写"待在画面下三分之二"**：那是把底空删掉，下降段必然踩底边
      （实测格 2/12/13 底空 0）。改成"待在画面中部、上下都留空"。
    量的工具：`characters/cell-bounds.mjs`（逐格内容包围盒 + 按装包闸门口径判越界 +
    顶/底移动量与内容高变化），出表后先跑它，再谈装包。

23. **`--keep-scale` 必须配 `--src-h`**（2026-09-24 踩过）。`stage-frame --keep-scale`
    的语义是"按**源画布**里的比例换算到目标画布"，`--src-h` 不给就按**目标画布**算：
    512×448 的机位格（角色 294px）摆进 768×672，不传 `--src-h 448` 会得到
    294/672=**0.44** 的小人，而 Idle/Walk 是 0.65——**她一做这个动作就明显缩一号**。
    传了才是 294×(672/448)=441 → 0.656。摆完必须把 `figureHeightRatio` 和别的动作
    对一遍（同一角色的动作组之间尺寸要一致）。


## 五、画布尺寸怎么定

**客户端 normalize 按高度归一**：`targetH = canvas.h × 0.94`，宽度跟着高度走。

```
画布宽 ≥ canvas.h × 0.94 × 所有动作里最大的宽高比
```

侧身四足是**宽>高**（实测走路 1.19、下落 1.33、低伏爬行 1.75），正面角色是**高>宽**（0.74）。
超过就会**横向裁掉**，而 `pet-creator/run.ts` 只记一条 `clipped` 警告、**不报错**。

⚠ **这个数不能靠推——量。** 归一化倍率的分母是**「组内最高包围盒」**，不是这一帧自己的高：

```
归一化后宽度 = 该帧包围盒宽 × (canvas.h × 0.94 / 组内最高包围盒)
```

而「组」= **帧尺寸相同的一组**（同一批出图切出来的格一样大 → 同一组）。由此：

- 矮姿势**不会**被补到和别人一样高——它跟着组里最高的那个走。这是刻意的：
  逐帧各自撑满会把蹲下的帧放大到和站直一样高，切动作看起来像在抽搐。
- **往组里加一个更高的动作，整组会变小、所需宽度反而变窄。** 所以拿单个姿势的
  宽高比乘 421 是**错的**（偏大，而且随批次变动）——这条我先写错过一次。
- 正面表与侧身表出图宽度不同（576 vs 768），切出来的格尺寸不同 → 天然分两组，
  各自归一。

用 `sheet-canvas.mjs` 量**所有已出的表**：

```bash
node <技能>/characters/sheet-canvas.mjs --dir <动作表根目录> --char <角色> --canvas 448x448
```

它按格尺寸分组、算出每组倍率与所需宽度；给了 `--canvas` 时还会逐个动作报
「会被裁掉多少 px」（超了就退出码 1）。⚠ **等动作表出齐再量最后一次**——
少一个最高的动作，算出来的数会偏宽。

⚠ 动作表目录名是 `<角色>-<动作>-sheet`，**不含视角**：换视角重出会**覆盖**同一个
目录。于是重出失败时旧素材会留在原地冒充新素材被装进去。**出图前先把旧目录挪走**
（改名成不以 `-sheet` 结尾），别让它在测量和安装里混过去——这条是实测踩到的
（正面版的 `fall` 表就差点被当成侧身版装进去）。

⚠ **`canvas.h` 不能动**——宠物在屏幕上的观感大小 = `canvas.h × scale`。
换算 scale 时按**高度**换算（`scale × 旧画布高 / 新画布高`），按宽度算会在改比例时让宠物凭空缩小。

量宽高比用 `pose-pick.mjs`：它逐帧量**包围盒宽高比**（正面基准 0.78、侧身 >1），
并推荐该开多大画布。**判据别用镜像不对称度**——跨角色比会重叠（团子正面素材 24~36% 与
Shimeji 侧身行 34~60% 撞在一起，因为尾巴和抬起的手臂本来就打破对称）。

## 六、命令速查

两种用法等价，挑一种：**直接调**（路径相对本技能目录，`<技能>` = 本文件所在目录），
或**经 `run.ts`**（`SKILL_PARAMS` 传参，见文末协议）。⚠ 两者都**必须在仓库树内运行**——
工具脚本要 `import sharp`，而 ESM 的裸模块是从脚本位置向上找 `node_modules`；
技能被投放到 `~/.lumii/workspace/skills/` 后那条路径上没有 sharp（实测 MODULE_NOT_FOUND）。
`run.ts` 就是替你把位置找对的。

```bash
# 0) 摆首帧（生成画布上的机位标定）
node <技能>/characters/stage-frame.mjs <立绘.png> <staged/角色.png> \
  --canvas 576x672 --ratio 0.70 --baseline 0.856 --bg 00ccff --meta <staged/角色.json>

# 1a) 姿势图（尾帧自由；跑完用 pose-pick 挑帧）
node <技能>/characters/h3-motion.mjs pose --char <角色> --action side   # side / cling / creep / falling / sitting / purring
node <技能>/characters/pose-pick.mjs <拼条.png> --cols 16 --pick desc   # asc=取最窄高（贴墙）
#    ⚠ 拼条里裁出来的格要 `--src-h 448`，否则角色会**再缩 0.667 倍**（硬规则 5）
node <技能>/characters/stage-frame.mjs <挑中的帧.png> <staged/角色-姿势.png> \
  --canvas 768x672 --keep-scale --src-h 448 --baseline 0.93 --meta <staged/角色-姿势.json>

# 1a-2) 全部动作出齐后量画布该开多宽（归一化按「组内最高包围盒」算，推不出来）
#    ⚠ 列数由每张表自己的 f0000.json 给（8 列与 16 列会并存，硬规则 15）
node <技能>/characters/sheet-canvas.mjs --dir <动作表根目录> --char <角色> --canvas 448x448

# 1b) 动作表（生成+抠底+抽帧+拼条，一次出图）
#    ⚠ 抽帧数与片长**成对**（硬规则 10）：默认 107 帧取 16；改一个就得改另一个
node <技能>/characters/h3-motion.mjs sheet --char <角色> --action <动作>
node <技能>/characters/h3-motion.mjs batch --jobs "<角色>:walk,<角色>:climb" --sheet --frames 107 --picks 16
#    ⚠ 批量里排后面的任务会**先超时**——超时从"轮到它跑"算（2026-09-24 修）之前，
#      排第 8 位的干等 44 分钟就被误判成「等待超时」。真超时了先看日志里有没有
#      `（排队 Ns 后轮到它跑）`，别急着重出：**ComfyUI 对同图同 seed 的重复提交
#      是全量缓存命中、秒回**，重提交不会重跑。

# 2) 装进客户端（组数与帧数都由 ACTIONS 表定，可逐条带 cols / fps）
#    ⚠ 画布宽**必须先用 sheet-canvas.mjs 量**（见第五节）：有侧身动作时 ≠ 384
#    ⚠ 新动作进了同一组就可能**改整组的倍率**（硬规则 16），量完跟旧值对照
#    装完会自动量好 perchGaps 补进清单（硬规则 9）；Crawl 行按 ACTIONS 的 invertY 翻转
node <技能>/characters/install-pet.mjs --id <客户端目录名> --dir <动作表根目录> \
  --canvas <量出来的宽>x448 --bg 00ccff
```

测**交互**（拖动夹取、贴边吸附、抛掷）要合成一次拖拽——它自己拍帧找宠物再派发：

```bash

```

⚠ `drag-pet.mjs` 头部记着两个必踩的坑：速度要落在 `isThrowable`（320px/s）之下，
以及**真鼠标的移动会打断合成拖拽**（它带 `buttons: 0`，而画布把它当"左键已松开"）。


⚠ 宠物窗口是**全透明**的，截出来整幅 alpha=0（看着全黑）。往页面里注入
`#root>div{background:#f2f2f7 !important}` **能生效**，但注入 `html,body{...}` 不行
（`getComputedStyle` 仍是 `rgba(0,0,0,0)`）；CDP 的
`Emulation.setDefaultBackgroundColorOverride` 实测**不生效**。细节见
`shot-probe.mjs` 顶部。

## 八、动作组名是契约（缺组不报错）

仓库里有**两套「九个动作」**，混了不会报错——客户端 `PetOrchestrator.resolveAmbientGroup`
找不到组时**静默回落到基础待机**，表现为宠物一边平移一边播呼吸（像在滑行）。

| 规范 | 组 |
| --- | --- |
| **交互** | Idle / Talk / Jump / Wave / Nod / Shake / Picked / Land / PlayBall |
| **行为** | Idle / Walk / Sit / Talk / Fall / Picked / Jump / Climb / Crawl |

`Walk / Climb / Crawl / Fall` **必须是 `kind: "loop"`**：驱动会在同一姿态上停几十秒（实测一次攀爬 30 秒），
`once` 会让动作放完就僵住。判据：日志搜 `[setAmbientActivity]`，打 `→ 组 "(基础待机)"` 就是缺组。
