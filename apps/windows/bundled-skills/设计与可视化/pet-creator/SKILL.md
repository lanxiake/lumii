# 宠物创作（pet-creator）

把用户的描述变成一只**能在客户端跑起来**的桌宠。设计依据见
`docs/design/客户端UI/2026-09-20-虚拟人精灵图渲染后端设计.md` §3.2 / §5.1。

## 一、先理解这条链路的能力边界（别承诺做不到的事）

**主流生图模型结构性无法直出精灵图序列**，这不是提示词能解决的：

| 限制 | 后果 |
| --- | --- |
| 输出无透明通道 | 精灵图必须有 alpha → 必须后处理抠底 |
| 尺寸只有 1024 / 1536 | 做不出 32×32 的像素帧 |
| 无像素网格概念 | 像素风的整数网格对齐无法保证 |
| 帧间无一致性保证 | 生成"同一动作第 1/2/3 帧"会逐帧漂移，动作不成立 |

**实测数据（别推翻它）**：图生图参考链相邻一跳剪影 IoU 91–93%，**相隔三跳降到 73%**，
且**参考图会压过文字提示**（要求"回到站立"，模型仍保持参考帧的坐姿比例）。

→ **不要用链式图生图做序列帧。** 正确分工是：

- **AI 出静态部件**：身体 / 表情差分 / 口型档位 / 场景道具 / 缩略图
- **运行时做动画**：呼吸、摇摆、眨眼、浮动、点头（程序化原语）
- **要多个姿态？让模型一次出一张多格图集**（如 2×2），一致性由单次生成天然保证，成本是链式的 1/N

## 二、每次生成都必须满足的两条硬约束

这两条是 P-1 验证用实测换来的，写错会让整批素材报废：

1. **底色必须与角色所有颜色（尤其描边）保持足够距离。**
   抠底靠连通性 flood fill，容差一旦超过"描边色距底色的距离"就会穿透描边漏进角色内部
   ——实测误差从 0.00028 暴涨 300 倍。
   提示词里明确写：`背景为纯色 #RRGGBB，且该颜色与角色所有颜色（特别是描边线）保持明显区别`。
   **不要**用与角色同色系的底色（棕角色配米色底、粉角色配浅粉底都踩过）。

2. **底色不要写死成某个精确值就当它会准。**
   实测提示词写 `#D9218F`，实际产出在 `#d11b89`–`#db1782` 之间波动。
   工具链会自动估计底色，**不要传 `--bg`**，除非你确认估计错了。

## 三、标准流程

### 第 1 步：问清楚（不确定就问，别猜）

用户只说"我想要一只猫"时，至少确认：

- **风格**：像素风（整数倍缩放、硬边）还是 2D 高清（连续缩放、抗锯齿）？——这决定 `pixelArt`
- **配色**：有没有想要的色系？——这影响提示词里的底色选择
- **名字**：宠物叫什么？

用户已经说清楚的就别追问。一次问完，不要挤牙膏。

### 第 2 步：算出目标画布尺寸

**先定画布，再定出图**。客户端按画布像素渲染，尺寸决定它在桌面上多大：

| 风格 | 画布 | 注册表 `scale` | 屏幕高度 |
| --- | --- | --- | --- |
| 像素风 | 48×56 | 2 | ≈112px |
| 2D 高清 | 144×168 | 0.65 | ≈109px |

想让宠物更大/更小，改 `scale` 或画布，别改出图分辨率（出图统一 1024，由切分与缩放落到画布）。

### 第 3 步：设计出图批次（这里是判断力的地方）

**一次出图能拿到的部件越"同质"越好**。推荐拆成两三批，每批内部一致性由单次生成保证：

| 批次 | 提示词要点 | 网格 |
| --- | --- | --- |
| 身体姿态 | "同一角色，2×2 四格，四格分别是站立/呼吸起伏/抬手/低头，**四格角色完全一致，只改姿势**" | 2×2 |
| 表情差分 | "同一角色的头部特写，2×2 四格，分别是睁眼/闭眼/笑眼/难过眼，**除眼睛外完全一致**" | 2×2 |
| 口型差分 | "同一角色的嘴部特写，2×2 四格，嘴从闭到张四档" | 2×2 |

**每一批都要重新完整描述角色**（种类、配色、风格、描边），不要只说"同上"——
不同批次之间没有记忆，一致性靠你复述。

### 第 4 步：调 `image_generate` 出图

用文生图。把角色描述 + 硬约束（第二节）+ 网格要求写进 prompt。
每次只出一批，出完立刻处理，别攒着。

### 第 5 步：跑 `pet-creator` 脚本处理

把出图路径与你规划好的槽位结构传给脚本（见 SKILL 末尾的调用示例）。
脚本会依次做：**抠底 → 切格 → 按地线对齐 → 打包图集 → 写清单 → 校验 → 安装**。

### 第 6 步：报告结果

告诉用户宠物的名字、帧数、装到了哪里，并提醒**在客户端设置里选中它**。

## 四、脚本不做判断，判断是你的

`run.ts` 只做确定性的像素操作。以下都要你来决定：

- 出几张图、每张几格、每格叫什么名字
- 哪些槽位是整体帧（`base`）、哪些是分层覆盖（`face`/`scene`）
- 动作组怎么组织（哪个是待机、哪个是说话、哪些是点击触发的单次动作）

**默认给一套够用的动作集**：`Idle`（循环）+ `Talk`（循环）+ 一到两个单次动作。
不自作主张加很多组——用户没要求的东西会变成控制坞里的噪音。

## 五、失败怎么退

| 现象 | 处理 |
| --- | --- |
| 抠底残留背景 > 5% | 底色与角色太近。**换底色重新生成**，不要硬调容差 |
| 抠底后部件报废（包围盒为空） | 整格没有角色内容。检查网格行列数是不是切错了 |
| 四格里角色明显不是同一只 | 生图模型没守住一致性。重出这一批，提示词里更强调"四格为同一角色" |
| 切出来的格子大小不一 | 正常。对齐步骤会按地线归位，不需要重出 |
| 工具链报"未抠底" | 说明还没跑 cutout，或抠底没有生效。检查输入图是否真的是那一批出图 |

**绝不**为了让它"能装上"而放宽校验或手改清单去凑——装一个坏模型比装不上更糟，
它会在用户每次进宠物模式时白屏。

## 六、调用示例

```
execute_skill({
  id: "pet-creator",
  params: {
    action: "build",
    id: "my_pixel_cat",            // 只能用小写字母/数字/下划线/短横线
    name: "我的像素猫",
    canvas: { w: 48, h: 56 },
    anchor: [24, 54],              // 脚底中心
    pixelArt: true,
    scale: 2,
    // 每一批出图 → 一个槽位组
    batches: [
      { file: "<workspace>/outputs/pet-raw/body.png", cols: 2, rows: 2,
        slot: "base", names: ["body_00", "body_01", "body_02", "body_03"] },
      { file: "<workspace>/outputs/pet-raw/eyes.png", cols: 2, rows: 2,
        slot: "face", category: "eyes",
        names: ["eye_open", "eye_shut", "eye_happy", "eye_sad"] },
      { file: "<workspace>/outputs/pet-raw/mouth.png", cols: 2, rows: 2,
        slot: "face", category: "mouth", names: ["m0", "m1", "m2", "m3"] }
    ],
    mouthLevels: ["m0", "m1", "m2", "m3"],
    personaAddon: "你是一只叫咪咪的像素猫，活泼爱撒娇，说话口语化适合朗读。"
  }
})
```

脚本返回 `{ ok, id, installedDir, frames, warnings, ... }`；
`ok: false` 时把 `error` 如实转述给用户，**不要**自己编一个成功的结果。
