# 宠物创作（pet-creator）

把用户的描述变成一只**能在客户端跑起来**的桌宠。设计依据见
`docs/design/客户端UI/2026-09-20-虚拟人精灵图渲染后端设计.md` §3.2 / §5.1。

## 一、先理解这条链路的能力边界（别承诺做不到的事）

**主流生图模型结构性无法直出精灵图序列**，这不是提示词能解决的：

| 限制 | 后果 |
| --- | --- |
| 输出无透明通道 | 精灵图必须有 alpha → 必须后处理抠底 |
| 尺寸只有 1024 / 1536 | 做不出 32×32 的像素帧 |
| 无像素网格概念 | 像素风的整数网格对齐无法保证 |
| 帧间无一致性保证 | 生成"同一动作第 1/2/3 帧"会逐帧漂移，动作不成立 |

**实测数据（别推翻它）**：图生图参考链相邻一跳剪影 IoU 91–93%，**相隔三跳降到 73%**，
且**参考图会压过文字提示**（要求"回到站立"，模型仍保持参考帧的坐姿比例）。

→ **不要用链式图生图做序列帧。** 正确分工是：

- **AI 出静态部件**：身体 / 表情差分 / 口型档位 / 场景道具 / 缩略图
- **运行时做动画**：呼吸、摇摆、眨眼、浮动、点头（程序化原语）
- **要一段动作？一个动作一批，一批一张多格图集**（如 2×2）——一致性由单次生成天然保证，
  成本是链式的 1/N。**格子的阅读顺序就是时间顺序**，见第 3 步

## 二、每次生成都必须满足的两条硬约束

这两条是 P-1 验证用实测换来的，写错会让整批素材报废：

1. **底色必须与角色所有颜色（尤其描边）保持足够距离。**
   抠底靠连通性 flood fill，容差一旦超过"描边色距底色的距离"就会穿透描边漏进角色内部
   ——实测误差从 0.00028 暴涨 300 倍。
   **这条已经交给代码**：把角色身上出现过的颜色（含描边）列进 `characterColors`，
   出图计划会算出离它们都最远的那个颜色当底色。**别自己指定 `background`**——
   这是能算的题，肉眼估会踩坑（棕角色配米色底、粉角色配浅粉底都踩过）。

2. **底色不要写死成某个精确值就当它会准。**
   实测提示词写 `#D9218F`，实际产出在 `#d11b89`–`#db1782` 之间波动。
   工具链会自动估计底色，**不要传 `--bg`**，除非你确认估计错了。

## 三、标准流程

### 第 1 步：问清楚（不确定就问，别猜）

用户只说"我想要一只猫"时，至少确认：

- **风格**：像素风（整数倍缩放、硬边）还是 2D 高清（连续缩放、抗锯齿）？——这决定 `pixelArt`
- **配色**：有没有想要的色系？——这影响提示词里的底色选择
- **名字**：宠物叫什么？

用户已经说清楚的就别追问。一次问完，不要挤牙膏。

### 第 2 步：算出目标画布尺寸

**先定画布，再定出图**。客户端按画布像素渲染，尺寸决定它在桌面上多大：

| 风格 | 画布 | 注册表 `scale` | 屏幕高度 |
| --- | --- | --- | --- |
| 像素风 | 48×56 | 2 | ≈112px |
| 2D 高清 | 144×168 | 0.65 | ≈109px |

想让宠物更大/更小，改 `scale` 或画布，别改出图分辨率（出图统一 1024，由切分与缩放落到画布）。

### 第 3 步：设计出图批次（这里是判断力的地方）

**一批 = 一个动作组；格 = 这段动作的关键帧；格子的阅读顺序就是时间顺序。**

这条是硬的。曾经有个版本写成「2×2 四格，分别是站立/呼吸起伏/抬手/低头」——那是
**四个互不相干的姿势**，切成帧序列播出来，待机循环里会冒出抬爪和低头
（实测产出 `real_dog` 就是这样）。**四个姿势不等于一段动作。**

所以每批要给两样东西：**动作名**（`action`）与**动作经过**（`motion`）。
只给名字（「挥手」）模型会自由发挥成四个看着像挥手的姿势；给了经过它才有东西照着排。

| 批次 | `action` | `motion`（按时间顺序写经过） | 网格 |
| --- | --- | --- | --- |
| 待机呼吸 | `待机呼吸` | `胸口缓缓起伏 → 起伏到顶 → 缓缓落下 → 回到起始` | 2×2 |
| 挥手 | `挥手` | `右前爪从身侧抬到耳侧 → 向左边摆 → 摆回右边 → 缓慢落回身侧` | 2×2 或 3×2 |
| 点头 | `点头` | `头缓缓低下 → 低到最低 → 抬回中位 → 略微上扬 → 回到中位` | 3×2 |

- **四格起步，动作复杂就上六格**（`cols: 3, rows: 2`）。格数一多模型越容易把中间几格画成别的动作，
  所以**格数要配得上你写的经过**：经过里几个阶段，就大致给几格。
- **动作数不必多**：`Idle` + `Talk` + 两三个点击动作就是一套够用的。
- **首尾要能接上**：末格回到首格附近，否则循环时会有一次跳变。

**表情/口型批要给 `diffBase`**（见第 5 步）：它们出的是「同机位全身、**除眼睛外完全一致**」的图集，
流水线会拿它跟基准帧做差分，把眼睛那一层抠出来。

**每一批都要重新完整描述角色**（种类、配色、风格、描边），不要只说"同上"——
不同批次之间没有记忆，一致性靠你复述。

### 第 4 步：取提示词并出图

**提示词不要自己写**，用 `action: "plan"` 让工具链渲染出来（技术段的约束都是实测换来的，
自己重写会丢掉它们）：

```
execute_skill({
  id: "pet-creator",
  params: {
    action: "plan",
    character: "<角色与画风的完整描述，就是你想写进创作段的那段话>",
    characterColors: ["#f3e2c7", "#4a3520", "#1a1a1a"],   // 角色身上出现过的颜色，含描边
    batches: [
      { action: "待机呼吸", motion: "胸口缓缓起伏 → 起伏到顶 → 缓缓落下 → 回到起始", cols: 2, rows: 2 },
      { action: "挥手",     motion: "右前爪从身侧抬到耳侧 → 向左边摆 → 摆回右边 → 缓慢落回身侧", cols: 3, rows: 2 }
    ]
  }
})
```

返回 `{ background, batches: [{ action, motion, cols, rows, filename, prompt, warnings }], warnings }`。

然后每个批次调一次 `image_generate`：

- `prompt` **原样**传，`filename` 用它给的名字。别改写、别翻译、别增删。
- **`background` 别自己指定**——它是按 `characterColors` 算出来的，
  见第二节第 1 条。也不要跳过 `plan` 直接自己编 prompt。
- `warnings` 非空先修正再出图（比如创作段里出现了阿拉伯数字或"帧"这类技术词）。
  出一次图要一分钟和一次真金白银，返工代价不对等。

### 第 5 步：跑 `pet-creator` 脚本处理

把出图路径与你规划好的槽位结构传给脚本（见 SKILL 末尾的调用示例）。
脚本会依次做：**抠底 → 切格 → 按地线对齐 → 打包图集 → 写清单 → 校验 → 安装**。

### 第 6 步：报告结果

告诉用户宠物的名字、帧数、装到了哪里，并提醒**在客户端设置里选中它**。

## 四、脚本不做判断，判断是你的

`run.ts` 只做确定性的像素操作。以下都要你来决定：

- 出几张图、每张几格、每格叫什么名字
- 哪些槽位是整体帧（`base`）、哪些是分层覆盖（`face`/`scene`）
- 动作组怎么组织（哪个是待机、哪个是说话、哪些是点击触发的单次动作）——
  出图批次直接带 `group`（单次动作再加 `kind: "once"` 与 `next`）；
  **不带给 `base` 批次的都会被当成待机帧拼进同一个 Idle 循环**，多个动作要分开就得各自命名

**默认给一套够用的动作集**：`Idle`（循环）+ `Talk`（循环）+ 一到两个单次动作。
不自作主张加很多组——用户没要求的东西会变成控制坞里的噪音。

## 五、失败怎么退

| 现象 | 处理 |
| --- | --- |
| 抠底残留背景 > 5% | 底色与角色太近。**换底色重新生成**，不要硬调容差 |
| 抠底后部件报废（包围盒为空） | 整格没有角色内容。检查网格行列数是不是切错了 |
| 四格里角色明显不是同一只 | 生图模型没守住一致性。重出这一批，提示词里更强调"四格为同一角色" |
| 切出来的格子大小不一 | 正常。对齐步骤会按地线归位，不需要重出 |
| 工具链报"未抠底" | 说明还没跑 cutout，或抠底没有生效。检查输入图是否真的是那一批出图 |

**绝不**为了让它"能装上"而放宽校验或手改清单去凑——装一个坏模型比装不上更糟，
它会在用户每次进宠物模式时白屏。

## 六、调用示例

整条链路是两次 `execute_skill` 调用，中间夹 N 次 `image_generate`。

**第一次：取提示词（`action: "plan"`）**

```
execute_skill({
  id: "pet-creator",
  params: {
    action: "plan",
    character: "一只叫咪咪的像素猫，橙白相间，圆脸大眼，深棕色粗描边，简洁平涂",
    characterColors: ["#e08a3c", "#f6efe3", "#3a2418"],
    batches: [
      { action: "待机呼吸", cols: 2, rows: 2 },
      { action: "挥手",     cols: 2, rows: 2 }
    ]
  }
})
```

**第二次：把出好的图交给流水线（`action: "build"`）**

```
execute_skill({
  id: "pet-creator",
  params: {
    action: "build",
    id: "my_pixel_cat",            // 只能用小写字母/数字/下划线/短横线
    name: "我的像素猫",
    canvas: { w: 48, h: 56 },
    anchor: [24, 54],              // 脚底中心
    pixelArt: true,
    scale: 2,
    // 每一批出图 → 一个槽位组。names 数量必须等于 cols×rows
    batches: [
      // 不带 group 的 base 批次 = 待机帧（Idle 与 Talk 都播它）
      { file: "<workspace>/outputs/pet-raw/pet-sheet-1.png", cols: 2, rows: 2,
        slot: "base", names: ["body_00", "body_01", "body_02", "body_03"] },
      // 带 group 的 base 批次 = 独立动作组。不给 group 的话这些帧会被拼进 Idle 循环里播
      { file: "<workspace>/outputs/pet-raw/pet-sheet-2.png", cols: 3, rows: 2,
        slot: "base", group: "Wave", kind: "once", next: "Idle", fps: 6,
        names: ["wave_00", "wave_01", "wave_02", "wave_03", "wave_04", "wave_05"] },
      // 表情批：带 diffBase 时，流水线会拿它跟基准帧差分，只留下眼睛那一层。
      // 出图时**必须**把基准帧当参考图一起给 image_generate，否则机位对不上、差分不成立。
      { file: "<workspace>/outputs/pet-raw/pet-sheet-3.png", cols: 2, rows: 2,
        slot: "face", category: "eyes", diffBase: "body_00",
        names: ["eye_open", "eye_shut", "eye_happy", "eye_sad"] }
    ],
    personaAddon: "你是一只叫咪咪的像素猫，活泼爱撒娇，说话口语化适合朗读。"
  }
})
```

`params.animations` 是给「不挂在任何批次上的动作组」用的逃生口；
出图批次对应的动作组直接写在批次上（`group` / `kind` / `next` / `fps`），
别用两处描述同一件事。

脚本返回 `{ ok, id, installedDir, frames, animationGroups, warnings, ... }`；
`ok: false` 时把 `error` 如实转述给用户，**不要**自己编一个成功的结果。
