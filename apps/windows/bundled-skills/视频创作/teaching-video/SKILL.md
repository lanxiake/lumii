# 教学视频（三个工具，按顺序用）

做一条带动画、配音、字幕的 MP4 教学视频。**三个工具是三段，不要合并调用。**

| 工具 | 耗时 | 产出 | 用户此时该做什么 |
|---|---|---|---|
| `teaching_video_plan` | ~40 秒 | 大纲 + 分镜 + `review.md` | **确认讲法** |
| `teaching_video_produce` | ~1 分钟 → ~6 分钟 | 首节预览 → 全片 | **确认风格** |
| `teaching_video_revise` | ~1 分钟 | 重做的几节 | 指出问题 |

## 一、什么时候用

**该用**：用户要「讲明白」一个东西，且画面能帮上忙——数学/物理推导、技术原理、
产品功能、就医决策、数据解读、历史演进、操作教程。

**不该用**：纯文字总结（用 Markdown）、真实录屏（用 `screen-tutorial-pipeline`）、
需要实拍或 AI 生成画面的创意视频（用 `video-creation-pipeline`）。

## 二、三步流程（**必须按顺序**）

### 第 1 步：`teaching_video_plan` —— 出草稿

```
teaching_video_plan({ topic, audience?, durationMinutes?, style? })
```

40 秒返回，**不渲染、不配音**。拿到后必须做三件事：

1. **列出每节讲什么**：节标题 + 每节一句话
2. **复述旁白**：每节打算口头讲什么（结果里有 `sectionNarration`）
3. **主动挑毛病**，然后问用户

挑毛病看这几处：

- **推导有没有跳步**：第一节用到的东西，前面讲过吗？
- **有没有漏掉的前提**：讲「负数乘负数」，绝对值的直观讲了没有？
- **节数与时长匹配**：4 分钟塞 6 节是不是赶？
- **哪一节可以删**：删了会不会塌？

最后问：「这个讲法对不对，要不要调」。**不要**直接调 produce。

### 第 2 步：`teaching_video_produce` —— 出片（分两次）

**第一次**（不传 `skipPreview`）：只渲第一节，返回 `previewPath`。

```
teaching_video_produce({ fromDir: <plan 的 outputDir> })
```

把预览图给用户看，问「**风格、字号、密度可以吗**」。这一分钟是省下来的——
等 6 分钟出全片才发现风格不对，就要整条重来。

**第二次**（用户认可后）：出全片。

```
teaching_video_produce({ fromDir: <同一个 outputDir>, skipPreview: true })
```

只有用户明确说「不用看预览、直接出」时才第一次就传 `skipPreview: true`。

### 第 3 步：`teaching_video_revise` —— 只改有问题的那节

```
teaching_video_revise({ fromDir: <同一个 outputDir>, sectionIds: [2], feedback: "公式太挤" })
```

- `sectionIds` **必须给**——整条重跑要多花十几分钟
- `feedback` 写**用户的原话**，它会进场景生成的提示词。
  只给节号不给原因，模型只能原样重画一遍

## 三、人工审核的三个点

这是这套流程的核心：**三个地方必须停下来等用户，不要自己往下走。**

| 审核点 | 用户看什么 | 你要问什么 |
|---|---|---|
| plan 之后 | 分节结构 + 旁白 | 这个讲法对不对？有没有漏前提？ |
| produce 预览后 | 首节画面 | 风格/字号/密度可以吗？ |
| revise 之前 | 用户指出的节 | 具体哪里不对？（写进 feedback） |

## 四、结构模板：选对骨架

工具会自动选模板。**如果用户明显说了类型，告诉他选的是哪个**，让他有机会否掉。

| 用户说 | 模板 | 骨架 |
|---|---|---|
| 「讲清楚 X 是什么/为什么」 | 通用解释 | 钩子 → 直觉 → 机制 → 例子 → 收束 |
| 「推导/证明/一步步算」 | 逐步推导 | 起点 → 一步一改 → 验算 → 落点 |
| 「对比/区别/正负」 | A/B 对比 | 建 A → 建 B（同坐标）→ 分歧点 → 结论 |
| 「数轴/距离/方向」 | 数轴/度量 | 立轴 → 走一趟 → 读成数 → 换起点 |
| 「规律/数列/统计」 | 找规律 | 摆数据 → 逐行填 → 命名规律 → 验 |
| 「流程/步骤/怎么走」 | 流程/步骤 | 初始态 → 步骤 1..N → 终态 |
| 「由什么组成/分几层」 | 结构拆解 | 整体 → 拆件 → 配合 → 拼回 |
| 「为什么导致/连锁」 | 因果链 | 条件 → 第一环 → 第二环 → 反证 → 必然 |
| 「什么是 X」（定义） | 定义/概念 | 三个例子 → 共同点 → 定义 → 边界 → 回看 |
| 「历史/演进/复盘」 | 时间线 | 立时间轴 → 放事件 → 讲因果 → 看影响 |
| 「什么情况选哪个」 | 决策/分岔 | 起点 → 判据 1 → 判据 2 → 易错点 → 顺序 |
| 「数据说明什么」 | 数据解读 | 问题 → 数据 → 对比 → 结论 |
| 「怎么用/操作」 | 操作教程 | 目标 → 前置 → 步骤 → 验收 |
| 「案例/经历」 | 案例/叙事 | 角色 → 困境 → 转折 → 结果 → 启示 |
| 「产品/卖点/发布」 | 产品/卖点 | 钩子 → 卖点 → 卖点 → 行动 |

## 五、视觉风格：选对长相

| 风格 | 长什么样 | 什么时候用 |
|---|---|---|
| `3b1b` | 近黑深蓝底、细亮线 | 数学、物理、算法（默认） |
| `chalkboard` | 墨绿黑板、粉笔、楷体 | 课堂推导，「一步一步写」 |
| `clean` | 白底深线、圆点编号 | 产品、商业、投影环境 |
| `metro` | 暖米白、粗彩色线 | 决策、分岔、排查路线 |
| `tech-dark` | 深灰、等宽字体 | 技术、代码、架构 |

用户说了「黑板」「白底」「科技感」这类词，就显式传 `style`。

## 六、画质与音色（produce 的两个参数）

### `quality` —— 三档，默认 `standard`

| 档位 | 帧率 / CRF | 单节耗时 | 什么时候用 |
|---|---|---|---|
| `draft` | 12fps / crf 28 | ~35 秒 | 快速验证讲法 |
| `standard` | 24fps / crf 20 | ~85 秒 | **默认**，成片够用 |
| `high` | 30fps / crf 17 | ~130 秒 | 用户说「要发出去 / 画质好一点」 |

**首节预览固定走 draft**（只看风格，不需要高帧率）。
用户说「先快速看看」→ 成片也用 `draft`；说「要发布」→ `high`。

### `voice` —— 留空按受众自动挑

儿童 → 晓伊（活泼、放慢）；历史故事 → 云健（浑厚）；技术数学 → 云希（沉稳男声）；其余 → 晓晓（温柔女声）。

用户说「换成男声 / 亲切一点 / 稳重一点」时，按语义直接传完整的 edge voice id：
`zh-CN-XiaoxiaoNeural` / `zh-CN-YunxiNeural` / `zh-CN-XiaoyiNeural` / `zh-CN-YunjianNeural`。

**换音色是免费的重渲**——用户看完预览说声音不对，带新 `voice` 再调一次 produce 即可。
各节响度已统一到 -16 LUFS，换音色不会出现忽大忽小。

## 七、画面元素：模型能用哪些

`text` / `rect` / `circle` / `line` / `formula` / **`tex`**（真公式）/
**`axis`**（数轴）/ **`arrow`**（箭头）/ **`table`**（表格）/ **`brace`**（花括号）/
**`curve`**（曲线）/ **`code`**（代码）/ **`highlight`**（高亮块）

**每步最多 3 个元素**。超了会被打回重做——这是硬约束，不是建议。

## 八、质量告警怎么读

工具结果里可能有三种告警，**都要如实转述给用户**，不要自己咽下去：

| 字段 | 意思 | 怎么处理 |
|---|---|---|
| `layoutWarnings` | 元素重叠 / 出界 / 极扁的 rect（想画线却用了框） | 让用户知道哪一节有问题，提议 revise |
| `sceneWarnings` | 某步元素超量被截断 / 步数不足 | 同上 |
| `frameWarnings` | 抽帧看到空白帧、内容太散、太小、偏角 | 同上 |

## 九、常见错误

### **不要自己写渲染脚本**（最重要的一条）

**必须用这三个工具**，不要自己拼 HTML、写 `_render.js`、
调 ffmpeg 手动截图合成。

为什么这条排第一：实测有会话里 Agent 看到目录里落着 `section_N.html`，
就以为是「HTML 转视频」的任务，于是自己写 `_render.js` 逐帧截图——
结果绕过了配音、字幕、元素动画、布局门禁，出来的是一版纯画面，
而且下一轮它会学着上一轮的样继续手搓。

- 工具产出的 `section_N.html` 是**中间产物**，不是让你接手渲染的入口
- 需要改动就用 `teaching_video_revise`，不要改文件
- 如果用户说「上次那样自己渲染更快」，告诉他那样会丢配音和字幕

### 其他

- **别跳过 plan**。用户没确认讲法就出片，大概率要整片重做。
- **别忘 `fromDir`**。produce / revise 不带它会新建目录、重新生成，白花 token。
- **别为改一节跑全片**。用 `sectionIds`。
- **别把 `generationMs` 当视频时长**。`videoSeconds` 才是成片长度，
  `generationMs` 是这台机器算这次花了多久。
- **别自己编数字**。画面上的每个数都要能在用户的材料里找到；找不到就不写。

## 十、能讲什么（领域参考）

数学与线代（变换、特征值、行列式）、微积分（极限、导数、积分、泰勒）、
概率统计（贝叶斯、中心极限、分布）、物理光学（折射、干涉、全息）、
算法与机器学习（注意力、反向传播、梯度下降）、工程与协议（TCP、缓存、队列）、
健康决策（分诊、用药）、产品与商业（选型、成本、复购）。

不限于教学——任何「用动画能讲得更清楚」的东西都适用。
