## 核心建议

### 短期 (2 周) - 快速赢 [P0]

#### 方案 A: 增强后台任务卡片 (3 天)
```typescript
新增字段:
  • progress?: number              // 0-100%
  • currentPhase?: string         // "正在处理第 3/7 个文件"
  • logs?: TaskLog[]              // 实时日志
  • milestones?: Milestone[]      // 关键里程碑

UI 改动:
  ├─ 进度条 [████░░░░] 45%
  ├─ 阶段文本 "正在处理..."
  ├─ 日志面板 [展开/折叠]
  └─ 产出物预览 (就地)

工作量: 3 天
收益: 用户能看清 Agent 在干什么
ROI: 高
```

**优先级**: ⭐⭐⭐⭐⭐ (必做)

---

#### 方案 B: 结果预览面板 (4-5 天)
```
产出物类型支持:
  ✓ 图片 (Lightbox 预览)
  ✓ 视频 (HTML5 播放器)
  ✓ 表格 (可排序的 table)
  ✓ 代码 (语法高亮)
  ✓ Markdown (富文本渲染)

快捷操作:
  ├─ [下载]
  ├─ [复制]
  ├─ [在编辑器中打开]
  ├─ [导出 {CSV/PNG/PDF}]
  └─ [分享]

工作量: 4-5 天
收益: 用户不用打开多个窗口看产出物
ROI: 高
```

**优先级**: ⭐⭐⭐⭐⭐ (必做)

## 技术决策清单

### ✅ 已确定

| 决策 | 方案 | 理由 |
|------|------|------|
| **数据结构** | 扩展现有 BackgroundTask 类型 | 向后兼容，无需迁移 |
| **注册表实现** | TypeScript 静态类 + Singleton | 简洁、易用、性能好 |
| **插件隔离** | MVP 信任用户，后续 Web Worker | 快速上线，迭代优化 |
| **日志实时性** | 轮询 500ms (降级方案) | 平衡延迟和成本 |
| **结果格式** | 两层方案 (基础类型 + Registry) | 兼容 + 可扩展 |
| **UI 框架** | React + 现有样式系统 | 无新依赖，集成成本低 |
| **图表库** | Plotly (暂定) | 交互好，导出丰富 |

---

### ⚠️ 需要讨论

| 决策 | 选项 A | 选项 B | 建议 |
|------|--------|--------|------|
| **日志存储** | 内存 + 滚动 | IndexedDB 持久化 | A (快速) → B (稳定) |
| **插件加载** | 本地文件 + npm | CDN 动态加载 | A (MVP) → B (生态) |
| **权限细度** | 粗粒度 (工具级) | 细粒度 (API 级) | A (MVP) → B (安全) |
| **看板性能** | 虚拟滚动 | 全量渲染 | 建议虚拟滚动 |

## 风险评估

### 高风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 后端日志推送延迟 | 20% | 高 | 轮询降级，合理间隔 |
| 插件安全漏洞 | 15% | 高 | 权限系统，代码审查 |

### 中风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| UI 性能瓶颈 | 25% | 中 | 虚拟滚动，代码分割 |
| 用户适应成本 | 30% | 中 | 渐进式发布，文档引导 |

### 低风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 浏览器兼容性 | 10% | 低 | Polyfill，降级方案 |
