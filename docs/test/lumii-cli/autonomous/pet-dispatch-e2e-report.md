## 一条对审查结论的纠正：那条回归的代价**不是**"整轮不落库"

复审给的 #4（会话补建被挪到收尾）说"那一轮的正文、工具调用、思考一条都不写"。
**实测证伪**：收尾有一条兜底路径 `持久化 AI 回复（无流式占位）`，会把正文/工具/思考补写进去，
`persistSuccess` 也置 true（归档与技能进化照跑）。真机日志上两次并排看得很清楚：

| 时刻 | 代码 | 序列 |
|---|---|---|
| 15:53:44 | 旧（`ensure` 只在回执里） | `agent:start` → **跳过占位行：对话已不存在** → 整轮 → `agent:end` → **新建对话记录** → 回执 |
| 16:48:27 | 新（`ensure` 在建实例前） | `runPetDispatch 派发` → **新建对话记录** → `createInstance` → … → `持久化 AI 回复（收尾）` |

真正丢的是**过程**（那一轮没有流式占位，用户看不到"正在打字"）与**顺序**（会话是跑完才建的）。
所以 P9 的判据是这两条**机制签名**，不是"消息条数"——见下面第 3 条坑。

## 写这份脚本时踩的四个坑（都不是产品缺陷，但都伪装成了缺陷）

1. **假失败：读一次日志 vs 轮询**（P6）。渲染层处理 IPC 是异步的，`cron run` 返回时
   那行冒泡日志可能还差 ~15ms 才落盘。读一次的写法稳定报"没冒泡"。
2. **假失败：字节偏移切字符下标**（P6）。`statSync().size` 是**字节**，`readFileSync(p,'utf8').slice(n)`
   的 `n` 是**字符**下标。这份日志是大半中文的 4MB 文件（字节数 > 字符数），切出来直接是空串。
   改用 `Buffer.subarray(offset).toString('utf8')`。
3. **假通过：拿"消息条数"当回归判据**（P9 第一版）。两条路最后**都是 3 条**（兜底也会写正文），
   于是"整轮不落库"那条断言在**旧代码上也会绿**。改成机制签名之后才有区分度。
   ——这一版是 P9 写完当场推翻的：判据必须先问"旧代码会不会也过"。
4. **假失败又来一次：读一次日志 vs 轮询**（P9 第二版，同一个坑的同一个形态）。
   `message:end` 的落库**晚于**目标落终态，`waitForTerminal` 一返回就读会读到一个没刷盘的空窗口。
   改成 `waitForLogLine` 轮询。
   ⚠ 由此定下的顺序：**先等正向签名出现，再断言反向签名不出现**——
   反过来写的话，"不该出现"那两条会因为读得太早而必然全 0，那才是真正的空判。
