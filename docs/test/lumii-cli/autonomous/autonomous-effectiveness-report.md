## 一、执行摘要（三问直接回答）

**「真的能让 Agent 自主进化吗？」——能，机制实证存在，但速度受探索机制限制。**

- 负反馈（用户不满信号）**确实改变后续选择**：注入 1 条低分 → 变体统计与 UCB 立即重排 → 12 个新会话 **12/12** 跟随新排名（实验 A，两次运行一致）。
- **失败→反思→目标→批准→执行→沉淀→召回**完整闭环走通；执行产出是**真实的工作成果**（见下），不只是一段话。
- **但**：UCB 的探索奖赏（`ln(T)/n` 项）会让「低平均分但试验少」的变体反复回归——**淘汰一个劣质变体需要大量一致性负反馈，这是 1-2 天「看不出区别」的机制性原因之一**。

**「有什么用？」——三类实证价值。**

1. **越用越懂我（学习）**：低分被真实评估 → 生成针对性改进目标 → 执行 → 产出沉淀进记忆/Wiki → 后续可召回（memory search 命中 7 条训练详情）；复测同类任务表现改善（overall 0.488 → 0.763）。
2. **主动帮我干活（行动）**：目标执行**真的在干活**——一次「document_analysis 专项校准」目标执行真实创建了训练语料工程（`outputs/document-analysis-training/`：诊断协议、百分制评分 Rubric、4 个样本文档含标准答案），**Agent 自评「轮2有效分 74.5，合格未过关」，并自行排期 9/14 轮3盲测**；planner 自建任务手动执行产出高质量规则文本（两例）。
3. **有生命感（内在状态）**：Mood 由真实事件驱动（目标完成 → valence +0.183 / arousal -0.382，方向符合设计）；日记内容**引用了当天真实事件**（「坐在长文档面前练习拆结论」「处理记忆文件同步冲突」）——对比 9/6-9/8 的 8 篇纯思辨/空洞日记（「今天没有特别的事」）是质变；牵挂跨会话连续（raisedCount 递增、冷却后移）。

**「在什么情况下有用？」——见第七节条件清单。** 核心前提：**功能开着** + **有人处理待审批目标** + **有真实使用互动** + **知道去哪看**（`evolution:main` 会话 / 设置→实验功能→自主进化页）。

**为什么你开着用了两天「没看出区别」——三个直接原因（均有实据）**：

1. **心跳可能已静默瘫痪**：一次日常「打断（abort）」操作即可留下 `streaming=1` 残留消息 → 心跳全部 `skipped: user turn in progress`（本测试**2 次稳定复现**，缺陷 #1）。
2. **目标全部卡在待审批**：9/6-9/7 生成的 18 个目标至今 pending——无任何提醒、无超时，用户不知道要批，进化最大的「行动环」死了。
3. **可感知窗口极深**：开关与仪表板藏在「设置 → 实验功能 → 自主进化页」，无侧栏入口、无待审角标；主动消息只是一条标题「Lumii」的系统通知；高价值产出（训练语料/评分/排期）只有 DB 和 `evolution:main` 会话里有。

## 二、实验 A：变体选择的学习行为（create 探针 ≈ 0 LLM 成本）

**设计**：读取会话创建时被分配的 Prompt 变体 → 对当前 argmax 变体注入负反馈（2×abort + 失败工具，overall 0.488）→ 复算 UCB（表内 `ucb_score` 为死列，按 `avg + 2√(ln T / n)` 本地重算）→ 观察排名与后续选择。

| 阶段 | 结果 |
|---|---|
| run1 现状 | 最差变体 k2yezex **是 argmax**（UCB 1.3499 > baseline 1.3455）；历史 exploit 选中 99 次 |
| run1 注入 1 条低分 | trial 55→56、avg 0.736→0.7316 → baseline 反超；**后续 4/4 create 改选 baseline** |
| run2 现状 | 6/6 探针选 baseline（收敛到当前排名） |
| run2 注入 1 条低分 | baseline UCB 1.3458→1.3329 跌至第 3；argmax → k2yezex |
| run2 验证 | **12/12 新会话全部跟随新 argmax**（注入前该变体被选 0 次） |

**结论**：**反馈 → 统计回写 → UCB 重排 → 选择行为改变**，因果链完整、可复现。
**机制洞察**：UCB 探索奖赏使 `n` 较小的变体获得探索津贴，低平均分变体在 n 追平前会反复回归——「淘汰」不是一次性的，而是渐进收敛；这也解释了为何历史数据 114 次试验后系统仍在利用最差变体。

## 三、实验 B：短板闭环（失败 → 反思 → 目标 → 执行 → 沉淀 → 召回）

| 环节 | 结果 |
|---|---|
| B1 低满意 → 目标 | run1：overall 0.488 → 生成「改善用户反馈质量：学习更好的交互模式」（pending）；run2 同分因**同描述去重**被拦（SKIP，产品既有行为） |
| B2 反思 → 建议 | reflect 落库，建议 **3/3 条全部落地为新 pending 目标**（如「完成 document_analysis 专项校准：选取30至50个长文档…」） |
| B3 批准 | CLI approve → **executing**（审批链路真实流转） |
| B4 执行 | tick 派发执行 → **completed**；`evolution:main` +4 条；**产出为真实训练语料工程**（协议/Rubric/4 样本/自评 74.5/排期 9/14 轮3盲测） |
| B5 沉淀 | 工作记忆「document_analysis 专项校准本轮完成。总结如下：…」+ Wiki 知识页「学习成果 · 完成 document_analysis 专项校准…」 |
| B6 召回+复测 | memory search「document_analysis」**命中 7 条**（训练语料/评分/排期详情）；复测同类任务 overall **0.763 ≥0.6**、task=0.75（不再盲从失败工具，vs 低分基线 task=0.5） |
| B7 自建任务 | planner 自建任务**手动执行成功 2 例**——「把小提示写出来」→「先问一句，是把问题的边界摸清楚…」；「文档先按事实/约束/验收/证据四层」→ 规则产出 |

**结论**：闭环全部环节真实可用；**「学过的东西」确实沉淀且可召回、复测可见改善**。
**⚠️ 发现**：9/7 planner 自建的两个周期性 cron **至今 0 次执行记录**（自动调度环节存疑，手动执行正常）；22:20 批次新目标与 9/7 批次描述高度复刻（planner 在重复自己）。

## 四、实验 C：生命感

| 用例 | 结果 |
|---|---|
| C1 Mood 事件驱动 | 目标完成 → valence 0.6→0.783（+0.183）/ arousal 0.5→0.118（-0.382），方向符合设计 |
| C2 日记质量 | 825 字，无指标词，防重生效；**人工评审：真实事件引用成立**（「坐在长文档面前练习拆开一句结论」）；同日另一篇明确写「处理了一次记忆文件里的同步冲突」 |
| C3 牵挂连续性 | raisedCount 1→后移冷却，不打扰用户 |
| C4 token 预算 | 今日累计 2000+（计费真实） |

**结论**：内在状态**由真实事件驱动**、**反映真实经历**——满足设计铁律「状态影响决策/反映经历，不只影响措辞」。
**观察**：日记仍有习惯性开场（「今天仍然是淡的/没有风」），质量有模板化痕迹；单点加速观察，长期稳定性未知。

## 五、现状基线（为什么「开着也没区别」——9/6-9/8 历史实据）

- 8 篇日记全部为纯思辨/空洞独白；18 个目标全部卡 pending（5-6 天）；13 次主动消息=标题「Lumii」的系统通知；
- 变体 114 次试验全部劣于基线，且**最差变体仍是 argmax**（学习尚未产生可感知影响）；
- 22:20（本地）planner 真实运行一次：7 目标 + 6 自建 cron（排期 23:10-05:00）+ 8 todos——**主动规划活着，但产出重复、且执行依赖心跳**（心跳受缺陷 #1 影响时会静默死亡）。

## 七、什么情况下有用（条件清单）

**能产生价值**（每一项都有本次实验的实证）：

1. **功能开着**且**心跳未被缺陷 #1 瘫痪**（建议检查 `local_cron_runs` 是否大量 `skipped: user turn in progress`）；
2. 有**真实使用互动**（产生满意度/负反馈信号，系统才有的学）；
3. 有人**处理待审批目标**（或评估 `approvalMode` 调整），否则学习建议全部烂在队列里；
4. 给**足够时间**：变体收敛需大量样本 + UCB 探索期；设计预期 2-4 周稳态；
5. 关注「**Agent 自主事务**」而非对话体验：去 `evolution:main` 会话（或仪表板）看它执行的产出——本次实证的高价值产出（训练语料工程、自我评分、9/14 排期、规则沉淀）**只能在那里看到**；
6. 对它安排的任务**手动触发验证**（缺陷 #3 未修复前）。

**当前无法产生价值的情况**：心跳瘫痪时（缺陷 #1）；无人审批时（缺陷 #2）；用户不打开观测窗口时（缺陷 #6）；期望 1-2 天内对话体验肉眼可见变化时（机制性不支持）。

## 八、局限与遗留

- **加速实验证明「机制有效性」，不证明「长期使用必然有感知」**（本轮未做多日纵向观察，用户已定）。
- 实验真实写入了：变体统计（即学习证据）、测试目标、反思、沉淀记忆/Wiki、日记（今日 2 篇）、探针会话（`[evo-e2e-*]`，CLI 无删除能力，保留待人工处理）；快照恢复项见 evidence 的 SNAPSHOT/RESTORE 记录。
- 测试期间为修复心跳瘫痪**清理了 streaming 残留**（均为测试会话产物：abort 占位 + 执行中瞬时态）；此类残留建议产品侧加启动自愈。
- B1 run2 因去重 SKIP——反映的是产品既有行为（同描述 pending 拦截），非测试缺陷。
- 22:20 planner 批次的 6 个自建 cron（排期今夜 23:10-05:00）在测试后已恢复 enabled，**将按计划真实执行**（用户环境内的正常自主行为，特此声明）。
