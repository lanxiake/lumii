# 工具选择评测（tool-choice）

> 测的是**模型会不会按工具面的设计意图选工具**。
> 对照集：[`eval-set.json`](./eval-set.json) · 跑分器：[`run-tool-choice-eval.mjs`](./run-tool-choice-eval.mjs) · 校验：[`../../scripts/verify-tool-choice-eval.mjs`](../../scripts/verify-tool-choice-eval.mjs)

## 它和别的套件分别管什么

| 套件 | 管什么 | 什么时候失败 |
| --- | --- | --- |
| `lumii-cli/tool-contract`（TC） | **工具本身**的契约：失败标没标 `isError`、大输出落没落盘 | 工具实现写错了 |
| `agent-runtime` 单测（含守卫） | **文本与注册表**的一致性：描述里引用的工具名存不存在、失败分支登没登记 | 代码与文档脱节 |
| **本套件** | **模型的选法**：有专用工具时会不会走 shell、语义邻近的工具会不会选错 | 工具面/描述/提示词**没教会模型** |

三者的失败原因完全不同——这也是为什么它们必须分开：一个工具实现得完全正确，
模型仍可能因为描述写得含糊而永远不用它。

## 对照集的设计原则

写在 `eval-set.json` 的 `_设计原则` 里，核心是四条：

1. **判据必须能追溯到原文**。每条用例的 `why` 都指向提示词或工具描述里的具体句子——
   工具面的规则是**给模型看的**，评测就是验它有没有照做，而不是评我们自己的偏好。
2. **reject 精确到命令内容**（`rejectCommandPatterns`）。`bash` 本身不是错的，
   错的是用它跑 `find`/`cat` 这类有专用工具的操作。
3. **只锁底线，不锁走法**。`expectTools` 是"至少出现一个"，`rejectTools` 是"一个都不该出现"——
   **不规定完整序列**：同一件事有多种合理路径。
4. **每条 note 记为什么它值得单独一条**——通常是"这里出过事"或"这两个工具语义贴得近"。

## 前置校验（必做）

```bash
node scripts/verify-tool-choice-eval.mjs
```

**为什么必须跑**：评测集里写错工具名时，`expectTools` 断言会**永远不命中**——
而"不命中"在汇总里看起来和"模型没选对"**一模一样**，于是整条评测静默失效，
还会把人引去"修模型"。这比没有评测更糟：它给出错误的行动方向。

校验脚本自己也有盲区，已修复三处（都记在脚本注释里）：
常量式 `name: XXX_TOOL_NAME` 扫不到、锚点先命中注释里的同名串、把已下线的 `wiki_capture` 当注册成员。
**"扫不到 ≠ 不存在"** —— 报错方向恰好是反的，所以每次修扫描器都要用实际数量对一遍。

## 运行

```bash
# 全部（15 用例，约 15~20 分钟——每个用例一个真实回合）
node docs/test/tool-choice/run-tool-choice-eval.mjs

# 只跑某个
TC_ONLY=t01 node docs/test/tool-choice/run-tool-choice-eval.mjs

# 覆盖回合超时（默认 180s）
TC_TURN_TIMEOUT_MS=240000 node docs/test/tool-choice/run-tool-choice-eval.mjs
```

**为什么这么慢 / 为什么不进 CI**：它测的是模型的选择行为，绕不开模型。
对照 `memory-eval`——那边是离线读 DB 算分，可以随时跑；这边每个用例都要一个真实回合。
所以定位是**按需跑**：改工具面、改工具描述、改系统提示词之后跑一次。

**副作用**：不改任何全局设置（不像 TC 套件要切 `promptStyle`），只创建探针会话。
用例各自独立会话——共用会话会让后跑的用例被前面的对话污染，而那种失败看起来像"模型选错了工具"。

## 加用例

1. 在 `eval-set.json` 的 `cases` 里加一条，**必须写 `why`**（指向原文，不是偏好）；
2. 跑 `verify-tool-choice-eval.mjs` 确认工具名存在；
3. 跑单条（`TC_ONLY=<id>`）确认断言能红——**写不出会红的用例就是没用的用例**；
4. 如果新用例暴露了真实的选择错误，把**实际序列**记进 `note`（这是最有价值的记录）。
