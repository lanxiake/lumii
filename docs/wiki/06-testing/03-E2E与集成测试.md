# E2E 与集成测试

## 1. 自主进化 Agent E2E 测试框架

自主进化 Agent 采用「分层递进」的四套 E2E 套件，从命令行到全链路逐层验证。

### 1.1 四套套件总览

| 套件 | 执行器 | 覆盖层级 | 核心验证点 |
|------|--------|----------|------------|
| 自主 CLI | `run-autonomous-cli-suite.mjs` | 命令层 | 10 个 CLI 命令白名单、字段映射、SQL 查询、算法一致性 |
| 自主生命 E2E | `run-autonomous-life-e2e.mjs` | 生命层 | 心跳 tick、状态机运转、内在目标生成、人格事件落库 |
| 自主规划 E2E | `run-autonomous-planning-e2e.mjs` | 规划层 | 目标批准流转、执行调度、反思记录、变体成功率 |
| 全链路 E2E | `run-autonomous-full-e2e.mjs` | 全栈贯通 | 生命 + 规划 + CLI 查询完整闭环 |

### 1.2 自主 CLI 套件（P0）示例覆盖

| 用例 ID | 验证点 |
|---------|--------|
| TC1 | 正式表结构齐全（12 张表齐全性校验） |
| TC2 | help 暴露全部 autonomous 命令（10 个命令可被 Agent 发现） |
| TC3 | status 空数据降级（hasData=false，不抛异常） |
| TC4 | 满意度四维加权公式一致性（overall=0.6750，与设计公式 0.695 一致） |
| TC5 | 满意度趋势判定（trend=improving，3 点升序） |
| TC6 | 时间窗口过滤边界（7d=3 / 30d=3 / all=4） |
| TC7-TC13 | 目标列表、状态过滤、批准流转、拒绝、重复审批、不存在目标、缺参数 |
| TC14-TC18 | 能力维度查询、反思 JSON 解析、脏 JSON 降级、变体成功率、零试验除零 |
| TC19-TC22 | 开关持久化、默认启用、agentId 隔离、未知子命令报错 |

### 1.3 套件依赖关系

```
自主 CLI (P0, 22 条)
    ↓ 通过门槛
自主生命 E2E (P1) + 自主规划 E2E (P1)
    ↓ 分别通过
全链路 E2E (P1, 组合回归)
```

## 2. Agent 能力测试八大套件

完整覆盖从冒烟到护栏的八个维度，每套按 A/B/C/D/E/F/G/H 字母编号。

### 2.1 套件清单与目标

| 套件 | 名称 | 依赖模型 | 用例数示例 | 门槛类型 |
|------|------|----------|------------|----------|
| A | 冒烟 | 否 | 4 | 必过阻塞项 |
| B | 基础对话 | 是 | 3 | 必过 |
| C | 子 Agent 调度 | 是 | 4（含 1 SKIP） | 必过 C-01/C-02/C-04 |
| D | 打断与恢复 | 是 | 4（含级联 abort） | 必过 D-01/D-03 |
| E | 单项工具能力 | 是 | 6 | 全过 |
| F | 复杂编排 | 是 | 4 | 必过 F-01 |
| G | 边界护栏 | 是 | 3 | 必过 G-01 |
| H | 会话运维 | 部分 | 3（含 1 SKIP） | 建议过 |

### 2.2 各套件核心断言锚点

**A 冒烟**：
- A-01：`tools list` 含 `spawn_agent` 工具
- A-02：`conversation create` 返回 sessionKey
- A-03：`context messages` 可读 items 数组
- A-04：未知命令 exit=2

**C 子 Agent 调度**（日志锚点断言）：
| 日志锚点 | 含义 | 用例 |
|----------|------|------|
| `[SubagentBroker] registerRun ... mode=sync` | sync 子 Agent 注册 | C-01 |
| `[SubagentBroker] finalizeRun ... succeeded` | 子 Agent 成功结束 | C-01/C-02 |
| `[AgentOrchestrator] spawn async started` ×2 | 双 async 启动 | C-02 |
| `[subagent-delivery] prompt(internal)` + `followUp` | 投递分流两种模式至少各一 | C-02 |
| `[subagent] child destroyed after delivery` | 投递后销毁 | C-02 |
| `[Subagent] complete` | IPC 完成事件 | C-04 |

**D 打断与恢复**：
| 锚点 | 用例 |
|------|------|
| `[AgentRuntime] Aborted agent (cascade)` | D-01 父任务、D-03 级联 |
| `[abortSession]` + `stopReason: aborted` | D-01 中止完整链路 |
| abort 后下一轮 `send` 成功送达 | D-02 恢复可聊 |

**G 边界护栏**：
- G-01：并发第 6 次 `acquire denied` / `spawn denied concurrency`
- G-02：深度护栏 `getDepth` 阻止超限嵌套
- G-03：`startStaleMonitor` 启动存活监控

## 3. 测试用例编写模板

所有 E2E / 集成测试用例统一按以下六段式结构编写。

### 3.1 标准模板

| 段落 | 说明 | 示例 |
|------|------|------|
| **前置条件** | 运行前必须满足的环境/状态 | 应用已启动、控制口可达、模型配置就绪 |
| **输入** | 用户侧操作或命令序列 | 1. `conversation create --title "ctx-test-B01"`<br>2. `send --session <key> --text "压缩测试探针 OK"` |
| **预期输出** | CLI 返回 / UI 可见的显性结果 | ① 返回 sessionKey ② assistant 可见文本含「OK」 |
| **断言方式** | 如何判定通过（代码锚点） | exit=0 + JSON 含字段、日志锚点出现、关键词匹配 |
| **人工核查项** | 自动化难覆盖、需人工确认的点 | 摘要生成语义合理性、消息排版无错乱 |
| **清理** | 执行后恢复环境（仅删探针数据） | 删除 `wiki-cli-*` 前缀页面、清理临时 DB 行 |

### 3.2 用例文档的通用约定节

```markdown
## 0. 通用约定

### 0.1 CLI 契约
| 项 | 值 |
|----|-----|
| 退出码 | 0 成功 / 1 其他错误 / 2 参数错误 / 3 应用未运行 / 4 认证失败 / 5 被拒绝 |
| 控制口 | `http://127.0.0.1:<port>/command`，POST，Bearer token |

### 0.2 日志锚点（断言用）
| 锚点 | 含义 |
|------|------|
| `[SubagentBroker] acquire ok` | 并发槽占用成功 |

### 0.3 判真规则
1. 禁止仅用用户提示词中的关键字冒充通过
2. 工具类断言必须看到 `type=tool` 的真实 `result`
3. 子 Agent 完成必须看到 `finalizeRun` + `delivered`

### 0.4 调试日志前缀
`[<套件前缀>-TEST][<CASE-ID>][<阶段>]`，阶段 ∈ {准备, 执行, 断言, 清理, 结束}
```

## 4. E2E 测试的非确定性处理

### 4.1 允许部分 SKIP 的场景清单

| 分类 | 场景示例 | 处理方式 |
|------|----------|----------|
| **环境条件缺失** | web_search 未配置、bash 工具禁用 | 记 SKIP + 写明原因，配置后补跑 |
| **时间/成本过高** | Idle 真实触发（>390K tokens / 6+ 分钟） | 由单测覆盖，报告注明「成本原因未执行」 |
| **防污染保护** | synthesis confirm 自动修改知识库、source:delete 真删 | 人工触发或环境变量解锁后补跑 |
| **强 UI 交互** | 文件拖拽、系统通知、语音麦克风光标 | 人工核查清单勾选 |

### 4.2 证据链而非唯一答案

对于 AI 输出，不要求与固定字符串逐字匹配，而是验证「证据链完整」：

| 验证方式 | 示例 |
|----------|------|
| **工具调用存在性** | 日志出现 `[ToolRunner] → skill_search` + `← skill_search` |
| **状态流转正确** | pending → executing → approved，状态列 + approved_at 时间戳回查 DB |
| **字段完整性** | 返回 JSON 含 goalId、status、priority、createdAt 且类型正确 |
| **关键词 AND** | 回复同时含「已完成」+「3 个文件」+「没有错误」 |
| **数值单调性** | 压缩后 `usedTokens_after ≤ usedTokens_before + 小容差` |
| **日志锚点命中** | 提交期日志出现 `压缩事务提交成功: 移出 N 条` |

### 4.3 容差配置建议

| 断言类型 | 默认容差 | 说明 |
|----------|----------|------|
| token 计数 | ±10% | 摘要 token 可能反向短时增加 |
| 耗时 | 默认 120s，模型调用 300s | 含指数退避重试窗口 |
| 文本关键词 | AND 组合中允许漏 1 个非核心 | 核心关键词必须全中 |
| 并发时序 | 允许投递模式顺序颠倒 | 只要两种模式均至少出现 1 次 |

## 5. 真实用户场景验证方法

从生产日志抽取真实任务，转化为可回放的 E2E 用例，是发现边界缺陷的最高效手段。

### 5.1 抽取→转化流程

```
1. 筛选真实日志
   ↓ 筛选条件：异常报错栈、用户反馈复现、高复杂度任务
2. 脱敏处理
   ↓ 移除：用户明文、API Key、私有文件路径、个人标识
   ↓ 保留：任务结构（工具调用序列）、错误消息模式、消息数量级
3. 转化为 CLI 回放脚本
   ↓ 提取消息序列 → 构造 conversation create + send × N
   ↓ 注入种子数据到临时 DB
4. 自动化执行 + 差异比对
   ↓ 新代码跑同样的输入
   ↓ 比对：工具调用数量级、最终成功/失败、关键路径是否重现
5. 归档为「真实用户场景回归集」
   ↓ 写入 docs/test/2026-08-24-real-user-scenario-validation.md
```

### 5.2 场景优先级

| 优先级 | 抽取来源 | 典型场景 |
|--------|----------|----------|
| P0 | 用户反馈的复现用例 | 消息乱序、数据丢失、崩溃复现 |
| P1 | 线上错误日志 Top 10 | 数据库锁、上下文溢出、工具参数错误 |
| P2 | 高价值任务（长对话 + 多工具） | 自主进化全天运行、知识库批量导入 |
| P3 | 新版本迁移 | DB Schema 升级、旧数据兼容 |

## 6. Playwright UI E2E 的标准流程

### 6.1 页面测试标准流程

| 步骤 | 操作 | 断言点 |
|------|------|--------|
| 1. 启动 | 启动 Electron 应用，等待 splash 消失 | 主窗口 `isVisible()` |
| 2. 登录/初始化 | 跳过欢迎引导或使用已有 Profile | Dashboard 可见 |
| 3. 导航 | 跳转目标页面（Chat / Settings / Wiki / Memories） | 页面标题 + 根容器渲染 |
| 4. 交互执行 | 核心用户路径：输入→发送→等待回复 | 消息出现、工具卡片渲染、加载骨架消失 |
| 5. 错误路径 | 触发边界：空输入、断网、权限拒绝 | 错误横幅可见、状态回滚正确 |
| 6. 清理 | 关闭弹窗、删除测试会话 | 回到初始态无残留 |

### 6.2 UI 断言优先级

| 优先级 | 断言方式 | 场景 |
|--------|----------|------|

| - | CSS Class 查询 | 禁止，与实现耦合 |

### 6.3 必测页面清单

| 页面 | 核心路径 |

| ChatPage | 创建会话、发送文本、等待回复、中止、子 Agent 卡片展开 |

## 7. 数据库 Schema 迁移测试

### 7.1 自动迁移验证矩阵

| 迁移路径 | 脚本/方式 | 验证点 |
|----------|-----------|--------|
| V29 → V31 → Vxx | `docs/test/自主进化Agent/migrate-to-v29.mjs` | `user_version` 正确、新增表齐全、旧数据行保留、列默认值填充 |
| 空库 → 最新版 | 直接启动新代码 | 全部 `CREATE TABLE` 执行无错、完整性约束生效 |
| 脏数据 → 最新版 | 构造含非法 JSON/非法外键的 V29 | 迁移脚本降级而非崩溃、整表仍可查询 |

### 7.2 迁移测试脚本模板

```javascript
function runMigrationSteps() {
  const db = new DatabaseSync(':memory:')
  try {
    // 1. 模拟 V29 Schema
    execLegacySchemaV29(db)
    seedLegacyRowsV29(db)

    // 2. 执行迁移
    migrateToCurrent(db)

    // 3. 断言
    assertVersion(db, CURRENT_VERSION)
    assertTablesExist(db, ['autonomous_goals', 'autonomous_capabilities', '...'])
    assertLegacyRowsPreserved(db)
    assertNoOrphanRows(db)
  } finally {
    db.close()
  }
}
```

## 8. 跨层功能的集成测试策略

### 8.1 IPC 三层调用的联合断言

Electron 三层架构（main / preload / renderer）下的集成测试，必须在「同一用例」中断言三层各有痕迹。

| 层级 | 断言位置 | 典型断言 |
|------|----------|----------|
| Main 进程 | 主进程日志 + DB 数据 | `[CloudSync] 已创建冲突处理目标 goalId=...`，数据库 `autonomous_goals` 行数 +1 |
| Preload 桥 | 类型定义 + 调用日志 | `ElectronAPI` 接口定义存在对应方法，bridge call 计数 +1 |
| Renderer UI | Playwright / 组件单测 | 冲突提示 Banner 渲染，点击按钮触发 handler |

### 8.2 云同步冲突检测的跨层断言示例

```
用例：检测到冲突 → 创建自主目标 → Agent 处理
  断言 1 [main]：enterConflict() 触发，onConflictDetected 回调被调用
  断言 2 [DB]：autonomous_goals 表新增 1 行 status='executing' priority=0.9
  断言 3 [心跳]：下一轮 tick 收集到该目标（日志：collectTickSignals found executing goal）
  断言 4 [工具]：Agent 调用 cloud_sync_read_file + resolve_sync_conflict（均有 ToolRunner 锚点）
  断言 5 [同步]：sync-manager resolveConflict 应用决策，冲突状态清除
```

### 8.3 测试分层策略矩阵

| 功能域 | 单元测试占比 | 集成测试占比 | CLI E2E 占比 | 关键集成点 |
|--------|-------------|-------------|-------------|------------|
| 上下文压缩 | 70%（策略/算法） | 15%（bridge + compact-persist） | 15%（CLI 全链路） | compact → 事务提交 → 写 DB |
| 云同步 | 40%（纯函数） | 40%（sync-manager 状态机） | 20%（CLI 冒烟） | adoptRemote → Git 操作 → FS 备份 |
| Agent 子调度 | 45%（broker/registry） | 35%（orchestrator + runtime） | 20%（A-H 套件） | spawn → delivery → cascade abort |
| 自主进化 | 30%（算法/公式） | 40%（心跳 + 状态机） | 30%（四套套件） | goal 插入 → tick 收集 → Agent 执行 |
