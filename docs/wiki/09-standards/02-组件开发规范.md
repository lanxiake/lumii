# 02-组件开发规范

## 一、组件分类体系

### 1.1 组件层次结构

```
components/
├── ui/              # 原子/基础组件（Atomic）
├── layout/          # 布局组件（Layout）
├── business/        # 业务组件（Business）
├── pages/           # 页面组件（Pages）
└── [根级组件]        # 应用级组件
```

### 1.2 组件类型定义

| 层级 | 说明 | 示例 | 依赖 |
| --- | --- | --- | --- |
| UI | 基础可复用组件，无业务语义 | Button、Input、Card | 无业务依赖 |
| Layout | 页面结构组件 | MainLayout、Sidebar、TitleBar | 可能依赖 UI 组件 |
| Business | 领域特定复合组件 | DeviceCard、SkillCard、ApprovalSettings | 依赖 UI + 业务类型/Hooks |
| Pages | 完整页面（路由级） | DashboardPage、SettingsPage | 依赖所有下层组件 |

### 2.2 UI 组件 6 条强制规范

1. **单一职责**：每个组件只做一件事，UI 组件不包含业务请求/状态管理
2. **可组合性**：必须支持 `children` 组合，不把父组件 layout 死写内部
3. **可定制性**：必须接收 `className?: string` 用于样式扩展
4. **可访问性**：键盘可达 + ARIA 属性；`role` / `aria-label` / `aria-disabled` 正确
5. **类型安全**：Props 接口完整定义，所有变体用联合类型不用 any
6. **样式隔离**：必须使用 `ComponentName.module.css` CSS Modules 文件，不用全局样式污染

### 2.3 UI 组件标准模板

**ComponentName.tsx**

```typescript
import React from 'react';
import styles from './ComponentName.module.css';

export interface ComponentNameProps {
  className?: string;
  disabled?: boolean;
  size?: 'small' | 'medium' | 'large';
  onClick?: () => void;
}

export const ComponentName = React.forwardRef<
  HTMLDivElement,
  ComponentNameProps
>(({ className, disabled, size = 'medium', onClick }, ref) => {
  const classNames = [
    styles.componentName,
    styles[`componentName--${size}`],
    disabled && styles['componentName--disabled'],
    className,
  ].filter(Boolean).join(' ');

  return (
    <div ref={ref} className={classNames} onClick={disabled ? undefined : onClick}>
      {/* 组件内容 */}
    </div>
  );
});

ComponentName.displayName = 'ComponentName';
```

**ComponentName.module.css**

```css
.componentName {
  padding: var(--mt-spacing-md);
  border-radius: var(--mt-radius-md);
  transition: all var(--mt-transition-fast);
}

.componentName--small {
  padding: var(--mt-spacing-sm);
  font-size: var(--mt-font-size-sm);
}

.componentName--medium {
  padding: var(--mt-spacing-md);
  font-size: var(--mt-font-size-base);
}

.componentName--large {
  padding: var(--mt-spacing-lg);
  font-size: var(--mt-font-size-lg);
}

.componentName--disabled {
  opacity: 0.5;
  cursor: not-allowed;
}

.componentName:hover:not(.componentName--disabled) {
  background-color: var(--mt-bg-tertiary);
}
```

**index.ts**

```typescript
export { ComponentName } from './ComponentName';
export type { ComponentNameProps } from './ComponentName';
```

### 3.2 业务组件（已存在）

| 组件 | 用途 |

| ConnectionStatus / DualConnectionStatus | 双连接状态指示器 |

| DeviceCard / SkillCard / SkillStoreView | 设备与技能卡片 + 商店 |

| UpdaterView | 应用更新检查界面 |

### 3.3 页面组件四状态强制要求

每个 Page 组件**必须完整处理以下四状态**，缺任何一状态不允许合并：

| 状态 | 触发条件 | 必须渲染组件 |
| --- | --- | --- |
| **加载态 Loading** | 首次请求 / 刷新数据中，`loading && !data` | `<Loading fullPage />` 或局部骨架屏 `<Skeleton>` |
| **空数据态 Empty** | 数据成功返回但长度 0 / null | `<Empty description="暂无数据" action={<Button>刷新/新增</Button>} />` |
| **错误态 Error** | 请求失败 / 校验错误 / 权限拒绝 | `<ErrorBanner message={error.message} onRetry={refresh} onClose={clearError} />` |
| **成功态 Success** | 正常有数据渲染 | 业务内容（列表/卡片/表格等） |

## 四、CSS Modules 原则与使用

### 4.1 强制要求

- ✅ **所有组件样式放在同名 `.module.css` 文件**：`Button.tsx ↔ Button.module.css`
- ✅ **所有颜色/间距/字号/圆角/阴影用 CSS 变量**：`var(--mt-bg-primary)` 等设计令牌，**绝对不硬编码十六进制值/像素固定值**
- ✅ **BEM 变体用双连字符**：`.button--primary` / `.button--disabled`
- ❌ **禁止行内样式 `style={{ color: '#fff' }}`**（桌宠坐标/滚动偏移这种动态像素除外，且必须有注释说明）
- ❌ **禁止引入 CSS-in-JS 运行时（styled-components/emotion）**
- ❌ **禁止 `!important`**，除非是覆盖第三方库且有注释说明原因

### 4.2 样式编写规则

| 规则 | 说明 |
| --- | --- |
| **不跨组件覆盖样式** | 组件 A 的 module.css 中不能出现组件 B 的内部选择器 |
| **修饰符不独立** | 修饰符（`--primary`）必须和区块（`.button`）联合，不单用 |
| **不嵌套超过 3 层** | `.page .list .item .title .icon` 超过 3 层必须拆分 |
| **媒体查询就近放** | `@media (max-width: 768px)` 紧跟在被修改的选择器后 |
| **`prefers-reduced-motion`** | 过渡动画必须包在 `@media (prefers-reduced-motion: no-preference)` 中 |

## 五、组件开发三段式检查清单

### 5.1 创建新组件前（不满足不写代码）

- [ ] 在 ui/layout/business/pages 四个目录搜索，确认没有类似组件
- [ ] 明确分类（放哪个子目录），与现有命名风格一致
- [ ] 设计完整 Props 接口（所有变体、事件、ref 转发）
- [ ] 确认所有视觉设计所需的 CSS 变量（颜色/间距/字号）都已在 `tokens.css` 中存在
- [ ] 决定是否需要状态（stateful），能纯函数就纯函数，能 `memo` 就 memo 但不过度

### 5.2 开发组件中（每 30 分钟自检一遍）

- [ ] 文件结构符合：`ComponentName.tsx` + `.module.css` + `index.ts`，可选 `.test.tsx`
- [ ] TypeScript strict 模式，`no-explicit-any` 全关
- [ ] 所有 Props 变体：variant/size/disabled/loading 全部实现并测试
- [ ] 公共/业务接口写 JSDoc：`/** 按钮变体 */ variant?: 'primary' | ...`
- [ ] 纯净组件：同 props 同输出，不依赖外部隐式全局（除了设计令牌 CSS 变量）
- [ ] 性能优化：渲染开销大 + props 变化少的加 `React.memo`，回调 props 传的用 `useCallback`

### 5.3 组件完成后（MR 合入前必过）

- [ ] 单元测试覆盖 4 状态 + 3 交互（点击/输入/禁用），覆盖率 > 80%
- [ ] `components/ui/index.ts` 桶导出（ui/layout/business 各自）
- [ ] 至少在 2 个页面中实际验证展示 / 交互行为
- [ ] `pnpm --filter ./apps/windows lint` + `pnpm typecheck` 零 warning
- [ ] 深色主题 + 浅色主题（若支持）都检查过，对比度达标（文字 4.5:1）
- [ ] 可访问性：Tab 键可达 / 焦点可见 / 屏幕阅读器朗读 label 正确

## 六、响应式设计实现

### 6.1 断点系统（设计令牌 breakpoints.ts）

| 断点名称 | 宽度范围 | 典型设备 |
| --- | --- | --- |
| Mobile | < 768px | 小屏笔记本竖屏 / 平板小 |
| Tablet | 768px – 1024px | 平板横屏 / 中型笔记本 |
| Desktop | > 1024px | 桌面 / 大屏笔记本 |

### 6.2 两种实现方式结合使用

**方式 A：CSS 媒体查询（推荐 90% 场景）**

```css
.dashboardGrid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: var(--mt-spacing-lg);

  @media (max-width: 1024px) {
    grid-template-columns: repeat(2, 1fr);
    gap: var(--mt-spacing-md);
  }

  @media (max-width: 768px) {
    grid-template-columns: 1fr;
    gap: var(--mt-spacing-sm);
  }
}
```

**方式 B：Responsive 组件（条件渲染，布局完全不同场景）**

```tsx
import { Responsive } from '@/components/ui/Responsive';

<div>
  <Responsive showOn="desktop">
    <DesktopSidebar />  {/* 桌面端侧边栏 */}
  </Responsive>
  <Responsive showOn="mobile-tablet">
    <MobileDrawer />   {/* 移动端抽屉 */}
  </Responsive>
</div>
```

### 6.3 暗色主题优先清单

**写任何组件样式时必须通过以下 5 项检查**：

1. [ ] 颜色：没有一个硬编码颜色值，全来自 `var(--mt-bg-*)` / `var(--mt-fg-*)` / `var(--mt-color-*)`
2. [ ] 边框/阴影：`var(--mt-border)` / `var(--mt-shadow-sm)` 令牌
3. [ ] 反色：若组件做了"卡片背景"，不要假设父背景一定是 `--bg-primary`，要用语义的 `--mt-surface-rgb` 而不是具体色
4. [ ] 对比度：前景文字与背景对比度 ≥ 4.5:1（可在 DevTools Color Picker 直接看 AA/AAA）
5. [ ] 测试：在 DevTools「渲染」面板强制 color-scheme light/dark 分别看一遍没有不可读

## 七、组件通信与回调命名

### 7.1 Props 传递（禁止全展开）

✅ 显式列必要 props：

```tsx
interface ParentProps { user: User; onUpdate: (u: User) => void }
const Parent: React.FC<ParentProps> = ({ user, onUpdate }) => (
  <Child user={user} onUpdate={onUpdate} />
);
```

❌ 禁止 `{...props}` 全展开，隐藏真实依赖。

### 7.2 回调函数命名规范

| 前缀 | 使用方 | 示例 |
| --- | --- | --- |
| **onXxx** | 事件触发方（子组件 → 父组件发出） | `onClick` / `onChange` / `onSelect` / `onSubmit` / `onCancel` / `onClose` |
| **handleXxx** | 事件响应方（父组件内部实现） | `handleUserUpdate` / `handleRefreshClick` |
| **onUpdate / onRefresh / onDelete / onCreate** | 状态更新方（业务动作） | 语义化，不是 UI 点击而是业务结果 |

### 7.3 Context 适用边界

**使用 Context**：跨 3+ 层级的全局状态——主题、认证、连接状态、全局设置。

**不使用 Context（改用 props 或局部 state）**：
- 仅父子通信（直接传 props）
- 仅单组件局部状态（useState）
- 可"提升共享状态"到最近公共祖先的场景
