# modelcontextprotocol/servers 设计解构与 Lumii 参考建议

## 1. 结论

该仓库是 MCP 示例/参考 servers 的集合，不是完整的个人知识库。与记忆最相关的 `src/memory` 提供一个持久化 JSON 知识图：实体携带字符串 observations，关系为三元组，所有变更后重写文件并发送 resource 更新通知。它可作为最小、可审计的图 API 参考；不适合直接用于 Lumii，因为没有全文/语义检索、版本或作用域隔离，且其 MCP 进程边界不同于 Electron IPC。

下文结论基于 `599dafc1054550a6eeb87a6545c1e1b03b3ca827`。许可证正处于迁移期，详见源码说明，不能按单一许可证假设复用。

## 2. 已验证：最小图谱契约

```text
create_entities / add_observations / create_relations
       -> 内存知识图 -> JSON 文件
       -> memory://knowledge-graph resource updated notification

read_graph / search_nodes / open_nodes
       -> entities + relations 的结构化快照
```

- memory server 的实体包含 `name`、`entityType`、`observations: string[]`；关系包含 `from`、`to`、`relationType`。创建实体和关系会跳过重复项；删除实体会级联删除相关关系，删除 observation/relationship 按完全匹配执行。
- `read_graph` 返回完整图；`search_nodes` 按名称、类型、observation 内容做大小写不敏感的子串查找，并包含命中实体相连的关系；`open_nodes` 按名称返回请求实体及其相互关系。
- `memory://knowledge-graph` resource 与变更工具相连。测试验证 graph 文件路径、增删改与 resource 内容/更新通知。

## 3. 已验证：边界与安全参考

- 仓库的 `everything` server 将 tools、prompts、resources 与 stdio/SSE/Streamable HTTP transport 分离，可作为“领域能力不直接依赖 transport”的正面示例。
- `filesystem` server 的路径测试覆盖 `..`、相对路径、符号链接、真实路径与授权根目录；也明确演示了检查和写入之间的 symlink race。它用 `realpath`、父目录解析、独占创建或原子替换降低风险，但测试本身说明路径字符串前缀检查并不充分。

## 4. 对 Lumii 的建议

- P0 使用显式 `entity`、`observation`、`relation` 的概念前，先交付 Markdown 页面、链接、反链和 FTS；实体观察值应保留来源页、时间、状态，而不是裸字符串数组。
- 若 P2 需要图 API，采用 `create candidate -> 人工确认 -> active` 的流程。删除页面或事实改为软删除/归档和 audit log；不能沿用示例服务器的立即级联物理删除。
- 可采用“核心领域服务与 transport 分离”：图和检索逻辑放 `packages/agent-runtime`，Electron 专属 handler 放 main，preload 提供窄 API，renderer 不直接访问数据库。
- 对未来文件型 Markdown 存储，文件访问必须在 main 进程做规范化、realpath 和授权根校验；创建/覆盖需避免 TOCTOU。不要把 MCP filesystem 的测试结论误认为跨平台安全承诺，需在 Windows reparse point 上补测。

## 5. 不适合直接采用的部分

- JSON 全量重写无并发控制、迁移、备份增量和大文件检索策略；不适合 Lumii 的持久记忆。
- `search_nodes` 是线性子串搜索，`read_graph` 可输出全图；没有 scope、分页、排序、时间语义或上下文预算，不能直接暴露给 Agent。
- MCP tools/resources/notifications 和多 transport 服务进程是协议示例。Lumii 应映射为现有 IPC 调用与 renderer 状态更新，不能嵌入一个无边界 MCP server 来管理本地数据。
- 许可证迁移导致不同文件可能适用不同许可，任何代码级复用前都需要逐文件法律核验。

## 6. 可迁移决策

| 模式 | 阶段 | 决策 |
| --- | --- | --- |
| 明确实体、观察、关系 API | P2 | 条件采用，补来源/状态/审计 |
| resource 更新式状态通知 | P0/P1 | 采用其思想，映射到 IPC/renderer store |
| 核心逻辑与 transport 分离 | P0 | 采用 |
| JSON 全量图、全图读取、子串搜索 | 不采用 | 仅作教学参考 |
| 文件访问 realpath/授权根原则 | P0 | 采用并做 Windows 安全测试 |
| MCP server 多 transport | 不采用 | Lumii 不是外部 server 产品 |

## 7. 待验证问题

1. Lumii 是否把 Markdown 作为正式真相源；若是，导入与写入如何保证原子性和 Windows reparse point 安全。
2. 图关系达到多少规模才需要实体表，而不是页面链接。
3. UI 如何展示来源、争议、过期与删除历史，避免 Agent 静默改变用户资料。
