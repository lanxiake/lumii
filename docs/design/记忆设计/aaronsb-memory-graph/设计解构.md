# memory-graph 设计解构与 Lumii 参考建议

## 1. 结论

`aaronsb/memory-graph` 是 MCP 导向的轻量图记忆实现：一个内存中的节点 Map 和边数组承担运行态，JSON、SQLite、MariaDB 仅是可替换持久化后端。它适合说明“domain 隔离 + 显式边 + 有界 BFS”的最小模型；不适合直接作为 Lumii 的持久化架构，因为保存策略是整域快照，检索与实体抽取较为朴素，且许可证声明冲突。

分析基于 `5cfd2382778837b9f6399080956eee670d00452c`；“已验证”与 Lumii“建议”严格分开。

## 2. 已验证：模型、隔离和运行态

```text
MCP tool -> MemoryGraph（当前 domain 的 Map<node> + edges[]）
                    -> MemoryStorage 接口
                       -> JSON | SQLite | MariaDB
```

- 初始化会创建 `general` domain，加载保存的当前 domain，再把该域全部 node/edge 读进内存。切换 domain 时先保存当前全部状态、清空内存、再加载目标域。
- node 有 content、timestamp、path、tags、title、keyEntities、summary 和跨域引用；edge 有 source、target、type、strength、timestamp。关系只在目标节点已存在时写入。
- `extractKeyEntities` 只是英文大写词和引号短语正则，最多五个；标题默认取首句 40 字符。这是展示性启发式，并非通用知识抽取。
- `related` 与 `traverse` 以队列 BFS 遍历，按 `maxNodes`、深度、关系类型和最低强度截断。测试覆盖域切换、存储恢复、编辑/删除、工具参数和 Mermaid 生成。

## 3. 已验证：存储与检索

- `MemoryStorage` 抽象提供 domain、状态、全量保存和 `searchContent`；工厂按配置选择 JSON、SQLite 或 MariaDB。
- SQLite 后端建立 `DOMAINS`、`PERSISTENCE`、`MEMORY_NODES`、`MEMORY_TAGS`、`MEMORY_EDGES`、`DOMAIN_REFS`，另建 FTS5 `memory_content_fts`。`searchContent` 以 `MATCH` 查询内容/摘要并返回 node；内存中的 legacy 搜索则支持关键字、正则和编辑距离模糊匹配。
- `saveMemories` 的接口和数据库基类表明它按当前域的完整 nodes/edges 进行保存，不是面向单条业务记录的 repository/迁移事务模型。

## 4. 对 Lumii 的建议

- 可采用显式 scope（用户、Agent、工作区、路径）和有界图遍历的概念；定义链接时需存 source page、解析状态和创建来源，不能只保存临时内存数组。
- 可复用“存储接口隔离”的方向，但 Lumii 应以 `packages/agent-runtime` 中的纯 TypeScript repository 接口和 SQLite 迁移为主，不为 JSON/MariaDB 做产品级多后端承诺。
- P0 以 Wiki 页面、`[[wikilink]]`、backlinks、FTS 和可重建索引构成闭环。P1 才增加 `decision`/`observation` 等结构化类型。图遍历必须限制 hops、节点数和 scope，并显示为何某项被带入上下文。

## 5. 不适合直接采用的部分

- 当前 domain 是服务实例可变全局状态；跨 domain 引用通过临时切换并保存恢复实现。在 Electron 多窗口、并发 IPC 或后台任务下会有竞态，不应作为 Lumii API。
- 全域快照保存会放大写入、难以实现审计和部分失败恢复；用户资料需要条目级事务、版本与索引重建路径。
- 英文正则实体提取、字符级模糊检索和固定 `score: 1` 的 FTS 结果没有中文质量、排序或安全边界验证，不能作为知识提取/检索策略。
- MCP tool schema、stdio/HTTP transport 和 Mermaid 输出是外部集成层，不是 Lumii 记忆领域模型。
- 许可证为 ISC 与 MIT 的冲突未解决，故只记录设计思想，不复制实现。

## 6. 可迁移决策

| 模式 | 阶段 | 决策 |
| --- | --- | --- |
| 显式 node/edge 与有界 BFS | P1/P2 | 条件采用 |
| domain/scope 隔离 | P0 | 采用，但无全局可变当前域 |
| SQLite FTS5 | P0 | 采用，索引可重建 |
| 多后端存储适配 | 不采用 | 当前没有实际需求 |
| 全量快照、启发式实体提取 | 不采用 | 以条目事务和显式编辑替代 |

## 7. 待验证问题

1. Lumii 的 workspace/agent/user 作用域如何组合，跨域链接能否默认禁止。
2. Markdown 真相源与 SQLite 页面表的导入、导出、冲突恢复边界。
3. 图遍历在真实中文笔记量下的上下文预算和可解释 UI。
