# P3 · EXE / APP 复刻 · 设计

> 上位设计：[`2026-11-01-逆向复刻与流水线编排设计.md`](./2026-11-01-逆向复刻与流水线编排设计.md) §8.4
> 本文回答 §8.4 留下的那个洞：「EXE/APP 复刻**另立设计**」——另立的是什么。
> 状态：设计定稿，C1-a 待实施。

## 1. 结论先行：这不是 web 复刻的延伸

web 复刻能成立，靠的是一条**同态映射**：源是 HTML/CSS/JS，产物也是 HTML/CSS/JS。
读到的每一条 computed style、每一个资源文件，都能一对一搬进产物。

**EXE 没有这条映射。** 一个 `.exe` 可能是：

| 它其实是什么 | 复刻意味着 |
|---|---|
| Electron / NW.js 套壳 | 解出 JS 与资源，重建成可编辑的前端工程——**同态** |
| PyInstaller / .NET 打包 | 解出字节码或 IL，重建成可读工程——**近似同态** |
| Flutter / Unity | 只能重建出**外观与交互**，业务逻辑在内核里——**形态复刻** |
| 手写 C++ / Rust / Go | 没有可搬的源码结构，只能重写行为——**规格复刻** |

所以**不能设计「EXE 复刻」这一件事**。能设计的是：按「它其实是什么」分层的一组能力，
每层能独立交付、独立验证，越往下越贵、越不确定。

**本期只做 L0–L2，L3 明确不做**（依据见 §4）。

## 2. 四层

| 层 | 做什么 | 需要运行目标吗 | 产物 | 现状 |
|---|---|---|---|---|
| **L0 观察** | 格式/架构/函数数/导入能力/字符串/签名 | 否 | `analysis/` | ✅ 已有（`reverse_probe` + Ghidra） |
| **L1 解包** | 认出打包壳并解出内层资产 | 否 | `unpacked/` + 清单 | ⬜ 本文新增 |
| **L2 重建** | 按解出的资产重建可构建的工程 | 否 | `projects/<slug>/` | ⬜ 复用 `clone` 的流程 |
| **L3 行为对齐** | 跑起来、看动态行为、对齐交互 | **是** | `states.md` | ❌ 本期不做 |

**先静后动**（`reverse/SKILL.md` 五步的第二条）在这里是硬约束：L3 是唯一需要执行目标的层，
而执行来路不明的二进制本身就超出「复刻」该承担的风险。

## 3. L1：认出壳并解包

### 3.1 判据表（先看文件，再看同目录，最后才猜）

| 证据 | 结论 | 怎么解 |
|---|---|---|
| `resources/app.asar` 存在 | **Electron** | 读 asar 头（§3.2），纯 Node，无依赖 |
| `nw.pak` / `nw.dll` 存在 | NW.js | 同上（`.pak` 是 v8 快照，JS 在 `package.nw/` 侧） |
| 文件里有 `_MEI` / `PYZ\0` / `pyi-` | PyInstaller | 归档格式，需外部工具；本机缺就写 UNRESOLVED |
| `BSJB` 签名命中 | .NET | 需 ILSpy/dnSpy 才到 IL 层，否则停在元数据 |
| `libflutter.so` / `flutter_windows.dll` | Flutter | Dart 快照，只能到外观层 |
| `UnityPlayer.dll` / `*_Data/Managed` | Unity | 至少资源可解（`.assets`） |
| 都没有 | 原生程序 | **停在 L0**，不假装能复刻 |

**判定顺序不能反**：Electron 的 exe 本身是个壳，`strings` 会命中大量 Chromium 符号，
和「原生 C++ 程序」看起来差不多。**必须先看同目录的 `resources/`**，再看二进制。

### 3.2 asar 格式（本机实测，两个真实样本）

已用本机两个 Electron 应用的 `app.asar` 验证（WeFlow 5.0.0，678 MB；LiteShell 0.2.5，45 MB）：

```
offset 0   u32  = 4                  pickle 首个 int 的字节数
offset 4   u32  = header payload 大小（8 字节对齐）
offset 8   u32  = 字符串区长度（= json 长度 + 4）
offset 12  u32  = JSON 长度
offset 16  ...   = JSON（{files: {...}} 递归树）
dataStart  = 8 + u32@4   （实测与 16 + u32@12 相等）
```

条目字段：`{size, offset, integrity:{algorithm:'SHA256',hash,blockSize,blocks}, unpacked?}`。
`offset` 是**相对 dataStart 的**；`unpacked:true` 的条目实际在同目录 `app.asar.unpacked/` 下。

LiteShell 实测：7017 个条目，其中 29 个 unpacked；应用自身代码只有 11 个文件
（`out/main/index.js` 187 KB、`out/renderer/*` 约 6.2 MB，**无 sourcemap**）。

**两个坑**（不踩会读错但不报错）：

1. 别用 `8 + u32@12` 当 dataStart——`u32@12` 是 JSON 长度，`u32@4` 才是 payload 长度。
   两者在实测样本里凑巧能对上（因为 payload = 8 对齐后），但格式上不是同一个量。
2. `unpacked` 条目**不在 asar 里**，按 `offset` 去读会读到隔壁文件的内容——必须按
   `app.asar.unpacked/<同相对路径>` 另读。

### 3.3 L1 的完成判据（可复算，不靠眼睛）

```
UNPACK_OK=1
ENTRIES=7017   UNPACKED=29
BYTES_VERIFIED=7017/7017        # 每个条目按 size 读出且 SHA256 与 integrity 一致
```

`BYTES_VERIFIED` 必须逐条核 SHA256——asar 头里自带 `integrity.hash`，这是**白送的复算**，
不核等于放弃唯一一个客观判据。（blockSize 分块时按块核，末块按余数。）

## 4. L3 为什么默认不做

**本机实测（2026-11-02）**：

| 检查项 | 结果 |
|---|---|
| `Win32_ComputerSystem.HypervisorPresent` | **False** |
| `C:\Windows\System32\WindowsSandbox.exe` | 不存在 |
| 服务 `vmcompute` / `vmms` | **absent**（Hyper-V 未安装） |
| 服务 `HvHost` | Stopped |
| 处理器 `VirtualizationFirmwareEnabled` | True（固件支持，但没启用任何虚拟化平台） |

结论：**本机没有可用沙箱**。这不是「暂时没配」，是缺组件。所以：

1. Lumii **不提供**「自动在沙箱里跑一遍」的能力——没有沙箱可提供；
2. Lumii **不提供**「直接跑目标看行为」的默认路径——复刻场景的目标是别人的程序，
   `bash` 工具「沙箱外执行」标注本身就写了这条警告（`reverse/SKILL.md` 工具表）；
3. 用户坚持要动态观察时，**由用户自己准备隔离环境**（另一台机器 / 用户自建虚拟机），
   Lumii 只做**观察的记录方**：`screen_screenshot` 截窗口、`browser_requests` 看网络、
   用户回传的文件系统快照做 diff。**Lumii 不代跑、不代装虚拟机、不代配沙箱。**

这条写进技能参考的降级表，不让 Agent 自由发挥。

## 5. L2：复刻产出长什么样

L2 不是「让解出来的包跑起来」，那叫**重打包**。复刻的定义仍是 `clone/SKILL.md` 的四步
（Map → Observe → Build → Compare），只是 Observe 的证据来源从浏览器换成解包产物：

| 阶段 | web 复刻 | EXE 复刻（L2） |
|---|---|---|
| Map | 列页面路由 | 列**界面**（窗口 → 视图 → 交互点） |
| Observe | computed style / 资源 / 状态 | 解包出的 JS/CSS/资源 + 截图 + 字符串 |
| Build | Next.js 工程 | **同一套**静态工程 |
| Compare | 双视口截图 | **同视口截图**（原程序 vs 产物） |

产物目录复用 §4.4 的契约，只多一个 `unpacked/`（L1 的原始证据，不进产物工程）：

```
{workspace}/projects/<slug>/
  NOTICE.md                     # 来源与合规声明
  analysis/                     # L0 + L1 的结论（复用 reverse 的产物契约）
  unpacked/                     # L1 解出的原始资产（证据，不参与构建）
  docs/research/brief.md        # 界面清单与样式读数（含证据出处）
  src/ public/ package.json     # L2 重建出的工程
```

**Electron 目标的特殊待遇**：解出的 renderer 是**已经能跑的前端**。这时 L2 的价值不是
「重写一遍」，而是让 Agent 把解出的 bundle 当**证据源**（真实组件结构、真实文案、真实样式），
重建一份**可编辑、可维护**的源码。直接复用解出的 bundle = 等于重打包，不是复刻。

## 6. 判据：什么算复刻成功

沿用 §4.5 的强制条款——**禁止截图相似度阈值当通过条件**。

| 层 | 判据 | 谁来判 |
|---|---|---|
| L1 | `BYTES_VERIFIED = ENTRIES/ENTRIES`（逐条 SHA256） | 代码，硬断言 |
| L2 | ① 产物 `npm run build` 退出 0；② 关键界面元素存在（`browser_eval` 断言）；③ 文案与证据的一致率 | 代码（①②）+ agent（③） |
| L3 | —— | 不做 |

**文案一致率**不是新造的指标：L1 已经解出了真实文案，逐条核产物里有没有即可，
不需要模型判断。这是 EXE 复刻比 web 复刻**更好判**的地方——证据是白送的。

## 7. 合规

- **`provenance` 软门禁已存在**（spec 字段，P2 已在用），继续复用，不新增门禁；
- **`NOTICE.md` 目前没人生成**（实测：`src/main` 里零引用）。设计 §4.4 写了「自动生成」，
  实际没做。本期**不承诺**自动生成——写进 L2 的 agent 步提示词，和 `README.md` 一样由 Agent 写；
  如果要变成硬保证，得先决定「谁来判它写得对」，否则又是一份没人看的样板文件；
- 技能包首段已有「目标明确禁止逆向/复现时先确认授权」，EXE 线沿用同一句。

## 8. 实施顺序

| 步骤 | 内容 | 成本 | 依赖 |
|---|---|---|---|
| **C1-a** | `reverse_probe` 加 **asar 后端**（纯 Node，认 Electron 并解包 + 逐条核 SHA256） | 小 | 无（本机两个真实样本可验） |
| **C1-b** | `desktop.md` 补「Electron 套壳」一节：指到 C1-a，去掉「需要 `asar` 命令」的旧说法 | 小 | C1-a |
| **C1-c** | L2 配方：`bundled-pipelines/` 加一条 `exe-clone` spec（agent 步复用 `clone` 四步法） | 中 | C1-a/b 有真机结果后再定 |

**C1-c 的前置判断**：只有在 C1-a 对**至少两个不同 Electron 应用**跑出可复算的 L1 结果后，
才值得写 L2 配方。否则会写出一条「只有作者样本能跑」的流水线——这与 P2 修 `scaffold`
撞 `analysis/` 的教训是同一类错误。

**不做**：`.deb` / `.dmg` / AppImage 解包（各自一套格式，本机无样本）；
`.NET` IL 反编译（需外部工具）；任何形式的脱壳。
