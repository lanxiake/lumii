## 0. 结论摘要

| 项 | 结论 |
|---|---|
| 用户要什么 | 客户端能**逆向分析**别的软件、按规范**复刻**网页/APP/EXE、并对**自有产物做安全验证与红蓝对攻**；能力可**沉淀成插件/工具**；流程要**稳定可重复**，且流水线里能有 Agent 节点 |
| **原子能力（拍板）** | **克隆 / 逆向 / 红队 / 蓝队 四个能力本身是原子**，各自可**单独使用**、可**拆解**、可**重新组合**。流水线只是把它们串起来的**一种样板**，不是唯一路径（§5） |
| 原子的形态 | **一个技能目录 + SKILL.md**。不新增工具、不新增插件、不新增引擎；原子之间靠**磁盘 artifact** 交接，不靠内存状态 |

| 预览方案 | `next build` 静态产物 + `lumii-local://` 协议在客户端内打开，**不做常驻 dev server 管理** |
| 对比方案 | **Agent 看"像不像"，代码查"对不对"**：视觉差异由 agent 节点看图判断，确定性断言只查关键元素的 computed style / 资源 200 / 文本一致 |
| 技能包 | 两个域：**复刻域**搬 cloner 四步法 + reverse-skill 的 R0/静态分析/前端 JS；**安全域**搬 R11/R12/R14/R17/R18/R24/R10，但 frame 成"验证自己的防御"——产出的主交付是**检测规则与加固**，不是可分发样本（§8） |

## 2. 代码事实核查（每条都已在本仓库核实）

### 2.1 pipeline 的真实边界

`apps/windows/src/plugins/builtin/pipeline/`：

- **节点只有一种**：`steps[]` 每项是 `{id, tool, params, holdMs, expect, narration}`，**没有 kind 判别**（`types.ts:17-29`）。要跑 shell 就 `tool: "bash"`，要跑 Agent 就只能 `tool: "spawn_agent"`。
- **线性、无分支、无循环、无重试**；`{{}}` 引用**只能向后**，加载期校验（`spec.ts:121-131`）。
- **失败即停**，返回 `{failedAt, expected, observed}`；`postCleanup` 无论如何都跑（`runner.ts:166-174`）。
- **rehearsal** 跳过 `needsPermission === true` 的工具，并塞 `{}` 占位（`runner.ts:319-326`）——**依赖其产物的后续步骤在彩排下必然失败**，这是既有语义（实施总结 L5）。
- 执行上下文由 `bridge.createPipelineExecutor()` **注入**（`bridge.ts`）。内层工具走 `assembleTools` + `PIPELINE_TOOL_DEF`，该定义写着 **`canSpawnSubAgents: false`**（`bridge.ts:98-108`），而 `filterToolsByDefinition` 会据此**摘掉 `spawn_agent` 与 `send_message`**（`host-kit/tool-assembly.ts:46-48`）。

> **⇒ 结论 A：今天的 pipeline 里写 `tool: "spawn_agent"` 一定失败**（加载期就被 `knownTools` 通过，运行期被过滤掉）。"Agent 节点"必须做成**一等节点类型并由 bridge 注入执行函数**，而不是借用工具表。

### 2.2 子 Agent 可直接调用

`AgentOrchestrator.spawnAgent(params, parentId)`（`packages/agent-runtime/src/agent/orchestrator.ts`）支持 `agentType / mode(sync|async) / model / allowedTools`，sync 模式阻塞返回 `output`。**语义正好是"Agent 节点"需要的**：一次自包含的 LLM 回合。

`parentId` 的来源：`toolCallInstanceMap.get(toolCallId) ?? getCurrentToolExecutorInstanceId()`（与 `spawn_agent` / `send_message` / `handoff` 同一惯例，见 `bridge-tool-registrar-handoff.ts:102`）。**因为流水线只能被 Agent 的回合触发（§4.1），`parentId` 必然存在**——这是把"执行归属"定死带来的附带收益。

### 2.3 浏览器工具缺三样关键能力

`bridge-browser-tools.ts` 只暴露 10 个工具（navigate / snapshot / screenshot / click / type / scroll / wait / eval / back / forward）。但 `packages/browser-control` 内部路由**已经有**：

| 已有路由 | 文件 | 对复刻的价值 |
|---|---|---|
| `/screenshot` 带 `fullPage` | `agent.snapshot.ts:104` | 整页取证，**缺它就拍不到折叠区** |
| `/set/device` | `agent.storage.ts:408` | 移动端视口（UA + deviceScaleFactor + isMobile + hasTouch） |
| `/requests` | `agent.debug.ts:64` | 网络清单 → 资源映射表 |
| `/response/body` | `agent.act.ts:482` | 取真实响应体（含 AVIF 伪 PNG 校验） |
| `/download` | `agent.act.ts:447` | 按 ref 下载资源到指定路径 |

后三个未注册成 Agent 工具。**复刻能力的天花板就在这三样上**——不补，就只能拍桌面截图 + 手抄资源。

### 2.4 没有的能力（也不该在第一期做）

- **无常驻进程管理**：`bash` 默认 120s、上限 600s、超时杀进程树（`tool-providers/local-bash.ts`）。**跑不了 dev server**。
- **无像素对比工具**：仓库里搜不到 `compare-screenshot*`（记忆里那条已失效）。
- **插件无沙箱**：`manifest.ts:12-14` 明说"刻意不含 permissions，插件与主进程同权限"。

### 2.5 现成的复用点

| 能力 | 落点 | 复刻时怎么用 |
|---|---|---|
| 项目目录 | `{workspace}/projects/<name>`（`coding-dev-projects.ts`） | 复刻产物本身就是项目，自动进项目列表/文件树/ACP cwd |
| 写文件根约束 | `resolveAgentFilePath`：`workspace + 已注册项目 realPath + ~/.lumii` | `projects/` 在 workspace 内，`file_write` 直接可写 |
| 预览通道 | `lumii-local://local/<abs>`（`local-media-protocol.ts:45-48`）+ ACL 覆盖整个 workspace | 静态产物里的相对图片能正确解析（2026-10-31 刚修过这条） |
| 内嵌 webview | `FilePreviewModal` 用 `<webview>` 渲染含脚本 HTML | 左源站右本地，并排对照零新组件（需补一处布局） |
| 技能斜杠命令 | 技能目录名自动成为 `/xxx`，args 拼进提示词 | `/web-clone https://x.com` 开箱可用 |

## 3. 定位与合规（两个域，两档门禁）

用户拍板：**个人自用**，且额外要**对自己产物做安全验证 / 红蓝对攻**。于是合规不是一档，而是两档：

### 3.1 复刻域 —— 软门禁（留痕，不拦路）

1. spec 顶层加一个可选块：

```jsonc
"provenance": {
  "target": "https://example.com",       // 分析目标
  "purpose": "自有站点迁移 / 学习 / 开源复刻",
  "authorization": "self-owned"           // self-owned | open-source | authorized | learning | unspecified
}
```

2. 执行期**只做两件事**：写进 `meta.json`；渲染在产物 README 与时间线卡上。**不校验、不拦截、不弹窗**。
3. 产物根目录固定生成 `NOTICE.md`，含来源 URL、抓取时间、以及 cloner 原文的三条禁止（钓鱼冒用 / 冒认版权设计 / 违反目标方 ToS）。

### 3.2 安全域 —— 声明式门禁（开局必填，仍不做网络强拦）

复刻域的目标是"别人写的东西"，安全域的目标是"**我自己的东西**"。两者的门禁强度必须不同：

```jsonc
"scope": {
  "targets": ["http://localhost:3000", "https://staging.mysite.com"],
  "ownership": "self-built",            // self-built | self-hosted | authorized-engagement | lab
  "statement": "复刻产物的本地副本，验证 XSS/CSRF/依赖风险",
  "boundary": { "network": "localhost+staging", "noExternal": true }
}
```

**规则（写进 `redteam` / `blueteam` 技能与 spec 校验里，不是网络层拦截）**：

| 规则 | 落地 |
|---|---|
| `targets` 非空，`ownership` ∈ 枚举 | 加载期拒——**但这是 spec 校验，不是防火墙** |
| 产出的 Findings 必须带 `evidence_ids`（复现命令 + 观测） | 复用 reverse-skill 的 Evidence→Finding→Path 契约（§7.2） |
| 默认只跑**被动/本地**检查（依赖审计、构建产物扫描、本地起服务的 OWASP 检查） | 主动扫描（nmap/nuclei/sqlmap）需要用户显式在 spec 里引用 `redteam` 技能并写进 `scope.targets` |
| **产物里不落可分发样本 / 免杀载荷 / C2** | 见 §5.3 的三条硬约束 |

> **一句话**：门禁写在 spec 与技能文档里，由 Agent 遵守；客户端**不做网络层封锁**（那需要驱动级 hook，成本远超收益，且与"个人自用"定位不符）。这是有意识的取舍，不是遗漏。

## 4. 核心设计

### 4.0 执行归属：流水线是资产，Agent 是执行者（用户拍板）

这条改变整个架构的形状，先说清楚：

| | 之前的设计假设 | 拍板后 |
|---|---|---|
| 谁能触发 `pipeline_run` | UI 按钮 / Agent 工具 / cron | **只有 Agent 的回合**（cron 也走这条：cron 驱动一轮 Agent，那一轮再调 `pipeline_run`） |
| UI 的角色 | 触发执行 + 看进度 | **只读进度 + 管理（列表/详情/历史/打开目录/停用）** |
| `parentInstanceId` | 可能为 `undefined` | **必然存在**（调用者就是父实例） |

**落到代码**：`pipeline:run` 这个 IPC handler **删掉**（`ipc.ts:39-48`），`PipelinePage` 的「彩排 / 录制运行」按钮改成「在对话里运行」——把 `跑流水线 <id>（彩排）` 预填进当前会话的输入框，由用户回车发送、当前 Agent 去调。`pipeline:cancel` 保留（用户要能停）。

**收益**：① 没有"无父实例"的边界情况；② 流水线的每一次执行都有归属会话，产出与成本可追溯；③ 与人拍板的直觉一致——"流水线就像技能一样，哪个 Agent 调用，哪个 Agent 执行"。

**代价**：UI 少一个一键按钮。接受。

### 4.1 三层，别混

```
① 知识层（怎么想）   SKILL.md 包        —— 走现有技能体系，零新代码
        ↓ Agent 读、组织工具调用
② 执行层（怎么不跑偏）pipeline + agent 节点 —— 扩展 runner，一处改动
        ↓ Agent 调 pipeline_run，代码逐步执行，每步落 journal
③ 资产层（产物去哪）  {workspace}/projects/<slug>/ —— 复用项目/预览/ACP
```

**分工判据**：一段工作**路径能不能预先枚举**？
- 能枚举（打开页面、拍全页、导资源清单、跑 build、查文件存在）→ **写成 tool 节点**
- 不能枚举（"这段布局是怎么做到的""哪里不一样、怎么改"）→ **封装成一个 agent 节点**

### 4.2 关键判断：Agent 节点 = 不可枚举部分的封装

这是本设计最重要的一条，也是"加 Agent 会不会毁掉确定性"的答案。

**确定性在这里被重新定义为「路径确定」，不是「执行确定」。**

| | 传统 pipeline | 加 agent 节点后 |
|---|---|---|
| 下一步做什么 | spec 写死 | **仍然 spec 写死** |
| 某一步怎么完成 | 一次工具调用 | 可以是一次 LLM 回合 |
| Agent 能否改变流程 | 否 | **否**（agent 的产出只作为数据，不参与路由） |
| 失败是否可见 | 是（failedAt） | 是（同机制） |
| 能否续跑 | 是 | 是（agent 节点的产出落盘即可跳过） |

**所以被明令禁止的是**：让 agent 节点"决定要不要跑下一步"或"产出分支条件"。需要分支 = 路径不可枚举 = 那一段整个收进**一个** agent 节点内部，由它自己的回合循环解决。

> 这条直接决定了 web-clone 的形状：**"对比 → 修 → 再对比"这个循环不进 pipeline**，它被包在 `build` 这个 agent 节点里（agent 本来就有多轮）。pipeline 只在外面钉住三个检查点：必须对比、必须过阈值、必须声明剩余差异。

### 4.3 pipeline schema 扩展（只加一种节点）

`types.ts` 的 `PipelineStep` 变成判别联合：

```ts
type PipelineStep = ToolStep | AgentStep

interface BaseStep {
  readonly id: string
  readonly label?: string
  readonly narration?: string
  readonly holdMs: number
  readonly expect?: StepExpect
}

interface ToolStep extends BaseStep {
  readonly kind?: 'tool'              // 缺省 = tool，老 spec 零改动
  readonly tool: string
  readonly params?: Record<string, unknown>
}

interface AgentStep extends BaseStep {
  readonly kind: 'agent'
  /** 用哪个 Agent：通用（assistant / builtin:explore）或专用（security）。缺省 assistant */
  readonly agentType?: string
  /** 自包含提示词——子 Agent 看不到父对话。可含 `{{}}` 向后引用 */
  readonly prompt: string
  readonly allowedTools?: readonly string[]
  readonly model?: string
  readonly maxTurns?: number
  /** 彩排时是否执行。缺省 'skip'（agent 可能有副作用，默认保守） */
  readonly rehearsal?: 'run' | 'skip'
}
```

**用通用还是专用 Agent（用户拍板：都行，spec 里指定）**：

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 取证、读文件、整理 brief | `builtin:explore` | 已存在、`permissionMode: readOnly`，写不了东西，天然安全 |
| 建页、改代码 | `assistant` 或 `code-dev` | 复刻的护栏已在 `clone/SKILL.md` 里，不需要专用 Agent（§5.4） |
| 安全验证、红蓝 | `security`（P4 新增） | **唯一值得做专用 Agent 的场景**：靠 `permissionMode` + `tools` 白名单做结构性护栏，技能做不到 |
| 长任务并行 | 任意 + `mode: async` | 但 **pipeline 内一律 sync**（同步才可断言、才可续跑） |

**`forge` 不做（相对 D2 的修正）**：原子化之后它的价值被掏空了——复刻的四步法与质量红线已经在 `clone` 技能里，塞进 systemPrompt 只是每轮全价常驻。用 `assistant` + `clone` 技能即可。详见 §5.4。

**`security` 按需加载（用户拍板）**：定义为 `isActive: false`。

| 规则 | 落地 |
|---|---|
| 默认不出现 | `isActive: false` → `agents-repo.ts:94` 映射成 `isEnabled: false`，UI 里是"未启用" |
| 用户在「Agents」页显式启用后才可用 | 与现有 `selectable` / 启用开关同一套机制，不新造 |
| **systemPrompt 保持短**，专业知识走技能 | `security` 的 prompt 只写"只验自有目标"的红线；手法库在 `redteam`/`blueteam` 技能里按需拉 |
| `tools` 白名单按实测裁剪 | P4 实施时按真实工具用量定，不预先猜一套 |

> **审计过的问题（这条必须硬校验）**：`orchestrator` 对**未知 `agentType` 是静默回落 `assistant`**（`orchestrator.ts:524`，工具描述也明说"Unknown ids are treated as omitted"）。
> 对交互式对话这是善意兜底；**对流水线是灾难**——spec 里写 `agentType: "security"`，用户没启用它，就会静默跑成 assistant，而作者以为用的是专用 Agent（提示词与工具有差异），结果不可复现且毫无提示。
>
> **所以 agent 节点必须硬校验，禁止回落**：`createPipelineExecutor()` 额外暴露 `knownAgents: () => ReadonlySet<string>`（来自 definitionStore 里 **`isActive !== false`** 的 id），`validateSpec` 加第三个参数，**加载期就拒**——与 `knownTools` 同一原则（"加载期拒绝优于运行期失败"）。错误信息要能直接指导操作：`未知或未启用的 Agent "security"：请先在 Agents 页启用它`。

**校验规则（`spec.ts`）**：
- `kind === 'agent'` 时要求 `prompt` 非空，**不要求 `tool`**，**跳过 knownTools 检查**，改为查 `knownAgents`
- `agentType` 必须 ∈ `knownAgents`（**缺省 `'assistant'` 也算校验**）；未知或未启用 → 加载期拒，**不允许回落**（理由见上）
- `prompt` 里的 `{{}}` 同样做向后引用校验（`refsIn(prompt)`）
- 其余三关不变（非空 steps、id 唯一、未知 kind 拒绝）

**`validateSpec` 签名变更**：`(raw, knownTools, knownAgents)`。第三个参数是**必填**（不是可选）——可选参数会让所有老调用点静默跳过校验，正是 `knownTools` 当初要防的那类坑。

**执行（`runner.ts`）**：主循环里 `deps.callTool(...)` 换成分支：

```ts
const r = step.kind === 'agent'
  ? await deps.runAgentStage({ agentType: step.agentType, prompt: params.prompt, ... })
  : await deps.callTool(step.tool, params, opts.signal)
```

`params` 解析复用现有 `resolveParams`（它已经支持字符串内嵌引用），所以 agent 节点能自然吃到上游工具的结构化输出。

**Journal**：加一个可选字段 `kind?: 'tool' | 'agent'`，缺省 `'tool'`——老 journal 照常可读。

**rehearsal**：`kind === 'agent' && step.rehearsal !== 'run'` → 记 `skipped: 'rehearsal'` 并塞 `{}`（与工具同语义，同样的 L5 限制）。

**bridge 侧新增一个注入函数**（与现有 `screenRecord` 同形）：

```ts
runAgentStage: (opts: {
  agentType?: string; prompt: string; allowedTools?: readonly string[]
  model?: string; maxTurns?: number; signal?: AbortSignal
}) => Promise<{ ok: boolean; data?: unknown; error?: string }>
knownAgents: () => ReadonlySet<string>
```

实现走 `ensureOrchestrator().spawnAgent({...}, parentInstanceId)`，`parentInstanceId = toolCallInstanceMap.get(toolCallId) ?? getCurrentToolExecutorInstanceId()`（§2.2，且 §4.0 保证了它必然存在）。**默认 `allowedTools` 排除 `pipeline_run` 与 `spawn_agent`**，防止 agent 节点递归触发流水线。

### 4.4 产物目录契约

复刻产物 = 一个 Lumii 项目，**同时遵循 cloner 的目录约定**：

```
{workspace}/projects/<slug>/
  NOTICE.md                      # 来源、时间、合规声明（自动生成）
  README.md                      # route map + 运行方式 + 剩余差异（agent 生成）
  package.json / src/ / public/  # 复刻出的真实工程
  docs/research/<site>/
    brief.md                     # 页面 brief：段落顺序、字号/行高/间距、资产映射
    assets.md                    # 源 URL → 本地路径，含 content-type 核对结果
    states.md                    # 触发 → 可见结果的采样记录
  public/sites/<site>/           # 下载的真实资产（字体/图/SVG/视频）
```

**为什么落在 `projects/`**：它已经在 `getAllowedRoots` 里，`file_write` 直接可写；项目列表/文件树/ACP cwd 全部复用；`lumii-local` ACL 覆盖 workspace，`out/` 里的相对资源能正确加载。

### 4.5 对比：Agent 看"像不像"，代码查"对不对"

明确禁止"截图相似度阈值"当通过条件——那是把不确定性搬回执行器（沿用确定性流水线设计 §4.5 原话）。

| 谁来判 | 判什么 | 手段 |
|---|---|---|
| **agent 节点** | 布局/排版/间距/动效"像不像" | 自己导航、自己截图、自己看图、自己改 |
| **tool 节点（断言）** | 关键元素存在、关键 computed style 读数一致、资源全部 200、无横向溢出 | `browser_eval` 返回扁平对象 + `expect.fields` 子集匹配 |

`expect.fields` 的路径写法：`browser_eval` 现在返回 `{ok, result:{result, url}}`，所以引用形如 `{{probe.result.result.heroFontSize}}`（**这是现成能力，不需要新断言类型**，但路径难看——见 §9 待定项 3）。

### 4.6 预览：不做 dev server

1. 构建：`bash` 跑 `npm run build`（Next 用 `output: 'export'`）
2. 预览：`lumii-local://local/<abs>/out/index.html` 交给现有 `<webview>`
3. 对照：左栏 webview 载源站 URL，右栏载本地产物（`WikiSourceDetailDrawer.tsx:134` 已有单 webview 先例）

需要服务端的复刻（SSR/API 路由）**第一期不支持预览**——在 README 里如实写明"需自行 `npm run dev`"。不为此引入进程管理器。

## 5. 四个原子能力（先原子，后流水线）

### 5.0 原子模型

**四个原子：克隆 / 逆向 / 红队 / 蓝队。** 每个都能单独用、能被拆开、能被重新组合。

**原子的形态 = 一个技能目录**（`skills/<分类>/<原子>/SKILL.md`）。理由不是"省事"，是它恰好满足三个硬要求：

| 要求 | 技能体系为什么正好满足 |
|---|---|
| 能单独触发 | 目录名自动成为斜杠命令 `/clone` `/reverse` `/redteam` `/blueteam`（`slash-commands.ts:243-330`） |
| 能按需加载 | 工具化技能只常驻 ~86 tokens 的名字+描述，正文 `skill_invoke` 拉（`skills-section.ts`） |
| 能带脚本 | `scripts/` 下有入口就自动成为可执行技能，`execute_skill` 可调（`skill-external-loader.ts:83-158`，120s 超时） |

**不新增工具、不新增插件、不新增引擎。** 已有的 `browser_*` / `bash` / `file_*` / `spawn_agent` 就是原子的手脚，原子只负责"知道该怎么用"。

**原子之间靠磁盘 artifact 交接，不靠内存状态**：

| 原子 | 单独怎么用 | 吃进 | 吐出 | 落在 |
|---|---|---|---|---|
| **克隆** `clone` | `/clone https://x.com` | 目标地址（可选：逆向产出的理解） | 可构建的工程 + research 三件套 | `projects/<slug>/` |
| **逆向** `reverse` | `/reverse ./app.exe` | 任意目标（网页/二进制/APK/前端 JS） | 它**怎么工作的**（结构、数据流、关键算法、资源清单） | `projects/<slug>/analysis/` |
| **红队** `redteam` | `/redteam http://localhost:3000` | 一个**跑得起来的目标**（自己写的或刚复刻的） | Findings：洞在哪、怎么复现 | `<target>/security/findings/` |
| **蓝队** `blueteam` | `/blueteam <findings>` | 红队的 Findings | 检测规则 + 加固补丁 + **复跑验证结果** | `<target>/security/rules/` |

**这张表就是"可拆解、可重组"的全部实现**：原子只认目录里的文件，不认谁调用它、也不认上游是谁。所以：

- 克隆可以**不经过**逆向（目标是个静态站，直接看就行）
- 逆向可以**不产出**克隆（只想看懂一个算法，不重建）
- 红队可以**打**用户自己写的项目，跟克隆毫无关系
- 蓝队可以吃**人工写的** finding，不是红队产的

### 5.1 三种用法，从轻到重

```
① 单独用       /clone https://x.com              —— 一次对话，按 SKILL.md 走
② 手工串       先 /reverse 再 /clone，把 analysis/ 当输入 —— 主 Agent 组织，跨两轮
③ 流水线串     pipeline_run 里把三件事钉成固定顺序 —— 可重复、可断言、可续跑
```

**流水线是配方，不是唯一路径。** 它只在同时满足三条时才有价值（沿用确定性流水线的判据）：路径能预先枚举、每步有可断言结果、且会重复跑。

**所以流水线里的每个 tool/agent 节点，都必须对应一个**能单独做的事**。** 这条是硬约束——如果某个步骤单独做不了（依赖上一步的内存状态），那它就不该是流水线节点，应该被吸收进相邻的 agent 节点里。

> 反过来也成立：**能给原子用的东西，不要藏进 pipeline。** 这是本设计对上一版的重要修正——上一版把"取证链"写死进了 spec，等于只有跑流水线才能取证。现在取证是 `clone` 原子的一节，单独也能做，流水线只是把它排成固定顺序。

### 5.2 复刻域的原子与子技能

```
apps/windows/bundled-skills/逆向与复刻/
  capability-router/    路由：这个任务该用哪个原子（可选，先路由后动手）
  clone/                原子①  克隆
  reverse/              原子②  逆向
  redteam/              原子③  红队
  blueteam/             原子④  蓝队
```

`clone` 与 `reverse` 是本期的重点：

| 原子 | 内容 | 来源 | 期 |
|---|---|---|---|
| `clone/SKILL.md` | 四步法 + 检查清单 + 什么时候**不该**复刻 | cloner `SKILL.md` 中文化精简 | P0 |
| `clone/references/inspection-guide.md` | 视觉结构 / 资源 / 状态证据的取证方法（**这是"取证"的唯一正本**，流水线节点只是它的自动化版） | cloner 同名文件 | P0 |
| `clone/references/framer-and-motion.md` | 驱动源辨识 + Lenis/IntersectionObserver 判据 | cloner 同名文件 | P0 |
| `reverse/SKILL.md` | 目标类型判定 → 分派到子参考；triage → static → dynamic → synthesis | reverse-skill R0 + `MASTER-ROUTING.md` 精简 | P1 |
| `reverse/references/binary.md` | 二进制：IDA/Ghidra/r2 的**选用判据**（不预置工具，缺什么报什么） | reverse-skill R0 精简 | P2 |
| `reverse/references/frontend.md` | 前端签名定位、运行时采样、本地复现 | reverse-skill R3 精简 | P2 |
| `reverse/references/mobile.md` / `desktop.md` | APK / EXE 逆向 | reverse-skill R1/R5 精简 | P3 |
| `capability-router/SKILL.md` | "先路由后动手"：这个任务属于哪个原子、要不要组合、工具路径不猜 | reverse-skill `RULES.md` 精简 | P1 |

> **`reverse` 与 `clone` 的关系**：`reverse` 回答"它是怎么做的"，`clone` 回答"我怎么重做一遍"。克隆一个复杂站点时，先跑 `reverse` 会快得多（省掉试错），但**不是必需**——静态站直接 `clone` 就行。`reverse` 的产出 `analysis/` 是 `clone` 的**可选**输入。

### 5.3 安全域的原子

**定位**：**验证自己的产物**，不是攻击别人。同一个技术，两种 frame：

| reverse-skill 原始 | 移植后的 frame |
|---|---|
| "绕过 WAF" | "验证我的 WAF 规则是否生效" |
| "免杀 / EDR 绕过" | "验证我的检测规则能否抓到这种手法" |
| "Getshell" | "确认我的上传过滤是否真的挡住了" |
| "提取凭据" | "确认我的凭据存储是否有明文" |

| 原子 | 内容 | 来源 | 期 |
|---|---|---|---|
| `redteam/SKILL.md` | **红队**：对自有目标找洞并复现。范围门槛 + 手法库 + 证据链 | reverse-skill R11 + R17/R18/R24 手法 | P4 |
| `redteam/references/attack-playbook.md` | 手法库：XSS/CSRF/SSRF/IDOR/注入/auth bypass/依赖投毒，每条 4 段（我有没有 / 怎么复现 / 怎么检测 / 怎么加固） | R17/R18/R24 提炼 | P4 |
| `blueteam/SKILL.md` | **蓝队**：把 Findings 转成检测规则 + 加固补丁 + 复跑验证 | reverse-skill R27 + R14 改造 | P4 |
| `blueteam/references/detection-rules.md` | Sigma / Semgrep / YARA 规则写法 | `yara-sigma-rules.md` | P4 |
| `blueteam/references/hardening-checklist.md` | 逐类漏洞的加固清单（OWASP 对照） | 新写 | P4 |

**红蓝本身是一对**：`redteam` 与 `blueteam` 可以单独用（**只做蓝队**：拿到一份人工写的 finding，写规则；**只做红队**：先摸自己有什么洞，规则以后再说），但**组合起来才是闭环**——蓝队的验收标准就是"红队再打一次，这条规则抓住了"。

**安全域的三条硬约束（写进 SKILL.md 首段）**：

1. **目标是"我自己的东西"**。`redteam` 首段就要确认 `ownership`；对第三方目标一律先引导回 `clone`，或让用户明确声明授权。
2. **产物形态是"防御资产"，不是"攻击资产"**。交付物必须是：Findings 报告 + **检测规则** + **加固补丁**。**不做**免杀 payload 生成、不写 C2、不产出可直接分发的 exploit 二进制——这些既不是"验证"必需的，也是唯一会让这套能力变成危险武器的部分。
3. **P4 才做，且默认关闭**。`redteam` / `blueteam` 技能随内置技能播种但 `activation_scope: on_demand`（只能显式 `/redteam` 触发，不参与自动激活）；`security` 专用 Agent `isActive: false`。

> **诚实说明**：这是**自律约束**，不是技术强制。一个能读代码、能跑命令的 Agent，用户自己写提示词也能做危险的事。我们做的是：**默认不提供这类内容的"成品化流程"**，让每一步都需要用户自己拼——这已经挡掉了大部分"顺手就用了"的风险。不假装能完全防住。

### 5.4 专用 Agent 与原子的关系（重要修正）

原子化之后，`forge` 这个专用 Agent **价值被掏空了**：

| | 专用 Agent 能给什么 | 原子技能给不了什么 |
|---|---|---|
| `forge`（复刻） | 一段身份提示词 | 什么都没有——复刻的护栏（四步法、禁止自称像素级完美）已经写在 `clone/SKILL.md` 里，塞进 systemPrompt 反而每轮全价常驻 |

**所以 `forge` 建议不做**（D2 的修正）：`clone` 技能 + `assistant` 已经覆盖。少一个 Agent 定义、少一套工具白名单要维护。

`security` 专用 Agent **保留**，但理由要说准：它的价值不是"身份"，而是**结构性护栏**——`permissionMode` 收窄 + `tools` 白名单 + `disallowedTools` 摘掉 `pipeline_run`。这些是技能做不到的（技能是散文，拦不住工具）。

### 5.5 统一改写原则（四个原子都适用）

1. 路径全部换成 Lumii 的工具名（`browser_navigate` 而不是 `take_screenshot`）
2. 证据链改成 Lumii 的落点（`analysis/`、`security/findings/`）——不用 reverse-skill 的 `work/<case>/evidence/`
3. 删掉所有"检查本机工具路径 / bootstrap 安装"段落——Lumii 没有那套工具链自举，缺什么就报什么
4. 每条 SKILL.md 首段必须写"什么时候**不该**用它"（YAGNI 护栏）
5. **每节都要能单独执行**：不许出现"必须先跑完上一节"的硬依赖（除了原子内部固有的顺序）

## 6. "把别人的能力变成客户端能力"的三条落法

按成本从低到高，**默认只做前两条**：

| 落法 | 形态 | 成本 | 何时用 |
|---|---|---|---|
| **1. 技能包**（推荐） | 一个目录 + `SKILL.md` + `scripts/` | 零 | 能力是"怎么用某个 CLI/流程"，如 CLI-Hub 先例 |
| **2. MCP server** | `~/.lumii/config/mcp-servers.json` 加一条 | 低 | 能力是"一组结构化操作"，需要长连接或状态 |
| 3. 客户端插件 | `~/.lumii/extensions/<dir>/main.js` | 高 | **仅当用户明确要求**；无沙箱，且注册工具要改 `bridge.ts` |

**导出产物**（`capability_export`，P2）就吐前两种：一个可直接拷进 `skills/` 的目录，外加一段可粘进 `mcp-servers.json` 的 JSON。**不自动注册插件**——插件与主进程同权限，自动生成插件等于自动生成任意代码执行。

- 第 6 步把"看截图 + 补观察 + 写 brief"打包成一个 agent 节点（不可枚举）

- 第 10–11 步是**代码检查**（build 退出码、computed style 与源站一致）

**同一件事单独怎么做**（原子性的验收）：

| spec 步骤 | 单独做 |
|---|---|
| 1–5（取证） | `/clone <url>` 让 agent 按 `clone/SKILL.md` 第 2 节做，产出同一套 research 文件 |
| 6（brief） | 同上，第 2 节的收尾动作 |
| 7（scaffold） | 直接说"在 projects/qx 下建个 Next 工程" |
| 9（build） | 手动说"按这份 brief 重建首页"，或 `/clone` 一次说完 |
| 10–12（校验+报告） | 直接说"检查下这个页面有没有横向溢出" |

**如果某个步骤单独做不到，它就不该是节点**——应该被吸收进相邻的 agent 节点里。

### 7.2 证据链契约（红队/蓝队复用）

reverse-skill 的 `ops/evidence-finding-path.md` 把"结论"约束成三个可校验的 Markdown 结构。**这套契约原样保留**，只换落点：

```
{project}/security/
  evidence/E-001.md      # 不可变观察：observed_at / source_ref / content_hash / repro_command / raw_excerpt
  findings/F-001.md      # 结论：severity / category / evidence_ids[] / location / impact / confidence / repro_steps / remediation
  paths/P-001.md         # 路径：attack | callflow | solve，每步绑 evidence + finding
```

**三条硬校验（写进 `redteam` / `blueteam` 技能，由 agent 自检，不写代码）**：
- Finding 的 `evidence_ids` 非空，且引用的 E-* 文件真实存在
- 每条 Evidence 必须有 `repro_command`（第三方可跑，或注明离线限制）
- `status=validated` 的 Finding 不得 `confidence=low`

**为什么不把它做成执行器断言**：这三条都是"文档内部一致性"，用代码校验等于在 Lumii 里再造一个 case-review 工具；而 agent 读一遍文件就能自查。**保持纯文档契约**——与 pipeline 的 `expect` 分工一致：机器判机器能判的（退出码、样式读数），人/agent 判语义的。

### 9.1 已定（2026-11-01 用户拍板）

| # | 决策 | 影响 |

## 10. 风险

| 风险 | 缓解 |
|---|---|
| **agent 节点被滥用成"万能步骤"**，退化回自由循环 | spec 校验强约束：agent 节点不能产出路由条件；技能包与工具描述里写死判据（能枚举→tool，不能枚举→agent） |
| **`agentType` 静默回落 assistant**（`orchestrator.ts:524` 的既有行为），导致"以为用了专用 Agent，其实没用" | `validateSpec` 用 `knownAgents` 硬校验，加载期拒；`agentType` 缺省也算校验。**不允许在 pipeline 路径上回落** |
| **成本失控**（3 个 agent × 60 轮） | `maxTurns` 强制注入（D3，缺省 40）；时间线卡显示每步 token |
| **软门禁被误读成"没有边界"** | 复刻域产物强制带 `NOTICE.md`；安全域 spec 必须有 `scope.ownership`；技能包首段写明允许的用途 |
| **安全域被当攻击工具** | 产物只出"检测规则 + 加固补丁"，不出载荷/C2/exploit 成品；`security` Agent 默认关闭；这是自律约束，**不假装能技术防住** |
| **复刻产物质量不可判** | 硬性要求"代码断言 + agent 目视 + 如实声明剩余差异"三件套；禁止"像素级完美"话术 |
| **原子被流水线"绑架"**（只有跑流水线才能做），退化成一堆不可复用的 spec | D10/D11 顺序约束：先立原子（技能），流水线后做；每个节点必须对应"能单独做的一件事"；P0/P1/P4 的退出标准里各有一条"单跑"验收 |
| **目标站反爬/需登录** | precondition 里先 `browser_navigate` 断言 200；失败即停并说明，不硬闯 |
| **插件化踩坑** | §6 默认只导出技能包与 MCP 配置；插件形态需用户显式要求 |
| **pipeline 新节点破坏老 spec** | `kind` 可选、缺省 `'tool'`；journal 新字段可选；老 spec 与老 journal 零改动可读 |
| **删 `pipeline:run` 破坏现有 UI** | `PipelinePage` 同批改；`usePipelines.run` 移除；`PipelinePage.test.tsx` 同步改 |
