# 用户/好友知识与行为蒸馏 · 设计

> 状态：**开发中** ｜ 领域：`渠道与CLI`
> 关联：技术研究 §7.4（本方向立项）、现有读层 = 微信 MCP（`apps/windows/resources/wechat-mcp/`）
> 目标功能：把「读到的微信历史」从**帮回复的素材**升级为**长期知识资产**——蒸馏出**用户画像 / 好友画像 / 行为特征**，喂给 Agent 与记忆·场景记忆体系。

## 0. 一句话
`聊天记录（语料） → 结构化 digest（统计+样本） → 画像（LLM/模板） → 注入（场景记忆/Wiki）`。

## 1. 边界与隐私（硬约束，先于功能）
- **仅本人账号数据**、**全本地处理**、**不外传/不上传第三方**。
- 默认只做**本地确定性统计**；**LLM 提炼为可选**（涉及把聊天内容喂给模型，须显式开启；走本地模型则另说）。
- **范围开关**（可只对指定会话蒸馏）与**一键清除**；产物落本地数据目录，不进 Wiki 公开区。
- 只读微信库，**不改动**微信任何数据。

## 2. 读层事实（已实测，2026-10-07，新号）
- **分片**：消息按**时间滚动**落在 `message_N.db`（`0`=最新、数字越大越旧；实测 0=2026、1=2025、2=2024~25初）。
  **完整语料必须合并所有分片** —— 已实现（`wechat_core._msg_shard_rels/_refresh/_rows/talkers`，`sessions 40→279`）。
- **发送者**：`Msg_*.real_sender_id` → `Name2Id.rowid` → `user_name`，**可精确判定每条消息的发送者**（群/单聊都行；比自己==`self_wxid` 即"我发的"）。比"内容前缀"可靠得多。
- 字段：`create_time`(Unix秒)、`local_type`(1=文本/3=图片/49=文件…)、`message_content`(可能 zstd)、`real_sender_id`。

## 3. 分层（L0–L3 语义金字塔 + 可追溯）
业界（TencentDB Agent Memory / Context0 / Bi-Mem / RGMem）已收敛到同一蓝图：**原始对话逐层蒸馏为紧凑、可演化的画像**，检索跨层进行。

| 层 | 产出 | 落点 | 本轮 |
|---|---|---|---|
| **L0 原始** | 微信消息（本人账号，只读） | 微信库（不改动） | ✅ 已有 |
| **L1 统计/原子事实** | `wechat_digest`：统计 + 样本（**已有**）；后续 LLM 抽**原子事实**（每条带 `evidence`=来源 ts/原文片段，可追溯） | `~/.lumii/wechat-distill/facts.jsonl` | 统计 ✅ / 事实 P1 |
| **L2 场景块** | 按会话/关系组织的 Markdown 片段（白盒、人可编辑） | `~/.lumii/wechat-distill/contacts/<talker>.md` | P1 |
| **L3 画像** | 用户画像 `self.md` + 好友画像（约 150 词级的"画像卡"） | `~/.lumii/wechat-distill/self.md` | P1 |
| **注入** | 命中即注入 | 渠道场景记忆（`weixin`）/ Wiki 条目 | P1 |

**四个来自调研的硬约束**（避免"蒸馏"变成噪声放大器）：
1. **稳定性闸门**（IRIS/GIFT）：画像只在**证据足够**时更新；语义变化小于阈值才接受，否则"阻尼合并"，并**定期用累积事实重合成**，防漂移。
2. **增量而非重跑**：存**水位**（`state.json` 记"处理到哪条 ts/哪个分片"），只处理新消息；旧 L1 事实与 L2/L3 保留。
3. **结构化压缩**：不把整库倒给模型；每条抽取成**定长字段**（压缩约 10×），检索/画像都基于压缩件 + 回链原文。
4. **白盒可追溯**：L2/L3 是**明文 Markdown**，事实带来源；用户可读、可改、可一键清除。

## 4. digest 数据模型（P0）
```
{
  "scope": "all" | "<talker>",
  "generated_at": <unix>,
  "shards": <分片数>,
  "self":  { "total", "from_me", "from_others", "by_type", "hour_hist[24]", "avg_len",
             "top_contacts": [{talker,name,sent_to,len}], "top_words": [{word,n}] },
  "contacts": [ { "talker","name","total","from_me","from_them","first_ts","last_ts",
                  "sample_from_me":[...], "sample_from_them":[...] } ],
  "samples_from_me": [ ... ]        # 供 LLM 提炼"我的表达习惯"
}
```
- `self.top_contacts`：我**发给谁最多**（关系热度）。
- `contacts[*].sample_*`：双方代表性消息（截断，供画像）。
- 全部**截断+限额**，避免把整库倒出（隐私 + token）。

## 5. 路线与落地
| 阶段 | 内容 | 状态 |
|---|---|---|
| **P0** | `wechat_digest(scope, limit, since)` 多分片统计 + 样本；`devcli digest` | ✅ |
| **P1** | 画像落盘 `~/.lumii/wechat-distill/{self,contacts/*}.md` + `wechat_profile_save/get`；`read_history` 带 `from_me`；Agent 驱动 | ✅ |
| **P2** | 增量水位（`state.json`+`since`）/ 画像稳定性（`.prev`）/ 指令级注入 | ✅ |
| **P3** | 增量蒸馏 ✅ / 一键清除 `wechat_distill_clear` ✅；范围开关 UI、定期重合成 | 🟡 |
| **P4** | 知识条目→Wiki、语义稳定性闸门、好友画像批量、注入渠道场景记忆 | ⬜ |

**落地要点（2026-10-07）**
- **读层**：多分片合并（`sessions 40→279`）+ `real_sender_id→Name2Id.user_name` 发送者判定（`read_history`/`search_messages` 均带 `from_me`/`sender`）。
- **工具面 8 → 15**：+ `wechat_digest` / `wechat_distill_state` / `wechat_distill_clear` / `wechat_profile_save` / `wechat_profile_get`。
- **真机端到端**：Agent 由 `wechat_digest` **自主**产出**用户画像**（成都 / 政企信创研发骨干 / 家人 / 短句+表情缓冲+文档链接控）与**好友画像**（张文根：张老板 / 川渝口音 / 1:1 平等互动 / 短平快 16.5 字）。
- **测试**：WM-18/19/20（确定性）；修一处**测试红线**——`LUMII_WECHAT_DISTILL` 可覆盖产出目录，测试**不再动用户真实画像**。

**接进代聊（2026-10-08）**
- **自动注入**：回路每轮把「关于我（本人）」+「关于这个人」拼在提示词最前面（冲突时以消息为准），并记 `[wechat-watch] 已注入画像 peer=… chars=…` 作可观测证据（提示词不落盘，否则"注入了没有"无法归因）。
- **约定进 Agent**：蒸馏的**时机与口径**（缺/过期就先 digest→profile_save→水位，画像卡 ≤250 字，别在回话里提画像）写进「灵栖代聊」的 systemPrompt，作为一个**程序维护**的分区（标记 `<!-- lumii:relay-workflow v1 -->`，追加式升级、不覆盖用户改过的内容）——事实会变（每轮拼），约定不变（住在 Agent 里）。
- **缺画像不再静默跳过**：提示词里写一句**事实**（"还没有画像"/"已过期"），步骤留在 Agent 那侧。

## 6. 借鉴（2026-10 网络调研）
| 来源 | 可取之处 | 我们的取舍 |
|---|---|---|
| **TencentDB Agent Memory**（全本地 SQLite+sqlite-vec，BM25+向量+RRF） | L0→L3 分层、`persona.md` 白盒、层间检索；PersonaMem 48%→76% | **采纳分层与白盒**；向量检索待 P2（先确定性统计 + FTS） |
| **Context0**（PolarDB-X） | 三层 + **画像卡 ≈150 token** + `source_episode_id` **可追溯** + 异步蒸馏 | **采纳"画像卡 + 事实回链原文"**；异步化待 P3 |
| **Structured Distillation**（arXiv 2603.13017） | 每条对话压成 4 字段（≈38 token，**11× 压缩**），检索等效 96% | **采纳"定长字段压缩 + 保留样本"** |
| **IRIS / GIFT**（稳定性闸门） | 画像更新前算语义增量，超阈值才接受、否则阻尼合并；**定期重合成防漂移** | **采纳"闸门 + 定期重合成"** |
| **Bi-Mem**（归纳 Agent + 反思 Agent 双向） | 自底向上聚事实 + 自顶向下校准全局画像 | P2：设"反思"步骤校准 |
| **Distilly**（Person Profile 打包成 Agent Skill） | 把"某人的专长/判断/风格"做成可复用画像包 | 好友画像可导出为技能/提示片段 |
| **agent-persona / PRISM** | 规则 + LLM 混合；**置信度 + 时间衰减** | 词频/行为用规则；画像用 LLM；加置信度与衰减 |

**结论**：原设计方向正确；据此补强 **① L0-L3 分层与可追溯、② 稳定性闸门与定期重合成、③ 增量水位、④ 结构化压缩与白盒**。

## 7. 风险 / 待定
- **隐私**：LLM 提炼与"注入"等于把聊天内容送进模型上下文。原设计是**默认不自动注入**、靠 `wechat_profile_get` **按需取**；**2026-10-08 用户明确改为：代聊每一轮自动注入**（`bridge.wechatProfilePrompt` 拼在提示词最前面，每份 ≤1500 字）。口径：画像产物是**本机白盒文件**（`~/.lumii/wechat-distill/`，用户可编辑可删），注入范围**仅代聊 Agent**（不污染通用对话）；范围开关 UI 仍待做。
- 稳定 vs 可塑：好友/用户会变，闸门阈值需可调，避免过度保守。
- 多账号：已支持 `LUMII_WECHAT_ACCOUNT` 锁定；`LUMII_WECHAT_DISTILL` 可换产出目录。
- 词频用**极简分词**（中英按正则切），不引重依赖。
