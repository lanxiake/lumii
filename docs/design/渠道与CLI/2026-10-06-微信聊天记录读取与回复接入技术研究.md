## 0. 结论先行

1. **需求必须先澄清一个语义分叉**（见 §1），它决定整个技术选型：
   - **语义 A「副驾驶」**：Agent 读*用户本人*与好友/群的会话，帮用户起草/发送回复 → **现有 iLink 通道做不到**，必须走本地数据或自动化，属灰色地带。
   - **语义 B「助手信箱」**：用户与一个 bot 对话，Agent 回复 → **现有能力已基本满足**，只差上下文增强。
2. **读取与写入必须解耦**。读取可以纯只读、零封号风险；写入（以用户身份发送）才是唯一的高风险动作。所以组合策略是：**读层选最稳的，写层单列并分级**。
3. **本机环境是有利版本**（§2）：微信 **3.9.8.15 经典版**，正处于工具链兼容性最好的区间——无需面对 4.x 的自绘 UI 破解，也无需 4.1+ 的 DLL 注入取密钥。
4. **候选技术全景 6 类、12 项**（§4）。初步判断：**读取层首选 `chatlog`**（只读、跨版本、自带 HTTP API + MCP + 实时 webhook）；**发送层待定**（wxauto / WeChatFerry 二选一，取决于对实时性与风险的容忍度）。
5. 但判断必须由 **PoC 实测**支撑，不能靠文档下结论——因此本文的重心是 **§6 全技术测试方案**（隔离、判据、统一评分），用户要求「全面测试所有技术后选最优组合」，测试结论回填 §7 评分表。

## 1. 需求澄清：两种语义，两条路

用户目标表述为「让 Agent 帮助用户回复微信消息」。这句话对应两种本质不同的产品形态：

| | 语义 A —— 副驾驶（Copilot） | 语义 B —— 助手信箱（Inbox Bot） |
|---|---|---|
| 谁在和 Agent 说话 | 用户的好友/群成员（Agent 旁观真实会话） | 用户本人（用户主动给 bot 发消息） |
| Agent 能看到的 | 用户全部真实会话（历史 + 实时） | 只有用户发给 bot 的消息 |
| 回复发给谁 | 好友/群（**以用户本人身份**） | 用户本人（bot 身份） |
| 技术门槛 | 需越界读本地库 / UI 自动化 / 注入 | 官方 iLink 即可 |
| 合规风险 | **高**（违反微信协议，有封号风险） | 低（官方背书的功能） |
| 现有实现 | ❌ 不支持 | ✅ 已实现（`WeixinLoginService`） |

**这是本项目的第一个、也是最重要的决策点。** 现有代码 100% 在语义 B；用户字面诉求（读历史、读实时、帮回复真实微信）指向语义 A。

> **建议**：无论最终选哪条，都先做**读层**（低风险、高价值），把「Agent 能读懂用户在聊什么」跑通；写层作为独立决策，默认走**草稿模式**（Agent 出建议、用户手动发），把"自动以用户身份发送"作为需要显式授权的 P3。

## 2. 现状盘点与硬约束

### 2.1 现状能力（iLink / ClawBot）

| 能力 | 现状 | 落点 |
|---|---|---|
| 扫码登录 | ✅ | `weixin-login-service.ts` `startLogin()` |
| 实时收消息 | ✅ `getupdates` 35s 长轮询 | `pollLoop()` |
| 发送文本 / 文件 | ✅ `sendmessage` + CDN 上传 | `sendTextReply()` / `sendMediaReply()` |
| 图片/语音/文件/视频 | ✅ 含 SILK ASR 转录 | `normalizeMessage()` |
| 会话路由 / 斜杠命令 / 跨渠道接续 | ✅ | `weixin-channel-adapter.ts` |
| **历史消息** | ❌ | — |

### 2.2 三条硬约束（决定了不能只靠官方通道）

1. **协议层**：`getupdates` 是**游标式增量**，只返回登录后到达的消息，且社区能力表明确标注 `Fetch messages history: No`。
2. **策略层**：官方明示 ClawBot「不涉及对微信的自动化操作，**不会获取用户和其他好友的单聊、群聊记录**」，且**仅限一对一私聊、不可拉群**。它是「用户与自己 AI 之间的一条私密通道」，不是「用户的微信收件箱」。
3. **身份层**：iLink 的 `sendmessage` 只能回复**与 bot 会话的对方**，无法以用户身份向好友/群发消息。

> 结论：**要满足语义 A，必须引入官方通道之外的第二条技术栈。**

## 3. 目标环境（本机实测）

```
微信版本   : 3.9.8.15（经典 PC 版，WeChat.exe）
安装路径   : E:\mysoft\WeChat\WeChat.exe
数据目录   : C:\Users\Administrator\Documents\WeChat Files\wxid_sngf3b86qbz021
进程状态   : WeChat.exe 运行中；WeChatAppEx 多实例（小程序容器）
架构判定   : 3.9.x 经典架构（WeChatWin.dll + Msg/*.db SQLCipher）
            —— 非 4.x 的 Weixin.exe + xwechat_files，也非 4.1+ 的 passphrase+KDF
```

**为什么这个版本重要**：

| 版本 | 密钥提取 | UI 自动化 | 结论 |
|---|---|---|---|
| **3.9.x（本机）** | 内存扫描偏移，成熟 | UIAutomation 节点尚在，wxauto 可用 | **工具链最友好** |
| 4.0.x | 内存扫 `x'<key><salt>'` | 自绘 UI，需 Qt 无障碍门破解 + OCR | 较难 |
| 4.1+ | 内存扫描失效，需 DLL 注入 / Frida 取 passphrase + PBKDF2 | 同上 | 最难 |

⚠️ **风险提示**：微信会自动升级。方案必须具备应对 4.x 的退路（见 §4.5 密钥提取专题），否则一次升级即全盘失效。

## 4. 技术全景（6 类 · 12 项）

### 4.1 A 类：官方 iLink / ClawBot（现状）

- **协议**：`https://ilinkai.weixin.qq.com`，HTTP/JSON；`bot_token`（Bearer）+ `X-WECHAT-UIN` 防重放。
- **接口**：`get_bot_qrcode` / `get_qrcode_status` / `getupdates`（长轮询 35s）/ `sendmessage` / `getuploadurl` / `getconfig` / `sendtyping`。
- **关键字段**：`context_token` 是回复投递的会话令牌（24h 过期，`errcode=-14`），必须在收到用户消息后回传。
- **能力**：实时收（仅 bot 会话）✅、发送 ✅、媒体 ✅、历史 ❌、覆盖范围 ❌（读不到好友/群）。
- **定位**：保留为**语义 B 通道 + 发送兜底**，不是本需求的主力。

### 4.2 B 类：本地数据库解密读取（只读，低风险）

微信 PC 本地库为 **SQLCipher 加密**（3.9.x：AES-256-CBC，page_size 1024，kdf_iter 64000；4.x：SQLCipher4，page 4096，PBKDF2-SHA512 × 256000）。解密后即可全量读历史。

| 编号 | 工具 | 定位 | 读取 | 实时 | 发送 | 版本 | 备注 |
|---|---|---|---|---|---|---|---|
| B1 | **chatlog**（sjzar，Go） | **首选** | ✅ 全量 | ✅ webhook 回调 | ❌ | 3.x / 4.x | HTTP API + MCP + TUI，单文件 |
| B2 | WeChatMsg / PyWxDump | 历史 | ✅ | ❌ | ❌ | 3.9.x / 4.0 | **PyWxDump 2025-10 收律师函删库**；导出型 |
| B3 | WeChatDataAnalysis | 分析 | ✅ | ✅ 界面刷新 | ⚠️ 高级版付费 | 4.x | 公开版只读，写入需向作者购高级版 |
| B4 | 自研解密 | 可控 | ✅ | 需自建 | ❌ | 需适配 | 直接啃 SQLCipher + 页解密，成本高 |

**B1 chatlog 关键事实（据官方与社区文档）**：
- 命令：`chatlog key`（取密钥）→ `chatlog decrypt`（解密）→ `chatlog server`（起 HTTP 服务）。
- HTTP API：`127.0.0.1:5030`，`/api/v1/chatlog?talker=xxx&time=...&format=json`、`/api/v1/contact`、`/api/v1/chatroom`、`/api/v1/session`；媒体走 `/image/<id>`、`/voice/<id>`、`/file/<id>`。
- MCP：SSE `/sse`（新版为 Streamable HTTP），可直接挂进 AI 工具。
- **实时**：开启自动解密后，命中 `webhook.items[]`（`talker`/`sender`/`keyword`）的新消息 POST 到指定 URL；本地回调延迟约 **13s**，远程约 45s。
- 配置文件：`%USERPROFILE%\.chatlog\chatlog.json`；或环境变量 `CHATLOG_WEBHOOK` / `CHATLOG_WEBHOOK_HOST` + `CHATLOG_WEBHOOK_ITEMS`。
- 限制：Windows 密钥提取支持 `< 4.0.3.36`（本机 3.9.8.15 在范围内）；Docker 因进程隔离无法取密钥；需微信在线。

### 4.3 C 类：UI 自动化（可读 + 可写）

| 编号 | 工具 | 读 | 写 | 实时 | 版本 | 原理 |
|---|---|---|---|---|---|---|
| C1 | **wxauto**（cluic） | ⚠️ 窗口可见 + LoadMore | ✅ 文本/文件/@/引用 | ✅ 监听循环 | **3.9.x** | Windows UIAutomation |
| C2 | wechatauto-replica | ✅ 走本地库 | ✅ GUI | ✅ 库轮询 | 4.x | 库解密 + UIA/OCR 混合 |
| C3 | WeChatAuto.SDK（.NET） | ✅ | ✅ | ✅ | 3.9+ | RPA / UIAutomation |

**C1 wxauto 关键事实**：
- `WeChat()` 连接已登录客户端；`SendMsg(text, who)`、`SendFiles()`；`GetAllMessage()` 取当前窗口消息，`LoadMoreMessage()` 加载更多；`AddListenChat()` + `GetListenMessage()` 做**实时监听**。
- 版本敏感：官方 v3.9 文档标 3.9.12、社区分支标 3.9.11.17，**本机 3.9.8.15 需实测**。
- 前提：必须登录、窗口可用；**锁屏 / 最小化 / 窗口无响应会失败**。
- 4.x 有 `wxauto4`（免费）/ `wxautox4`（Plus）。

### 4.4 D 类：进程 Hook / DLL 注入（能力最强、风险最高）

| 编号 | 工具 | 读 | 写 | 实时 | 版本 | 风险 |
|---|---|---|---|---|---|---|
| D1 | **WeChatFerry (wcf)** | ✅ | ✅ | ✅ <100ms | 特定 3.9 小版本 | 高（注入，封号） |
| D2 | wxhelper | ✅ | ✅ | ✅ | 特定 3.9.x | 高 |
| D3 | wcferry 各语言 SDK | 同上 | 同上 | 同上 | 同上 | 同上 |

- **wcf** 版本号编码 `w.x.y.z`（如 v39.4.0 = 微信 3.9.12.17）；**公开适配列表含 3.9.2.23 / 3.9.10.19 / 3.9.10.27 / 3.9.11.25 / 3.9.12.17，未见 3.9.8.15**——本机直接用**大概率不匹配**，需升级微信或换 wxhelper 对应版本。
- 实时性最优（事件回调）、覆盖最全（好友/群/全部），但：依赖已登录客户端、**微信升级即失效**、注入行为触发风控概率最高。

### 4.5 E 类：密钥提取（独立的横切议题）

所有 B 类方案的前置条件。按版本分三档：

| 微信版本 | 密钥形态 | 提取手段 | 本机适配 |
|---|---|---|---|
| 3.9.x | 明文 raw key（内存） | 内存扫描 `WeChatWin.dll` 基址 + 偏移 | ✅ 可直接用 |
| 4.0.x | `x'<64hex key><32hex salt>'` | 内存模式匹配 + HMAC 校验 | 备用 |
| 4.1+ | 32B passphrase（需 KDF 派生） | **DLL 注入 / Frida**，且常需重启登录触发 | 退路 |

- 工具：`wx_key`（DLL 注入，4.1.x）、`wcdb-key-tool`（跨平台）、`wechat-4.1.12-decrypt`（Frida）。
- **注意**：每个 `.db` 文件 salt 不同，需分别派生；密钥常驻运行中进程内存，**微信必须在线**。

### 4.6 F 类：其他（评估后可排除）

- WeChat 网页版协议：早已封禁，不适用。
- 手机端备份解析（迁移到电脑 + 解析备份）：仅补历史，非实时，工程量大。
- 云端 / 第三方 SaaS 代收：数据出境，不可接受。

## 6. 全技术测试方案（本文核心）

用户要求「**全面测试所有技术，再选最优组合**」。因此本节定义统一的测试方法、判据与评分，保证各技术结果**可比**。

### 6.0 测试红线（先立规矩）

1. **隔离账号**：B/C/D 类的**写入与注入类测试一律使用测试小号**，严禁在用户主号上执行 Hook 注入。
   - 依据：[`feedback: dd-test-user-data-guard`]——测试话术/操作不得触及用户真实数据；维护官曾因「整理」话术误归档 84 条真实记录。
2. **只读优先**：先测只读路径（B 类）跑通，再评估写入。
3. **可回滚**：测试前对 `WeChat Files` 做**文件级快照**（复制到独立目录），PoC 只在该副本上解密；`finally` 恢复。
4. **证据留存**：每项技术产出 `evidence.jsonl`（原始命令、耗时、返回样本、失败堆栈），放 `docs/test/lumii-cli/wechat/`。
5. **不落敏感内容**：证据里对消息正文截断/脱敏，只留结构与计数。

### 6.1 统一测试用例矩阵

| 用例 | 说明 | 通过判据 |
|---|---|---|
| U1 环境探测 | 版本/路径/进程/数据目录 | 与 §3 一致，可脚本化复现 |
| U2 密钥提取 | `chatlog key` / 注入取密钥 | 拿到密钥且能解密首个库 |
| U3 读历史 | 指定 `talker` 拉一段历史 | 条数、时间序、内容与客户端一致 |
| U4 读实时 | 测试号发消息 → 系统收到 | 端到端延迟 < 目标阈值（记录实测） |
| U5 媒体解密 | 图片/语音/文件 | 可还原为可用文件；语音可转 MP3 |
| U6 发送 ×N | 文本/文件/@/引用（分身份） | 对方真实收到；UI 校验回读一致 |
| U7 稳定性 | 连续 30min / 微信重启 / 锁屏 | 是否掉线、报错、需重登 |

| U9 故障恢复 | 微信升级/退出/断网 | 失败模式是否干净、可诊断 |

### 6.2 各技术 PoC 步骤与判据

**T-A｜iLink（基线，回归用）**
- 步骤：现有流程发一条测试消息 → 观察 `getupdates` 收到 → `sendmessage` 回复。
- 判据：U4/U6 通过；**U3 明确失败**（用于确立"官方通道读不到历史"这一基线事实）。

**T-B1｜chatlog（重点）**
- 步骤：① 取密钥 → ② 解密副本 → ③ 起 server → ④ `GET /api/v1/chatlog?talker=...` 拉历史 → ⑤ 配 webhook 指向本地接收器，测试号发消息看回调 → ⑥ 挂 MCP 看 AI 侧可用性。
- 判据：U2–U5、U7、U8 通过；U4 延迟记录（预期 ~13s）。
- 关注：3.9.8.15 是否在 chatlog 支持矩阵内（**需实测**，社区样本多为 3.9.12）。

**T-B2/B3｜WeChatMsg / WeChatDataAnalysis**
- 步骤：以导出/分析为主，验证 U3 历史导出的完整性与格式。
- 判据：能拿到可被 Lumii 消费的结构化历史（JSON/SQLite）。
- 关注：B2 项目已下架，作为**历史对照**而非现役方案。

**T-C1｜wxauto**
- 步骤：① 连接客户端 → ② `GetAllMessage` 读当前窗口 → ③ `AddListenChat` 监听测试号 → ④ `SendMsg` 发送到测试号。
- 判据：U4/U6 通过；**U3 只能是"窗口可见范围"**（能力上限，记为局限）。
- 关注：3.9.8.15 的 UI 节点兼容性（版本敏感，最可能失败点）。

**T-C2｜wechatauto-replica**
- 步骤：仅在评估"升级到 4.x 后"的退路时执行；按官方 `pip install` + `WeChatDB` 读库 + `quick_send(verify=True)` 发送。
- 判据：U3–U6 通过。
- 关注：本机是 3.9.x，此方案**目标版本不符**，仅做**方案储备验证**，不作为当前主选。

**T-D1/D2｜WeChatFerry / wxhelper**
- 步骤：**仅用测试小号 + 隔离环境**；注入 → `enable_receiving_msg` → 收测试消息 → `send_text` 回发。
- 判据：U4（<100ms）/U6 通过。
- 关注：**3.9.8.15 未在适配列表**，预估需升到 3.9.10/3.9.11/3.9.12 或放弃；注入的**封号风险**要在结论里显式标注。

## 7. 组合方案与推荐（待 PoC 校准）

### 7.1 候选组合

| 组合 | 读 | 实时 | 写 | 特点 |
|---|---|---|---|---|
| **K1 只读 + 草稿** | chatlog | chatlog webhook | 无（Agent 出草稿，用户手发） | **风险最低、价值最快兑现** |
| K2 只读 + UI 发送 | chatlog | webhook | wxauto（用户身份） | 全闭环，风险中 |
| K3 只读 + Hook 发送 | chatlog | webhook | wcf（用户身份） | 实时最优，风险最高 |
| K4 全 iLink | iLink（无历史） | iLink | iLink（bot 身份） | 现状，语义 B |
| K5 全 Hook | wcf | wcf | wcf | 一体，但版本锁死 + 最高风险 |

### 7.2 推荐（**2026-10-07 经 P3–P6 定案**）

**读层**：**wechatauto-replica**（v1.2.4.4，官方验证于 **4.1.15.13 —— 与本机同版本**）为主；自研 SQLCipher 直读
（`wxkey4`+`wxread4`）保留为对照/兜底。二者**底层同路线**（SQLCipher4 直读 + 只读内存扫密钥），wechatauto 额外拿到
**图片密钥**与媒体解密、朋友圈、结构化导出。chatlog 降为**可选历史导出**，不承担实时。

**写层**：**默认草稿模式**（Agent 读 + 出建议、用户点发送）。自动发送 = **`OCR 定位 + SendInput`（零注入）**，
已加固到可用（`wxsend2.py`：确定性窗口布局 + **数据库锚点校验** + 输入落地校验 + 发送成功校验 + fail-closed），
但作为**显式开启的实验特性**（OCR 误读/布局依赖仍在）。

**实时**：轮询副本（≈11s 延迟）+ 增量查询（`wechat_poll`）。

**接线**：走 Lumii 内置 **MCP server（stdio）**——微信读取包成 Python MCP server，**零产品代码改动**。

**Hook 类（K3/K5）**：WeChatFerry 停更、wxhelper 无 4.x，且注入=封号风险，**默认不纳入**。

### 7.3 Lumii 侧落点（架构建议，2026-10-07 校准）

| 层 | 落点 | 说明 |
|---|---|---|
| 读 / 实时 | **MCP server（`mcp__wechat__*`）**：`wechat_sessions` / `wechat_history` / `wechat_poll` | 复用 Lumii 既有 MCP 客户端（`mcp-client.ts`），无需新增工具代码 |
| 配置 | `~/.lumii/config/mcp-servers.json` 加一项 `wechat` | 标准 stdio 配置；见计划 §6.9 |
| 写（草稿） | 复用现有渠道/通知出建议，用户点发 | 复用 [`2026-09-22-Agent通知与审批闭环设计.md`](../客户端UI/2026-09-22-Agent通知与审批闭环设计.md) |
| 写（自动） | `wxsend2.py` 作为**实验特性**（默认关闭） | 需显式开关 + 用户在场判定；四道校验 + fail-closed |
| 会话模型 | 走 MCP 工具，**不需要**新增「旁观会话」channel 模型 | 语义 A 不必套 `IChannelAdapter` |

### 7.4 衍生能力：用户/好友知识与行为蒸馏（2026-10-06 用户提出）

读取到的历史消息不只是「帮回复」的素材，更是**长期知识资产**：可让 Agent 学习用户的表达习惯、知识领域与决策偏好，并**蒸馏出用户本人及其好友的画像**。用户明确要求**作为独立功能保留**。

- **定位**：与「帮回复」解耦、并行推进的独立能力，二者共享同一读取层。
- **与现有体系的关系**：天然接入 Lumii 的**记忆系统 + Wiki 知识库**（[`../记忆系统/`](../记忆系统/)、[`../Wiki知识库/`](../Wiki知识库/)）——聊天记录作为语料，产出结构化的用户画像 / 好友画像 / 知识条目。
- **价值**：喂养「自主进化 Agent」的人格与场景记忆，让 Agent 更懂用户；也可用于关系维护、话题推荐等。
- **约束**：数据涉及他人隐私。必须坚持「仅本人账号数据、全本地处理、不外传」，并提供一键清除与范围开关（可只对指定会话蒸馏）。

| 测试误触真实数据 | 用户损失 | §6.0 红线：快照 + 副本 + finally 恢复 |
