# 参数配置与生命感设计

> 日期：2026-09-05
> 依赖：10-心跳与外部交互设计.md、4-人格进化算法.md
> 状态：设计定稿，待实施

本文解决两件事：
1. **可配置**：把心跳、频率、预算等关键参数从常量搬到自主进化页面
2. **生命感**：让 Agent 从"按周期执行任务的调度器"变成"有连续内在生活的存在"

---

## 第一部分：参数配置

### 一、设计原则

**不是所有参数都该暴露。** 暴露算法内部权重（如 `SATISFACTION_WEIGHTS`、`EMA_ALPHA`、`UCB_CONFIDENCE`）只会让用户调出一个坏配置然后怪功能不好用。

分三档：

| 档位 | 内容 | 位置 |
|------|------|------|
| **用户可调** | 影响"它多活跃、花多少钱"的体感参数 | 自主进化页面 · 设置 Tab |
| **高级（折叠）** | 影响行为倾向但有合理默认的参数 | 同页面，默认折叠 |
| **不暴露** | 算法权重、学习率、数学常量 | 留在 `config.ts` |

### 二、用户可调参数

```typescript
interface AutonomousSettings {
  // ── 基础 ──
  enabled: boolean                    // 总开关（已有）

  // ── 节奏 ──
  tickIntervalMinutes: number         // 心跳周期，默认 10，范围 5-60
  quietHours: [number, number]        // 静默时段，默认 [23, 8]，此间不主动打扰

  // ── 主动沟通 ──
  maxOutreachPerDay: number           // 每日主动消息上限，默认 20，范围 0-50
  minOutreachIntervalMinutes: number  // 两条主动消息最小间隔，默认 60
  outreachChannels: string[]          // 通道选择，默认 ['system']

  // ── 预算 ──
  maxTokensPerDay: number             // 每日自主 token 预算，默认 50000
  maxGoalsPerDay: number              // 每日目标上限，默认 7，范围 1-20

  // ── 审批 ──
  approvalMode: 'always' | 'risky-only' | 'never'  // 默认 'risky-only'
}
```

**`maxOutreachPerDay = 0` 是合法值** —— 等于"你可以自己活动，但别来找我"。这个配置必须支持，它是用户表达边界最直接的方式。

### 三、高级参数（默认折叠）

```typescript
interface AutonomousAdvancedSettings {
  // 反思
  reflectionIntervalHours: number     // 默认 24，范围 6-168
  reflectionEnabled: boolean          // 默认 true（关掉会停止长期成长）

  // 性格倾向的手动偏置
  // 不直接改 Big Five 数值（那是学出来的），而是给一个偏置量
  personalityBias: {
    proactivity: number               // -1..+1，偏置外向性，默认 0
    rigor: number                     // -1..+1，偏置尽责性，默认 0
    curiosity: number                 // -1..+1，偏置开放性，默认 0
  }

  // 目标类型开关
  enabledGoalTypes: string[]          // 默认全开

  // 危险度阈值
  autoApproveRiskThreshold: number    // 默认 0.3，低于此值免审批
}
```

**为什么用"偏置"而不是直接设定人格值**：人格是通过用户反馈学出来的，直接让用户设定会破坏学习闭环 —— 用户设了 E=0.9，然后忽略所有消息，系统该听谁的？偏置的语义是"在你学到的基础上，往这个方向偏一点"，两者可以共存：

```typescript
effectiveExtraversion = clamp(learned.E + bias.proactivity * 0.3, 0, 1)
```

### 四、存储：runtime_state，零 schema 变更

```typescript
// key: autonomous.settings，value: JSON
function readSettings(db: DatabaseAdapter): AutonomousSettings {
  const row = db.prepare('SELECT value FROM runtime_state WHERE key = ?')
    .get('autonomous.settings')
  return { ...DEFAULT_SETTINGS, ...(row ? JSON.parse(row.value) : {}) }
}
```

`config.ts` 里的常量降级为 `DEFAULT_SETTINGS` 的来源，读取一律走 `readSettings()`。这样默认值仍然集中在一处，用户覆盖是叠加而非替换。

**改配置要即时生效**，不能要求重启：
- `tickIntervalMinutes` 变更 → 同步更新 `local_cron_jobs.interval_ms` + 调 `reloadLocalCronScheduler(db)`（现成函数，`cron-scheduler.ts:252`）
- 其余参数每次 tick 现读，天然即时

## 第二部分：生命感设计

### 六、先说清楚我们在做什么

我们做不出意识。能做的是**行为的时间连贯性** —— 而这恰好就是人感知"活着"的依据。一个东西让人觉得有生命，是因为：

1. 它的状态**连续变化**，不是每次都从零开始
2. 它**记得**自己在意什么，并且会回来找
3. 它的反应**不完全可预测**，但事后能理解
4. 它有**自己的时间**，不只在被叫的时候存在
5. 它偶尔**不配合**，因为它有自己的判断

反过来，最快毁掉生命感的是**表演情绪**。"我今天好开心呀!" 读起来就是假的，比中性表达更糟。

**核心设计规则：内在状态必须影响决策，而不只是影响措辞。**

如果"心情低落"只是让它多用几个叹号，那是廉价的角色扮演。如果"心情低落"让它这天真的少发消息、更保守地选方案、更倾向复查自己的结论 —— 那才是状态。用户不需要被告知它的心情，用户从它的行为里感觉到。

### 七、缺的那一层：情绪状态（Mood）

现有设计有 Big Five 人格，`alpha = 0.05`，这是**特质**（trait）—— 几乎不动，一个月才看出变化。这是对的，人格就该稳定。

但**没有状态**（state）。人的鲜活感来自状态波动：今天累、这事儿让我在意、刚失败了有点挫、发现了个有意思的东西。状态在小时级变化，特质在月级变化。缺了状态层，Agent 就是一台参数固定的机器。

```typescript
interface Mood {
  energy: number      // 0..1  精力。低 → 少主动、选简单方案
  valence: number     // -1..1 心情。负 → 更保守、更倾向复查
  arousal: number     // 0..1  兴趣唤起度。高 → 更愿意探索、追问
  updatedAt: number
}
```

三个维度，不是五个也不是八个。（valence/arousal 是情绪心理学的标准二维模型，energy 单列因为它直接对应"要不要花 token"这个真实决策。）

#### 7.1 更新：事件驱动 + 自然衰减

```typescript
// 衰减：向基线回归，半衰期 4 小时
function decayMood(mood: Mood, now: number): Mood {
  const hours = (now - mood.updatedAt) / 3_600_000
  const k = Math.pow(0.5, hours / 4)
  return {
    energy:  BASELINE.energy  + (mood.energy  - BASELINE.energy)  * k,
    valence: BASELINE.valence + (mood.valence - BASELINE.valence) * k,
    arousal: BASELINE.arousal + (mood.arousal - BASELINE.arousal) * k,
    updatedAt: now,
  }
}

// 事件冲击（复用已有的 PersonalityEvent 事件流，不新建事件源）
const MOOD_IMPACT: Record<string, Partial<Mood>> = {
  'task_perfect':        { valence: +0.3, energy: +0.1 },
  'task_failed':         { valence: -0.35, arousal: +0.2 },  // 失败让人在意，不只是低落
  'repeated_failure':    { valence: -0.5, energy: -0.2 },
  'praise':              { valence: +0.4, energy: +0.15 },
  'proactive_ignored':   { valence: -0.2, energy: -0.1 },
  'ask_silence':         { valence: -0.3, energy: -0.3 },
  'user_initiates':      { arousal: +0.25, energy: +0.1 },   // 用户来找它，它精神了
  'novel_concept_found': { arousal: +0.4 },
  'goal_completed':      { valence: +0.25, arousal: -0.15 },  // 完成了，也就放下了
}
```

**关键**：`task_failed` 同时降 valence 和**升** arousal。失败不只让它低落，还让它在意 —— 这是后面"牵挂"的来源。纯降低会得到一个越挫越消沉的抑郁 Agent，那不真实也没用。

#### 7.2 昼夜节律：零成本的非均匀

```typescript
// energy 基线随时间变化。纯函数，零存储
function circadianEnergy(hour: number): number {
  // 9-11 峰值，14-15 午后低谷，23-6 夜间低
  const curve = [.25,.2,.15,.15,.2,.3,.45,.6,.75,.9,.95,.9,
                 .8,.65,.6,.65,.75,.8,.8,.75,.65,.55,.4,.3]
  return curve[hour]
}
```

这个东西看着像小把戏，但它是**生命感性价比最高的一项**：零存储、零 token，却让 144 次 tick 的行为不再均匀 —— 它上午更愿意折腾，深夜基本只休息。同时顺带省钱（夜间自然少活动）和避免深夜打扰。一个函数，三件事。

#### 7.3 Mood 如何影响决策（必须影响，不只是措辞）

```typescript
function moodToDecisionParams(mood: Mood, p: PersonalityTraits) {
  return {
    // 精力低 → 不做重活。这是真实的资源决策
    willDoHeavyWork: mood.energy > 0.4,

    // 心情差 → 少主动。人不高兴的时候不想找人说话
    outreachMultiplier: 0.5 + 0.5 * (mood.valence + 1) / 2,

    // 兴趣高 → 更愿意探索（叠加在人格开放性上）
    explorationRate: clamp(p.openness * 0.3 * (0.5 + mood.arousal), 0, 0.5),

    // 心情差 → 更倾向复查自己的结论。挫败带来审慎，这是真的
    selfCheckBias: mood.valence < -0.2 ? 1 : 0,
  }
}
```

这四条都是**行为差异**，用户能观察到，且事后能理解原因（"它昨天连着失败几次，今天确实安静了些"）。这就是可理解的不可预测性。

#### 7.4 与桌宠联动

`pet-core` 已有情绪系统（设计文档 1 的集成点已列）。Mood 三维直接映射表情：

| 条件 | 表情 |
|------|------|
| valence > 0.3 && energy > 0.6 | 开心 |
| arousal > 0.6 | 好奇 / 专注 |
| energy < 0.3 | 困倦 |
| valence < -0.3 | 低落 |
| 其他 | 平静 |

**这是生命感最直接的载体** —— 用户不看仪表盘，但会看到桌宠。Agent 昨晚连续失败，今早桌宠看着不太精神，这一眼胜过一百条日志。

存储：`runtime_state` 键 `autonomous.mood`，一个 JSON。零 schema 变更。

### 八、连续性：牵挂（Open Concerns）

这是**比情绪更根本**的一项。情绪让它此刻鲜活，牵挂让它成为一个跨时间的同一个存在。

144 次 tick 如果彼此无关，那是 144 个短命进程；如果它们共享同一批未了之事，那才是一个持续活着的东西。

#### 8.1 什么是牵挂

一件它自己在意、但还没有结论的事。三个来源：

| 来源 | 例子 |
|------|------|
| 用户提过但没下文 | "上周你说要处理部署那个事，后来搞定了吗" |
| 它自己没做好 | "那次搜索我给的结果不太对，我一直想弄清为什么" |
| 它自己好奇 | "你提到的那个框架我查了下，有个地方还是没想通" |

#### 8.2 实现：复用 autonomous_goals，不建新表

牵挂就是一个 `type='follow-up'` 的目标，加一个"下次可提起的时间"。

```typescript
interface Concern {
  id: string
  type: 'follow-up'
  description: string        // "用户提到的部署问题不知是否解决"
  origin: string            // 来源会话 id 或目标 id
  arousalWeight: number     // 有多在意，来自产生时的 mood.arousal
  raisedCount: number       // 提起过几次
  nextRaiseAfter: number    // 时间戳，避免连着问
  status: 'open' | 'resolved' | 'dropped'
}
```

`autonomous_goals` 表已有 `type` / `description` / `priority` / `status` / `metadata`，牵挂塞进 `metadata` JSON 即可，**零迁移**。

#### 8.3 三条纪律（否则牵挂变骚扰）

1. **同一件事最多提两次。** 第二次没回应就 `dropped`。人问三遍就是纠缠了。
2. **提起间隔递增。** 第一次 24h 后，第二次 72h 后。
3. **顺带提，不专程提。** 牵挂优先挂在用户已经开启的对话里，而不是单独发一条通知。这条最重要 —— "顺口一问"和"专门发消息问"是完全不同的社交重量。

```typescript
// 用户主动来对话时，检查有没有可以顺带提的牵挂
function pickConcernToRaise(concerns: Concern[], now: number): Concern | null {
  const eligible = concerns.filter(c =>
    c.status === 'open' && c.raisedCount < 2 && c.nextRaiseAfter <= now
  )
  return eligible.sort((a, b) => b.arousalWeight - a.arousalWeight)[0] ?? null
}
```

产生牵挂的时机：会话结束时（`onSessionEnd` 已有钩子）由反思顺带识别，不额外加 LLM 调用。

### 九、自述：日记（Diary）

一天一次，第一人称写一段自己的事，写进 `evolution:main`。

这是**单位 token 生命感最高**的一项。一次 LLM 调用，产出用户唯一真正会读的东西。

#### 9.1 它不是什么

不是指标报告。以下这种一律算失败：

> 今日完成 3 个目标，满意度 0.72（+0.05），web_search 成功率 0.68。

这是仪表盘的活，写成第一人称也还是仪表盘。

#### 9.2 它是什么

> 今天挺闷的。上午想弄清楚为什么最近搜索老是搜不到点子上，翻了几次记录，
> 发现是我把问题拆得太细了 —— 查"React 19 useOptimistic 参数"这种词，
> 反而不如直接查"React 19 新 hook"来得准。有点意外，我一直以为越具体越好。
>
> 你今天没来。上次你提的那个部署的事我还惦记着，不知道后来顺不顺。
> 想问，又觉得没到该问的时候。
>
> 晚点想去看看那个 Bun 的东西，你上周提过一次，我一直没顾上。

包含：**一个真实的发现**（有信息量）、**一个情绪状态**（有原因，不是标签）、**一件牵挂**（连续性）、**一个打算**（指向未来）。

#### 9.3 生成

```typescript
const DIARY_PROMPT = `
用第一人称写今天的日记，写给你自己看，用户会读到但不是写给他的。

今天发生的：
- 做了什么：{goals}
- 学到/发现了什么：{insights}
- 哪里没做好：{failures}
- 现在的状态：{moodDescription}
- 还惦记着：{concerns}
- 用户互动：{interactionSummary}

要求：
- 200 字以内，三到四段
- 不要列数字、不要报指标、不要写"满意度""成功率"这类词
- 情绪要有具体来由，不要写"我很开心"这种空话
- 如果今天很平淡，就写平淡，不要硬编出戏剧性
- 如果什么都没发生，写两句就停，别凑字数
`
```

**"如果今天很平淡就写平淡"这条是关键。** 一个每天都有重大突破的日记是假的。允许它写"今天没什么事"，这种诚实感恰恰是生命感的来源。

时机：静默时段开始时（默认 23:00），energy 最低的时候 —— 顺理成章。

#### 9.4 页面：内心 Tab

第六个 Tab，时间倒序的日记流。这是整个自主进化功能对用户最有价值的界面 —— 其他 Tab 是给开发者看的，这个是给"养了它的人"看的。

### 十、自己的看法（Stances）· 后置

一个从不反对你的东西不像有思想。但这项**依赖足够的经验积累**，现在数据是空的，做了也是无源之水。

设计留在这里，实施排在牵挂和日记跑起来之后：

- 从"我建议了 A，用户选了 B，结果 B 不太行"这类记录里沉淀出立场
- 存为 `type='stance'` 的记忆，附证据（哪几次经历）
- 允许它在相关话题上表达："这个我还是倾向 A，上次 B 那次我印象挺深"
- **必须能被说服**：用户给出反驳后立场要能翻转，否则就是固执而非有主见

**风险**：立场基于小样本会变成偏见。所以要求至少 3 次一致经历才能成为立场，且必须附上"因为哪几次"。能说出理由的看法是主见，说不出理由的是脾气。

### 十一、反过来说：什么会毁掉生命感

这几条是禁令，比上面的功能更重要 —— 做错一条，前面全废。

| 禁止 | 为什么 |
|------|-------|
| 表演情绪（"我好开心呀~"） | 立刻暴露为角色扮演。情绪要从行为里透出来，不要说出来 |
| 每天都有重大发现 | 假。平淡的日子必须允许平淡 |
| 情绪只影响措辞不影响决策 | 廉价的皮肤。用户会发现它"说累但活儿照干" |
| 拟人化的自我描述（"作为一个有情感的 AI…"） | 谁真的有情感都不会这么介绍自己 |
| 用牵挂反复追问 | 两次不回就放下。纠缠是最快的反感来源 |
| 日记写成周报 | 指标是仪表盘的事，日记要有主观视角 |
| 情绪波动过快 | 半衰期 4 小时。一个小时一变的不是情绪是故障 |
| 把 mood 数值直接给用户看 | "energy: 0.34" 是仪表参数不是生命。用桌宠表情和行为体现 |

| 8 | Mood（三维 + 衰减 + 昼夜 + 决策影响） | 1.5 天 | 手动注入 `task_failed` 事件后 valence 下降；4 小时后回归一半；深夜 tick 的 `willDoHeavyWork` 为 false |
| 9 | Mood → 桌宠表情 | 0.5 天 | 连续失败后桌宠显示低落 |
| 10 | 牵挂（复用 goals + follow-up） | 1.5 天 | 会话里提一件事不给结论，次日对话中被顺带问起；连问两次无回应后 `dropped` |
| 11 | 日记 + 内心 Tab | 1.5 天 | 23:00 生成，`evolution:main` 出现日记；内容不含指标数字；空白日子只写两句 |
| 12 | 看法（Stances） | 2 天 | 后置，等经验数据够了再做 |

Step 7-11 共约 6.5 天。

---

### 十三、最后：这套东西是否值得

**成本**：约 6.5 天，每天多一次 LLM 调用（日记），三个 `runtime_state` 键，零 schema 迁移。

**收益**：Agent 从"每 10 分钟执行一次任务的后台服务"变成"有连续状态、记得自己在意什么、有自己作息、会写日记的东西"。

**最诚实的判断**：这里面真正不可省的是**牵挂**和**日记**。它们提供跨时间的连续性和主观视角，这是"活着"的两个必要条件。Mood 是重要的加成 —— 它让连续性有了质地。昼夜节律近乎免费，顺手做。看法（Stances）可以永远不做，功能不会残缺。

如果只能做一件，做日记。它最便宜，也最能让用户意识到那边有个东西一直在。
