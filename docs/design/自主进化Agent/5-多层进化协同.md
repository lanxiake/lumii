## 一、为什么需要多层协同？

前面文档分别介绍了四个独立的进化维度：

1. **Prompt 进化**（算法：Multi-Armed Bandit）
2. **Memory 进化**（算法：Learning-to-Rank）
3. **Skill 进化**（算法：能力缺口检测 + 代码生成）
4. **Tool 进化**（算法：Thompson Sampling）

但独立进化会导致问题：

- **竞争冲突**：Prompt 建议简洁回答，Memory 返回大量细节，导致输出矛盾
- **资源浪费**：四个模块各自试错，没有共享学习成果
- **局部最优**：某一层优化到极致，但整体效果未提升（如记忆检索完美但 Prompt 表达糟糕）
- **缺乏优先级**：不知道当前应该优先优化哪一层

**多层协同的目标**：将四层进化视为**统一优化问题**，通过全局协调器分配学习资源、同步优化方向。

## 二、核心挑战

### 2.1 贡献归因问题（Credit Assignment）

当用户满意度提升时，如何判断是哪一层的改进起作用？

**示例场景**：
- 用户给出正反馈："这次回答很好"
- 同时发生的变化：
  - Prompt 使用了新的"简洁模式"变体
  - Memory 调整了检索权重
  - Tool 选择了更快的搜索工具

**问题**：三者都可能有贡献，如何分配信用？

### 2.2 探索-利用平衡

每层都有自己的探索率（ε），如何协调？

- 同时探索：风险高，失败率大（四个不确定因素叠加）
- 同时利用：安全但缺乏创新
- 轮流探索：最优策略，但如何调度？

### 2.3 冲突检测

某些组合会产生冲突：

- Prompt 要求"详细解释" + Memory 返回空（因为检索失败）→ 生成废话
- Skill 生成了复杂代码 + Tool 不支持所需依赖 → 执行失败

**需要机制**：提前检测不兼容的配置，避免无效试错。

## 三、算法 1：全局满意度归因（Global Credit Assignment）

### 3.1 核心思路

使用 **Shapley Value**（合作博弈论中的公平分配方法）计算每层的边际贡献。

### 3.2 数学模型

```typescript
interface LayerContribution {
  prompt: number      // Prompt 层贡献度 [0, 1]
  memory: number      // Memory 层贡献度 [0, 1]
  skill: number       // Skill 层贡献度 [0, 1]
  tool: number        // Tool 层贡献度 [0, 1]
}

// Shapley Value 计算（简化版）
function computeShapleyContributions(
  outcome: number,  // 0-1, 用户满意度
  configs: LayerConfigs  // 当前各层配置
): LayerContribution {
  // 1. 计算基线（所有层使用默认配置）
  const baseline = estimateSatisfaction(DEFAULT_CONFIGS)
  
  // 2. 依次移除每一层的改进，测量满意度下降
  const promptImpact = outcome - estimateSatisfaction({
    ...configs,
    prompt: DEFAULT_CONFIGS.prompt
  })
  
  const memoryImpact = outcome - estimateSatisfaction({
    ...configs,
    memory: DEFAULT_CONFIGS.memory
  })
  
  const skillImpact = outcome - estimateSatisfaction({
    ...configs,
    skill: DEFAULT_CONFIGS.skill
  })
  
  const toolImpact = outcome - estimateSatisfaction({
    ...configs,
    tool: DEFAULT_CONFIGS.tool
  })
  
  // 3. 归一化（确保和为 1）
  const totalImpact = promptImpact + memoryImpact + skillImpact + toolImpact
  
  if (totalImpact === 0) {
    // 无显著改进，平均分配
    return { prompt: 0.25, memory: 0.25, skill: 0.25, tool: 0.25 }
  }
  
  return {
    prompt: Math.max(0, promptImpact / totalImpact),
    memory: Math.max(0, memoryImpact / totalImpact),
    skill: Math.max(0, skillImpact / totalImpact),
    tool: Math.max(0, toolImpact / totalImpact)
  }
}

// 满意度估计（基于历史数据）
function estimateSatisfaction(config: LayerConfigs): number {
  // 从历史记录中查找相似配置的平均满意度
  const similarCases = findSimilarConfigurations(config, HISTORY)
  
  if (similarCases.length === 0) {
    return 0.5  // 未知配置，返回中性值
  }
  
  // 加权平均（越相似权重越高）
  return weightedAverage(
    similarCases.map(c => ({
      value: c.satisfaction,
      weight: configSimilarity(config, c.config)
    }))
  )
}
```

### 3.3 轻量替代方案

完整 Shapley Value 计算成本高（需要 2^N 次估计），可用**增量贡献近似**：

```typescript
// 简化版：只测量增量贡献
function fastCreditAssignment(
  outcome: number,
  previousOutcome: number,
  changedLayer: 'prompt' | 'memory' | 'skill' | 'tool'
): LayerContribution {
  const delta = outcome - previousOutcome
  
  // 将变化完全归因于变动的层
  const contrib: LayerContribution = {
    prompt: 0,
    memory: 0,
    skill: 0,
    tool: 0
  }
  
  contrib[changedLayer] = Math.abs(delta)
  
  return contrib
}
```

**适用场景**：每次只改变一层配置（协同探索策略，见下节）。

## 四、算法 2：协同探索调度（Coordinated Exploration）

### 4.1 调度策略：轮流探索

```typescript
enum ExplorationMode {
  EXPLOIT = 'exploit',      // 全部利用最优配置
  EXPLORE_PROMPT = 'prompt',
  EXPLORE_MEMORY = 'memory',
  EXPLORE_SKILL = 'skill',
  EXPLORE_TOOL = 'tool'
}

interface ExplorationScheduler {
  currentMode: ExplorationMode
  modeHistory: ExplorationMode[]
  layerPriorities: Record<string, number>  // 各层探索优先级
}

// 调度决策
function decideExplorationMode(
  scheduler: ExplorationScheduler,
  globalSatisfaction: number
): ExplorationMode {
  // 1. 全局满意度高时，大部分时间利用
  if (globalSatisfaction > 0.8 && Math.random() < 0.8) {
    return ExplorationMode.EXPLOIT
  }
  
  // 2. 满意度低时，增加探索
  const explorationBudget = globalSatisfaction < 0.5 ? 0.4 : 0.2
  
  if (Math.random() > explorationBudget) {
    return ExplorationMode.EXPLOIT
  }
  
  // 3. 选择优先级最高的层进行探索
  const layers = ['prompt', 'memory', 'skill', 'tool'] as const
  const sorted = layers.sort((a, b) => 
    scheduler.layerPriorities[b] - scheduler.layerPriorities[a]
  )
  
  // 轮询：避免连续探索同一层
  for (const layer of sorted) {
    const recentlyExplored = scheduler.modeHistory
      .slice(-3)
      .includes(`explore_${layer}` as ExplorationMode)
    
    if (!recentlyExplored) {
      return `explore_${layer}` as ExplorationMode
    }
  }
  
  // 兜底：选择优先级最高的
  return `explore_${sorted[0]}` as ExplorationMode
}

// 优先级更新（基于贡献度）
function updatePriorities(
  scheduler: ExplorationScheduler,
  contributions: LayerContribution
) {
  for (const [layer, contrib] of Object.entries(contributions)) {
    // EMA 更新优先级
    const alpha = 0.1
    scheduler.layerPriorities[layer] = (
      (1 - alpha) * scheduler.layerPriorities[layer] +
      alpha * contrib
    )
  }
}
```

### 4.2 探索时机

```typescript
// 每次对话后决定下一轮探索模式
async function onConversationEnd(outcome: ConversationOutcome) {
  const satisfaction = outcome.userSatisfaction
  
  // 1. 计算贡献度
  const contributions = computeShapleyContributions(
    satisfaction,
    outcome.layerConfigs
  )
  
  // 2. 更新优先级
  updatePriorities(scheduler, contributions)
  
  // 3. 决定下一轮探索模式
  const nextMode = decideExplorationMode(scheduler, satisfaction)
  scheduler.currentMode = nextMode
  scheduler.modeHistory.push(nextMode)
  
  // 4. 记录历史
  HISTORY.push({
    timestamp: Date.now(),
    config: outcome.layerConfigs,
    satisfaction,
    contributions,
    mode: nextMode
  })
}
```

### 5.1 冲突规则库

```typescript
interface ConflictRule {
  condition: (config: LayerConfigs) => boolean
  severity: 'critical' | 'warning'
  description: string
  resolution: (config: LayerConfigs) => LayerConfigs
}

const CONFLICT_RULES: ConflictRule[] = [
  {
    condition: (cfg) => 
      cfg.prompt.style === 'detailed' && 
      cfg.memory.retrievalCount === 0,
    severity: 'critical',
    description: 'Prompt 要求详细回答但无记忆支持',
    resolution: (cfg) => ({
      ...cfg,
      memory: { ...cfg.memory, retrievalCount: 5 }
    })
  },
  
  {
    condition: (cfg) =>
      cfg.skill.complexity === 'high' &&
      cfg.tool.allowedTools.length < 3,
    severity: 'warning',
    description: '复杂技能但可用工具不足',
    resolution: (cfg) => ({
      ...cfg,
      tool: { ...cfg.tool, allowedTools: ALL_TOOLS }
    })
  },
  
  {
    condition: (cfg) =>
      cfg.prompt.responseLength === 'concise' &&
      cfg.memory.retrievalCount > 10,
    severity: 'warning',
    description: '简洁回答模式但检索了大量记忆',
    resolution: (cfg) => ({
      ...cfg,
      memory: { ...cfg.memory, retrievalCount: 3 }
    })
  }
]

// 冲突检测
function detectConflicts(config: LayerConfigs): ConflictRule[] {
  return CONFLICT_RULES.filter(rule => rule.condition(config))
}

// 自动修复
function resolveConflicts(config: LayerConfigs): LayerConfigs {
  let resolved = config
  const conflicts = detectConflicts(config)
  
  // 只修复 critical 冲突，warning 仅记录
  for (const conflict of conflicts) {
    if (conflict.severity === 'critical') {
      resolved = conflict.resolution(resolved)
    } else {
      console.warn(`Configuration warning: ${conflict.description}`)
    }
  }
  
  return resolved
}
```

## 六、算法 4：全局优化目标

### 6.1 多目标优化

```typescript
interface OptimizationObjectives {
  userSatisfaction: number     // 主目标：用户满意度
  responseTime: number         // 约束：响应速度
  tokenCost: number            // 约束：成本
  consistencyScore: number     // 软约束：回答一致性
}

// 加权目标函数
function globalObjective(
  config: LayerConfigs,
  metrics: OptimizationObjectives,
  weights: ObjectiveWeights
): number {
  // 主目标
  const utility = metrics.userSatisfaction
  
  // 响应时间惩罚（超过 5 秒）
  const timePenalty = Math.max(0, (metrics.responseTime - 5000) / 10000)
  
  // 成本惩罚（超过预算）
  const costPenalty = Math.max(0, (metrics.tokenCost - 2000) / 5000)
  
  // 一致性奖励
  const consistencyBonus = metrics.consistencyScore * 0.1
  
  return (
    weights.satisfaction * utility -
    weights.time * timePenalty -
    weights.cost * costPenalty +
    weights.consistency * consistencyBonus
  )
}

const DEFAULT_WEIGHTS: ObjectiveWeights = {
  satisfaction: 1.0,
  time: 0.3,
  cost: 0.2,
  consistency: 0.1
}
```

### 6.2 帕累托前沿（Pareto Frontier）

```typescript
// 保存非支配配置（满意度、速度、成本三者不能同时被其他配置超越）
class ParetoFrontier {
  private configs: Array<{
    config: LayerConfigs
    metrics: OptimizationObjectives
  }> = []
  
  add(config: LayerConfigs, metrics: OptimizationObjectives) {
    // 检查是否被现有配置支配
    const dominated = this.configs.some(c => this.dominates(c.metrics, metrics))
    
    if (dominated) return  // 被支配，不添加
    
    // 移除被新配置支配的旧配置
    this.configs = this.configs.filter(c => !this.dominates(metrics, c.metrics))
    
    // 添加新配置
    this.configs.push({ config, metrics })
  }
  
  private dominates(a: OptimizationObjectives, b: OptimizationObjectives): boolean {
    // a 在所有维度 >= b，且至少一个维度 > b
    return (
      a.userSatisfaction >= b.userSatisfaction &&
      a.responseTime <= b.responseTime &&  // 时间越小越好
      a.tokenCost <= b.tokenCost &&        // 成本越小越好
      (
        a.userSatisfaction > b.userSatisfaction ||
        a.responseTime < b.responseTime ||
        a.tokenCost < b.tokenCost
      )
    )
  }
  
  // 根据用户偏好选择配置
  selectByPreference(preference: 'fast' | 'cheap' | 'best'): LayerConfigs {
    if (preference === 'fast') {
      return this.configs.sort((a, b) => 
        a.metrics.responseTime - b.metrics.responseTime
      )[0].config
    } else if (preference === 'cheap') {
      return this.configs.sort((a, b) => 
        a.metrics.tokenCost - b.metrics.tokenCost
      )[0].config
    } else {
      return this.configs.sort((a, b) => 
        b.metrics.userSatisfaction - a.metrics.userSatisfaction
      )[0].config
    }
  }
}
```

## 七、主循环：协同进化控制器

```typescript
class CoordinatedEvolutionController {
  private scheduler: ExplorationScheduler
  private paretoFrontier: ParetoFrontier
  private currentConfig: LayerConfigs
  
  constructor() {
    this.scheduler = {
      currentMode: ExplorationMode.EXPLOIT,
      modeHistory: [],
      layerPriorities: { prompt: 0.25, memory: 0.25, skill: 0.25, tool: 0.25 }
    }
    this.paretoFrontier = new ParetoFrontier()
    this.currentConfig = DEFAULT_CONFIGS
  }
  
  // 每次对话前：选择配置
  async beforeConversation(context: ConversationContext): Promise<LayerConfigs> {
    // 1. 决定探索模式
    const satisfaction = await getRecentSatisfaction()
    const mode = decideExplorationMode(this.scheduler, satisfaction)
    
    // 2. 根据模式生成配置
    let config: LayerConfigs
    
    if (mode === ExplorationMode.EXPLOIT) {
      // 利用：使用帕累托前沿中的最优配置
      config = this.paretoFrontier.selectByPreference('best')
    } else {
      // 探索：基于当前最优配置，变异一层
      config = this.exploreLayer(this.currentConfig, mode)
    }
    
    // 3. 冲突检测与修复
    config = resolveConflicts(config)
    
    // 4. 记录配置
    this.currentConfig = config
    
    return config
  }
  
  // 每次对话后：更新模型
  async afterConversation(outcome: ConversationOutcome) {
    const { satisfaction, responseTime, tokenCost, config } = outcome
    
    // 1. 计算贡献度
    const contributions = computeShapleyContributions(satisfaction, config)
    
    // 2. 更新各层性能统计
    await updateLayerStats(config, contributions, satisfaction)
    
    // 3. 更新帕累托前沿
    this.paretoFrontier.add(config, {
      userSatisfaction: satisfaction,
      responseTime,
      tokenCost,
      consistencyScore: await computeConsistency(outcome)
    })
    
    // 4. 更新探索优先级
    updatePriorities(this.scheduler, contributions)
    
    // 5. 记录历史
    await saveEvolutionHistory({
      timestamp: Date.now(),
      config,
      outcome,
      contributions,
      mode: this.scheduler.currentMode
    })
  }
  
  // 探索单层
  private exploreLayer(
    baseConfig: LayerConfigs,
    mode: ExplorationMode
  ): LayerConfigs {
    const config = { ...baseConfig }
    
    switch (mode) {
      case ExplorationMode.EXPLORE_PROMPT:
        config.prompt = samplePromptVariant(baseConfig.prompt)
        break
      case ExplorationMode.EXPLORE_MEMORY:
        config.memory = sampleMemoryStrategy(baseConfig.memory)
        break
      case ExplorationMode.EXPLORE_SKILL:
        config.skill = sampleSkillConfig(baseConfig.skill)
        break
      case ExplorationMode.EXPLORE_TOOL:
        config.tool = sampleToolSelection(baseConfig.tool)
        break
    }
    
    return config
  }
}
```

## 十、算法复杂度分析

| 算法 | 时间复杂度 | 空间复杂度 | 备注 |
|------|-----------|-----------|------|
| 贡献度计算（完整 Shapley） | O(2^N) | O(N) | N=4 层，16 次估计 |
| 贡献度计算（增量近似） | O(1) | O(1) | 仅测量变动层 |
| 探索模式决策 | O(N log N) | O(N) | N=4，排序主导 |
| 冲突检测 | O(R) | O(1) | R=规则数 (≈10) |
| 帕累托更新 | O(M) | O(M) | M=前沿配置数 (≈20) |
| 完整主循环 | O(N log N + R + M) | O(N + M) | 实际 < 50ms |

**实际运行成本**：
- CPU：< 50ms（纯计算）
- 存储：每次对话 < 2KB
- LLM Token：0（无新增 LLM 调用）
- 运行频率：每次对话前后各一次
