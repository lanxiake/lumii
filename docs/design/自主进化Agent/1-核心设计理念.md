# Lumii 自主进化 Agent 核心设计理念

> 日期：2026-09-03  
> 版本：v1.0  
> 状态：设计阶段

---

## 一、设计目标

构建一个具备以下特征的自主 Agent：

1. **长期运行**：不依赖用户指令，持续在后台运行
2. **自主进化**：能够根据使用反馈自动优化自身行为、技能和知识
3. **主动学习**：基于用户偏好、环境变化主动发现学习目标
4. **人格独立**：具备稳定且可进化的人格特质，而非机械执行预设规则
5. **情境感知**：理解当前情境，自主决定何时介入、何时沉默

**核心挑战**：现有系统是"响应式 + 定时触发"架构，需要演进为"自主目标驱动"架构，同时避免失控、骚扰用户、盲目进化等风险。

---

## 二、理论基础

### 2.1 Autotelic AI（自生目标）

**定义**：Agent 能够生成内在驱动的目标，而非仅响应外部指令。

**核心机制**：
```
内在动机 = f(好奇心, 能力边界, 用户偏好, 环境新颖度)
```

**实现要点**：
- **好奇心驱动**：发现知识空白→生成探索目标（如"用户提到的项目 X 是什么"）
- **能力提升驱动**：识别自身能力不足→生成学习目标（如"学习用户常用的工具 Y"）
- **价值对齐**：目标必须与用户长期利益一致，通过反馈强化学习调整

**防止目标失控的约束**：
1. 目标必须通过"用户价值函数"评分，低于阈值直接丢弃
2. 高风险目标（涉及外部操作）需用户批准
3. 目标生成频率限制：每小时最多 N 个新目标

---

### 2.2 Volitional Agency（意志性主体）

**定义**：Agent 具备"deliberation"（深思）能力，不是刺激-反应机器。

**决策层次**：
```
Level 1: 反射式响应（Fast Path）
  ↓ 用户直接问问题 → 立即回答
  
Level 2: 情境评估（Context Check）
  ↓ 环境触发 → 评估是否需要介入
  
Level 3: 深度思考（Deliberation）
  ↓ 复杂决策 → 模拟多个方案 → 选择最佳
```

**实现算法**：多因素加权决策树
```python
def should_intervene(context):
    urgency = compute_urgency(context)      # 0-1, 时间敏感性
    relevance = compute_relevance(context)  # 0-1, 与用户目标相关性
    user_state = get_user_state()           # busy/free/away
    
    # 加权评分
    score = (
        0.4 * urgency +
        0.3 * relevance +
        0.2 * (1 if user_state == 'free' else 0) +
        0.1 * novelty(context)
    )
    
    # 自适应阈值（根据历史反馈调整）
    threshold = get_adaptive_threshold()
    return score > threshold
```

**关键点**：
- 阈值不是固定的，通过用户反馈（主动关闭通知、忽略消息）动态调整
- 记录每次介入的结果（用户是否响应），用于强化学习

### 2.3 Self-Evolving Framework（自演化框架）

**四层进化目标**：

#### 层次 1：Prompt 进化
- **现状**：系统提示词固定在代码中
- **进化方向**：根据对话效果自动调整 prompt 片段
- **算法**：A/B 测试 + 多臂老虎机（Multi-Armed Bandit）

```typescript
// Prompt 候选池
const promptVariants = {
  greeting: [
    "你好，我是 Lumii",
    "Hi，有什么可以帮你的？",
    "在的，说吧"
  ],
  // ...其他片段
}

// 选择策略：ε-greedy
function selectPromptVariant(fragmentKey: string): string {
  if (Math.random() < epsilon) {
    // 探索：随机选择
    return randomChoice(promptVariants[fragmentKey])
  } else {
    // 利用：选择历史效果最好的
    return getBestPerforming(fragmentKey)
  }
}

// 效果评估
function recordOutcome(fragmentKey: string, variant: string, outcome: Feedback) {
  // outcome: { userSatisfaction: 0-1, responseTime: ms, ... }
  updatePerformanceStats(fragmentKey, variant, outcome)
}
```

#### 层次 2：记忆策略进化
- **现状**：固定的 BM25 + importance 加权检索
- **进化方向**：学习"哪些记忆在哪种情境下有用"
- **算法**：Context-Aware 记忆排序学习

```typescript
// 特征向量
interface MemoryFeatures {
  bm25Score: number
  recency: number
  importance: number
  categoryMatch: boolean
  previousUseCount: number
  contextEmbeddingSimilarity: number  // 当前对话 embedding 相似度
}

// 排序模型（可用简单线性模型或 LightGBM）
function rankMemories(query: string, context: ConversationContext): Memory[] {
  const candidates = searchMemories(query)
  
  // 为每条记忆提取特征
  const scored = candidates.map(mem => ({
    memory: mem,
    features: extractFeatures(mem, query, context),
    score: rankingModel.predict(features)
  }))
  
  return scored.sort((a, b) => b.score - a.score)
}

// 反馈学习
function learnFromUsage(memory: Memory, wasUseful: boolean) {
  // wasUseful 通过隐式信号判断：
  // - LLM 在回答中引用了该记忆 → useful
  // - 记忆被注入但 LLM 未引用 → not useful
  rankingModel.update(memory.features, wasUseful ? 1 : 0)
}
```

#### 层次 3：技能自动生成
- **触发条件**：发现能力缺口（用户请求无法满足 or 频繁失败的任务）
- **流程**：
  1. 检测缺口：工具调用失败 3 次 → 标记为能力缺口
  2. 生成草稿：调用 LLM 生成技能代码 + SKILL.md
  3. 验证：在沙箱中测试生成的技能
  4. 用户确认：弹出"我发现你经常需要 X，我生成了一个技能，要安装吗？"
  5. 持续优化：根据使用反馈迭代技能代码

```typescript
// 能力缺口检测
interface CapabilityGap {
  taskPattern: string        // "解析 .yaml 配置文件"
  failureCount: number
  lastAttempt: Date
  userFrustrationSignal: number  // 0-1，根据重试次数、用户负面反馈计算
}

async function detectAndFillGap(gap: CapabilityGap) {
  if (gap.failureCount < 3) return
  
  // 生成技能
  const skillDraft = await llm.generate({
    prompt: `用户经常需要"${gap.taskPattern}"，但现有工具无法完成。
    请生成一个技能，包含：
    1. SKILL.md（描述、用法、参数）
    2. 实现代码（TypeScript/Python/Shell）
    3. 测试用例
    
    已有工具：${listExistingTools()}
    用户历史操作：${gap.context}`
  })
  
  // 沙箱验证
  const testResult = await runInSandbox(skillDraft)
  if (!testResult.success) {
    // 重新生成或放弃
    return
  }
  
  // 请求用户确认
  const approved = await askUser({
    title: "发现能力缺口",
    message: `我注意到你经常需要"${gap.taskPattern}"，已生成技能草稿。要安装吗？`,
    preview: skillDraft.SKILL_MD
  })
  
  if (approved) {
    installSkill(skillDraft)
    trackSkillPerformance(skillDraft.id)
  }
}
```

#### 层次 4：工具选择策略进化
- **现状**：工具选择由 LLM 决定，无历史学习
- **进化方向**：记录工具使用成功率，优先推荐高成功率工具
- **算法**：Thompson Sampling（贝叶斯在线学习）

```typescript
// 工具性能跟踪
interface ToolStats {
  toolName: string
  successCount: number
  failureCount: number
  avgExecutionTime: number
  contextSuccessRate: Map<string, number>  // 不同情境下的成功率
}

// 工具推荐
function recommendTools(task: string, context: Context): string[] {
  const candidates = matchToolsByDescription(task)
  
  // Thompson Sampling：从每个工具的成功率分布中采样
  const sampled = candidates.map(tool => ({
    tool,
    sampledSuccessRate: betaSample(
      tool.stats.successCount + 1,
      tool.stats.failureCount + 1
    )
  }))
  
  // 返回采样成功率最高的 Top-K
  return sampled
    .sort((a, b) => b.sampledSuccessRate - a.sampledSuccessRate)
    .slice(0, 5)
    .map(x => x.tool.name)
}

// 贝叶斯更新
function updateToolStats(toolName: string, success: boolean) {
  if (success) {
    toolStats[toolName].successCount++
  } else {
    toolStats[toolName].failureCount++
  }
}
```

### 2.4 Personality Evolution（人格进化）

**理论模型**：Big Five 人格模型（五因素）
- **Openness**（开放性）：愿意尝试新工具、新方法
- **Conscientiousness**（尽责性）：任务完成的严格程度
- **Extraversion**（外向性）：主动沟通的频率
- **Agreeableness**（宜人性）：对用户请求的配合度
- **Neuroticism**（神经质）：对失败的敏感度

**数学模型**：
```python
# 人格特质向量（每个维度 0-1）
Personality = {
  'O': 0.7,  # 较高开放性
  'C': 0.8,  # 高尽责性
  'E': 0.4,  # 中等外向性
  'A': 0.9,  # 高宜人性
  'N': 0.3   # 低神经质
}

# 人格更新公式（指数移动平均）
def update_personality(trait: str, event_impact: float, alpha=0.05):
    """
    trait: 'O'/'C'/'E'/'A'/'N'
    event_impact: -1 到 +1，正值增强特质，负值减弱
    alpha: 学习率，越大人格变化越快
    """
    old_value = Personality[trait]
    # 将 event_impact 映射到 [0, 1]
    target = (event_impact + 1) / 2
    # EMA 更新
    Personality[trait] = (1 - alpha) * old_value + alpha * target
    # 边界约束
    Personality[trait] = max(0, min(1, Personality[trait]))

# 事件影响计算示例
def compute_event_impact(event: Event) -> dict:
    impacts = {}
    
    if event.type == 'user_explores_new_feature':
        impacts['O'] = +0.3  # 增强开放性
    
    if event.type == 'task_failed':
        impacts['C'] = -0.2  # 降低尽责性（反思是否过于严格）
        impacts['N'] = +0.4  # 增加神经质（对失败更敏感）
    
    if event.type == 'user_ignored_proactive_message':
        impacts['E'] = -0.5  # 降低外向性（减少主动沟通）
    
    if event.type == 'user_praised_response':
        impacts['A'] = +0.2  # 增强宜人性
        impacts['N'] = -0.3  # 降低神经质（增强自信）
    
    return impacts

# 人格到行为的映射
def personality_to_behavior(personality: dict) -> dict:
    return {
        'proactive_frequency': personality['E'] * 10,  # 每天主动沟通次数
        'exploration_rate': personality['O'] * 0.3,    # ε-greedy 的 ε 值
        'task_quality_threshold': personality['C'],    # 任务完成质量阈值
        'flexibility': 1 - personality['C'],           # 灵活性（与尽责性负相关）
        'error_tolerance': 1 - personality['N']        # 对错误的容忍度
    }
```

**关键设计**：
1. **人格稳定性**：`alpha` 设置为 0.05，确保人格不会因单次事件剧变
2. **边界约束**：人格值始终在 [0, 1]，防止极端化
3. **多事件累积**：单个事件影响小，但长期一致的反馈会显著改变人格
4. **可逆性**：如果用户行为模式改变，人格会相应调整回来

**用户可见行为示例**：
- **高开放性 + 低尽责性**：愿意尝试实验性方案，但可能不够严谨
- **低外向性 + 高宜人性**：不主动打扰，但一旦用户询问会非常配合
- **高神经质**：失败后会主动道歉、解释原因、提出补救方案

## 三、架构设计原则

### 3.1 分层解耦

```
Meta-Cognition Layer（元认知层）
  ↓ 自我评估、反思
Goal Generation Layer（目标生成层）
  ↓ 内在驱动目标
Evolution Layer（进化层）
  ↓ Prompt/Memory/Skill/Tool 优化
Execution Layer（执行层）
  ↓ 现有 Agent 运行时
```

**设计理由**：
- 元认知与执行分离：避免执行过程中的自我怀疑导致死循环
- 进化与运行分离：进化是低频后台任务，不阻塞正常对话
- 目标与计划分离：目标是"what"，计划是"how"

### 3.2 渐进演化（而非激进重构）

**原则**：复用现有基础设施，增量添加自主能力

**实施路径**：
1. **P0（MVP）**：元认知 + 简单内在目标生成
2. **P1**：人格进化 + Prompt A/B 测试
3. **P2**：技能自动生成 + 记忆策略学习
4. **P3**：多 Agent 自组织协作

### 3.3 安全约束

1. **沙箱隔离**：所有自生成代码必须在沙箱中验证
2. **用户批准**：高风险操作（安装技能、修改系统设置）需确认
3. **紧急停止**：用户可随时暂停自主行为
4. **审计日志**：所有自主决策记录到 `~/.lumii/logs/autonomous-decisions.log`
5. **性能限制**：自主任务占用 CPU/内存不超过阈值

## 五、防止失控的机制

### 5.1 目标合法性检查

```typescript
function isGoalLegitimate(goal: IntrinsicGoal): boolean {
  // 1. 必须与用户价值对齐
  if (goal.userValueScore < 0.5) return false
  
  // 2. 不能是无限循环目标（如"不断生成新目标"）
  if (isRecursive(goal)) return false
  
  // 3. 不能违反安全约束
  if (goal.requiresExternalAction && !goal.userApproved) return false
  
  // 4. 不能过于频繁（防止骚扰）
  if (recentGoalCount > MAX_GOALS_PER_HOUR) return false
  
  return true
}
```

### 5.3 用户反馈闭环

```typescript
// 隐式反馈
interface ImplicitFeedback {
  messageIgnored: boolean      // 用户未回复主动消息
  taskInterrupted: boolean     // 用户中断任务
  responseTime: number         // 用户响应延迟（过长可能表示不感兴趣）
}

// 显式反馈
interface ExplicitFeedback {
  thumbsUp: boolean
  thumbsDown: boolean
  reportAsSpam: boolean
}

// 综合评分
function computeFeedbackScore(implicit: ImplicitFeedback, explicit: ExplicitFeedback): number {
  if (explicit.reportAsSpam) return -1.0
  if (explicit.thumbsDown) return -0.5
  if (explicit.thumbsUp) return +1.0
  
  // 隐式信号
  let score = 0
  if (implicit.messageIgnored) score -= 0.3
  if (implicit.taskInterrupted) score -= 0.4
  if (implicit.responseTime > 600000) score -= 0.2  // 超过 10 分钟
  
  return Math.max(-1, Math.min(1, score))
}
```

## 六、可行性分析

### 6.1 技术可行性

| 能力 | 现有基础 | 缺口 | 实施难度 |
|------|---------|------|---------|
| 定时自主任务 | `ProactivityScheduler` 已支持 | 决策逻辑 | 🟢 低 |
| 记忆存储 | SQLite + 完整记忆系统 | 新增表/字段 | 🟢 低 |
| LLM 调用 | Direct-Stream 成熟 | 无 | 🟢 低 |
| 代码生成 | 技能生成已有原型 | 沙箱验证增强 | 🟡 中 |
| 人格建模 | 无 | 需从零实现 | 🟡 中 |
| 在线学习 | 无 | 需引入轻量 ML（如 LightGBM） | 🔴 高 |

### 6.2 性能可行性

**资源占用预估**（24 小时运行）：
- **CPU**：后台评估任务 < 5%
- **内存**：新增数据结构 < 50MB
- **磁盘**：审计日志 < 10MB/天
- **LLM Token**：自主目标生成 ~1000 tokens/天，成本 < $0.01

**对用户体验的影响**：
- 正常对话延迟：+0ms（自主任务异步执行）
- 主动打扰频率：可配置，默认 2-3 次/天
- 学习周期：2-4 周达到稳定状态

### 6.3 风险可控性

| 风险 | 缓解措施 | 残留风险 |
|------|---------|---------|
| 生成恶意代码 | 沙箱 + 代码审查 + 用户确认 | 🟢 低 |
| 骚扰用户 | 频率限制 + 反馈学习 | 🟡 中 |
| 人格崩溃 | 人格边界约束 + 慢速更新 | 🟢 低 |
| 进化失控 | 每层进化上限 + 紧急停止 | 🟢 低 |
| 性能劣化 | 进化前后 A/B 对比 + 自动回滚 | 🟡 中 |
