## 一、MVP 范围定义

### 1.1 P0 功能（必须实现）

基于"渐进演化"原则，MVP 专注于验证核心假设，避免全面铺开：

```typescript
interface MVPScope {
  // 元认知层（简化版）
  metaCognition: {
    satisfactionScoring: true      // 满意度评分
    capabilityTracking: 'manual'   // 手动记录能力边界（暂不自动检测）
    reflectionTrigger: 'scheduled' // 仅定时反思（每天 23:00）
  }
  
  // 目标生成层（受限版）
  goalGeneration: {
    types: ['learning', 'proactive-message']  // 仅支持学习目标和主动消息
    userApproval: 'always'                    // 所有目标需用户批准
    maxGoalsPerDay: 3
  }
  
  // 进化层（单层优先）
  evolution: {
    prompt: true       // P0：Prompt A/B 测试
    memory: false      // P1
    skill: false       // P2
    tool: false        // P1
  }
  
  // 人格系统（观察模式）
  personality: {
    tracking: true     // 记录人格事件
    evolution: false   // P0 不更新人格值，仅积累数据
    display: true      // 在仪表板展示当前人格状态
  }
}
```

**P0 验证目标**：
1. Agent 能否准确评估自身表现？
2. 生成的目标是否对用户有价值？
3. Prompt 进化能否改善用户体验？
4. 用户是否接受主动行为？

---

### 1.2 P1/P2 功能（后续迭代）

| 优先级 | 功能模块 | 触发条件 |
|-------|---------|---------|
| **P1** | 工具选择策略进化 | P0 运行 2 周后，有足够工具使用数据 |
| **P1** | 人格自动更新 | P0 积累 > 100 个人格事件 |
| **P2** | 记忆策略学习 | P1 完成后，内存占用 < 阈值 |
| **P2** | 技能自动生成 | P1 完成后，有明确能力缺口 |
| **P3** | 多层协同优化 | P2 完成后，四层独立进化数据充足 |

## 二、数据库设计（增量 Schema）

### 2.1 新增表（P0）

```sql
-- 满意度评分历史（元认知）
CREATE TABLE autonomous_satisfaction_scores (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  window_hours INTEGER NOT NULL,  -- 时间窗口：2/24/168 小时
  score REAL NOT NULL,             -- 0-1
  
  -- 原始指标
  tasks_completed INTEGER,
  tasks_failed INTEGER,
  positive_signals INTEGER,
  negative_signals INTEGER,
  tool_success_rate REAL,
  
  trend TEXT  -- 'improving' | 'stable' | 'declining'
);

-- 自主目标（内在动机）
CREATE TABLE autonomous_goals (
  id TEXT PRIMARY KEY,  -- UUID
  type TEXT NOT NULL,   -- 'learning' | 'proactive-message' | 'skill-generation'
  description TEXT NOT NULL,
  
  -- 评分
  user_value_score REAL NOT NULL,
  feasibility REAL NOT NULL,
  urgency REAL NOT NULL,
  
  -- 状态
  status TEXT DEFAULT 'pending',  -- 'pending' | 'approved' | 'rejected' | 'completed'
  created_at INTEGER NOT NULL,
  approved_at INTEGER,
  completed_at INTEGER,
  
  -- 结果
  outcome_json TEXT  -- 执行结果的 JSON
);

-- Prompt 进化（A/B 测试）
CREATE TABLE prompt_evolution_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  fragment_key TEXT NOT NULL,  -- 'greeting' | 'task-approach' | 'error-handling'
  variant_id TEXT NOT NULL,
  
  -- 效果指标
  user_satisfaction REAL,
  response_time INTEGER,
  task_success BOOLEAN,
  
  -- 上下文
  context_type TEXT  -- 'casual' | 'technical' | 'urgent'
);

-- Prompt 候选池
CREATE TABLE prompt_variants (
  id TEXT PRIMARY KEY,
  fragment_key TEXT NOT NULL,
  content TEXT NOT NULL,
  
  -- 统计
  usage_count INTEGER DEFAULT 0,
  success_count INTEGER DEFAULT 0,
  avg_satisfaction REAL DEFAULT 0.5,
  
  created_at INTEGER NOT NULL,
  last_used INTEGER
);

-- 人格事件记录（P0 仅记录，不更新）
CREATE TABLE personality_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  event_type TEXT NOT NULL,  -- 'USER_EXPLORES_NEW_TOOL' | 'TASK_FAILED' 等
  
  -- 影响（暂不使用，为 P1 准备）
  openness_impact REAL,
  conscientiousness_impact REAL,
  extraversion_impact REAL,
  agreeableness_impact REAL,
  neuroticism_impact REAL,
  
  context_json TEXT  -- 事件上下文
);

-- 人格状态快照（P0 手动初始化，P1 自动更新）
CREATE TABLE personality_state (
  id INTEGER PRIMARY KEY CHECK (id = 1),  -- 单行表
  openness REAL DEFAULT 0.7,
  conscientiousness REAL DEFAULT 0.8,
  extraversion REAL DEFAULT 0.4,
  agreeableness REAL DEFAULT 0.9,
  neuroticism REAL DEFAULT 0.3,
  last_updated INTEGER NOT NULL
);

CREATE INDEX idx_satisfaction_timestamp ON autonomous_satisfaction_scores(timestamp);
CREATE INDEX idx_goals_status ON autonomous_goals(status, created_at);
CREATE INDEX idx_prompt_fragment ON prompt_evolution_history(fragment_key, timestamp);
CREATE INDEX idx_personality_events_type ON personality_events(event_type, timestamp);
```

## 六、风险与缓解

### 6.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 满意度评分不准确 | 高 | 中 | 初期允许用户手动调整权重 |
| Prompt 变体差异不显著 | 中 | 低 | 准备 10+ 变体，拉大差异 |
| 目标生成质量差 | 中 | 高 | P0 强制用户批准，积累高质量样本 |
| 性能超预算 | 低 | 中 | 增加性能监控 + 降级机制 |

### 6.2 产品风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 用户不接受自主行为 | 中 | 高 | 默认关闭，opt-in 开启 |
| 生成目标骚扰用户 | 中 | 高 | 严格频率限制 + 批准机制 |
| 进化方向偏离预期 | 低 | 高 | 每周人工审查进化数据 |

## 七、成功指标（P0 验证）

### 7.1 量化指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 满意度评分准确性 | 用户主观评分与算法评分相关性 > 0.7 | 每周请用户手动打分对比 |
| 目标批准率 | > 60% | 统计 `approved / (approved + rejected)` |
| Prompt 进化效果 | 最优变体满意度 > 基线 +10% | A/B 测试对比 |
| 系统稳定性 | 连续运行 7 天无崩溃 | 监控日志 |
| 性能占用 | CPU < 5%, 内存 < 50MB | 资源监控 |

### 7.2 定性指标

- 用户访谈：是否感受到 Agent"在进化"？
- 用户反馈：生成的目标是否有价值？
- 开发者反馈：代码可维护性如何？

## 八、P0 → P1 决策标准

满足以下条件进入 P1：

1. **P0 运行稳定**：连续 14 天无重大 Bug
2. **数据积累充足**：
   - Prompt 进化数据 > 200 条
   - 人格事件 > 100 个
   - 工具使用记录 > 500 次
3. **用户满意度**：试用用户满意度 > 7/10
4. **核心假设验证**：
   - 满意度评分与用户感受一致
   - Prompt 进化确实改善体验
   - 用户接受自主目标生成

**不满足则**：
- 优化 P0 算法
- 重新设计满意度评分
- 调整目标生成策略

| 模块 | 关键测试用例 | 目标覆盖率 |
|------|-------------|-----------|
| MetaCognitionEngine | 满意度评分公式 | > 90% |
| IntrinsicGoalGenerator | 目标合法性检查 | > 85% |
| PromptEvolution | ε-greedy 选择算法 | > 90% |
| PersonalityTracker | 事件影响计算 | > 80% |

### 10.2 集成测试场景

1. **完整反思流程**：
   - 模拟 7 天对话数据
   - 触发定时反思
   - 验证生成目标质量

2. **Prompt 进化流程**：
   - 模拟 100 次对话
   - 验证变体选择分布
   - 验证统计数据准确性

3. **目标批准流程**：
   - 生成目标 → 推送通知 → 用户批准 → 执行目标
   - 验证状态流转

### 10.3 用户验收测试

| 场景 | 操作步骤 | 预期结果 |
|------|---------|---------|
