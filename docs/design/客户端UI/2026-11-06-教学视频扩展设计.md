# 教学视频生成扩展（Code2Video 范式）

> 2026-11-06 · `com.lumii.code2video` · 官方可选扩展

## 一、它是什么

给一个知识点，产出一条**教学视频 MP4**：大纲 → 分镜 → 逐节画面 → 合成。

方法论移植自 [showlab/Code2Video](https://github.com/showlab/Code2Video)（NeurIPS 2025 DL4C Workshop），
保留了它的三段式（Planner 出大纲与分镜、Coder 出可执行画面），**没有沿用 Manim 渲染器**。

## 二、为什么是插件而不是流水线

流水线引擎（`plugins/builtin/pipeline/runner.ts`）**只有顺序执行 + 向后引用，没有循环/条件/并发**。
而这个能力天生需要：

- 模型输出不合格时重试（JSON 解析失败 / 画面 HTML 不完整）
- 逐节渲染失败时跳过继续，而不是整条失败

硬塞进流水线只能砍掉重试，那就不是这个能力了。仓库自己的判据也指向这个方向：

> 「这次要的交付物，和这条流水线上次跑出来的，形状是不是一样的？」
> 一样 → 流水线；不一样 → 技能/自己做

——见 `packages/agent-runtime/src/prompt/sections/misc-sections.ts:418-430`

## 三、为什么不用 Manim

Manim 需要 Python + OpenGL 栈（moderngl / pyglet / pycairo）。两条实测约束：

1. 本应用的嵌入式 Python **没有 `venv` 模块**（`~/.lumii/runtimes/python-embed/python.exe -m venv` → `No module named venv`）
2. Manim 在 Windows 无 GPU 机器上的安装失败率是社区头号问题

改用 **HTML 渲染 + Electron 隐藏窗口逐帧截图 + ffmpeg 合成**：

| 环节 | 实现 | 新依赖 |
|---|---|---|
| 画面 | `BrowserWindow`（`useContentSize:true`）+ `capturePage()` | 无（应用本身就是 Chromium） |
| 截图驱动 | `window.__seek(ms)` 时间轴，逐帧 seek | 无 |
| 编码 | `runFfmpeg`（包内 `@ffmpeg-installer` 回退系统 PATH） | 无 |

代价：**没有 Manim 那种「公式逐项变形」的排版能力**。公式走 KaTeX 的 MathML 输出
（`katex.renderToString(tex, {output:'mathml'})`），Chromium 原生渲染，不下载字体、
不起 LaTeX 进程；复杂排版用内置的 13 种元素近似。这是有意识的取舍。

## 四、流程与落点

```
topic
 ├─ 0. 模板匹配 → 内置 15 套结构骨架（keyword → 模型选 → 兜底 explain）
 ├─ 1. 大纲  → outline.json      (LLM，重试)
 ├─ 2. 分镜  → storyboard.json   (LLM，重试；每节对齐 lectureLines/animations)
 ├─ 3. 画面  → section_N.html    (LLM 出画面 JSON，本地拼 HTML；独立重试)
 ├─ 4. 配音  → audio/<节>/       (逐句 TTS，量真实时长)
 ├─ 5. 渲染  → section_N.mp4     (逐帧 capturePage → ffmpeg，并发自适应)
 └─ 6. 合成  → teaching-video.mp4 (字幕烧录 + 混音 + loudnorm)
```

**顺序有意如此：先有声音，动画才跟着声音走**。若先算秒数再往里塞语音，
「3 秒的句子」和「15 秒的句子」会被切成一样长，听着就是背书。
配音与字幕共用同一份 `Cue[]`——两套时间轴是对不齐的根源。

产物根目录：`<workspace>/outputs/teaching-video/<安全主题名>-<时间戳>/`

同目录保留 `outline.json` / `storyboard.json` / 各节 HTML，**可以只改某一节重渲**，不用整体重跑。

## 五、与原版的差异

| 方面 | Code2Video | 本实现 |
|---|---|---|
| 渲染 | Manim（Python + OpenGL） | HTML + Electron + ffmpeg |
| LLM | 需自配 Claude/GPT API key | **复用客户端已配的 chat 槽**，零额外配置 |
| Critic | Gemini VLM 看渲染帧给美学建议 | **两层确定性门禁**：布局几何检测 + 抽帧像素检测 |
| 素材 | IconFinder API（需 key） | 不下载外部素材 |
| 并行 | ProcessPoolExecutor(6) | **先串行量首节耗时，再定并发**（1~3 个 worker） |
| 配音 | 无 | **逐句 TTS + 字幕 + loudnorm 统一响度** |
| 模板 | 无 | **15 套结构骨架 + 5 套视觉风格**，先匹配再生成 |
| 画质 | 固定 | **三档**：draft(12fps) / standard(24fps) / high(30fps) |

**Critic 为什么换成确定性判据**：原版用 VLM 每轮一次多模态往返，而它想解决的首要问题是
「元素互相遮挡」——这个问题几何上就能判死，零成本、可复现，失败原因还能直接回灌给模型。

## 六、实测记录（2026-11-06）

真机跑了 5 轮端到端，每一轮都暴露一个真实问题：

| 轮次 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 视频出来了，但右侧只有**重复两遍的文字** | 只跑模板，没接 Coder 阶段 | 加逐节画面生成 |
| 2 | 画面调用 **10/10 次返回空字符串**，耗时 80~120 秒 | 单轮调用输出**一整页 HTML** 时被上游截断；同批次只出 JSON 的 outline/storyboard 4~19 秒正常 | 改为模型只出**画面 JSON**（~200 token/节），HTML 由本地 `buildSceneHtml` 拼 |
| 3 | 1280×720 的窗口截出 **1264×655**，第三个面板被裁掉 | `BrowserWindow` 的 width/height 是**含边框的窗口尺寸** | `useContentSize: true` |
| 4 | 元素**互相压住**（「直角边 b」叠在「4→b」上） | 模型不遵守提示词里的间距约束 | `declutterSteps` 本地自动避让 |
| 5 | ✅ 画面干净、无重叠 | — | — |

另外两处修正在跑通过程中确认：

- `capturePage` 的尺寸可能不是偶数，libx264 会直接 `height not divisible by 2` 失败。
  ffmpeg 侧统一 `scale + pad` 到 1280×720。
- 外部扩展默认导出必须是 `export default { manifest, definition }`，否则加载器报「缺少 definition」。

**最终验证**（第 5 轮）：4~5 节、1280×720、12fps、约 100 秒、200~300KB，
`pnpm --filter ./apps/windows test:all` → 5463 passed。

## 七、已知限制

1. **单轮长输出会返回空**：这是上游 provider 的行为，不是本扩展能修的。所以画面走 JSON、
   HTML 本地拼。**不要**把这条改回「让模型直接吐整页 HTML」。
2. **时长偏差**：`durationMinutes` 是期望值，实际按「总时长 ÷ 节数」且每节有 4 秒下限；
   节数多时会超出。工具结果里的 `durationMs` 是**生成耗时**，不是视频时长。
3. **分辨率固定 1280×720**（`FRAME` 常量）。字幕字号按这个尺寸实测换算
   （libass 的 `FontSize` 不是 CSS px，实测比例约 0.39），改分辨率要重测。
4. **同帧元素仍可能挤**：`declutterSteps` 会本地挪开，实在放不下才接受重叠并出告警。
   没有强制网格化（那会把画面做呆板）。
5. **「无配音」降级**：语音插件被关掉或未就绪时自动出无声视频，不报错。

## 八、接线清单（新增本扩展时改了什么）

| 文件 | 变更 |
|---|---|
| `src/plugins/external-src/code2video/**` | 新增（`index.ts` / `tool-config.ts` / `impl/*`） |
| `scripts/build-official-extensions.mjs` | `ENTRIES` 加一行 |
| `src/main/agent-runtime/bridge.ts` | `createPipelineExecutor()` 加 `callLLM` / `ffmpeg` 两个注入点；`registerTool` 加可选 `factory` 参数 |
| `scripts/wiring-baseline.json` | ⑤ 死代码候选登记（官方扩展不从头入口静态可达） |

**`registerTool` 为什么加 `factory` 参数**：外部扩展被 esbuild 独立打包，如果插件为了注册
一个工具去 import `@mtbot/agent-runtime` 的 `createMtBotTool`，会把整包（openai / anthropic-sdk /
pi-ai / google-auth）打进来——实测 440KB → **5.2MB**。`factory` 让插件传入一份等价的最小构造器。

## 九、后续

**已完成的**（原「后续」三项里的两项）：配音+字幕已落地（`gates/narrate.ts`，
逐句 TTS → 真实时长 → 动画跟语音走 → libass 烧字幕 → loudnorm）；
Manim 后端经论证不做（见 §三），VLM Critic 也不做（见 §五「Critic 为什么换成确定性判据」）。

**还没做的**：

- **元素挤在一起时的兜底**：已有的 `declutterSteps` 会本地按「原行 → 下一行」逐格挪开，
  挪不下才接受重叠（少一个元素比整块画面崩掉更糟）。仍缺的是**强制网格化**——
  先给每个元素分配不相交的格子再渲染，代价是画面变呆板。
- **分辨率可配**：`FRAME` 硬编码 1280×720；一旦放开，字幕字号那个 0.39 的经验比例
  要按新分辨率重测（它随字体与分辨率变，不能按比例推）。
