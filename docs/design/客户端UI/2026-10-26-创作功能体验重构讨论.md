# 创作类功能体验重构（讨论稿）

**日期：** 2026-10-26
**状态：** 讨论中，未批准
**范围：** 写作 / 图片生成 / 视频生成 / PPT / 技能市场；以及全部复杂功能的入口引导
**参照：** 豆包桌面端（Chromium 壳 + 自研 pak，逆向笔记见 `reverse/doubao/DESKTOP-UI-REVERSE.md`）

---

## 0. 一句话结论

**把「对话」从主舞台降级成执行日志，把「产物」升级成主舞台。**

对话里只保留三样东西：**结果**（一行/一卡）、**对结果的操作**（一行）、**一句话过程**（一行，可展开）。
其余（工具名、参数、文件路径、思考全文）默认不进视野。

## 1. 现状盘点（从代码读出来的，不是印象）

### 1.1 已有的好东西（别推翻）

| 能力 | 现状 |
|---|---|
| 过程折叠 | `ActivityFold` 已经把「思考 + 工具 + 中间文本」折成一行，流式中显示进度（`任务 3/8` / `5/12 步`）＋最多 3 行迷你活动流，完成后收成摘要 + 耗时 |
| 工具分组 | `ToolBatchGroup` 把同轮连续工具折成「读取 2 个文件 · 搜索 3 次」 |
| 长任务 | `BackgroundTaskCard`（有 `progress` 数字）、`TodoPanel`（TodoWrite 进度）、`TaskCompleteCard`（收口摘要） |
| 右侧工作台 | `WorkspaceWorkbench`：文件 / 变更 / 版本 / 文档 四 Tab，可拖宽、可全屏 |
| 产物网格 | `WorkspaceChangesPanel` 已有「产物」模式：媒体文件按目录分批的网格 |
| 媒体预览 | `FilePreviewModal` 支持图片/音视频；`ImageLightbox` 统一点击放大 |
| 技能页 | `SkillsPage` 四 Tab（我的/商店/工具/MCP）+ `SkillStoreView` |

### 1.2 三个结构性问题是根因

**问题 A：结果没有被对象化。**
现在「结果」是三种东西的混合：markdown 里的图片、`ToolCallCard` 里嗅探出来的内联图、`fileChanges` 里的文件条目。同一份产出有 5 个呈现处：

```
① ToolCallCard 内联图（只对 image_generate / 截图这种按工具名嗅探）
② Markdown 内联图（模型自己写 ![](...)）
③ TurnFileChangesCard（本轮净变更，纯文件名）
④ Workbench「变更」列表（按轮/按目录）
⑤ Workbench「产物」网格（缩略图）
```

用户问「我刚生成的东西在哪」，答案取决于他记得哪个入口。**而视频根本没有 ①**：`ToolCallCard` 只对 `screen_record_stop` 输出文件 chip，H3/ComfyUI 产出的 mp4 在对话里是不可见的。

**问题 B：过程按「工具」组织，不按「阶段」组织。**
`ActivityFold` 的进度是「步」或「任务」，不是「阶段」。用户看到的仍是 `exec`、`read`、`mcp__comfyui__enqueue_workflow` 这类词。豆包那边所有创作过程都被翻译成用户语言（大纲 → 模板 → 生成、排队 → 关键帧 → 渲染 → 编码）。

**问题 C：入口面板过载，能力不可见。**
- 输入区：`+`、模型、思考开关、推理强度、审批、朗读、工作台、资料库、压缩、帮助、转向、语音、发送 —— 常驻 5 个，条件出现 8 个。
- 顶栏：侧栏、缩放、审批、朗读、工作台、资料库。
- 技能在对话里**不可见**：只能从 `+` → 「技能」子面板 → 「管理」进 `SkillsPage`；消息里不知道用了哪个技能、它能产出什么。
- 空态：84 个场景 / 13 个分类，随机抽 6 个展示。新用户看到的是「今天股市如何」和「写个爬虫」并列，没有「我想做张图」这条路。

## 2. 一条主轴：信息四层

| 层 | 内容 | 默认状态 | 谁看 |
|---|---|---|---|
| **L0 结果** | 结果卡（封面 + 标题 + 规格 + 一行动作） | 可见 | 所有人 |
| **L1 可调** | 对结果的操作：变体 / 局部改 / 参数 / 导出 | 可见（结果卡内） | 所有人 |
| **L2 过程** | 一行「做了什么 · 多久」，可展开成阶段进度 | 折叠 | 想确认的人 |
| **L3 调试** | 原始工具入参/出参、日志、原始思考 | 两次点击后才出现（展开过程 → 点某个工具） | 开发者 |

**规则**：一屏最多 L0 + L1 一行 + L2 一行；任何 L3 内容不得在默认状态下出现。

## 3. 核心改造：结果卡（Artifact v1）

### 3.1 契约（新增，落在已有通道上）

工具结果已经有 `details` 通道（`tool-runner.ts` 里 `details: { background, taskId }` 就是先例），直接扩展：

```ts
// packages/agent-runtime: ToolResult.details
details?: {
  artifacts?: Array<{
    kind: 'image' | 'image-set' | 'video' | 'audio' | 'doc' | 'slides' | 'sheet' | 'site' | 'file'
    path: string                    // 工作区相对路径
    title?: string
    cover?: string                  // 缩略图/首帧；缺省由前端按 kind 生成
    meta?: { ratio?, durationSec?, pages?, words?, model?, params? }
  }>
}
```

**为什么这么做**：现在 UI 是按工具名嗅探（`lname === 'image_generate'`、`screen_record_stop`）—— 84 个技能、每条 pipeline 都能产出新文件类型，逐工具打补丁不可持续。让**产出方声明**，UI 只认 `kind`。

**兼容**：没有 `artifacts` 的工具保持现状（文件 chip / 折叠过程），改造成本可控。

### 3.2 渲染

```
┌─ 结果卡 ──────────────────────────────────┐
│  [封面/首帧/首屏]   标题（可编辑？）        │
│                     规格：4096×4096 · Seedream 5.0 │
│                     一句话说明（来自 task_complete）│
│  ───────────────────────────────────────  │
│  [预览] [变体] [微调] [导出] [定位文件]     │
└───────────────────────────────────────────┘
```

- 同一轮多张图 → 一个 `image-set` 卡（网格 2×2，右上角「4 张」角标），不刷屏。
- 结果卡**永远在折叠块之外**（和 `TaskCompleteCard` 现在的做法一致：`pinned` 声明式拣出折叠区）。
- 结果卡与工作台「产物」网格共用同一个数据源（`fileChanges` + `artifacts`），点卡 = 定位到网格。

### 3.3 结果的动作（L1）

| 动作 | 含义 | 依赖 |
|---|---|---|
| 预览 | 全屏 / 内嵌播放 | 已有 |
| 变体 | 同 prompt 换 seed，或同 seed 改 prompt（两个按钮） | 需要工具接受 seed/参数回显 |
| 微调 | 回填参数 chip（比例/风格/模型），改完「重跑」 | 需要 `details.meta.params` |
| 局部改 | 选区（图）/ 单页（PPT）/ 单段（文） | P2，需要技能契约支持 |
| 导出 | 原格式 / 打包 zip / 复制到… | 部分已有 |
| 定位 | 在工作台里高亮该文件 | 已有（`onLocateFile`） |

## 4. 五个模块各自的改法

### 4.1 写作

**现状**：一条长 markdown，或落到 `.md/.docx`；改一篇只能整篇重跑。`docx` 技能产出的文档在对话里只有文件名。

**改法**

1. 结果卡 = 文档卡：标题 + 首屏缩略（取正文前 300 字渲染）+ 字数 + 章节数 + 「大纲 / 全文」两个视图切换（不打开文件也能改结构）。
2. 段落级动作：选中段落浮出 4 个动作（改写 / 扩写 / 精简 / 换语气），走**增量重写**（只重写该段），不是整篇重跑。
3. 长文分步：结果卡内显示「已完成 3/7 章」，点某章可单独重写；对应现在的「分步写作」开关（如果已有）。
4. 过程行：「写作 · 参考 3 篇 · 3 分 12 秒」。

### 4.2 图片生成

**现状**：`ToolCallCard` 里嗅探 `image_generate` 显示一张小图；参数（比例/风格/模型）只以文字形式进了 prompt。

**改法**

1. 结果卡 = 图片网格卡（一批 4 张），hover 出「做同款 / 变体 / 放大 / 去背景 / 导出」。
2. 参数回显为**可点 chip**（比例 1:1 / 风格 水彩 / 模型 Seedream 5.0），点开即改并「重跑」——不让用户回去改 prompt 文本。
3. 「变体」两按钮：**同提示词换个构图**（换 seed）/ **保留构图换风格**（改 prompt，保 seed）。
4. 失败/被拒单独一卡：给「换模型重试」，而不是无脑「重试」。
5. 过程行：「图片生成 · 4 张 · 18 秒」。

### 4.3 视频生成

**现状**：分钟级长任务，但对话里**没有视频**（只有文件 chip 或什么都没有）；进度只有 `BackgroundTaskCard` 的数字。

**改法**

1. 结果卡 = 视频卡（首帧海报 + 时长 + 分辨率）；未完成时**同一位置**显示阶段进度：
   ```
   排队中 → 生成关键帧 → 渲染 → 编码 → 完成
   ```
   当前阶段高亮 + 预计剩余（哪怕只是「约 3 分钟」）。
2. 「后台继续」：用户可以切会话/切页，完成后系统通知，回来时该卡原地变成成品。
3. 失败保留 prompt + 参数，一键重跑；允许「一次出 2 个候选」，减少反复等待。

### 4.4 PPT

**现状**：大纲 → 模板 → 生成 三步全藏在工具调用里；用户既看不到进度阶段，也不知道哪一步能改。`pptx` 技能产出的是 `.pptx` 文件。

**改法**

1. 结果卡 = 幻灯片卡（首页缩略 + 页数 + 模板名）。
2. 未完成时卡内直接给**三步条**：大纲（可编辑）→ 模板（可换）→ 生成（%）。
3. 大纲阶段允许「改标题 / 删页 / 加页」后点「按此大纲生成」——把豆包那个「先出大纲再生成」的正确流程显式化。
4. 生成后单页重做：点某页 → 换版式 / 换图 / 重写要点（P2）。
5. 过程行：「PPT · 12 页 · 2 分 30 秒」。

### 4.5 技能市场

**现状**：`SkillsPage` 四 Tab（我的/商店/工具/MCP）；商店是紧凑表格行（序号 + 图标 + 名称 + 描述 + 评分/下载）；对话里看不到技能。

**改法**

1. **对话内可见**：过程行/结果卡标注「由 xiaohongshu-content-pipeline 完成」，点击进技能详情。
2. **能力页统一**：能做什么（一句话）+ 需要什么输入 + 产出什么（**3 个产出示例缩略图**）+ 一个「试一下」按钮（带预填 prompt，点了直接进对话）。
3. 商店卡片带产出示例缩略图 —— 一张图胜过三行描述；这是豆包商店相比我们最明显的优势（它有卡片视觉，我们是表格）。
4. 安装后立刻给一次「试用」入口，别让用户回到空对话自己想办法。

## 5. 复杂功能怎么引导（三层递进）

功能多不是问题，**没有路径**才是问题。三层，按顺序出现，不要一次性教。

### 第一层：空态按「我要做什么」而不是「有哪些功能」

把 84 个场景收成 4 个意图入口：

```
写点东西   → 文章 / 文案 / 邮件 / 小红书
做张图     → 海报 / 插画 / 修图 / 去背景
做段视频   → 文生视频 / 图生视频 / 剪辑
做个 PPT   → 主题直出 / 大纲先行 / 文档转 PPT
（其余 60+ 场景收进「更多」/ 搜索）
```

点任一入口 → 预填 prompt + 选中对应技能（如果技能体系支持），而不是只往输入框塞一句话。

### 第二层：首次使用某技能时的「能力小卡」

不用弹窗教学、不用引导页。第一次触发某技能时，在输入框上方贴一张 3 行小卡：

```
能做什么：把一段话变成 6 页 PPT
需要什么：主题 + 可选模板
产出：.pptx（可导出/可单页重做）
                              [知道了] [别再提示]
```

关闭后永不再出现（localStorage 记 skill id）。

### 第三层：把「下一步」教在结果上

每个结果卡底部一行建议动作（导出 / 变体 / 继续改 / 用这个再做一个）。用户的技能是**在结果处学会的**，不是在看说明书时学会的。

## 6. 输入区做减法（具体清单）

| 控件 | 现状 | 建议 |
|---|---|---|
| `+`（附件/技能/MCP/Agent/资料库） | 主菜单 4 项 + 4 个子面板 | 保留，但子面板里**技能一栏变成「常用 5 个 + 搜索」**，不再是冷冰冰的开关列表 |
| 模型 | 独立下拉 | 保留 |
| 思考开关 + 推理强度 | 两个控件并排 | 合进模型选择器：每个模型显示「思考 / 不思考」两行，强度作为副选项 |
| 审批（顶栏） | 常驻 | 移到设置；结果卡需要审批时用 `PermissionCard` 就地出现 |
| 压缩 | 常驻（仅超阈值变色） | 仅在 >60% 阈值时出现 |
| 帮助 | 常驻问号 | 收进设置；首次使用走第二层「能力小卡」 |
| 朗读 / 资料库 / 工作台 | 顶栏 3 个图标 | 保留（声音相关是差异化），但工作台图标需要有「有 N 个新产物」角标 |
| 转向（中途插话） | 仅流式 | 保持（正确） |

常驻目标：`+` · 模型 · 发送 = 3 个。

## 7. 分期

### P0（1 周内，纯前端重排，不动 agent）
- 结果卡 v0：`image` / `image-set` / `video` / `doc` / `slides` 五种，先**从现有 `fileChanges` + 工具输出派生**兜底（不依赖新契约）
- 过程行改「阶段语言」：工具名 → 阶段名映射表（写文件→保存、exec→运行、image_generate→出图…）
- 空态改 4 个意图入口
- 视频补内联播放（复用 `FilePreviewModal` 的 blob 逻辑）

### P1（2–3 周）
- `details.artifacts` 契约 + 产出方声明（先接 `image_generate`、`pptx`、视频 pipeline 三条）
- 结果卡动作：变体 / 导出 / 定位
- 视频、PPT 的阶段进度 + 后台继续 + 完成通知
- 技能结果标注 + 能力页（含产出示例）

### P2
- 段落级 / 单页级局部重做（需要技能契约支持）
- 参数 chip 回显与重跑
- 结果卡的可编辑标题、批量导出、分享

## 8. 需要拍板的三件事

1. **结果卡是「新的一层实体」还是「ToolCallCard 的一个变体」？**
   - 选实体：要建 `artifacts` 索引 + 新组件，但能统一 5 个入口（推荐）
   - 选变体：改动小，但「产物」概念仍然散落在工作台
2. **对话和工作台谁是主舞台？**
   - 对话为主：结果卡内嵌大预览，工作台是附属
   - 工作台为主：结果卡只给入口，一键展开右侧（豆包是这条）
   - 我的倾向：**对话为主 + 工作台做「产物」汇总**，因为我们的技能产出类型比豆包杂（文件、代码、文档、宠物素材…），强行把一切都塞进右侧会变成文件管理器
3. **局部重做先做哪个？** 写作段落 / PPT 单页 / 图片变体 —— 三个都需要技能/工具契约支持，建议先做**图片变体**（工具已经在收 prompt+参数，改造最小、感知最强）

## 9. 附：和豆包的关键差异（避免照抄）

| 维度 | 豆包 | Lumii |
|---|---|---|
| 能力来源 | 服务端技能（固定几种：写/图/视频/PPT/播客） | 本地技能生态（84 场景 / 多 pipeline / MCP），种类不封闭 |
| 结果形态 | 云端产物（同一套 artifact） | 本地文件（什么都可能是产物） |
| 过程 | 服务端下发 block，天然结构化 | 工具调用 + 事件流，需要本地翻译成阶段 |
| 可抄 | 结果卡、阶段语言、模板即 prompt、能力小卡 | — |
| **不可抄** | 把所有产物都塞进右侧画布（它们产物形态单一） | 我们的产物要按 kind 分流：媒体走画廊、文档走预览、代码走 diff |
