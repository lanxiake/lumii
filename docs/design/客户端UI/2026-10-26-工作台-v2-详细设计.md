## 0. 设计主张

大多数 Agent 客户端的工作台是「IDE 的残影」：左边对话，右边文件树 + diff；Tab 按**文件类型**分（Files / Changes / Diff / Preview）。它们长得一样，是因为都在复用同一个心智模型：**用户是程序员，工作台是代码审阅器**。

但我们的实测数据说明另一件事（§1）：**用户产出的 69% 是图片**，一次任务平均 17 个文件、最多 1110 个，其中绝大多数是中间产物。对一个做图/做视频/做 PPT 的人来说，「文件树」和「diff」不是他要的东西。

因此 v2 的三条主张：

1. **任务优先于文件。** 默认视图是「这次任务产出了什么」，不是「工作区里有什么」。
2. **成品优先于过程。** 中间文件（切图、分段、normalized、缓存）默认折叠成一行，不占视线。
3. **一个面板，两栏永恒。** 左栏永远是可扫的清单，主区永远是当前选中内容的完整预览；弹窗预览退场。

## 1. 事实基础（本机运行时库实测）

数据来源：`~/.lumii/data/agent-runtime.db`，`messages.content_json` 里 3184 条含 `fileChanges` 的 assistant 消息（只统计 `confidence != unattributed`）。

| 指标 | 数值 |
|---|---|
| 有文件变更的回合 | **1050** |
| 每个回合的平均变更文件数 | **17.3** |
| 单回合最大文件数 | **1110**（一次宠物精灵图流水线：`parts/` 344 + `normalized/` 344 + 数百张 `cut-*.png`） |
| 1–2 个文件的回合 | 754（72%） |
| 6 个以上文件的回合 | 170（16%） |
| 30 个以上的回合 | 77（7%） |
| 有产出的会话 | 396；单会话最多 **4985** 个文件 |
| 扩展名分布 | png **12520**（69%）、md 2184、**lumii-ref 811**、html 620、json 449、py 245、js 144、mp3 131、mp4 42、pdf 53 |

三条直接结论：

1. **「多」是常态，不是边缘情况。** 7% 的回合会产生 30+ 文件；把它们铺平成列表，用户必然迷路。
2. **图片是主产物。** 产物视图必须为图片优化（缩略图、网格、批量），而不是为代码优化（行、diff、路径）。
3. **台账里有噪音。** `.lumii-ref`（wiki 侧车）这类记账文件不该出现在「我产出了什么」里。

## 1.5 参考研究与取舍

看 12 个产品，只保留能解决我们三个真实问题（产物多、要改、要等）的部分。

> **先校正四个时间线**，免得拿已死的产品当竞品：
> - Windsurf 已于 2026-06 更名 **Devin Desktop**，Cascade 2026-07 退役（[FAQ](https://docs.devin.ai/desktop/devin-desktop-faq)）；
> - GitHub Copilot Workspace 2025-05 结束技术预览（[GitHub Next](https://githubnext.com/projects/copilot-workspace/)）；
> - **ChatGPT Canvas 2026-05-28 下线**，能力折回消息流里的 writing/code blocks（[The Verge](https://www.theverge.com/ai-artificial-intelligence/940028/openai-is-sunsetting-chatgpts-canvas-interface)）——这是本设计最重要的一条反面证据；
> - **Claude Artifacts 2026-09-16 分新旧两套**，旧的聊天内 artifact 不再新建（[官方帮助](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)）。

### 1.5.1 创作工具：会话 / 素材库 / 画廊

**Runway**（[Sessions](https://help.runwayml.com/hc/en-us/articles/33545310653203-Generating-with-Sessions)、[Managing assets](https://help.runwayml.com/hc/en-us/articles/4408611980563-Managing-assets)）

| 看到的做法 | 我们的取舍 |
|---|---|
| **Session = 生成场所 + 作品文件夹**，一次迭代一个 Session；输出在右栏按时间顺序追加（旧上、新下） | **抄**：工作台以「任务」为第一层，同目录/同轮归并 |
| Session 列表只显示最近 30 个，全量在 Dashboard → Sessions | **抄**：rail 默认只展示最近若干，旧的在「更早」折叠 |
| Assets 库与 Session 分离：Recents / Projects / Assets / Favorited；按媒体类型和标签筛选 | **抄一半**：「产物」视图加「本会话 / 全部」作用域切换；不做收藏/项目 |

**Midjourney**（[Organizing Your Creations](https://docs.midjourney.com/hc/en-us/articles/33329462451469-Organizing-Your-Creations)、[New Tools for Organization](https://updates.midjourney.com/new-tools-for-organization/)）

| 看到的做法 | 我们的取舍 |
|---|---|
| Organize 页=倒序画廊；**右侧筛选**（模型/比例/类型），「同区多选=或，跨区=与」 | **抄简化版**：单一「类型」筛选 + 搜索；不做多区布尔筛选 |
| **时间轴条**：悬停看日期，点击跳到那天 | **P1 抄**：rail 顶部的「今天 / 昨天 / 更早」分节 + 点击跳转 |
| 网格 / 列表 / 紧凑 三种视图 | **抄**：rail 支持网格/列表切换（P1） |
| 批量操作条：下载 / 加入文件夹 / 删除 | **抄**：多选后底部浮出操作条 |
| 文件夹 + 文件夹组 + 保存的搜索 | **不抄**：我们产物类型杂（图/视频/文档/代码），文件夹会变成第二个文件管理器；「任务目录」已经承担了分组 |

### 1.5.2 产物面板：侧栏 / 版本 / 就地改

**Claude Artifacts**（[官方帮助](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)、[Claude Code artifacts](https://code.claude.com/docs/en/artifacts)、[Bug：版本历史入口消失](https://github.com/anthropics/claude-code/issues/96718)）

| 看到的做法 | 我们的取舍 |
|---|---|
| 产物在**对话旁边的独立窗口**打开，不是弹窗；有全宽模式但**会把对话整个藏掉** | **抄**：main 区内嵌预览；**不抄全宽藏对话**——我们满档改为「对话收成浮动输入条」（§3.2） |
| 版本：每次 publish 一个版本，**在 Share 控件里选版本**；旧版本只读；「从旧版继续」会生成新的最新版 | **抄**语义；**不抄入口位置**：版本必须常驻检查器顶部 |
| 新 Docs/Slides 模板**没有版本历史**，官方替代是「编辑早先的消息，生成带自己产物的会话分支」 | **记牢**：产物类型化之后，版本不能跟着丢；我们统一在检查器里给 |
| 文档里选中文字 → `Edit with Claude`，**只改那一块** | **抄**：选区动作条（P1） |
| 教训：旧版 Code tab **不能内联编辑**，小修也要回对话 | **红线**：预览必须可编辑（至少文档/表格），不能只读 |

**ChatGPT Canvas（已下线，仅作历史参照）**（[Introducing canvas](https://openai.com/index/introducing-canvas/)、[下线报道](https://www.theverge.com/ai-artificial-intelligence/940028/openai-is-sunsetting-chatgpts-canvas-interface)）

| 看到的做法 | 我们的取舍 |
|---|---|
| 左对话 + 右产物分栏；检测到长文/代码（约 >10 行）**自动打开** | **P1 抄「自动打开」的克制作法**：只在「长产物 + 用户没在看别的」时提示，不硬切 |
| **按产物类型给 5 个动词**：写作 = 建议修改/调长度/改阅读级别/润色/加 emoji；代码 = 审查/加日志/加注释/修 bug/移植语言 | **抄**：动作条按 kind 配置，**最多 5 个**，不做通用按钮墙 |
| 顶栏 ← → 翻版本 + `Show changes` | **抄**：「显示更改」= 版本间 diff（P2） |
| **下线原因**：把已经长成工作区的产物重新塞回消息流，长文档失去稳定入口/版本/独立分享 | **这是本设计最重要的反面证据**：产物必须有稳定容器（我们的工作台），不能只活在某条消息里 |

**Gamma**（[产品说明](https://gamma.app/zh-cn/explore/content/guides/gamma-ai-presentation-tool-fast-polished-outputs)）

| 看到的做法 | 我们的取舍 |
|---|---|
| **大纲先行**：先给一篇「每页标题+要点」的大纲，改结构在这里改（最便宜） | **抄**：PPT 预览默认先给大纲（可改标题/增删页）→ 再生成 |
| 生成时卡片**逐张出现在左侧列表** | **抄**：slides 预览 = 左侧页缩略图列表 + 右侧当前页 |
| 换主题**非破坏性**（只改样式不动文本），可最后再定 | **抄思路**：模板/主题是产物属性，可随时换，不重跑内容 |
| 每张卡可单独 AI 重写/拆页/换版式 | **P2**：单页重做 |

### 1.5.3 编码 Agent：审阅而非浏览

**Cursor（2.0 → 3.4）**（[3.4 Changelog](https://cursor.com/cn/changelog/page/5)；注：**官方文档没有**逐 hunk 接受/拒绝的说明，逐 hunk 接受是 stagewise/Nifty 这类第三方扩展的行为）

| 看到的做法 | 我们的取舍 |
|---|---|
| 2.0 起从「文件中心」改成「Agent 中心」，Agent 面板成为主工作区 | **抄**：产物视图是第一入口，文件树退为第二入口 |
| 3.4 的**全屏标签**：Files / Changes / Canvas / PRs / Browsers / Terminals 占满工作区，**聊天退化为浮动输入条** | **抄**：满档时对话不消失，收成浮动输入条（见 §3.2） |
| 工具调用密度三档：Compact / Balanced / Detailed | **P1 抄**：process 行密度可配（默认 Balanced） |
| 「Agent Review」页签在切换/回滚检查点时不关闭 | **抄**：壳不卸载（现状已做到） |
| 空态文案是全句而非占位：「No Local Changes」「No agents yet」「No Repo / Initialize Repository」 | **抄**：空态一律给具体句 + 一个可执行动作 |
| **关键坑**：agent 结束时改动**已经写盘**，diff 不是待应用补丁；关掉面板不选也照样保留 | **记牢**：我们的「撤销/删除」必须是**真删 + 二次确认**，文案不能说「未应用」 |
| 完成通知：Cursor 官方无原生设置（只有 MCP/hook 第三方） | **补课而非创新**：Claude Code / Zed / Trae 都有（见下），我们要做的是「分清等确认 vs 已完成」 |
| 逐 hunk 接受/拒绝 | **不抄**（我们不做部分暂存，已有设计决策）；只保留「撤销单个文件」 |

| **Trae 的教训**（[实测](https://juejin.cn/post/7529517954331492388)） | 有 Difference View，但 SOLO **在下一轮对话前自动接受**，审阅退化成事后审计 | **记牢**：我们没有「接受」这一步，所以文案必须写「已写入 · 可撤回」，绝不能写「待审阅」 |

### 1.5.5 「chat + 预览」双区的四种做法（补充）

| 产品 | 做法 | 我们怎么用 |
|---|---|---|
| **Lovable**（[History](https://docs.lovable.dev/features/projects/history)、[Editor](https://docs.lovable.dev/features/projects/editor)） | chat + 预览双区；`Cmd/Ctrl+B` **藏掉 chat 让预览占满**；History 面板分 History/Bookmarks，每行给 `Revert to this version` / `View code changes` / **`Go to message in chat`**；线上版打 `Published` 徽章 | **抄**：专注模式用 `Ctrl+B`；检查器版本行加「**回到产生它的那条消息**」 |

| **v0**（[Versions](https://v0.app/docs/versions)、[Code viewer](https://v0.app/docs/code-viewer)） | 每条生成消息挂版本控件；恢复旧版生成「新的最新版」，保持线性；只读 Diff tab，可在行号上留评论，**评论作为下一条 prompt 的上下文** | **P2 抄**：行/页级评论 → 作为下一轮指令（比让用户复述强得多） |
| **Manus**（[拆解](https://www.aiuxplayground.com/teardowns/manus/output/)） | 重交付物打开**全屏预览模态 + 横向 filmstrip**，chat 留在背后 | **抄一半**：满档的 slides 用横向 filmstrip（比左侧竖列更像看片） |
| **Gemini Canvas**（[官方](https://support.google.com/gemini/answer/16047321)） | 对话里**先出一张卡片，点开才进右侧面板**；官方未写宽度 | **抄**：结果卡是入口，工作台是按需展开，不是永远开着 |

**恢复边界要写清楚**：Lovable/Bolt 只回代码、不回数据库；Notion 版本历史按套餐 7/30/90 天；Gemini 只有 Previous/Next 查看。→ 我们的「恢复」只回**工作区文件**，不回环境/依赖/数据库，UI 上必须写明。

### 1.5.6 结论：五条「只抄这些」

1. **任务即容器**（Runway Session）——产物必须挂在任务下，不是挂在文件系统下。
2. **侧栏内嵌预览 + 版本常驻**（Claude Artifacts）——不要弹窗，不要把版本塞进二级菜单。
3. **大纲先行、卡片逐张出现**（Gamma）——长任务的「进度感」来自「东西一张张出现」。
4. **批量操作条 + 类型筛选 + 时间分节**（Midjourney）——数量大时的三个救命按钮。
5. **选区就地改**（Canvas）——「改一句」比「重写一篇」重要。

**明确不抄**：文件夹系统、多区布尔筛选、保存的搜索、逐 hunk 接受、把一切都塞进右侧画布。

## 3. 布局：三档宽度 + 双栏/三栏

### 3.1 结构

```
┌ 工作台 shell ───────────────────────────────────────────────────────────┐
│ header 40px: [本次任务 ▾] [只看产出 ☑] [工作区|版本]  [半|宽|满] [⋯] [×] │
├───────────────┬─────────────────────────────────────┬───────────────────┤
│ rail 260      │ main                                │ inspector 240     │
│ (清单/画廊)   │ (预览)                              │ (按需)            │
│               │                                     │                   │
│ ▸ 这次任务    │  ┌───────────────────────────────┐  │ 尺寸 1024×1024    │
│   [图][图]    │  │                               │  │ 2.1 MB            │
│   ▸ 1 个文档  │  │        预览内容               │  │ 来源 image_generate│
│ ▸ 今天 14:20  │  │                               │  │ ─────────────     │
│   [图][视频]  │  └───────────────────────────────┘  │ 版本 ① ② ③       │
│ ▸ 更早        │  ┌ 动作条 ────────────────────────┐  │                   │
│               │  │ 变体 | 微调 | 导出 | 定位 | ⋯ │  │                   │
└───────────────┴─────────────────────────────────────┴───────────────────┘
```

### 3.2 三档宽度（不再随 Tab 跳变）

| 档位 | 宽度 | 结构 | 用途 |
|---|---|---|---|
| 半（默认） | **480px** | rail 220 + main 260（或单栏画廊） | 边看边聊；默认 480 给对话多留 40px（已拍板） |
| 宽 | 860px | rail 260 + main 600 | 审阅文档/PPT/多图（对齐 Zed Agent 面板默认上限 850） |
| 满 | 对话剩 280px | rail 260 + main 剩余 + inspector 240 | 沉浸修改；**对话收成浮动输入条**（Cursor 3.4 的做法），而不是被挤到 280 |

**关键改动**：宽度是「工作台的宽度」，不是「Tab 的宽度」。切 Tab 不改宽，只有用户拖拽或按档位按钮才变。

### 3.3 断点与降级

| 可用宽度 | 布局 |
|---|---|
| ≥ 900 | rail + main + inspector（inspector 可手收） |
| 560–899 | rail + main（inspector 变浮层，点「信息」出） |
| < 560 | 单栏：rail 与 main 互斥，main 顶部出现「‹ 返回列表」 |

容器查询（`@container`）而不是媒体查询——工作台宽度由用户拖拽决定，与视口无关。

**专注预览**：`Ctrl+B` 或 `⋯ → 专注`临时收起 rail 与 inspector，只留 main（再按恢复）。对应 Lovable 的 `Cmd/Ctrl+B`（藏 chat 让预览占满）与 Krea 的 preview toggle——改图/看片时不想被列表挤。

### 3.4 与对话区的关系（技术前提）

现状是 `position: fixed` + `padding-right` 的假分栏。v2 要求改成**真实 flex 分栏**：

```
chat-page (flex row)
├ chat-main (flex:1, min-width:280)
└ workbench (flex: 0 0 <width>px)
```

理由：拖宽时只有一侧 reflow；Modal 边界可直接读父容器；键盘焦点顺序自然；不再需要 `getMaxWidth()` 去查 `[data-chat-dialog]`。

> 迁移风险可控：`WorkspaceWorkbench` 内部的宽度/记忆/键位逻辑原样保留，只把 portal 换成布局占位。见 §12。

## 4. 视图：4 个 Tab → 2 个（产物与文件合并，已拍板）

| v2 视图 | 内容 |
|---|---|
| **工作区**（默认） | 顶部一个开关 **「只看产出」（默认开）**：<br>· **开** = 按任务分组的产物卡（成品 + 中间产物折叠行），筛选（全部/图片/视频/文档/代码）+ 搜索 + 作用域「本会话 / 全部」<br>· **关** = 工作区文件（树 / 平铺可切），含未被识别为产物的文件 |
| **版本** | git 变更/历史（插件，内部设计沿用）；范围增加「**本回合**」（Codex 的 Last turn changes） |

**为什么合并**：现状「变更」与「文件」是同一批路径的两种视角，用户在两处之间反复横跳；合并后只留一个「我在看工作区」的心智，用开关切换**呈现密度**，而不是切换分区。

> 「本会话 / 全部」对应 Runway 的 Session ↔ Assets：日常只看本会话（默认），要找「上次那张图」时切「全部」（跨会话按时间倒序）。默认不展示全部，因为单会话就能到 4985 个文件。

**「文档」Tab 取消**：文档不再是一个分区，而是主区的一种预览内容（点 rail 里的文档卡 → main 显示可编辑文档）。理由：文档是个**内容类型**，不是**分区**；它作为 Tab 时，没打开稿件还得整条 Tab 隐藏（现状 `docEnabled` 判断）。

## 5. 五种状态

| 状态 | 触发 | 形态 | 文案 |
|---|---|---|---|
| **空** | 会话内无产物 | 居中插画 + 3 条建议动作 | 「这个会话还没有产出。试着让我写一份文档、做一组图，或整理一下当前工作区。」+ [写文档][生成图片][导入文件] |
| **进行中** | 当前回合有 running 工具 | 顶部 40px 进度条（阶段名 + 已用时）+ 已落地的产物实时插入 | 「正在生成图片 · 2/4 · 已用 38s」 |
| **有产物** | 有成品 | 默认折叠为「本次任务」组，展开最新一组 | — |
| **多产物** | 组内 > 6 或全会话 > 60 | rail 内滚动 + 按时间分节（本次/今天/更早）+ 搜索 | 「今天 14:20 · 6 个」 |
| **失败** | 本轮全部失败 | 组内一行失败态 + 重试 | 「这次没有产出成功 · 重试」 |

### 5.1 进行中的阶段语言（不要工具名）

工具名 → 用户语言映射（可配置表）：

| 工具/特征 | 阶段文案 |
|---|---|
| `image_generate` / `*.png` 写入 | 生成图片 |
| `enqueue_workflow` / `comfyui*` | 渲染视频 |
| `ffmpeg` / `*.mp4` 写入 | 编码视频 |
| `pptx` / `*.pptx` 写入 | 生成幻灯片 |
| `write` / `edit` / `*.md` | 撰写文档 |
| `bash` / `exec` | 执行命令 |
| `read` / `glob` / `grep` | 读取资料 |

规则：同一阶段连续出现只算一个；进度优先用「当前阶段 + 已完成 N/M」，没有总量就只给阶段名 + 计时，**绝不编造百分比**。

> 参照 Runway 的教训（[Why is my generation stuck?](https://help.runwayml.com/hc/en-us/articles/32881061675795-Why-is-my-generation-stuck)）：它显示百分比，但会长期停在 90%，用户以为卡死；且取消不退积分。**能显示真实信号（阶段、队列位次、已完成张数、已用时）时就不要显示假百分比**；同时必须在工作台内提供「取消本次生成」的入口，并说明已消耗的资源。
>
> 行业共识也印证这点：Codex 只给 `Step N/M` + `N actions done` + 已耗时（[SDK 文档](https://codex-app-sdk.github.io/codex-app-sdk/guide/messages-tools.html)），**没有任何一家给可信 ETA**。所以我们的进度条常驻右侧两个字段：**已用时** + **中断**（`Esc`），阶段名在左。

## 6. 产物卡（Artifact Card）

### 6.1 分类（kind）

| kind | 判定 | 默认呈现 |
|---|---|---|
| `image` | png/jpg/webp/gif/svg | 按原比例缩略图（不裁切） |
| `image-set` | 同一轮、同目录、≥3 张图 | 2×2 拼合卡 + 「4 张」角标（**一批默认 4 张**，批次由模型能力决定，参数面板要写明「本模型一次出 N 张」） |
| `video` | mp4/webm/mov | 首帧 + 时长角标 + 播放键 |
| `audio` | mp3/wav/m4a | 波形占位/图标 + 时长 |
| `doc` | md/docx | 首段文本 + 字数 |
| `slides` | pptx | 首页缩略（无则页数 + 图标） |
| `sheet` | xlsx/csv | 表格网格占位 + 行列数 |
| `site` | html | 迷你渲染（沙箱）或截图 |
| `code` | 其它源码 | 语言角标 + 行数 |
| `archive` / `other` | zip 等 | 图标 + 大小 |

> 判定优先级：**声明 > 派生**。有 `details.artifacts` 就用声明；没有就按扩展名 + 目录规则兜底（§12）。

### 6.2 卡片形态（rail 内）

```
┌──────────────────────────┐
│  ┌────────────────────┐  │  ← 缩略图 4:3（媒体按原比例）
│  │                    │ A│  ← 状态角标（A/M/D）
│  └────────────────────┘  │
│  宠物精灵图-正面.png      │  ← 名称 12px，单行
│  1024×1024 · 2.1 MB      │  ← 规格 11px fg-3
└──────────────────────────┘
```

- rail 宽 260 时，卡片单列；宽 640 时（宽档）自动 2 列。
- hover：缩略图描边转 accent 55%，右上出现 `⋯`（导出/定位/删除/重命名）。
- 选中：左侧 2px accent 竖条 + 卡底 accent 8%。

### 6.3 中间产物折叠

规则（按顺序命中即折叠）：

1. 声明 `role: intermediate`
2. 路径命中中间目录：`parts*/`、`normalized/`、`frames/`、`cut-*`、`tmp/`、`.cache/`
3. 同一任务超过 20 个同扩展名文件，且文件名呈序号（`xxx-12.png`、`frame_0012.png`）

折叠形态（rail 内一行，可点开）：

```
▸ 中间产物 1107 个（切片/归一化/帧）        [展开]
```

点开后在 rail 内以**网格**展示（不再逐行），并提示「这些是过程文件，通常用于重跑」。

**极端场景实拍（本机真实数据：1110 文件的一轮）**——rail 首屏应长这样：

```
14:20  帮我把这只兔子做成宠物精灵图（用户首句）        3 个成品
  ┌────────┐ ┌────────┐ ┌────────┐
  │ 精灵图 │ │ idle   │ │ sprite │
```

而不是 1110 行同名文件。这条是整个设计成立与否的验收线。

### 6.4 过滤、搜索与视图

- 默认过滤：`.lumii-ref`、`.git/`、`node_modules/`、`.cache/`、隐藏目录、`.tmp`
- 搜索：文件名 + 路径模糊匹配；支持 `kind:` 前缀（`kind:image 宠物`）
- 筛选 chips：全部 / 图片 / 视频 / 文档 / 代码 / 其它（单选，带计数）
- **视图切换（P1）**：网格（缩略图为主）/ 列表（名称+规格，密度高）——对应 Midjourney 的 grid/list；默认网格，>200 项时自动建议列表
- **时间跳转（P1）**：rail 顶部分节标题（今天 / 昨天 / 更早 / 具体日期）吸顶，点击滚动到该节

### 6.5 卡片生命周期（AG-UI 对齐）

卡片是**状态的视图**，不是渲染层按工具名猜出来的结果。状态模型对齐 AG-UI 的
「事件流 + 共享状态（snapshot/delta）+ interrupt/resume」，P1 先做本地子集
（不引依赖、不加 SSE，详见 [P1 实施计划 §2.3/§4.5](../../plans/客户端UI/2026-10-26-工作台v2-P1实施计划.md)）。

| 生命周期 | 来源 | 一级动作 |
|---|---|---|
| `running` | `TOOL_CALL_START`（当前只有生图；视频/录屏不造占位） | 中断 |
| `waiting_input` | `INTERRUPT`（权限审批 / 提问） | 允许一次 / 总是允许 / 拒绝 / 回答 |
| `ready` | 声明或 `fileChanges` + 路径 | 打开 / 导出 / 定位 / 对比 |
| `failed` | 工具失败（`TOOL_CALL_END` + isError） | 重试（只预填 prompt）/ 查看原因 |
| `cancelled` | 中断 / 进程重启 | 重试 / 移入回收站 |

约束：
- **Agent 权威、UI 本地**：产物/任务/中断来自事件；选中、筛选、宽度、跟随是本地状态。
- **snapshot + delta**：切会话全量重建，运行中只更新变化的那张卡；不每帧重算全会话台账。
- **不编造**：认不出的工具不造占位卡；没有真实总量不显示百分比。
- **动作随状态变**：不可用的动作不出现，不灰一片。

## 7. 预览（main 区）

### 7.1 原则

- **不再弹 Modal**：预览发生在 main 区，复用 `FilePreviewModal variant="embedded"`。
- 需要更大空间时：`双击` → `variant="window"` 独立窗；`⋯ → 在系统中打开`。
- 主区顶部有面包屑：`本次任务 / outputs/pet-demo/正面.png`，点「本次任务」回列表。
- **预览必须可编辑**（至少文档/表格）：Claude 旧版 Code tab 不能内联编辑，小修都要回对话——这是明确的反面教材。
- **不自动打开**：遵守 `2026-10-25-创作工作台布局设计.md` §3.1「Agent 选，UI 忠实执行」。v2 **不**做「检测到长产物就开面板」这类启发式；打开只有两条路——Agent 调 `app_panel`，或用户点结果卡/工具条入口。

### 7.2 各类型

| kind | 预览 | 主区还是独立窗 |
|---|---|---|
| image | 缩放/拖拽/适应（滚轮 + 双击复位） | 主区 |
| video | 播放器（`<video controls>`），支持 0.5×/1×/2× | 主区 |
| audio | 波形条 + 播放 | 主区 |
| doc | 阅读/编辑（沿用 markdown 编辑能力），工具栏固定；**P1 加选区动作条**（改写/扩写/精简/换语气） | 主区（编辑时建议宽档） |
| slides | **左侧页缩略图列表 + 右侧当前页**（Gamma 式），← → 翻页；未生成完时页缩略图逐张出现；**满档时改为底部横向 filmstrip**（Manus 式，更像看片） | 主区（宽档/满档） |
| sheet | 表格只读 / 前 200 行 | 主区 |
| site | 沙箱 iframe（沿用 html-active） | 主区 |
| code | 高亮 + 行号 + 复制 | 主区 |

### 7.3 动作条（main 底部，固定）

```
[变体] [编辑 ▾] [插入 ▾] [导出 ▾] [定位] [⋯ 删除/重命名/复制路径]
```

- **编辑 ▾**：把复合操作收进一处（图：局部重绘/扩图/放大/去背景；PPT：换版式/单页重写；文：改写/扩写/精简）——参照 MJ Editor「一次组合多种操作」。
- **最多 5 个一级动作**，且按 kind 配（Canvas 的 5 动词：写作与代码完全不同）。不做「通用按钮墙」。
- **插入 ▾**：插入画布 / 插入文档 / 用作参考（Canva 式「结果直接变可编辑元素」）。
- 动作可用性由 kind 决定；不可用的动作**不出现**，不灰掉占位。

> **P2 实况（2026-10-27）**：一级动作 = 变体 / 编辑 / 导出 / 定位 / ⋯。
> - 变体 = 同 prompt / 模型 / 尺寸**再生成一张新文件**（本机模型无 seed，不做「只换 seed」）；
> - 编辑 = Markdown 选区四动作 + PPT 单页标题/要点改写（候选 → 应用 → 可撤销）；
> - **图像局部（重绘/扩图/擦除/去背景）与 PPT 换版式/换图明确不做**（无安全入口），
>   插入 ▾ 尚未接线。偏差清单见 [P2 计划 §十一](../../plans/客户端UI/2026-10-27-工作台v2-P2实施计划.md)。

### 7.4 对比模式

多选 2–4 项 → main 切换为并排对比（图/视频首帧/PPT 首页可混排），每格标注版本与参数。用途：选封面、选变体、比较两次重跑。`Esc` 退出对比。

> 参照豆包「一张无限画布收拢图/视频并排比对」。我们不做画布，只在 main 内做对比视图。

### 7.5 跟随模式（默认关）

Trae 的做法：右栏跟着 AI 当前阶段自动切（写文档时切文档、跑终端时切终端），用户双击/滚动即交还控制权。

我们的实现：`⋯ → 跟随 AI` 打开后，main 在主区自动切到「本轮最新产物」；**用户一旦手动点选任意项或滚动，自动关闭跟随**（不做二次确认）。默认关闭，因为工作台开着往往正是用户在读旧东西。

> 这也是「进行中状态」的另一种答案：与其做一个大进度面板，不如让内容自己一页页翻过去。

## 8. 检查器（inspector）

只在有选中项且宽度 ≥900 时出现，可手动收起。内容按 kind：

| kind | 展示 |
|---|---|
| 媒体 | 尺寸、时长、大小、生成时间、来源工具、模型/参数（若有声明） |
| 文档 | 字数、章节数、最近修改 |
| 代码 | 语言、行数、关联 diff |
| 任意 | **版本历史**（同一路径在本会话的多轮出现 → ①②③，点切换预览、可「以此版为准」）；每行带 **「回到产生它的那条消息」**（Lovable 的 `Go to message in chat`） |

**恢复边界（必须写在 UI 上）**：我们的「恢复/以此版为准」只影响**工作区文件**，不恢复环境变量、依赖、数据库。参考 Lovable/Bolt 同样只回代码，把它们没说清的地方说清。

版本历史是**零新增存储**的：`fileChanges` 已按轮持久化，同一路径在第几轮被写过就是第几版；点某版 = 预览该轮产物（若文件已被覆盖，则只能看记录，标注「已被后续版本覆盖」）。

语义对齐 Claude Artifacts：**旧版本只读**；「从此版继续」= 把该版作为输入重跑一次（新结果成为最新版），而不是原地回写。版本条常驻检查器顶部，**不放进 `⋯` 菜单**。

> **P2 实况（2026-10-27）**：版本行 = `turn:<messageId>` / `local:<editId>` 两种来源；
> 「以此为准」= 把该版内容**复制**固化（`.lumii/pins/`，不是指针）；「恢复到此轮」= 本会话文件按路径回退 +
> 对话分支（备份提交 + 回收站，可撤销）；「从此版继续」未接线。
> 二进制旧版没有副本时如实标注原因，**不允许**拿当前文件冒充。

## 9. 任务分组（rail 的分节）

### 9.1 分组键

- 主键：assistant 回合（`messageId`）+ 该轮产出目录的第一段（如 `outputs/pet-demo/`）
- 同一目录在多轮被写 → 合并成一个「任务」，时间取最新

### 9.2 分组标题

```
14:20  生成一组成都市井风格的头像（用户首句，截断 24 字）   6 个
```

- 时间 `HH:mm`（今天）或 `MM-DD`（更早）
- 子 Agent 产出带标签：`[代码助手]`
- 右侧：成品数（不含中间产物）
- 进行中的任务组带状态点：**等输入**（accent 呼吸）/ **进行中**（旋转）/ **已完成**（实心）——对齐 Claude Code 的 Needs input / Working / Completed 分组语义

### 9.3 排序与默认

- 倒序（最新在上）；「本次任务」= 当前流式/最新一轮，默认展开，其余折叠。
- 新产出出现在「本次任务」顶部并做 1 次淡入，不自动滚动（避免抢走正在读的内容）。
- **「自上次查看」标记**（Devin 的 *Since last seen*）：以「上次打开工作台的时间」为界，之后的产物带一枚 accent 圆点；打开工作台即清除。这比「新增 A/M/D」更贴近用户的问题——他问的是「我上次走开之后又出了什么」。

## 10. 视觉规格

### 10.0 气质：像一块「工作室台面」，不像一块「后台管理页」

- **底**：玻璃（既有 `--mt-glass-bg` + blur 24），不要纯色面板；让对话在背后透出一点点，暗示「同一个空间」。
- **密度**：rail 是扫读区，一屏 ≥8 项；不要为了好看把行高撑到 44+。
- **层级靠明度**，不靠阴影：`surface-1/2/3` 三层足够，禁止再叠投影做层级。
- **颜色只表达状态**：accent 只给「选中 / 主操作」，success/warn/error 只给文件状态；其余一律中性灰。
- **三不**：不做渐变光晕、不做大圆角卡片墙、不给每个功能配彩色图标。
- **动效只做两件事**：进出（滑入 220ms decel）和出现（新产物一次淡入）。其余不动的就别动。

| 项 | 规格 |
|---|---|
| 壳背景 | `var(--mt-glass-bg)` + `blur(var(--mt-glass-blur))`；左缘 1px `--mt-border-hairline` |
| Header | 高 **40px**（现 44）；Tab 12px/600；激活 2px `--mt-accent-500` 下划线，左右内缩 8px |
| 角标 | 16px 高 pill，accent 12% 底，10px/700 |
| rail 行高 | 32px（单行）/ 44px（带副标题）；左右 padding 12px |
| 缩略图 | 圆角 8px；边界 1px `--mt-border-hairline`；hover 描边 accent 55% |
| 卡片间距 | 8px（网格）、4px（列表） |
| 分节标题 | 11px/600 `--mt-fg-3`，sticky，背景 `--mt-glass-bg` |
| 动作条 | 高 40px，底 `--mt-surface-2`，按钮 28px 高 |
| 状态色 | 新增 `--mt-success`、修改 `--mt-warning`、删除 `--mt-error`、中间产物 `--mt-fg-4` |
| 拖拽热区 | 8px（现 5px），hover 显示 2px accent 竖线 |
| 动效 | 面板滑入/改宽 `--mt-dur-normal` + `--mt-ease-decel`；缩略图入场 stagger ≤6 项；`prefers-reduced-motion` 全关 |
| 图标 | 一律 lucide-react，16px，stroke 1.8 |

**密度原则**：rail 是「扫」的，一屏至少 8 项；main 是「看」的，不放大留白但不放工具栏噪音。

## 13. 临时文件与清理（新增，已拍板）

### 13.0 为什么单独立一节

本机工作区 **3.0 GB**：`outputs/` 1.1 GB、`temp/` 1.3 GB（其中 `temp/github3` 940 MB）、`uploads/` 250 MB、`scratch/` 136 MB；单回合最高 1110 个文件，单会话 4985 个。
工作台的分组再好，也只是「把垃圾装进抽屉」。**分类与清理是这套设计能否长期成立的地基。**

### 13.1 四类文件（分类是清理的前提）

| 类 | 判定 | 例子 | 默认策略 |
|---|---|---|---|
| **成品 deliverable** | 声明 `role: deliverable`；或落在 `outputs/<task>/` 根层且未被判为中间 | 最终图、成片、pptx、docx | **永不自动删**；只能用户手动删（二次确认） |
| **中间产物 intermediate** | 声明 `role: intermediate`；或命中约定目录 | `outputs/<task>/parts*/`、`normalized/`、`frames/`、`cut-*.png` | TTL 7 天；配额紧张时**优先**清 |
| **临时 ephemeral** | 落在 `workspace/temp/**` | 截图、录屏、下载、实验脚本 | 截图启动即清（沿用现状）；其余 TTL 24h |
| **内部 internal** | 落在 `<dataRoot>/**` | 缩略图缓存、`.lumii-ref` 记账 | 缓存按 LRU ≤500 MB；记账不自动删 |

**判定优先级**：声明 > 约定目录 > 扩展名启发式。**认不出来的一律当成品**（保守，不删）。

### 13.2 五个触发时机

| # | 时机 | 动作 |
|---|---|---|
| 1 | 应用启动后 30s 空闲 | 清上次遗留的 `.trash-*`；清过期 ephemeral（截图目录沿用 `clearScreenshotTempDir`） |
| 2 | 每日一次（空闲时） | 扫 TTL：intermediate > 7 天、ephemeral > 24h |
| 3 | 配额触发 | 工作区 > 软阈值（默认 10 GB）→ 清 intermediate/ephemeral 至 80%；**仍超则提示用户，不碰成品** |
| 4 | 同一任务重跑 | 旧中间产物标「可清」，完成 1 小时后才真正进入候选（避免正在复用的素材被删） |
| 5 | 会话删除 / 归档 | 弹窗提示「一并删除该会话产物（可选）」，**显式勾选**才删 |

### 13.3 控制机制（默认 + 可调 + 可撤销）

- **默认策略**：成品永久 / 中间 7 天 / 临时 24h / 缓存 500 MB。设置 → 存储 可改（含「永久保留」档）。
- **干跑**：先出「将删除 N 个文件 · 释放 X GB」+ 分类计数 + 前 20 条列表；确认才执行。
- **可恢复**：删除 = `rename` 到 `<workspace>/.lumii/trash/<ts>/`，保留 7 天；到期再真删。
- **绝不阻塞主线程**：禁止同步递归删除。沿用截图清理的教训——1 万文件 `rmSync` 实测 1.57 s 主线程冻结；改为「rename（毫秒）+ 后台 `fs.promises.rm`」。
- **并发保护**：只清「最后写入 > 1 小时」的文件；跳过被占用/锁定/正在读取的文件；跳过最近 N 分钟内被任何会话写过的路径。
- **安全闸**：路径 resolve 后必须在工作区内；不跟随 symlink；跳过 `.git/`、`node_modules/`；**跳过被成品引用到的中间文件**（同目录相对路径引用扫描，命中即跳过）。
- **可见性**：中间产物折叠行右侧显示「1107 个 · 1.2 GB · 清理…」；设置 → 存储 页显示四类占用、当前策略、最近清理记录。
- **审计**：`<dataRoot>/logs/cleanup-<date>.jsonl`，每条含规则、文件数、字节数、trash 位置、耗时。

### 13.4 与技能规范的关系（已拍板：需要固化）

技能必须满足其一，否则其产出**按成品对待（永不自动清理）**：

1. 把中间产物写进约定目录：`outputs/<task>/{parts,normalized,frames}/` 或 `temp/<skill>/`；
2. 或在工具结果里声明 `artifacts[].role = "intermediate"`。

规则写进技能开发规范（`docs/standards/`），**UI、清理服务、技能三方读同一份规则**——避免「UI 认为是中间产物、技能认为是成品」的两套判断。

### 13.5 分期

- **P0**：识别四类 + 折叠 + 显示占用 + **手动**「清理中间产物」（干跑 + trash）。
- **P1**：TTL / 配额自动清理 + 设置页存储面板 + 审计日志 + 技能规范固化。
- **P2**：内容去重（hash 相同只留一份）+ 重跑时复用中间产物。

### 13.6 三个不能做

1. **不能删成品**——宁可提示「磁盘不足」，也不能自作主张删用户的作品。
2. **不能在主线程同步删**——会冻结（已有实测）。
3. **不能静默删**——必须留 trash + 日志；清理记录可查。

## 附录 A：本机实测数据的复现方式

```bash
node -e "
const {DatabaseSync}=require('node:sqlite');
const db=new DatabaseSync(process.env.USERPROFILE+'/.lumii/data/agent-runtime.db',{readOnly:true});
const rows=db.prepare(\"select content_json from messages where role='assistant' and content_json like '%fileChanges%'\").all();
let turns=0,total=0,max=0,hist={},ext={};
for(const r of rows){let j;try{j=JSON.parse(r.content_json)}catch{continue}
 const fc=(j.fileChanges||[]).filter(f=>f.confidence!=='unattributed');
 if(!fc.length)continue; turns++; total+=fc.length; max=Math.max(max,fc.length);
 for(const f of fc){const e=(f.path.split('.').pop()||'').toLowerCase();ext[e]=(ext[e]||0)+1}}
console.log({turns,total,max,avg:(total/turns).toFixed(1)});
console.log(Object.entries(ext).sort((a,b)=>b[1]-a[1]).slice(0,12));
"
```

> 注：`better-sqlite3` 是 Electron ABI，系统 Node 加载不了；用内置 `node:sqlite`（需 Node ≥22.5）。
