## 二、为什么"不止 5 个"

最初列的缺口是 5 个（Shake/Hop/Picked/Land/Sit），用户一句
**「不止剩余 5 个吧」**才对上账：**完整是 22 组**。

根因是我拿"已装的 6 组 + 印象里的 5 个"凑数，**没有去读契约**。
契约在 `pet-sprite-h3/characters/install-pet.mjs` 的 `ACTIONS`——一张表就是全集。

漏掉的 11 条在契约里全都有定义，其中八条还带着明确来源
（设计 §8.6.2「需新素材」三条、§4.4「会拒绝」、§7.3 目标完成/失败的可见形态）。

**教训**：数"还差多少"必须读契约。产物里没有只说明"还没做"，**不代表不需要做**，
也不代表"没做过"（可能做过又跑完了——见下条）。

## 三、四个被判据坑掉的回合

### 3.1 「不在队列里」被当成「没提交」

01:30 查 `/queue` 没看到 crawl/sit 的机位图任务，就写成「还没交」发给了 Agent。
Agent 核实后指出：**那两张早就跑完了**——它们在中止前那一批里，所以查队列时当然不在。

`不在队列里` 的因有两个：「没提交」**和**「提交了并且已跑完」。
**缺席不是否证**，要下结论得再查一处（`/history`、产物目录、`staged/`）。

### 3.2 帧里内嵌着 workflow——「这批是哪版提示词生成的」有硬证据

我误触发跑出的那批 Shake 帧，Agent **没有看图猜**，而是把 PNG 里内嵌的
workflow 元数据读出来——**提示词原文就在里面**。据此判定它用的是**四足通用版**
（`shakes its head … The tail stays still.`）且没挂 `_CLEAN_PLATE`。

这同时解释了**那批帧为什么会出问题**：跑它的时候 `moonrabbit.motions` 里还没有
`shake` 这一条，于是**静默回落**到全局四足版——**她没尾巴，模型就给她画一条**。

**可复用**：任何"这批素材是谁用哪版提示词生成的"问题，先读 PNG 元数据。
**`motions` 覆盖不全 = 静默回落到四足版**，与"缺组静默回落到基础待机"是同一个设计气味。

### 3.3 装包不是"最后一哆嗦"

Agent 原本的收口是「16 张表全就绪 → 验收 + 装包」。用户要求改成**边跑边装**。

改完当场撞出**四个坑**——而且**全是"一次性装到最后"永远不会暴露的**
（那时条件已经齐了）：

1. **fx 光环从来没真进过包**：拼条 alpha 全是 255、92% 是纯绿，**根本没抠底**。
   根因是**软光晕与绿幕天生冲突**——渐变每一级都要路过绿色，
   普通容差抠完最近保留像素离底色只有 **25**（安全线 150）。
   把 `tLow` 抬到 165 后，S8 变成**构造上**达标。代价：现在是偏实的细金环，
   不是原来那种柔光；要柔光得换非绿底重画。
2. **`install-pet` 在 `Crawl` 缺席时会把 `perchGaps` 抹平**（`{wall:0.317}` → `undefined`）
   ——它只在同时有 `Climb` + `Crawl` 时才写这条。
3. **`--fx-dir` 漏一次，fx 就静默消失**（历史上它就是这么没的）。
4. **并发**：20 分钟巡检和手动装撞在一起，两个全量重装**共用写死的 `<id>-work`
   中间目录**、互相删对方的文件（`ENOTEMPTY` / `cut-3.png` 写不进去）。
   已加带心跳的锁，排队不并行。

**判据没放松**（贴边不管、残留绿点不管、只有首尾跳变和身份画崩才判死）——
变的只是节奏。详见规范 §6.2.1。

### 3.4 「等全齐」是个脆门槛

那一夜客户端**重启两次**（01:25 那次还换了控制口 token），**打断 Agent 两轮**。
「全齐」随时可能永远等不到。增量装让坑在第一张表就暴露，而不是三小时后。

## 四、Agent 自己抓到并修掉的

- **`suspended` 锁定语写着"耳朵和尾巴在空中乱摆"**——她没尾巴，模型会给她长一条。
  改成"松散的悬挂物（长发、飘带、裙摆）"；猫那边身份描述本来就有尾巴，不受影响。
  同类的 `fall` 残留也一并清掉。
- **`moonrabbit-hop.png` 缺配套 `.json`**（`--meta` 要显式传）——画布尺寸和底色
  都存在那份 json 里，缺了 `resolveStage` 直接报错。
- **Cheer 走了两轮**：第一版 S1 越界 1.84%（举手雀跃顶到格线）被整批否决。
  修法是**压首帧摆放**（hop 首帧 `ratio 0.699/baseline 0.95` → `0.63/0.97`，
  头顶余量 168→229px）+ 措辞收紧（手不超过耳朵高度）。
  **不是裁像素，也不是放宽判据。**
- **`--keep-scale` 必须配 `--src-h`**：不给就按目标画布算，512×448 的机位格
  摆进 768×672 会得到 0.44 的小人（该有 0.65）——**她一做这个动作就明显缩一号**。

## 六、还没定的（要人的眼睛）

Agent 明确说它看不见图，这三条要人判：

1. **12 张表报"胯部最宽行比首格宽 1.3~1.55×"**。跳/雀跃时张腿是合理的；
   但 `yawn`/`scratch`/`droop` 这类脚不挪地的如果也变宽——正常是裙摆，真长东西就是画崩。
2. **`Crawl` 的倒挂位置**：像素确实翻了（`install-pet` 里 `sharp(src).flip()`），
   `ceiling=0.7121` 正好 = 1 − 内容顶/画布高，算得通；但要她真爬上顶边看一眼才知道
   是不是"脚贴顶、裙摆往下垂"。
3. **`Cheer` 这版碎块比别家多**（抹 66 块、保留 95 块最大 162px，绿色权重只降 96%）。
   按放宽容忍度不判死，但可以退。

另：**客户端要切一次宠物（或重启）才读得到新帧。**
