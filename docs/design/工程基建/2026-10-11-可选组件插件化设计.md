# 可选功能插件化设计（v2：统一插件中心）

> 状态：**P0–P3 已实施**（随包插件化落地：mermaid 排除、ffmpeg / wechat-mcp / 宠物资产改为按需下载；收尾项见 §8 与 §12）
> 日期：2026-10-11
> **v2 修订**：确立「所有可选重组件 = 插件；**安装入口唯一 = 插件中心**」。废弃 v1 的「散点安装入口」与「wechat-mcp 留在 MCP 页」。
> 范围：`apps/windows` 打包链路 + 运行期组件装配 + 插件中心
> 关联：[`2026-09-21-打包体积治理.md`](2026-09-21-打包体积治理.md)、[`2026-10-09-wechat-mcp-npm社区分发.md`](2026-10-09-wechat-mcp-npm社区分发.md)

## 0. v1 → v2 修订说明

v1 的错误是**名不副实**：

| v1 做法 | 问题 |
| --- | --- |
| ffmpeg 在「录屏流程」里装 | 三条不同的安装路径，三套状态/进度/UI |
| wechat-mcp 在「MCP 页」里装 | 违背插件原则；MCP 页是「连接管理」，不是「安装入口」 |
| 宠物在「宠物页」里装 | 同上 |
| 新造 `ComponentSpec` | 已有 `PluginDef` / `PluginCenterPage` 没用上 |

**v2 原则**：

> **有下载、有落盘、可卸载 = 插件；插件的安装/卸载**只在**插件中心**。
> 功能页（MCP 列表 / 宠物页 / 录屏）**只负责使用与配置**；未安装时给一句「去插件中心安装」的引导。

这条判据与仓库现状自洽：`plugins-registry.ts:14-22` 的注释明确写了 MemPalace 因为「没有安装、没有运行时、没有远端下载」**不算插件**而移出。反向成立——本期的四个大件全部符合插件定义。

## 1. 背景与目标

### 1.1 起因

2026-09-21 体积治理把 Windows 装包压到 **156.2 MiB**（治理文档 §1）。之后几项大件**静默**进包，装包涨回 **298.8 MB**：

| 日期 | 提交 | 加入 | 解包增量 | 进包方式 |
| --- | --- | --- | --- | --- |
| 2026-09-24 | `39bbf0ac` | mermaid 预览 | **+40 MB** | asar（**漏排除**） |
| 2026-09-25 | `7c9887ed` | 团子 / 月兔 pet-model | **+86 MB** | extraResources |
| 2026-10-07→09 | `4e8ef1a7`/`23d1e0c7` | wechat-mcp 进包 | **+37 MB** | extraResources |

### 1.2 目标

把大件从「随包捆绑」改为「**在插件中心按需安装**」，用户**自由选择**，同时把安装包拉回 200 MB 以内。

### 1.3 口径（本期只动 ≥25 MB）

| 入册 | 体积 | 类型 |
| --- | --- | --- |
| pet-models（卡通猫 35 / ug_official 3.3 / xiaomai 3.0） | 41 MB | 资源包 → **宠物插件**（随包**保留 mao_pro + 月兔**） |
| @ffmpeg-installer/win32-x64 | 62 MB | 二进制 → **1 个插件** |
| wechat-mcp | 37 MB | 二进制 → **1 个插件** |
| mermaid + @mermaid-js/parser | 41 MB | **非插件**（漏排除，见 §5.5） |

`<25MB`（sherpa 22 / sharp 19 / esbuild 11 / 渠道 SDK ~10 / 文档解析 ~15 / playwright 7 / better-sqlite3 2）**一律不动**——多在常用/半常驻路径，插件化收益小、风险高。

### 1.4 非目标

- 不改 Electron 运行时（248 MB）。
- 不改 `app.asar` 应用本体（`out/**`）。
- 不引入第三方可执行插件的任意安装（只做**内置插件清单**）。

## 2. 三类交付物（机制不同，但都归插件中心）

| 类型 | 交付物 | 插件 | 机制 |
| --- | --- | --- | --- |
| **A. 进程级二进制** | 单 exe | wechat-mcp、ffmpeg | 装 → 数据根固定路径 → 启动时解析路径 |
| **B. 资源包** | 目录/zip | 宠物（月兔/卡通猫） | 装 → 用户资源目录 → 扫描合并 |
| **C. 前端 JS 依赖** | renderer chunk | （无） | **不做插件**：mermaid 是构建期依赖，且 asar 那份是死重，直接排除（§5.5） |

插件中心统一呈现 A/B；C 类不进插件中心。

## 4. 统一设计

### 4.1 插件清单 = 唯一真源（`src/shared/plugins.ts`）

把 `PluginDef` 从渲染层上提到 `shared/`（主进程与渲染层共用），并扩展可安装字段：

```ts
interface PluginDef {
  // —— 现状字段（PluginCard 已在用）——
  id: PluginId                     // 'cloak-browser' | 'wechat-mcp' | 'ffmpeg' | 'pet:demo_moon_rabbit' | 'pet:demo_cartoon_cat'
  name: string; description: string; icon: string
  category: PluginCategory         // 扩：'browser' | 'comm' | 'media' | 'pet' | 'memory' | 'other'
  installSize?: string; features?: string[]

  // —— 新增：机器可读的装/卸描述 ——
  source: {
    npmPackage?: string            // 'wechat-mcp-win32-x64' | '@ffmpeg-installer/win32-x64'
    npmVersion?: string            // 跟随 SERVER_VERSION / 内置版本
    files?: { url: string; sha256: string }[]   // pet zip 直链
    mirrors?: string[]
  }
  target: { dir: string; entry: string }        // 相对数据根；entry = 就绪判据文件
  provides?: string[]              // 装了点亮哪些能力：'mcp:wechat-local' | 'screen-record' | 'pet:demo_cartoon_cat'
  defaultInstalled?: boolean       // 保底：迁移期老用户已装的可标 true（§7）
}
```

> `PLUGIN_REGISTRY` 从渲染层挪到 `shared/`，**主进程不再有第二份清单**。

### 4.2 生命周期状态机

```
absent ──install──▶ downloading ──完成+sha256校验──▶ ready
  ▲                    │ 失败/取消                      │
  └────── uninstall ◀──┴───────────────────────────────┘   (error 可重试)
```

- `ready` 判据：`target.dir/entry` 存在 **且** 有 `.lumii-complete`（含 `{completedAt, version, sha256}`，复用语音模块约定）。
- 下载中：`<entry>.part` + Range 续传；打标记前必须校验 sha256。
- `uninstall`：删 `target.dir` 整目录 + **执行反注册**（§4.4）。

### 4.3 `PluginManager`（主进程，取代硬编码）

新增 `main/plugins/plugin-manager.ts`，把 `setupCloakBrowserIpcHandlers` 的写法定式化为通用 IPC：

```
plugin:list                 → Array<{ id, def, status }>       // 清单 + 实时状态
plugin:install   (id)       → 下载→落位→标记→副作用注册
plugin:cancel    (id)
plugin:uninstall (id)       → 删目录→副作用反注册
plugin:progress  (event)    → { id, phase, percent, downloadedBytes, totalBytes, speed, mirror, error }
```

- 内核 = §3.2 的下载范式（多源测速 + `.part` 续传 + sha256 + `.lumii-complete`）。
- **CloakBrowser 迁到本机制**（`cloak-browser-progress` 并入 `plugin:progress`），消除唯一硬编码，顺带验证通用性。
- 渲染层 `PluginsContext/usePlugins` 改为调 `plugin:list/…`，`PluginCard` 基本不动（字段兼容）。

### 4.4 安装 = 下载 + 落位 + 标记 + **副作用注册**；卸载 = 删除 + **反注册**

| 插件 | 落位 | 安装副作用 | 卸载副作用 |
| --- | --- | --- | --- |
| cloak-browser | `~/.cloakbrowser/` | 无 | 无 |
| wechat-mcp | `<数据根>/mcp/wechat-mcp/` | 写 `mcp-servers.json` 的 `wechat-local` 条目（`enabled:true`） | 移除该条目（或置 `enabled:false`，见 §12-1） |
| ffmpeg | `<数据根>/tools/ffmpeg/` | 无（解析链自动命中） | 无 |
| pet:* | `~/.lumii/pet-models/<id>/` | 无（`mergePetRegistries` 自动扫到） | 无 |

**副作用注册统一走「插件声明的钩子」**，不在插件中心里写 if-else。

### 4.5 功能页与插件中心的分工

- **插件中心**：发现 + 安装 + 卸载 + 进度。**唯一安装入口。**
- **功能页**：使用与配置。
  - MCP 面板：装了才看到 `wechat-local`；没装时该 server **不出现**（不注册 = 不显示，无需占位）。
  - 宠物页：只列已装宠物；「更多宠物」入口跳插件中心。
  - 录屏：触发时若 ffmpeg 未装，提示「需要『本地媒体处理』插件」并给**跳转插件中心**的按钮（可带 `?focus=ffmpeg`）——**引导，不就地安装**。

## 5. 逐插件

### 5.1 反检测浏览器（已有 → 迁移）
现逻辑原样迁到 `PluginManager`；`plugin:list` 取代 `plugin:cloak-browser:status`。**验证通用机制的第一块试金石**。

### 5.2 微信本机助手（wechat-mcp）
- 源：`@lumii/wechat-mcp-win32-x64`（npm 平台包，含 `bin/wechat-mcp.exe`）→ npmmirror 加速。
- 落点：`<数据根>/mcp/wechat-mcp/wechat-mcp.exe`（**与 `getDeployedMcpExePath` 完全一致**）。
- 装：下载 + 写 `mcp-servers.json` 的 `wechat-local`（`presetToEntry` 复用）。
- 卸：移除/禁用该 MCP 条目。
- 不变量：`MCP_PRESETS` 里 `wechat-local` 的 `bundledExe` 语义由「随包拷贝」变为「插件安装后写入」，其余 MCP 链路（清单/开关/热重连/`McpServersPanel`）**零改动**。

### 5.3 本地媒体处理（ffmpeg）
- 源：`@ffmpeg-installer/win32-x64`（npm）→ npmmirror。
- 落点：`<数据根>/tools/ffmpeg/ffmpeg.exe`。
- 解析链最前插可下载落点：`LUMII_FFMPEG_PATH → <数据根>/tools/ffmpeg → 系统 PATH`（`screen-record/ffmpeg-runner.ts:41`）。
- 触发：录屏/旁白导出前 `ensure`；缺则引导去插件中心。

### 5.4 宠物包（卡通猫 / ug_official / xiaomai）
- **随包保留两只代表性的**：`mao_pro`(9.2) + `demo_moon_rabbit` 月兔小仙(51)，合计 ~60MB（2026-10-11 用户定，保「开箱即用」）。
- 其余三只移出随包、做成插件：`demo_cartoon_cat` 卡通猫(35) / `ug_official`(3.3) / `xiaomai`(3.0)。
- 源：GitHub Releases `pet-<id>-<ver>.zip`（含 `registry.json` 片段）；镜像前缀复用。
- 落点：`~/.lumii/pet-models/<id>/`（与 `mergePetRegistries` 一致，运行时零改动）。
- 卡片建议带缩略图（随包几百 KB，或装后显示）。

### 5.5 mermaid —— **不是插件**，是漏排除
`MermaidBlock.tsx:34` 动态 `import('mermaid')`，vite 已打进 `out/renderer`；但 `electron-builder.json` 排除名单里**没有 mermaid**（治理时排了 echarts/pixi/lottie，漏了 9-24 才加的它）→ asar 里那份 **37MB 是死重**。

```
// 顶层 files 追加（与已有 !node_modules/echarts/** 同款）
"!node_modules/mermaid/**",
"!node_modules/@mermaid-js/**"
```
按治理文档 §2 第 3 条「三条判据」验收（主进程无 require / 源码技能无 import / renderer chunk 确实含它）。**-40MB、零功能变化、零用户交互。**

## 6. 下载源与托管（国内用户优先）

**关键约束**：大部分用户在国内，直连 npm 官方 / GitHub 官方慢且不稳定。**镜像必须放首选**。

| 插件 | 首选源（国内） | 备用源 | 校验 |
| --- | --- | --- | --- |
| wechat-mcp | **npmmirror.com** tgz `@lumii/wechat-mcp-win32-x64` | registry.npmjs.org | `dist.integrity` |
| ffmpeg | **npmmirror.com** tgz `@ffmpeg-installer/win32-x64` | registry.npmjs.org | `dist.integrity` |
| 宠物 | **gh 镜像前缀**（`ghfast.top`/`gh.ddlc.top`/`gh-proxy.com`）`pet-<id>-<ver>.zip` | github.com 官方 | 清单内置 sha256 |

**下载策略**（复用 CloakBrowser 现有逻辑 `cloak-browser-downloader.ts:30-376`）：
1. 镜像前缀数组并发 **Range 测速**，择最快的（首字节延迟 < 50ms 优先）。
2. 单源 `fetch` 超时 10s，失败自动 fallback 下一源。
3. 不假设镜像永远可用——gh 镜像是社区维护，可能停服。

**托管产物发布**：
- wechat-mcp：`pack-wechat-mcp-npm.mjs --publish`（脚本已有）。⚠️ **2026-10-11 实测：`@lumii/wechat-mcp` 与 `@lumii/wechat-mcp-win32-x64` 在 npmjs / npmmirror 上均为 404——尚未发布**。P2 开工前必须先发布（需 npm 凭据），或改走 GitHub Releases 资产。
- 宠物 zip：新增 `pack-components.mjs` 产 zip，上传到 **§12-7 待核实的 GitHub repo**（`lanxiake/lumii` 或 `lumii/lumii`）的 Releases。若该 repo 不公开，改走**阿里云 OSS + CDN**。

## 9. 风险与权衡

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **泛化 `plugin-ipc.ts` 的工作量** | 主进程侧目前硬编码，泛化是 v2 新增成本 | 先拿 CloakBrowser 迁移验证（§5.1） |
| **信息架构** | 插件中心 vs 功能页可能让用户困惑 | 严守「装只在插件中心、用只在功能页」；未装给跳转引导 |
| **离线可用性下降** | 下载态组件无网不可用 | 默认宠物仍随包；下载前明确体积与来源 |
| **首次使用体验** | ffmpeg 录屏、微信首次要等下载 | 一键安装 + 进度条 + 续传；可在插件中心预装 |
| **托管成本** | 大二进制要托管 | npm 包用 npmmirror（阿里云全量镜像，国内标配）；宠物走 GitHub Releases + gh 镜像前缀（或阿里云 OSS，见 §12-5/7） |
| **国内可达性** | 直连 npm 官方 / GitHub 慢 | **镜像必须放首选**：npmmirror / ghfast.top 等；下载前并发测速（复用 CloakBrowser 逻辑） |
| **失败自愈** | 损坏/校验不过 | sha256 强校验 + `.part` 续传 + 失败清理 |
| **asarUnpack 白名单陷阱** | 配置层 `!` 排不掉 | 走 `before-pack.js` 删源文件 |

## 11. 验收判据

1. **体积**：逐期下降，记入体积治理文档。
2. **`verify:win-package all`**：asar 无越界项、启动四条就绪标记齐、`Cannot find module` 为 0。
3. **插件中心**：四个插件卡片可装/可卸；进度/取消/续传正常；卸载彻底（目录清空 + MCP 条目移除）。
4. **功能联动**：装 wechat-mcp 后 `list_sessions` 通、MCP 面板出现 `wechat-local`；卸后消失。装 ffmpeg 后录屏导出成功。宠物装上后可显示切换。
5. **迁移**：造「带旧 exe 的数据根」，升级后不重复下载、直接 ready。
6. **容错**：断网/半包/校验失败给明确错误与重试，不静默降级。

## 12. 拍板（2026-10-11）

> 用户授权「按推荐方案来」。以下为定稿。

1. **wechat-mcp 卸载语义 = 停用 MCP 条目（`enabled:false`），不删除**。⚠️ 2026-10-11 实测修正：原方案「删除条目」会留下「exe 已删但插件卡片还显示已安装 / MCP 面板条目凭空消失」的半死状态，且抹掉用户在面板里的调整。改为**停用**：非破坏、可逆，重装即恢复。用户**手工新增的其它 MCP server 不受影响**。
2. **wechat-mcp 首启不自动装**。微信相关调用失败（如 `poll_new`）时给明确引导「去插件中心安装（37MB）」；老用户靠 §7 迁移保 ready。
3. **ffmpeg**：插件中心为主入口、支持预装；录屏/旁白时若未装给**跳转引导**（不就地装）。
4. **默认随包宠物 = `mao_pro`(9.2) + `demo_moon_rabbit` 月兔小仙(51)**（两只代表性，2026-10-11 用户定）；其余 `demo_cartoon_cat`(35) / `ug_official`(3.3) / `xiaomai`(3.0) 移出随包做成插件。
5. **宠物托管 = GitHub Releases `lanxiake/lumii`**（公开库，见 #7）→ gh 镜像前缀有效。
6. **插件更新**：首期**随 App 版本**；独立自更新列入后续。
7. ⚠️ **「更新渠道不一致」= 确认是 bug**：实际 git remote 是 `git@github.com:lanxiake/lumii.git`，而 `electron-builder.json:334` 的 `publish` 写的是 `owner=lumii, repo=lumii` —— **二者不符**，会让 electron-updater 查错 repo（更新可能静默失效）。**建议单独一次修复改成 `lanxiake/lumii`**，不混进本期插件工作。
