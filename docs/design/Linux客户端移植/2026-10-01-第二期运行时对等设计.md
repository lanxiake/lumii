## §0 结论摘要

「运行时对等」指：Windows 上由内嵌运行时（内嵌 Python、uv 自动安装、PowerShell 安装脚本）或平台专有链路支撑的能力，在 Linux 上以系统运行时（系统 python3 + venv、curl|sh 配方、包内 ffmpeg/sherpa）等价落地。共四块：

| 工作流 | 一句话 | 相对调查文档的变化 |
|--------|--------|-------------------|
| **W1 ffmpeg** | 补 `LUMII_FFMPEG_PATH` 逃生口 + 系统 ffmpeg 兜底 | 文档原列「三级解析」，一期实测后降级为「补逃生口」（反思文档），本次确认该降级成立 |
| **W2 Python** | 系统 python3 + 应用 venv，技能页挂载点接线 | **不再依赖 `python3-venv` 包**（见 §0 实测 4） |
| **W3 uv / 编码 CLI** | Linux 安装配方 + 解除自动安装屏蔽 + 修文案回退缺口 | 与文档一致 |
| **W4 语音** | sherpa 链路在 Linux 启用（ASR + 本地 TTS）；Qwen3/克隆走 venv | **风险销掉**：asar 下 `.so` 加载已实测通过（见 §0 实测 1），原文「需实测」项完成 |

### 设计前完成的五项实测（2026-10-01，本机 + 9-23 打包产物）

| # | 实测 | 结果 | 影响 |
|---|------|------|------|

| 3 | 包内 ffmpeg 直接执行 | ✅ `@ffmpeg-installer/linux-x64`（4.1.0 静态版）`-version` 正常 | 打包链路无缺口；逃生口动机是「4.1.0 太老/用户想用新版」 |

## §1 范围与决策

### D21 · Linux Python 运行时 = 系统 python3 + 应用 venv

- **解释器**：系统 `python3`（要求存在；版本探测但不设硬门槛，venv/Torch 路径单独校验 ≥3.10）。不引入 python-build-standalone（+60MB，调查文档已列「首版不采用」）。
- **应用 venv**：`~/.lumii/runtimes/python-venv`，按需创建（首次有宿主级 Python 依赖需求时），**引导顺序**：
  1. `python3 -m venv <dir>`（系统装了 `python3-venv` 时一步到位）；
  2. 失败则 `python3 -m venv --without-pip <dir>` + 下载 `get-pip.py` 装入 pip（镜像同 `PYPI_MIRROR` 逻辑，与 Windows 内嵌流程同构）。
- **venv 的定位**：宿主级 Python 包的安装目标（模型下载器 modelscope、Qwen3 TTS 链路、Torch），替代 Windows 的 `python-embed`。**不是**技能脚本的强制解释器。
- Windows 侧零改动（内置 embed 链路原样保留）。

### D22 · 技能解释器链与依赖语义不变

- 解析顺序沿用 `python-runner.ts:45-70` 语义：**技能目录 `.venv` → 系统 python3 → 应用 venv（Linux 新增末级，对应 Windows 的 bundled 位）**。
- 宿主**不代装技能依赖**（现状全仓无 requirements.txt 处理逻辑，技能自带说明文档）。本期内不新增该能力。
- 系统无 python3 时：**不写指向不存在解释器的 shim**（修当前 Linux 假 shim 问题），矩阵 `missing-runtime` + apt 文案照旧。

### D23 · uv 在 Linux：官方脚本为主、venv pip 兜底

- 安装顺序：已装（探测）→ `curl -LsSf https://astral.sh/uv/install.sh | sh`（装到 `~/.local/bin`，无需 root）→ 失败且应用 venv 就绪时 `venv/bin/pip install uv`（PyPI 镜像，`mirrors.aliyun.com`/清华随环境）。
- 触发语义与 Windows 一致：MCP 需要 `uvx` 时按需安装，不新增确认弹窗（现状 Windows 也无确认；是否加确认属跨平台产品问题，本期内不做）。
- 检索目录：`~/.local/bin`、`~/.cargo/bin` 已在 `cli-user-path.ts:24-52` / `mcp-client.ts` 白名单；**补 `~/.lumii/runtimes/python-venv/bin`**（pip 兜底落点）。

### D24 · 编码 CLI（ACP tools）Linux 配方

- 四个工具各配 Linux 命令（**2026-10-01 已逐个探测，见实施计划 W3-0**）：

  | 工具 | Windows 现状（`coding-dev-cli-detect.ts:69-117`） | Linux 定案 |
  |------|--------------------------------------------------|-----------|
  | cursor | `irm 'https://cursor.com/install?win32=true' \| iex` | `curl https://cursor.com/install -fsS \| bash`（脚本实测可达） |
  | claude | `irm https://claude.ai/install.ps1 \| iex` | `npm install -g @anthropic-ai/claude-code`（官方 .sh 区域受限/非脚本，见 W3-0） |
  | codex | `irm https://chatgpt.com/codex/install.ps1 \| iex` | `npm install -g @openai/codex`（.sh 域不可达） |
  | opencode | `npm install -g opencode-ai` | 同 Windows（官方脚本在 GitHub 裸域，不可靠） |

- **执行原语**：新增 `main/platform/` 下的 `runShellCommand`（`bash -c` + 进程组 + 超时 kill，复用 `spawnChildInGroup`/`killProcessTree`），与 `runPowershell`（`coding-dev-cli-install.ts:211-268`）对位。ShellRunner 只接受脚本文件路径，不适用内联管道命令。
- **安装/卸载保持「用户点击才执行」**；卸载预览的 `automatic` 判据改为「该平台有命令」（`coding-dev-cli-install.ts:440`）。
- **修缺口**：`detectLocalAcpTool()`（`coding-dev-cli-detect.ts:377-385`）未过 `withPlatformInstallHints`，渲染层探测合并后 Linux 会显示 Windows 的 `irm ... | iex`——出口统一走 hints。

### D25 · ffmpeg：环境变量逃生口 + 系统兜底

- 解析顺序（`ffmpeg-runner.ts:22-30`）：`LUMII_FFMPEG_PATH`（显式指定，校验存在）→ `@ffmpeg-installer` 包内（现状）→ 系统 PATH `ffmpeg` → 报错。
- 动机：包内是 4.1.0（2018）静态版；用户想用发行版新版 ffmpeg（硬件编码/字幕滤镜较新）时现在无路可走。与 `LUMII_BROWSER_EXECUTABLE` 同一模式。
- `audio-duration.ts` / `channel/media-pipeline.ts` 同用该解析函数，自动受益。

### D26 · 语音：sherpa 链路启用，Qwen3/克隆依赖 venv

- **V1（不依赖 Python）**：
  - **ASR**：默认 provider 本就是 `local-paraformer`（sherpa），main 侧无平台守卫——**不改代码，改为验证并出报告**（模型下载 → wav 转写）。
  - **本地 TTS（MeloTTS / local-vits）**：解除矩阵屏蔽（`feature-availability.ts:147`），启用后由用户按现有流程下载模型。
- **V2（依赖 D21 的 venv）**：Qwen3 本地 TTS 与声纹克隆（克隆是 Qwen3 专属能力，见 `voice-service.ts:190-230`）：
  - `qwen3-tts-client.ts` 的「仅支持内置 Python」守卫改为「win32 用内置、Linux 用应用 venv」（`isAppManagedPython()`）；
  - **Torch 平台化按「Linux 首版 CPU-only」实施**（2026-10-01 定）：CPU 轮走 `pip install torch==2.5.1 --index-url …/whl/cpu`（命令本身跨平台，自动选轮）；CUDA 轮目录条目（win_amd64 专属）在非 win32 隐藏，GPU 偏好（`cuda`）在 Linux 显式报错「GPU 加速当前仅 Windows 支持」。按 venv Python 版本动态解析 cp 标签的 Linux CUDA 轮留待有真实 GPU 需求时再做（D6：GPU 本就是显式开关）；
  - `onnxruntime==1.20.1` 钉版（Win10 LoadLibrary 1114）改 win32 条件生效；
  - `modelscope-downloader.ts` Linux 链路改为 **venv 优先（不存在则就地创建）**，避免 PEP 668 externally-managed 报错。
  - **矩阵**：`voiceCloning` 在 Linux 由「平台不支持」改为「venv 未就绪 → `missing-runtime`（给初始化指引）」。

## §2 能力矩阵与探测扩展

`feature-availability.ts` 保持纯函数；新增探测输入（`FeatureProbeInput`）：

```
pythonVenvReady?: boolean   // 应用 venv 就绪（python + pip 可执行）
```

判定变化（Linux 分支）：

| 特性 | 现在 | 变更后 |
|------|------|--------|
| `pythonSkills` | python3 存在即可用（:141） | 不变（技能不强制 venv） |
| `codingCliAutoInstall` | 平台屏蔽（:144） | 取消屏蔽（有 Linux 配方） |
| `localTts` | 屏蔽（:147） | **可用**（sherpa 已随包实测可用） |
| `voiceCloning` | 屏蔽（:148） | venv 就绪可用；否则 `missing-runtime` + 初始化文案 |

文案表 `FEATURE_BLOCK_MESSAGES` 同步：`localTts` 文案删除/改写（它不再在 Linux 触发）；`voiceCloning` 文案指向 venv 初始化；`codingCliAutoInstall` 文案删除或仅留内部兜底。

**渲染层挂载点**（现状全部未接）：

1. **技能页**（`SkillsPage`）：`pythonSkills` 被屏蔽时，`runtime === 'python'` 的技能行禁用启用开关并显示 `getFeatureBlockMessage()` 原因。依赖把技能 `runtime` 暴露到渲染层（`useSkills.types.ts` 的 `InstalledSkillInfo` 当前无该字段，主进程 `skill-store.ts:85` 有——扩 IPC 类型 + hook 映射）。
2. **语音设置页**（`VoiceSettingsSection`）：现「MeloTTS / Qwen3 两项一起置灰」（:489,:674）拆开——MeloTTS 随 `localTts`，Qwen3/克隆随 `voiceCloning`。

**探测修复**：`detectSystemPython` 负结果 TTL 化（建议 30s，正结果保持缓存），并新增 `isPythonVenvReady()` 探测（venv python 存在 + `-m pip --version` 成功，负结果同样 TTL）。两处都保持 `_resetSystemPythonCache` 测试钩子语义。

## §4 验收标准

沿用一期口径：**Windows 零回归是硬门槛**（`test:all` 失败集合与基线一致：Linux 基线 2 文件 10 用例、Windows 基线全绿；本次改动若触碰 main，两侧都要跑）。

逐工作流验收：

| # | 项 | 判据 |
|---|----|------|
| W1.1 | `LUMII_FFMPEG_PATH` 生效 | 指到自备 ffmpeg → 录屏/时长解析使用之（单测 + 打包产物实测：塞一个改版 ffmpeg 到临时路径，断言 `-version` 被调用） |
| W1.2 | 回退链正确 | 环境变量无效 → 回退包内；包内缺失 → 回退系统；全缺 → 现有报错 |
| W2.1 | venv 可建（无 python3-venv 环境） | --without-pip + get-pip.py 路径产出可用 pip（本机即此环境，直接验） |
| W2.2 | shim 与解释器链 | 无 python3 时不再写坏 shim；有 python3 时技能用系统解释器；技能自带 `.venv` 优先 |
| W2.3 | 技能页置灰 | 模拟无 python3（探测注入）→ python 技能禁用 + 文案；有则恢复 |
| W2.4 | 缓存失效 | 探测失败 → 装 python3 → **30s 内**矩阵翻转（不重启应用） |
| W3.1 | uv 安装 | 本机（无 uv）走通官方脚本或 venv pip 兜底，`uvx --version` 可解析 |
| W3.2 | 编码 CLI 安装/卸载 | 至少 claude/opencode 之一真机走一遍（网络允许时）；卸载预览 `automatic=true` |
| W3.3 | 文案缺口修复 | Linux 下 `listLocalAcpToolsMetadata` 与 `detectLocalAcpTool` 两路出口都不再出现 `irm ...` |
| W4.1 | ASR | 模型下载（paraformer-zh-small + silero）→ 用 TTS 产物 wav 转写命中预期文本 |
| W4.2 | 本地 TTS | MeloTTS 模型下载 → 合成出 wav（`ffprobe` 验证时长/编码） |
| W4.3 | Qwen3/克隆（V2，视进度） | venv 就绪后 qwen3 引擎可选用；克隆开关在 Linux 可开（模型下载允许范围内） |
| 通用 | Windows 零回归 | `pnpm --filter ./apps/windows test:all`（Linux 侧）失败集合不变；改到的 win32 分支有单测且语义不变 |
