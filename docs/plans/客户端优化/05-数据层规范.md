## 二、技术方案

### 2a · 子片拆分（本片整体拆为三段，各自独立推进/结算）

| 子片 | 范围 | 体量 | 风险 |
|---|---|---|---|
| **5A · hooks 样板收敛** | 16 个候选逐个判定形态 → 查询型迁 `useQuery`、动作型视情况迁 `useMutation`、复杂型豁免并登记理由 | 约 4.9k 行存量，逐批迁移 | 中 |
| **5B · 调用点 → services 收敛** | 169 处/54 文件按页面域建 service、逐域替换；**不改 IPC 协议与行为** | 169 处 | 中 |
| **5C · 大 hook 评估** | `useWikiPage`(1304) / `useSkillStore`(738) / `useSettings`(343) / `useScreenRecord`(193) 只出评估报告（可否拆、拆哪、值不值），不动代码 | 只读 | 低 |

三段之间无硬依赖（5A 不搬 IPC 调用——与既有 4 个已迁移 hook 一致，queryFn 内仍可直接调 electronAPI；
5B 只处理 pages/components 的 169 处，两段范围不重叠，可任意顺序）。

### 2b · 5A 迁移规范（每批执行时遵守）

1. **先判定形态**：读完整 hook（不是 grep），按 1.1 表分类；适配才迁，不适配记录「豁免 + 理由」。
2. **行为等价三件套**：
   - loading/error 语义映射（`useQuery` 的 `isLoading` 与手写 `setLoading` 的时序差异需逐点核对：初始挂载即加载 vs enabled=false 不加载、silent 刷新不闪 loading）。
   - 竞态处理对照：`useQuery/useAsync` 内置 requestId 竞态保护，替换手写实现时**不能削弱**原有的竞态语义（如原来就没保护的可借势加固，但要登记为行为差异）。
   - `refetch` 与原有 `refresh` 的对外 API 兼容（返回名/参数/是否 await）。
3. **返回值形状不变**：hook 对外返回的对象键名尽量保持（消费方不改），除非同批一起改。
4. **验证**：typecheck + build + 受影响消费方的相关测试 + 人工冒烟点（该 hook 对应页面）。
5. **每批 2-4 个 hook**，独立提交、独立回滚。

### 2c · 5B 收敛规范

1. **按域建 service**（候选）：`skills-service`（SkillsPage 8 + SkillsContext 12 + useSkills/useSkillStore）、
   `settings-service`（SettingsPage 63，最大，需再拆子批）、`chat-files-service`（ChatPage 41）、
   `dashboard-service`、`agents-service`、`storage-service` 等；service 只做「IPC 薄封装 + 错误归一」，不做状态管理。
2. **替换一个域、提交一次**；域内先建 service → 再逐文件替换调用点（可再分批，如 Settings 按子页拆）。
3. **行为等价**：错误路径（原来 `catch` 后吞掉/提示/回退的）逐点核对；原代码里 `window.electronAPI?.xxx` 的可选链语义
   （API 不存在时静默返回）需在 service 中保留或显式登记差异。
4. **残留扫描**：每域完成后对该域目录复扫 `window.electronAPI`，非白名单（如 `useAgentRuntime` 命令通道等）应归零。
5. **验证**：typecheck + build + 该域相关测试 + 人工冒烟。

### 2d · 每批通用验证

- `pnpm typecheck`（apps/windows）+ `pnpm build` 必过；
- 渲染层全量测试对比基线（当前 21 失败，见 §1.4）；
- 残留扫描脚本（import 解析 + 字符串扫描双保险，沿用第 2/3 片教训）；
- 视觉无变化（本片不应有任何像素级变化；若出现，按原则 3 登记）。

- 不改任何 IPC 协议 / 主进程代码 / `window.electronAPI` 的 preload 定义。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| `useQuery` 的 loading 时序与手写不一致 → UI 闪动/卡死 | 每 hook 迁移前把「何时 setLoading(true/false)」逐点列出来对照；有初始即加载语义的用 `enabled` + 缓存初值对齐 |
| 手写竞态保护被削弱（useMemPalace/useWikiPage 类并发场景） | 只迁移能证明「useQuery 竞态保护 ≥ 原实现」的 hook；不能证明的豁免 |
| 消费方巨多（useWorkspaceVcs 有 8+ 消费文件） | 保持对外返回形状不变；每批跑该域测试 |
| 5B 替换调用点时的错误路径差异（吞错/提示） | service 层默认保留原 catch 行为；差异点逐条登记在提交信息 |
| 大 hook 被硬拆导致回归 | 5C 只评估不执行；确需拆分另立专项 |
| 与在途并行开发的冲突 | 每批独立小提交（pathspec 限定）、可单独回滚；不碰未提交的他人改动 |

## 六、决策记录（2026-09-12 已确认）

1. **推进顺序：先 5A hooks**，再 5B（services），5C 评估报告随时可出。
2. **hook 迁移原则：先判定形态，复杂型豁免**——查询型迁 `useQuery`；动作型视情况 `useMutation`；`useWikiPage`/`useSkillStore`/`useSettings`/`useScreenRecord` 只出评估（5C），豁免理由登记在本文档。
3. **测试策略：差异点才补测试**——基准验证为 typecheck/build/消费方既有测试/人工冒烟；仅当迁移中发现行为差异（竞态语义、loading 时序等）时为该 hook 补最小回归测试。

## 七、5A 执行记录（2026-09-12）

### 7.1 已迁移（5A-1，提交 `bf2a8a9`）

| hook | 迁移内容 | 行为等价说明 |
|---|---|---|
| `useProjectGitStatus` | 改 `useQuery({queryKey:['project-git-status', projectName], enabled:!!projectName})` | `projectName` 为空时对外恒为 null（local 收敛，与原实现一致）；附带获得竞态保护。顺带删除从未被消费的 `loading`/`refresh` 返回值 |
| `useWorkspaceVcs` | 历史/未提交变更两个查询改 `useQuery` 承载状态；`enabled:false` + `refresh()` 显式驱动 | 刻意不用挂载自动加载：主进程 `ensureInit` 首次并发会两次通过未初始化检查、产生**重复初始提交**，必须保持「先 ensureInit 再查询」顺序；`refresh` 用 `Promise.allSettled` 保持「单查询失败不向调用方抛错」原语义；loading/error 只映射历史查询（未提交变更静默），与原实现一致 |

验证：typecheck + build 通过；`useWorkspaceVcs.test.tsx`（4 用例）与 `WorkspaceWorkbenchCoordination.test.tsx`（2 用例）通过；渲染层全量测试 21 失败 = 基线，零新增。

### 7.2 16 个候选的形态判定结果（5A 收尾结论）

**关键系统性发现**：自研 `useQuery`/`useAsync` **没有 setData/乐观更新能力**（只读查询可用；查询结果一旦需要被本地动作原地更新就迁不动）。因此「查询结果会被本地动作原地更新」的 hook 一律豁免；强行迁移只能靠「动作后 refetch」，会引入多余 IPC 与列表闪烁，属行为差异。

| hook | 判定 | 理由（决定性的那一条） |
|---|---|---|
| `useProjectGitStatus` | **已迁移** | 纯查询 |
| `useWorkspaceVcs` | **已迁移（查询部分）** | 纯查询 + ensureInit 顺序约束已处理 |
| `useSoul` | 豁免 | 加载+保存混合：保存后用响应原地更新 soul（无 setData） |
| `useUserMemory` | 豁免 | 同上（含草稿与 30s 自动保存，非查询问题） |
| `useMemoryUsage` | 豁免 | 无数据状态（命令辅助型）：listMemories 由消费方自行调用持数，loading 仅装饰 |
| `useAgentFiles` | 豁免 | 分页追加 + 搜索 + 乐观删除；已自带 requestId 竞态保护，useQuery 无 append/setData |
| `useToolSearch` | 豁免 | 乐观切换 enabled 需原地更新 tools 列表（失败时才 refetch） |
| `useCodingDevProjects` | 豁免 | 建/开/删动作直接返回全量列表并原地 setProjects/setActiveProject |
| `useCronJobs` | 豁免 | 轮询（silent）+ 乐观删除本地 filter；fetchingRef 防并发与 useQuery 轮询语义不一致 |
| `useAuditLog` | 豁免 | loadMore 追加分页 + stats/config 多查询混合；clearLogs 已用「动作→重查」模式 |
| `useAgents` | 豁免 | 列表 + 选中态（localStorage 恢复）+ CRUD 动作改列表；另有 definitionSync 小型查询 |
| `useMemPalace` | 豁免 | 安装阶段/进度/分页/搜索多状态机 |
| `useSettings` | 豁免（5C） | 分类设置 + 节流保存，复杂型 |
| `useSkillStore` | 豁免（5C） | 738 行多子域状态机 |
| `useWikiPage` | 豁免（5C） | 1304 行超复杂状态机 |
| `useScreenRecord` | 豁免（5C） | 录音事件驱动状态机 |

**结论**：16 个候选中 2 个完成迁移，14 个按决策 #2 的「形态判定」原则豁免（其中 4 个列入 5C 评估）。
若后续希望继续收敛这批 hook，前置动作是给 `useAsync`/`useQuery` 增加 setData（含缓存写入）——属独立基础设施改动，未在本片执行。
