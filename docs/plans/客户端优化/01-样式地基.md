## 三、任务 1a · tokens.css 死定义清理

### 现状

`styles/tokens.css`(429 行) 含三个 `:root` 块：

| 块 | 行 | 定义数 | 职责 |
|---|---|---|---|
| 块1 | 9-292 | 199 | 原始定义（颜色刻度、间距、字号、z-index、旧别名…） |
| 块2 | 302-399 | 69 | **兼容映射层**：把旧 `--color-*` 名重新指向 `--mt-*`（后加载，同权重胜出） |
| 块3 | 404-410 | 5 | RGB 原始值（供 rgba 构造） |

**问题**：块1 中有 **66 个变量**被块2 重新定义。同为 `:root`、同权重，后声明的块2 胜出 → 块1 那 66 行是死定义。危险在于任何人（或 AI）去改块1 里的品牌色/圆角/阴影，**改了不生效**。

另有 1 条失真注释：文件头 `Generated from TypeScript tokens` —— 生成源已于 2026-08-25 删除（commit `03a853c`），现为纯手写文件。

### 处置

1. 删除块1 中这 66 个变量的定义行（**块2、块3 不动**）：

   | 分组 | 变量 | 数量 |
   |---|---|---|
   | 主色阶 | `--color-primary-500/600/700/900` | 4 |
   | 主色透明变体 | `--color-primary-500-5/10/15/20` | 4 |
   | 语义色 ×4（light/base/dark） | success / warning / error / info | 12 |
   | 背景 | `--color-bg-primary/secondary/tertiary/elevated/overlay` | 5 |
   | 文字 | `--color-text-primary/secondary/tertiary/disabled/inverse` | 5 |
   | 边框 | `--color-border/--color-border-light/--color-border-dark` | 3 |
   | 字体族 | `--font-family-sans/--font-family-mono` | 2 |
   | 阴影 | `--shadow-sm/''/md/lg/xl/2xl/inner` | 7 |
   | 圆角 | `--radius-sm/''/md/lg/xl/2xl/3xl/full` | 8 |
   | 过渡 | `--transition-fast/normal/slow/slower` | 4 |
   | 旧别名 | `--color-primary(--hover)` `--bg-*` `--text-*` `--border-color` `--border-radius` `--font-family` | 12 |

2. 更新文件头注释：说明"两层结构"（块1 = 存量原始定义；块2 = 映射层，指向 `--mt-*`），删除失真的 "Generated from TypeScript tokens"。

### 为什么是零视觉变更

CSS 级联规则：同选择器、同权重时**后者胜**。被删的 66 行全部是"已经输掉"的声明；删除后块2 的声明仍是唯一胜出者，`getComputedStyle` 取值不变。注意一个是易错点：即使块2 的 `var(--mt-*)` 引用链断裂，CSS 规范也不会回退到块1 的值（custom property 引用无效 → 计算值失效），所以不存在"靠块1 兜底"的隐藏依赖。

### 验证

见第五节「1a 等价性证明脚本」。

| 57-62 | `.chat-sidebar/.chat-toolbar { user-select:none }` | **删** | 这两个类名以 CSS Modules 使用（`ChatSidebar.module.css:2`、`ChatPage.module.css:81`），构建后被哈希，字面类名永不匹配 → 已是死规则；组件内部 `ChatSidebar.module.css:217/298` 已各自管理 user-select |

## 五、任务 1c · 未定义变量补齐

### 现状

全仓扫描（1688 个文件）：**63 个变量被引用但从未定义**（另有 8 个是 JS 运行时注入的正确用法，不动；`--x`/`--font-size-` 2 条为注释误报，忽略）。引用时各写各的 fallback，导致品牌色在界面上不统一、且**主题切换时这些颜色不变**。

既有先例：`tokens.css:330-337` 已为 `--color-accent` 系列做过同样的事（注释记录了 6 种不同蓝 fallback 的问题）。

### 分类处置

| 桶 | 内容 | 数量 | 处置 |
|---|---|---|---|
| **A · 别名遗漏** | `--color-bg-hover`(28×)、`--text-tertiary`(9×)、`--font-mono`(7×)、`--color-primary-rgb`(7×)、`--color-surface-hover`(6×)、`--bg-code`(4×)、`--color-text`(3×)、`--border-radius-lg`、`--spacing-xl` 等 | ~30 | 在 tokens.css 映射层（或旧别名区）补齐，指向对应 `--mt-*` / `--color-*`。多数与现有 fallback 值接近，视觉变化小 |
| **B · `--mt-*` 笔误/漏定义** | `--mt-accent`(8×)→`--mt-accent-500`、`--mt-danger`(5×)→`--mt-error`、`--mt-primary`(4×)→`--mt-accent-500`、`--mt-fw-normal`→`--mt-fw-regular`、`--mt-border-1`、`--mt-space-1-5`、`--mt-bg-hover`、`--mt-bg-3` 等 | ~10 | **修正使用处**（改名为正确的 `--mt-*`），不在设计系统里补别名 |
| **C · 语义色变体** | `--color-danger`(23×)→`--mt-error`、`--color-success-bg`(7×)、`--color-danger-600`(6×)、`--color-warning-bg/text/border`、`--color-error-bg`、`--color-info-bg/border`、`--color-primary-light/subtle/bg` 等 | ~20 | 映射到 `--mt-*` 语义色的对应档位；无对应档位的用 `color-mix()` 或就近档位（逐项登记） |
| **D · 运行时注入（不动）** | `--mood-*`(5，MoodAvatar.tsx:92-96)、`--progress`(AudioPlayer.tsx:107)、`--mt-p`(Gauge，配 `@property`)、`--wiki-subtopic-bar-height`(WikiTab.tsx:497-502) | 8 | 正确用法，仅登记说明 |
| **E · 组件局部（保留）** | 自带 fallback 且无主题语义的组件私有变量（如 `--chat-content-max-width`） | ~3 | 就地保留，仅登记 |

**注意**：7 处 `--color-bg-active` 与 2 处 `--mood-accent` 类引用**不带 fallback** —— 按 CSS 规范，这些声明当前**整体无效**（属性不生效）。补齐变量后它们会**开始生效**，属可见变化，必须逐处列出。

### 检查点（执行时先审后用）

执行第一步先产出**逐项对照表**（变量 → 引用次数 → 主要引用文件 → 当前 fallback → 拟映射目标 → 预期视觉变化等级），交你过目后再落盘。避免"批量映射一时爽，界面变样没人认领"。

## 七、风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 1a 删错行导致某变量失去定义 | 低 | 等价性脚本兜底；被删者若真"胜出"会立刻被断言抓出 |
| 1b 删除的规则其实有隐藏使用者 | 低 | 已逐名检索；`data-tooltip` 无任何 tsx/html/ts 命中 |
| 1b 滚动条/焦点环视觉变化不符合预期 | 中低 | 已列入"预期视觉变化"清单，冒烟确认；不满意可单点恢复 |
| 1c 补齐变量后界面局部变色 | 中 | 检查点先审对照表；无 fallback 的 9 处单独列出 |
| 主题切换后颜色仍不对 | 低 | 1c 本来就为此而做，可用亮/暗切换验证 |

**回滚**：三个任务各自独立 commit，`git revert <hash>` 单片回退互不影响。
