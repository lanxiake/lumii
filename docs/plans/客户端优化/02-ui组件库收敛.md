## 一、复核结论（两条推翻了旧结论）

### 1. 六个零引用组件：确认零使用

| 组件 | 规模 | 外部 import | JSX 使用 | git 历史 |
|---|---|---|---|---|
| Avatar | 143 行 | 0 | 无 | 初始提交引入，此后从未修改 |
| Divider | 100 行 | 0 | 无 | 同上 |
| Radio | 197 行 | 0 | 3 处 `<Radio>` **均为 lucide-react 图标** | 同上 |
| Responsive | 280 行 | 0 | 无 | 同上 |
| Skeleton | 121 行 | 0 | 无 | 同上 |
| Table | 175 行 | 0 | 无 | 同上 |

合计约 **1016 行**（含各自 module.css）。唯一"引用"是 `ui/index.ts` 的桶导出条目本身。

### 2. 推翻旧结论：桶导出**并非** 0 消费者

`components/ui/index.ts` 被 **6 个文件**以 `from '../ui'` 消费：`McpServersPanel/{index,McpConfigFileModal,McpServerEditModal}.tsx`、`ScreenRecord/{RecordingSubtitleEditor,ScreenRecordConfirmDialog,ScreenRecordPanel}.tsx`。此前统计写死了 `components/ui` 子串，漏掉相对路径写法 → **桶导出必须保留**，只删死条目。

### 3. Button 的真实使用面

46 个文件 import、142 处 JSX（不是"没人用"）。但全仓仍有约 400 处原生 `<button>`，其中一部分自造了变体系统（如 SessionFileList 的 `.btn` / `.btnPrimary` / `.btnDanger`），与 Button 已有的 `secondary/primary/danger` + `sm/md/lg` 重复。

### 4. 依赖链检查

- `styles/tokens/breakpoints.ts` 的唯一消费者是 `Responsive.tsx`；但 `tokens.css:150` 注释将其指定为"断点常量来源"（建议保留，见 2a 决策点）
- 6 个组件无任何 CSS/工具文件的交叉引用；`Table.tsx` 引用 `Empty`（方向安全）

## 二、方案

### 2a · 死组件清理（需确认）

1. 删除 6 个组件目录（12 个文件，约 1016 行）：
   `ui/{Avatar,Divider,Radio,Responsive,Skeleton,Table}/`
2. 删除 `ui/index.ts` 中对应导出条目（约 12 行）
3. 同步更新 `docs/standards/component-standards.md` 的「现有 UI 组件」表（移除 6 行，21 → 15 个）
4. **决策点**：`styles/tokens/breakpoints.ts`（约 30 行）是否一并删除
   - 保留：它是 `tokens.css` 注释指定的断点常量来源，体积小
   - 删除：删掉 Responsive 后它零引用，符合"零引用即清"原则
   - 建议：保留
5. 验证：`pnpm typecheck` + `pnpm build`；6 个桶导出消费者仅使用 `Button/Empty/Input/Loading/Switch/Modal`，不受影响

### 2b · 缺口补充（原则：先有采用场景，再建组件）

**不预先创建** IconButton / Tabs / Segmented —— 否则重演"建而不用"（本轮刚清掉 6 个这样的组件）。
执行 2c 试点时若确需 icon-only 按钮或分段控件，再按需补，且必须同批有实际采用点。

### 2c · 按页替换试点：SessionFileList（1 个文件，4 个按钮）

| 现状 | 目标 |
|---|---|
| `.btn`（基础）| `ui/Button` `variant="secondary"` `size="sm"` |
| `.btnPrimary`（下载）| `variant="primary"` |
| `.btnDanger`（删除）| `variant="danger"` |
| `.inlineMoreBtn`（更多）| 保留（特殊交互，不在本试点） |

- 同步删除 `SessionFileList.module.css` 中被替换的变体样式块
- 风险：视觉可能细微变化（本地紧凑样式 vs Button sm 的 28px 高）→ 冒烟确认
- 这是"替换路径"的验证试点；通过后 AgentsPage 等其他页面另批进行

## 五、执行记录（2026-09-12）

### 2a · 死组件清理 ✅

- 经用户确认后删除 6 个组件目录（13 个文件，约 1016 行）+ `ui/index.ts` 12 行死条目
- `docs/standards/component-standards.md` 组件表同步（21 → 15 个）+ 快速参考 import 示例同步
- `breakpoints.ts` 保留（`tokens.css` 注释指定的断点常量来源）
- 验证：残留引用终检为空；`pnpm typecheck` 4 包全过；`pnpm build` 通过（bundle 6,389.45 → 6,387.26 kB）

### 2c · 按钮替换试点 ✅（试点对象由 SessionFileList 调整为 AutonomousPage）

**调整原因**：执行前复核发现 SessionFileList 的 `.btnPrimary`（淡色底+蓝字）/`.btnDanger`（透明底+红框）与 Button 现有变体语义不符——直接替换会把紧凑列表里的次级操作变成实心蓝/实心红，属界面重设计而非收敛。而 AutonomousPage 的 `.btnPrimary`（实心蓝+白字）/`.btnSecondary`（描边透明）与 Button 的 `primary`/`ghost` **语义完全一致**。经用户确认改此文件为试点。

**实际改动**：
- 4 个按钮改用 `ui/Button`（`primary`/`ghost`，`size="md"`）：重置规划、保存设置、批准并执行、拒绝
- 删除 `.btnPrimary`/`.btnSecondary` 及其 hover 共 7 个样式块（31 行）；保留两个纯布局类 `.flexBtn`（flex:1）/`.saveBtn`（min-width:120px）
- 验证：无残留引用；typecheck 通过；build 通过

**预期视觉变化（冒烟时确认）**：

| 项 | 原 | 新 |
|---|---|---|
| 字号/字重 | 12px / 600 | 14px(md) / 500 |
| 高度 | ~34px | 36px |
| 次要按钮 hover | 描边与文字变蓝 | 灰底填充 + 文字变亮（ghost 标准行为） |
| 禁用态 | 无视觉反馈 | 0.5 透明 + not-allowed（新增，replanning/saving 时可见） |

### 遗留（下一批）

- SessionFileList / CreateJobModal 等"淡色/描边"风格按钮：若要收敛，需先决定是否给 Button 增加 `soft` / `soft-danger` 变体（属设计系统决策）
- 其余页面的原生按钮（AutonomousPage 尚有 20+ 处非标准按钮，如 tab、图标按钮）
