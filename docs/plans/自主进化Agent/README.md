## P3 的由来（重要）

P3 的实际起点与原路线图设想不同。经代码核查，P2 交付的四个协同算法模块（`coordinated-scheduler`、`conflict-detector`、`pareto-frontier`、`shapley-attribution`）**仅在 `index.ts` 导出，无任何业务代码消费，且全为无持久化的内存态**；`apps/windows/src` 对整个 autonomous 模块的引用数为 **0**。

因此 P3 = 让已有算法真正连上电，而非再造新算法：

- **主线 A：协同闭环落地（必做）** — `CoordinationController` 有状态门面 + V31 状态持久化 + 配置下发 + Electron 主进程接线
- **主线 B：审批链路实施（必做）** — 离线审批架构 A1–A8，解开"目标生成后无人可批、占满配额、不再生成"的进化死锁
- **主线 C：多 Agent 自组织（选做）** — 设门控条件：主线 A 稳定运行 2 周且观测到探索排队才启动
