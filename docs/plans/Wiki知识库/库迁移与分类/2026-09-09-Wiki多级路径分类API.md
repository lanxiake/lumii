# Wiki 多级路径分类 API 文档

## 数据结构

### WikiSource

```typescript
interface WikiSource {
  id: string
  agent_id: string
  user_id: string
  title: string
  source_path: string | null
  source_url: string | null
  media_type: string
  mime_type: string | null
  extracted_text: string | null
  origin_context: string | null
  
  // 分类字段
  topic_category: string | null      // 大类：工作、学习、生活、收藏
  topic_subtopic: string | null      // 小类：开发、文档、在学等
  topic_project: string | null       // @deprecated 已废弃，使用 user_path 替代
  
  // 新增字段
  user_path: string | null           // JSON 数组：多级用户路径
  tags: string | null                // JSON 数组：标签列表
  description: string | null         // 文本：资料描述
  
  created_at: number
  updated_at: number
  use_count: number
}
```

#### updateSourceTopic

更新资料的分类信息。

```typescript
updateSourceTopic(
  agentId: string,
  userId: string,
  sourceId: string,
  category: string,
  subtopic: string | null,
  options?: {
```

```typescript
const updated = repo.updateSourceTopic(
```

## 数据库迁移

### V39 迁移

```sql
-- 添加新字段
ALTER TABLE wiki_sources ADD COLUMN user_path TEXT;
ALTER TABLE wiki_sources ADD COLUMN tags TEXT;
ALTER TABLE wiki_sources ADD COLUMN description TEXT;

-- 重建索引
DROP INDEX IF EXISTS idx_wiki_sources_topic;
CREATE INDEX idx_wiki_sources_topic 
  ON wiki_sources(agent_id, user_id, topic_category, topic_subtopic);
```

**注意事项：**
- `user_path` 和 `tags` 存储为 JSON 字符串
- 读取时需要 `JSON.parse()`
- 存储时需要 `JSON.stringify()`
- NULL 和空数组的区别需要正确处理

```typescript
// 使用新特性

  tags: ['guide', 'tutorial']
```

### 3. 批量分类流程

```typescript
// 1. 扫描并分组
const groups = groupByDirectory(inboxItems);

// 2. 对每个组生成提示词
for (const group of groups) {
  const prompt = buildBatchClassificationPrompt(group, topicTree);
  
  // 3. 调用 AI
  const result = await callAI(prompt);
  
  // 4. 根据置信度决定
  if (result.confidence >= 0.8) {
    // 自动应用
    await applyClassification(group, result);
  } else {
    // 标记待审查
    markForReview(group, result);
  }
}
```

## 迁移指南

### 从旧的三级分类迁移

**旧格式：**
```typescript
{
  topic_category: '工作',
  topic_subtopic: '开发',
  topic_project: 'Lumii项目'
}
```

**新格式：**
```typescript
{
  topic_category: '工作',
  topic_subtopic: '开发',
  user_path: ['projects', 'Lumii'],
  tags: ['开发', 'TypeScript', 'Electron']
}
```

### 批量迁移脚本示例

```typescript
// 将 topic_project 转换为 user_path
const sources = repo.listAllSources();
for (const source of sources) {
  if (source.topic_project && !source.user_path) {
    repo.updateSourceTopic(
      source.agent_id,
      source.user_id,
      source.id,
      source.topic_category,
      source.topic_subtopic,
      {
        userPath: ['projects', source.topic_project]
      }
    );
  }
}
```

## 常见问题

### Q1: user_path 和 topic_project 的区别？

**A:** `topic_project` 是单层的项目名称，而 `user_path` 是多级的路径数组，支持任意深度的层级结构。

### Q2: 如何决定使用 user_path 还是保持 topic_project？

**A:** 新代码应该使用 `user_path`。`topic_project` 仅为向后兼容保留。

### Q3: JSON 字段的性能如何？

**A:** JSON 字段不建索引，适合展示和简单筛选，不适合大量的复杂查询。

### Q4: 可以同时使用 topic_project 和 user_path 吗？

**A:** 技术上可以，但不推荐。应该选择其中一种方式。
