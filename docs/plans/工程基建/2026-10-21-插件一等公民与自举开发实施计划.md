# 插件一等公民与自举开发实施计划

> 状态：**已确认，实施中**（2026-10-21）
> 关联：[插件化收尾与后续实施计划](2026-10-21-插件化收尾与后续实施计划.md)、
> [P5 插件中心与开发者工具](2026-10-20-P5插件中心与开发者工具实施计划.md)、
> [插件开发规范](../../standards/plugin-development-standards.md)
> 决策：页面壳**只做插件版**（不迁内置页）；Agent 写插件代码**复用 `file_write`**（不新增绕过权限的写入通道）。

---

## 0. 结论先行

三件事，都是「把已有的能力接完整」，不是新架构：

| 切片 | 问题 | 做法 |
|---|---|---|
| **S1 重启闭环** | 主进程扩展开关写盘后要重启才生效，UI 只说了一句「重启后生效」，没有入口 | 列表按「偏好 vs 启动快照」算出 `pendingRestart`，横幅 + 立即重启按钮，复用已有的 `requestAppRestart()` |
| **S2 自举开发** | Agent 能写文件（`~/.lumii` 已在 `getAllowedRoots` 里），但不知道插件契约、也看不到「有没有加载成功」 | 只读工具 `plugin_dev`（guide / status / check）+ 渲染层把加载状态上报主进程 |
| **S3 前端一等公民** | 插件页自己写 `padding:24`，而主内容区已有 20px，看起来比内置页「胖一圈」；格式化函数每个插件各写一份 | `api.Page`（与概览页同口径的壳）+ `api.format` + `api.storage` |

**明确不做**：插件构建/打包链（单文件、保存即热更，加构建链与目标相反）、主进程扩展运行时启停、
沙箱/权限体系、内置页迁移到统一壳。

## 1. S1 重启提示与入口

### 1.1 生效时机（事实）

| 类型 | 生效 | 原因 |
|---|---|---|
| 主进程扩展（内置 + `~/.lumii/extensions/`） | 重启后 | 启动时取出的 `perf/voice/...` 单例被十余处直接引用；语音 ONNX 顺序闸不可逆 |
| 客户端插件（`~/.lumii/plugins/`） | ≤1 秒 | 宿主每秒拉一次 `list.json`，开关随同一轮到达 |

### 1.2 实现

- `ExternalExtensionRuntime` 暴露 `startupDisabledIds()`（构造时那张禁用表的只读快照）。
- `ExtensionControl.list()` 每行加 `pendingRestart`：
  - 内置：`prefs.enabled !== host.get(id) 是否存在`；
  - 外部：`prefs.enabled !== !startupDisabledIds().has(id)`。
  - 用「偏好 vs 启动快照」而不是组件内临时状态：切走再回来、重开设置页都能正确显示。
- IPC `extension:restart`：`setupExtensionIpcHandlers({ restart: requestAppRestart })`；
  preload `extensions.restart()`。
- 设置 › 扩展：存在待重启项时顶部横幅「N 项改动待重启生效」+「立即重启」；执行中禁用按钮。

### 1.3 验收

- [ ] 关掉一个内置扩展 → 该行立刻显示「已禁用」，顶部出现横幅；
- [ ] 切到别的设置页再切回来，横幅仍在；
- [ ] 点「立即重启」→ 客户端重启，扩展不再启动，横幅消失；
- [ ] 没有改动时不显示横幅（不误报）。

## 2. S2 Agent 自己给自己开发插件

### 2.1 已有前提（实测）

- `file_write / file_edit` 的写入白名单已包含 `~/.lumii`（`index.ts:419`，2026-10-09 决策）；
  因此 Agent **不需要新的写文件通道**，权限确认沿用现有 `file_write`。
- 客户端插件与主进程外部扩展都是**单文件、无构建**，保存后分别约 0.3s / ≤1s 生效。
- 主进程扩展的运行时状态在 `ExternalExtensionRuntime.inspect()` 里；
  **客户端插件的加载结果只在渲染层**（语法错误、槽位撞 id），主进程看不到。

### 2.2 新增工具 `plugin_dev`（只读，`needsPermission: false`）

| action | 返回 |
|---|---|
| `guide` | 绝对路径（plugins/extensions 根）、热更时效、两种模块契约、槽位表、`api` 全量、硬规则、工作流、**无构建步骤**、持久化约定 |
| `status` | 外部扩展的 `state/error` + 渲染层上报的客户端插件 `state/error/reportedAt`；渲染层从未上报时如实说明 |
| `check {kind, id}` | 静态体检：`plugin.json` 合法性、`client.js` 语法、是否恰好一次注册、注册 id 与 `plugin.json`/目录名一致、槽位 id 前缀与已知槽位、硬编码十六进制色、不支持的 `import/require`；附运行时错误 |

`check` 的错误返回 `ok:false`（`jsonToolResult` 据此置 `isError`），warning 不置错。

### 2.3 渲染层状态上报

- `client-plugin-host` 在 `rebuildStates()` **签名变化时**调用
  `window.electronAPI.extensions.reportClientStates(states)`；
- 主进程 `ipcMain.on('extension:client-states')` 做类型清洗、条数上限（200），存模块级快照；
- 只在变化时发，避免每秒一次 IPC。

### 2.4 持久化

- 客户端插件：`api.storage`（按插件 id 前缀命名空间的 localStorage；get/set/remove/keys/clear）。
- 主进程扩展：约定写 `~/.lumii/plugin-data/<id>/`（已在可写白名单内，直接用 node fs）。

### 2.5 提示词分组

- `plugin_dev` 归入 `SELF_CONFIG_TOOLS`，补 `TOOL_SUMMARIES`；
- `bridge-tool-prompt-groups.test.ts` 的扫描清单加入新源文件（否则落进 Other Tools 无人发现）。

### 2.6 验收

- [ ] Agent 调 `plugin_dev guide` 能拿到可直接写盘的两个根路径与完整契约；
- [ ] 写一个语法错误的 `client.js` → `plugin_dev status` 能看到渲染层上报的具体错误；
- [ ] `check` 能分别抓出：缺注册、注册两次、id 不一致、未知槽位、硬编码色；
- [ ] 生成的插件在 `~/.lumii/plugins/` 里，重启客户端后仍在。

## 3. S3 插件页面前端

### 3.1 页面壳 `api.Page`

根节点与概览页同口径：

```css
max-width: var(--mt-page-max); margin: 0 auto; height: 100%; min-height: 0;
```

**不额外加 padding**——`.main-layout-content-inner` 已有 20px。标题/副标题/操作区 + 内容区自滚。
示例插件与 README 全部改用它。

### 3.2 格式化 `api.format`

`number / percent / currency / bytes / date / dateTime / relative`，中文口径。
放在 `renderer/utils/format.ts`，与宿主共用、可单测。

### 3.3 验收

- [ ] 示例插件页与概览页左右边距、最大宽度一致（不再多出 24px）；
- [ ] 深色/护眼/四档字号下只用令牌，无硬编码色；
- [ ] `api.format.bytes(1536)` 等边界有单测；`api.storage` 两个插件互不串 key。

## 5. S7 来源、兼容性与生命周期（2026-10-21 追加）

### 5.1 问题

客户端插件原来是三者里治理最弱的一环：`plugin.json` 只有 `{id,name,version}`，
没有 engines、没有来源、面板里也无法打开/删除。Agent 写的插件与用户手写的完全无法区分。

### 5.2 实现

- `plugin.json` 扩容：`description / author / origin(agent|user) / engines.lumii`；
- 校验复用 `validateManifest`（结构 + engines），客户端 id 规则放宽为
  `^[a-z0-9][a-z0-9._-]*$`（允许目录名单段名，避免已有插件升级后突然不加载）；
- 清单错误 → `manifestError`（面板显示「失败」）；engines 不满足 → `incompatibleReason`
  （面板显示「不兼容」）；两种情况都**不激活**；
- revision 包含 `plugin.json` 的 mtime+size：只改清单也会触发热更新；
- 来源徽标：内置 / 外部 / Agent 创建；`plugin_dev guide` 要求 Agent 写 `origin:"agent"`；
- 生命周期：外部扩展与客户端插件支持「打开目录」「删除」（二次确认）；
  内置只允许禁用。删除外部扩展先卸载再删目录，并清掉禁用记录。

### 5.3 验收

- [x] 不兼容 engines 的插件不加载、面板显示原因；
- [x] Agent 生成的插件显示「Agent 创建」；
- [x] 删除客户端插件目录后行消失；删除外部扩展后不再被 `rescan` 扫回来；
- [x] 内置扩展没有删除按钮（IPC 层也拒绝）；
- [x] `plugin_dev check` 能报 manifest 错误与 engines 不兼容。

## 5.4 命名与依赖联动（2026-10-21 追加）

**问题**：设置里并排两个页签「插件」「扩展」，用户分不清；扩展依赖的外部组件
（录屏 → ffmpeg）也没有任何提示。

**做法**：

- 页签改名：`扩展` → **代码扩展**（主进程扩展 + 客户端插件）。数据模型不合并——
  两者生命周期不同；
- 清单新增 `requires: { assets, optional }`。扩展卡片显示「依赖/可选依赖：本地媒体处理
  （已安装/未安装）」，未安装时就地安装（可取消、显示进度），不再跳页签；
- 资产注册表从 `pages/PluginCenterPage/plugins-registry.ts` 移到
  `renderer/data/asset-plugins.ts`（功能页共用，避免反向 import 页面）。

**验收**：

- [x] 代码扩展卡片显示 ffmpeg 的安装状态；
- [x] 未安装时就地出现「安装」，不用离开代码扩展页；
- [x] 缺 ffmpeg 不影响录屏扩展激活（只是导出 MP4/烧字幕不可用）。

## 5.5 运行时组件拆到功能页（2026-10-21 追加）

**决策**：不再保留「运行时组件」页签。二进制/模型无法变成客户端插件，但安装入口
应该出现在使用它的地方：

| 组件 | 新入口 |
|---|---|
| CloakBrowser | 工具 › 浏览器控制 |
| ffmpeg | 代码扩展 › 录屏卡片依赖行 |
| wechat-mcp | MCP › 微信本机助手（可选组件） |
| 宠物模型 | 设置 › 宠物模式 › 形象资源 |

**实现**：

- `AssetPluginCard`（复用原 `PluginCard`，支持紧凑形态）挂在上述四个功能页；
- 状态来自全局 `PluginsProvider`，安装/取消/进度跨页面一致；功能页挂载时重扫一次；
- 删除 `PluginCenterPage` 与 `plugins` Hub 页签；
- 宠物形象安装后自动重扫模型列表（只看 installed 布尔组合，不看下载进度）。

**验收**：

- [x] 设置页只剩「代码扩展」一个相关页签；
- [x] 工具页、MCP 页、宠物设置分别出现对应组件卡片；
- [x] 录屏卡片可就地安装 ffmpeg（隐藏运行目录后显示「未安装/安装」，恢复后「已安装」）；
- [x] 宠物形象安装/卸载后模型下拉自动刷新。

## 5.6 官方外部扩展试点：perf（2026-10-21 追加）

**目标**：验证「可选功能不进主 bundle」的整条链路，为后续抽云同步/录屏/桌宠打样。

**做法**：

- `perf` 从 `BUILTIN_EXTENSIONS` 移出；
- `scripts/build-official-extensions.mjs` 用 esbuild 把它打成
  `resources/extensions/com.lumii.perf/main.js` + `build-info.json`（sha256）；
- 启动时 `syncOfficialExtensions()` 按 sha256 同步到 `~/.lumii/extensions/`：
  内容没变只读 marker、不碰用户目录；目标目录若是用户自己的（无 `.official.json`）拒绝覆盖；
- manifest 新增 `origin: 'official'`，列表显示「官方」；官方扩展只允许禁用，不显示删除；
- **顺序约束**：`index.ts` 必须在 `externalExtensions.loadAll()` 之后再读 `S.perf`
  （内置激活时它一定在容器里；外部加载时不是）；
- 外部校验没有 `builtin` 豁免，manifest 必须声明 `main`，模块必须有 `export default`。

**验证**：

- [x] 启动日志：`官方扩展已同步: com.lumii.perf` → `com.lumii.perf active` → `perf 服务: 就绪`；
- [x] 设置页显示「性能监控 / 官方 / 运行中」，无删除按钮；
- [x] 主 `index.ts` 的 perf 消费者拿到非空实例（`perf 服务: 就绪`）。

**未完成 / 下一步**：

- 分发仍随安装包（`extraResources`），**还没有按需下载**；真正减小安装包需要扩展目录清单、
  SHA256 校验与更新策略（原 S5）。
- `cloud-sync` 暂未外置：实现 2294 行且被多处模块级访问器引用。已先把
  `sync-accessor` 改成 `globalThis` 槽位，为外部 bundle 共享单例铺路；下一步再整体打包。

## 6. 风险

| 风险 | 处置 |
|---|---|
| `check` 对主进程 `main.js` 只能做静态近似（ESM 语法无法在 `vm.Script` 里编译） | 运行时错误以加载器 `inspect()` 为准，guide 里写明 |
| 渲染层上报依赖窗口存在 | `status` 返回 `reportedAt`，超时/缺失时明确说「渲染层未上报」，不假装没有错误 |
| dev 版重启会杀掉当前 dev 会话 | 复用 `lumii-ui restart` 同一条已验证路径；不新写重启逻辑 |
