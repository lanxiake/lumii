## 0. 目标

把**所有**插件按同一份规范梳理一遍，做到四件事：

1. **低耦合**：核心不 import 插件实现（只认服务访问器）；插件之间不运行期互相 import。
2. **高内聚**：一个插件的前后端代码、测试、界面都在它自己的目录里。
3. **统一**：内置 / 官方 / 用户三种来源用同一份清单、同一套生命周期、同一套能力。
4. **开放**：主进程与渲染层的扩展能力都对外提供——**外部插件也能同时有前后端两半**。

## 2. 规范 v2（目标形态）

### 2.1 一个插件包

```
<plugin>/
  plugin.json            LumiiPluginManifest（内置可写在 index.ts 里）
  main.js | index.ts     主进程半边（可选）
  client.js | renderer.tsx  渲染层半边（可选）
  ui/                    渲染层独占的组件/样式（内置与官方外部扩展都拆目录）
```

- 两半边**都可选**，但至少一个；两半边共用同一个 `id`。
- `manifest` 里用 `main` / `client.entry` 声明入口（已有字段，内置插件豁免文件路径）。

### 2.2 能力目录（插件能做什么）

| 层 | 能力 | 入口 |
|---|---|---|
| 主进程 | 服务 | `ctx.provide(S.xxx, impl)`；核心 `defineServiceAccessor` 现取 |
| 主进程 | IPC（请求/响应） | `ctx.registerIpc(ch, fn)` 或 `createIpcTable()` |
| 主进程 | IPC（单向） | `ctx.registerIpcListener(ch, fn)` |
| 主进程 | 事件 | `ctx.on / ctx.emit / ctx.waterfall` |
| 主进程 | 定时器/副作用 | `ctx.effect(dispose)` |
| 主进程 | 工具注册 | `ctx.get(S.agentRuntime)?.installXxxTools()`（返回 disposer） |
| 渲染层 | 槽位 | `api.registerSlot('app.view' / 'app.overlay' / 'app.titlebar.actions' / 'dashboard.*' / 'settings.category.<id>' / 'settings.channel.<渠道>' / 'settings.section.<名字>' / 'workspace.version', …)` |
| 渲染层 | 卡片 | `api.registerCard('type', renderer)` |
| 渲染层 | 设置项 | 实验项：`{id,title,Summary,Detail}` 登记到 `renderer/experiments.ts` |
| 渲染层 | 存储/格式化 | `api.storage` / `api.format`（客户端插件已有，内置插件补齐） |

**不提供**：权限/沙箱（D1/D2 不变）。

### 2.3 启停语义（统一）

```
extension:set-enabled → host.activate/stop（服务、IPC、定时器随作用域拆）
                     → plugin:state-changed {id, enabled}
                     → 渲染层：插件 setup/teardown（UI 消失，不是灰掉）
```

- 内置：已按此实现（`hot` 批次全量覆盖）。
- 外部扩展：✅ 已即时生效（阶段 3c）——加载器在启用时补 `register`+`activate`。
- 客户端插件：沿用 1 秒轮询（它们来自磁盘、可能被外部改动）。

## 6. 最终形态（2026-10-23）

### 6.1 目录

```
apps/windows/src/
  main/                 核心：kernel / ipc / agent-runtime / channel / 服务契约
  plugins/
    api/                核心 ↔ 插件的唯一入口（访问器 / IPC 表 / RendererPlugin 类型）
    builtin/<id>/       index.ts + renderer.tsx + ui/ + 该插件独占实现与测试
    external-src/<id>/  index.ts + impl/ + renderer.tsx + ui/
                        → esbuild 成 resources/extensions/<id>/main.js
    external/           外部扩展加载器（多根发现、1s 热重载、运行期启停）
    renderer/           渲染层运行时：启停状态源、槽位清单、实验项登记
  renderer/             宿主与**共享**渲染设施（不再有插件独占 UI）
```

`src/main/plugins/`、`src/renderer/pet/` 等历史落点已删除（2026-10-23）。

### 6.2 服务契约（核心持有，插件实现）

| 契约文件 | 内容 |
|---|---|
| `main/kernel/screen-record-contract.ts` | `ScreenRecordService` / `NarrateService` / `RecordingInspector` + globalThis 访问器 |
| `main/kernel/cloud-sync-contract.ts` | `CloudSyncManagerLike` / `SyncSchedulerLike` + globalThis 访问器 |
| `main/kernel/services.ts` | `S.*` 服务键（内置服务的类型只从这里来） |
| `plugins/renderer/state.ts` | 渲染层唯一的启停状态源（`extensions.list()` + `plugin:state-changed`） |

契约的目的只有一个：**插件停用后，核心拿不到实例并自然降级**。新插件接核心能力时，
先加契约再写实现——核心永远不 import 插件。

### 6.4 启停语义

所有来源一致：`extension:set-enabled` → 主进程作用域拆/挂 → `plugin:state-changed` →
渲染层 `PluginRuntime` setup/teardown 对应槽位条目。**UI 是消失，不是灰掉。**

- 内置插件：标 `hot: true` 的即时；其余重启。
- 官方/用户外部扩展：即时（加载器负责补 `register`/`activate`）。
- 客户端插件：渲染层 1 秒轮询清单。

### 6.5 已知边界（有意保留）

| 边界 | 原因 / 后续 |
|---|---|
| 官方外部扩展的渲染层半边随主包打 bundle | 外部 `client.js` 管线只支持 `__LUMII_REGISTER_PLUGIN__` + api 能力，不支持 TSX / 核心组件 / CSS Modules。要省安装包体积时补官方 client 构建 |
| 核心保留共享渲染设施 | `services/*-service.ts` 薄封装、`FilePreviewModal`/`ImageLightbox`、`PetSessionSync`、`useSettings`、`renderer/state.ts`、`quote-bridge` / `webview-selection-bridge`——它们被多个插件与核心页面共用，搬进任何单个插件都会制造假边界 |
| 客户端插件仍靠轮询 | 它们来自磁盘、可能被外部直接改动，轮询是发现变更的手段 |
| 实验项不走槽位 | 需要「摘要 + 详情子页」的成对契约，`ExperimentEntry` 比通用槽位更窄也更好校验 |
