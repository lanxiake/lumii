## 0. 目标

把**所有**插件按同一份规范梳理一遍，做到四件事：

1. **低耦合**：核心不 import 插件实现（只认服务访问器）；插件之间不运行期互相 import。
2. **高内聚**：一个插件的前后端代码、测试、界面都在它自己的目录里。
3. **统一**：内置 / 官方 / 用户三种来源用同一份清单、同一套生命周期、同一套能力。
4. **开放**：主进程与渲染层的扩展能力都对外提供——**外部插件也能同时有前后端两半**。

### 1.2 三种来源

| 来源 | 目录 | 主进程半边 | 渲染层半边 | 启停 |
|---|---|---|---|---|
| 内置 | `src/plugins/builtin/<id>/` | `index.ts` | `renderer.tsx` | 运行期，推 `plugin:state-changed` |
| 官方可选 | `plugins/external-src/<id>/` → 发布 → `~/.lumii/extensions/<id>/` | `main.js` | **没有** | 需重启 |
| 用户扩展 | `~/.lumii/extensions/<id>/` | `main.js` | **没有** | 需重启 |
| 客户端插件 | `~/.lumii/plugins/<id>/` | **没有** | `client.js`（另一套 API） | ≤1 秒轮询 |

**问题**：外部扩展只能做后端，客户端插件只能做前端，两套渲染 API。

## 2. 规范 v2（目标形态）

### 2.1 一个插件包

```
<plugin>/
  plugin.json            LumiiPluginManifest（内置可写在 index.ts 里）
  main.js | index.ts     主进程半边（可选）
  client.js | renderer.tsx  渲染层半边（可选）
  ui/                    渲染层独占的组件/样式（内置插件才需要拆目录）
```

- 两半边**都可选**，但至少一个；两半边共用同一个 `id`。
- `manifest` 里用 `main` / `client.entry` 声明入口（已有字段，内置插件豁免文件路径）。

### 2.2 能力目录（插件能做什么）

| 层 | 能力 | 入口 |
|---|---|---|
| 主进程 | 服务 | `ctx.provide(S.xxx, impl)`；核心 `defineServiceAccessor` 现取 |
| 主进程 | IPC（请求/响应） | `ctx.registerIpc(ch, fn)` 或 `createIpcTable()` |
| 主进程 | IPC（单向） | `ctx.registerIpcListener(ch, fn)` |
| 主进程 | 事件 | `ctx.on / ctx.emit / ctx.waterfall` |
| 主进程 | 定时器/副作用 | `ctx.effect(dispose)` |
| 主进程 | 工具注册 | `ctx.get(S.agentRuntime)?.installXxxTools()`（返回 disposer） |
| 渲染层 | 槽位 | `api.registerSlot('app.view' / 'dashboard.*' / 'settings.section' / 'settings.experimental', …)` |
| 渲染层 | 卡片 | `api.registerCard('type', renderer)` |
| 渲染层 | 设置项 | 实验项：`{id,title,Summary,Detail}` 登记到 `renderer/experiments.ts` |
| 渲染层 | 存储/格式化 | `api.storage` / `api.format`（客户端插件已有，内置插件补齐） |

**不提供**：权限/沙箱（D1/D2 不变）。

### 2.3 启停语义（统一）

```
extension:set-enabled → host.activate/stop（服务、IPC、定时器随作用域拆）
                     → plugin:state-changed {id, enabled}
                     → 渲染层：插件 setup/teardown（UI 消失，不是灰掉）
```

- 内置：已按此实现。
- **外部扩展**：服务契约铺完后也应即时（不再需要重启）——见 §4 阶段 3。
- 客户端插件：沿用轮询（它们来自磁盘、可能被外部改动）。

## 3. 工作分解

### 阶段 1：核心解耦收尾（⑪ 26 → 0）

| 批次 | 插件 | 服务键 | 边界 | 验收 |
|---|---|---|---|---|
| 1a | dashboard-feed | ✅ `S.dashboardFeed` | 4 | cron/wiki/api/bridge 四处改用 accessor；常量移到 `shared/dashboard-feed.ts` |
| 1b | vcs | ✅ `S.vcs` | 5 | 快照入服务；`workspace-queue` 与 `VCS_SKIP_DIRS` 移到核心（它们不是 vcs 专属） |
| 1c | voice | `S.voice`（已有键，去掉启动期缓存） | 3 | `index.ts` 与 bridge 现取；语音启停仍即时 |
| 1d | pet | `S.pet` | 10 | 窗口/模式/虚拟人三块入服务；托盘/协议/提示词分支关闭 |
| 1e | 守卫 | — | — | ⑪=0；规则改为「核心只许 `plugins/api` + type-only」；⑫ 清零 |

**做法（每个插件一致）**：
1. 插件目录加 `service-api.ts`（type-only 契约）；
2. `apply` 里 `ctx.provide(S.x, impl)`；
3. 核心加 `*-accessor.ts`（`defineServiceAccessor`）+ `index.ts` 注入；
4. 调用点改 `getXService()?.…`，拿不到走既定降级；
5. 测试：插件服务随启停来去 + 调用点降级。

### 阶段 2：前端代码进插件（逐域）

按「界面归属清晰、文件少」先做：

| 批次 | 域 | 迁入内容 | 判据 |
|---|---|---|---|
| 2a | usage | `UsagePanel` + `usage-service` | 禁用用量插件 → 设置页用量分区消失 |
| 2b | dashboard-feed | `NewsFeed` + `dashboard-feed-service` | 禁用 → 概览资讯卡消失 |
| 2c | file-preview | `FilePreviewWindowApp` 及样式 | 禁用 → 预览窗入口消失 |
| 2d | voice | `VoiceSettingsSection` / `VoiceModelsPanel` / `VoiceProfilesPanel` / `AsrLiveTestPanel` + hooks | 禁用 → 语音设置消失、工具不注册 |
| 2e | channels | 4 个渠道设置面板 + 渠道卡片 + `ChannelsSection` | 禁用某渠道 → 该渠道设置与卡片消失 |
| 2f | vcs | 工作区版本管理 UI + `useProjectGitStatus` | 禁用 → 版本管理入口消失 |
| 2g | pet | `renderer/pet/**`（68 文件）+ `PetSettingsSection` + 相关 hooks | 禁用 → 桌面宠物整体消失（窗口、设置、托盘项） |

**迁移规则**：渲染层文件只能 import `renderer/`、`shared/`、`plugins/api`（守卫 ⑫ 已强制）；
页面里不再写死插件域组件，一律通过槽位或实验项登记。

### 阶段 3：外部扩展前后端一体

| 批次 | 内容 |
|---|---|
| 3a | `client-plugin-discovery` 同时扫 `~/.lumii/plugins` 与 `~/.lumii/extensions`（后者要求有 `client.js` 或 manifest 声明 `client`）；协议按根目录白名单解析 |
| 3b | 渲染层宿主改调 `RendererPlugin.setup(api)`；`__LUMII_REGISTER_PLUGIN__` 保留为兼容层（内部转成 RendererPlugin） |
| 3c | 外部扩展启停即时化：服务契约铺完后用同一套 `activate/stop + plugin:state-changed`；仍需排除「核心缓存过服务」的残留 |
| 3d | 插件中心列表合并三种来源，同一张表、同一套开关 |

### 阶段 4：官方外部扩展「代码」迁出

perf / cloud-sync / screen-record 的实现从 `src/main/` 迁进 `plugins/external-src/<id>/`，
核心改走服务契约。**判据**：迁完后 `src/main/{perf,cloud-sync,screen-record}` 目录消失，
`check-wiring` 的 ⑪ 不变（它们不再属于核心）。

### 阶段 5：脚手架与守卫

| 项 | 内容 |
|---|---|
| 脚手架 | `packages/create-lumii-extension` 生成两半边 + 单测 + README，默认带 `renderer.tsx` 占位 |
