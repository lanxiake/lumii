## 0. 结论先行

**已经没有「必须做才能用」的项了。** 插件系统的能力闭环（卡片 / 整页 / 设置分区 /
启停 / 热更新 / 示例生成）都在，剩下的工作分两类，不要混在一起排期：

| 类别 | 含义 | 排期 |
|---|---|---|
| **清债（S1）** | 门禁是红的，每次跑全量都要人工分辨「这 4 条是不是我弄的」 | 现在做 |

| **按需（S4/S5）** | cron/数据库/阶段拆解、分发 | **不排期**，等触发条件 |

一条重要判断写在这里，避免以后反复讨论：

> **剩余重构不阻塞任何功能。** `initializeCronScheduler`(487) / `initializeDatabaseAndRepos`(252) /
> `index.ts` 的阶段函数，只在**要改那块代码时**才值得先拆。为行数拆它们是用回归风险换一个好看的数字。

## 2. 口径统一（决策项）

设计索引写「P5 完成时 `bridge.ts` ≤300 行」，P2 计划写「P2-4 后 ≤1200 行、公有方法 ≤40」。
**取后者**，并把索引改掉：

- 300 行的前提是「bridge 不留任何转发方法」，意味着 137 个调用点一次性改完——
  这正是 P2-1 试过并回滚的路（44 个测试失败，测试注入的假 bridge 被绕过）。
- 转发方法是**调用方渐进迁移的保险**：服务搬走、桥上一行转发、调用点不动。
- 真正该压的是**公有方法数**（135 → 40），行数自然跟着降。

### 5.7 第二轮：槽位与边界（2026-10-21，探针 `probe-slots` / `probe-collide`，验完已删）

| 场景 | 结果 |
|---|---|

| 同一槽位多条目的 `order` 排序（10 / 40 / 500） | ✅ 概览插件带按 10 → demo(40) → 500 排列 |
| 往 `dashboard.grid` 塞第 4 张（页面 `max=3`） | ✅ 不渲染 + 一条去重告警：`未渲染：probe.slots.grid` |
| 两个插件抢同一个槽位 id | ✅ 后来的**激活失败并显示原因**，先来的不受影响（不静默覆盖） |
| 失败后修好重试 | ❌ → ✅ **又抓到一个真 bug**（见下） |
| 折叠侧栏 | ✅ 插件导航只剩图标（`collapsed` 生效） |

**又抓到一个真 bug：半截注册会泄漏，插件从此永远起不来。**

冲突失败时，工厂已经注册了一部分槽位（grid 成功、plugins 撞 id），而 `loaded` 只在
激活成功后才赋值。`unload()` 原本第一步就 `if (!entry) return` —— **disposers 被跳过**，
半截条目永久留在注册表里。下次重试撞上**自己上次留下的** id：

```
probe.slots 激活失败：slot "dashboard.grid" 里已存在 id "probe.slots.grid"
```

修法：`unload()` 不再依赖 `loaded` 条目，disposers 一律执行。
（P4 §6.7 第 5 条「工厂中途抛错时槽位泄漏 → 失败分支 unload」只修了一半：
调用点有了，但被调用的函数早退。）

> 这个 bug 只在「先失败一次、再重试」时出现——正常的单次加载永远看不到，
> 所以按设计写的用例不会覆盖它。

**修完之后还剩一个恢复问题（同轮修掉）**：因冲突失败的插件，在冲突源被删除后
不会自动恢复——`failedRevision` 只认「自己文件的 revision」，对方删掉不会触发重试。
两处改动：

1. 清单里的**集合**变化（增/删）时清空 `failedRevision`，整体重试一次；
2. **先卸载清单里消失的插件，再加载**。顺序不能反：否则同一轮里冲突方还没释放，
   重试会再失败一次、重新记进 `failedRevision`，于是又不恢复了。

实测：A 占着槽位 → B 失败；删掉 A 后 **B 在 1 秒内自动加载**（无重启）。

## 9. 纪律（每片都适用）

1. **先量后改**：拆之前先数行数/调用点/赋值，计划的字面顺序经常被实测推翻（P2-3 就是）。
2. **动过 `src/main/**` 必须跑全量**：`cd apps/windows && pnpm test:all`。
3. **抽函数模板**：显式 deps（结构类型收窄，不 import 大对象）+ 独立测试 + 守卫跟着代码走。
4. **组合根不外提**：依赖 >20 个或「每个都是 getter」时，留在类里。
5. **提交按文件显式 add**；提交信息写清「为什么」与「验证命令」。
