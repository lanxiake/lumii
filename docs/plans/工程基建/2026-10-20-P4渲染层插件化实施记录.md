## 0. 一句话

渲染层的**注册机制**已经建好并且有真实消费者（概览页），但**插件加载器**还没做——
所以在当前状态下，「插件能注册卡片/槽位」是对的，「插件能加一整页」还不能。

## 1. 已完成

### 1.1 卡片注册表（P4-a）

`components/A2UIRenderer/card-registry.ts`

- 插件类型先查注册表，未命中再走内建 switch；
- **内建 12 种的实现一行没动**——它们的 props 各不相同，硬套统一签名要写 12 个适配器，收益为零；
- 内建类型不可被插件覆盖（防劫持整个渲染面）；
- 重复注册抛错，而不是后者静默生效（「谁生效」不该取决于加载顺序）。

### 1.2 SlotHost（P4-b）

`components/slots/slot-registry.ts` + `SlotHost.tsx`

- `registerSlot(slot, {id, component, order, owner})` 返回注销函数；
- 同 slot 内 id 唯一；按 order + 注册顺序排序；
- `SlotHost` 只负责「渲染谁、按什么顺序」，**布局与上下文留在页面**。

### 1.3 第一个真实消费者：概览页

`pages/DashboardPage/dashboard-cards.tsx`

- 拆成**两个** slot：`dashboard.main`（整宽资讯）/ `dashboard.grid`（底部三栏）。
  两个而不是一个，因为「顶部整宽 + 底部三栏」是**页面布局**，不该由注册表决定；
- 内置 4 张卡片用同一个 `registerSlot` 注册（幂等），插件卡片走同一套 API。

**验证**：真机截图与改动前布局一致；7 个注册表用例全绿。

## 2. 实施时抓到的两个真问题

### 2.1 `useSyncExternalStore` 的快照必须缓存

`getSlotEntries` 原本每次返回新数组（spread + sort），React 判定快照变化 →
**Maximum update depth exceeded**，页面无限重渲染。

单测全绿，只有把页面真跑起来才暴露。修法：按 slot 缓存快照，任何增删时清空。

**教训**：渲染层改动必须用真浏览器验证——纯函数测试看不到「渲染循环」这类问题。

### 2.2 布局不属于 slot

最初想用一个 `dashboard.card` slot 把 4 张卡都塞进去，但顶部资讯是整宽、底部三栏是网格。
硬塞进一个 slot 等于把布局决策搬进注册表——插件将无法知道「我这张卡会被放进哪种容器」。

改成两个语义明确的 slot 后，页面继续掌握布局，slot 只表达「这里有位置可以放东西」。

## 3. 还没做（以及为什么现在不做）

### 3.1 渲染层插件加载器（阻塞项）

没有它，外部插件无法在运行时注册卡片/槽位。要解决的事：

| 项 | 说明 |
|---|---|
| 文件送达 | 主进程用协议（如 `lumii-plugin://<id>/client.js`）提供插件文件；dev 与打包后路径不同 |
| 共享模块 | React / react-dom / SDK 由宿主提供，插件不得自带第二份 React |
| 注册协议 | `globalThis.__LUMII_REGISTER_PLUGIN__(id, factory)`，工厂拿 `{ registerSlot, registerCard, React }` |
| 热更新 | 改文件 → 重新注入 → 旧 scope 注销 → 新 scope 注册；失败保留旧版本 |
| 隔离 | 依决策 D2：同上下文执行，**不做沙箱**；不可信内容只能走声明式卡片 |

### 3.2 `app.view` slot（被 3.1 阻塞）

`Router` 的 `activeView` 目前是联合类型，加通配视图需要放宽类型并改多处调用点。
**消费者是插件加载器**——加载器没做之前加 `app.view` 只是又一个空抽象。

### 3.3 页面迁移（8 个视图 + 20 多个设置分区）

每个页面迁移都要真浏览器验证布局与交互，是回归风险最高的一类改动。
建议等加载器就位后，按「页面的卡片化程度」从高到低推进，而不是按行数。

## 4. 当前的扩展能力边界（如实记录）

| 能力 | 主进程 | 渲染层 |
|---|---|---|
| 可注册新卡片类型 | — | ✅ `registerCard` |
| 可往已有 slot 加卡片 | — | ✅ `registerSlot` |
| 可新增整页视图 | — | ❌ 需加载器 + `app.view` |
| 可新增设置分区 | — | ❌ slot 未建 |
| 外部插件运行时加载 | ✅ 文件系统 + 动态 import | ❌ 未实现 |
| 热更新 | ✅ 轮询 + 重新 import（~1s） | ❌ 未实现 |

---

## 5. 下一步建议顺序

1. **渲染层插件加载器**（3.1）——打通「插件代码怎么进来」；
2. 用加载器带一个示例插件，真机验证「注册卡片 → 出现在概览页 → 卸载后消失」；
3. 再按需建 `app.view` / `settings.section`；
4. 最后才是 8 个页面的迁移。
