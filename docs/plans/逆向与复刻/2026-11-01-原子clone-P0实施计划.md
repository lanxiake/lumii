## 1. Goal

让 `/clone <url>` **单独可用**：Agent 读完 `clone` 技能，用补全后的浏览器工具，把一个网页的**真实内容、资源、布局、交互状态**取证下来，产出可交给后续重建的三份 research 文件。

**可验证判据（三条，缺一不算完成）**：

1. 对一个真实站点跑 `/clone`，产出 `brief.md` / `assets.md` / `states.md` 三份文件 + 桌面/移动全页截图 + 资源清单
2. 三份文件里的每条指标都能追溯到具体命令或截图（不许出现"大约"）
3. 资源清单里每个 URL 都核对过真实 content-type（扩展名 ≠ MIME 的情况被记下来）

**本期不做**：不出代码、不建工程、不对比、不上流水线。**取证是 P0 唯一的交付物。**

## 3. 设计决策（本期新增，需在实施时写进代码注释）

### D-P0-1 设备做成独立工具，不做 screenshot 参数

**理由**：`/set/device` 是**状态变更**，截图是**读取**。合成一个工具会让"截桌面图"和"切设备"产生隐式副作用——连续两次截图之间视口被人换掉，且失败时无法分辨是哪一步错。独立工具才能组合。

工具名 `browser_set_device`，接受官方设备名；另外支持 `width/height` 走 `/act` 的 `resize` 分支（自定义视口，不改 UA）。

### D-P0-2 `browser_eval` 扁平化，但保留 `ok`

现状 `{ok:true, result:{result:X, url, targetId}}` → 改为 `{ok:true, result:{ok:true, ...X, url?, targetId?, note?}}`。

- `X` 是对象 → 展开到顶层
- `X` 是标量 → 放进 `value`

**为什么保留外层 `ok`**：`jsonToolResult` 用 `payload.ok === false` 判失败；`pick` 的返回值被包在 `result` 里，不影响外层。多一个 `ok` 只是让内层也自描述，路径仍是 `{{x.result.y}}`，比现在少一层。

**影响面**：现有 5 条断言 `payload.result` 的测试要改；仓内 grep 无其他消费方（`bundled-skills` / `bundled-pipelines` 均未引用 `result.result`）。

### D-P0-3 取证模板用固定占位符，不引入运行时变量

本期**不给 runner 加 `vars` 机制**。模板里写 `"__TARGET_URL__"`，技能要求 Agent 先 `file_write` 替换成真实 URL 再跑。

代价：每次克隆都改 spec，`specHash` 变化 → resume 失效。**可接受**，因为每次克隆本就是新目标、新产物目录。

> 若将来真的需要参数化，那是 P1/P2 的事，届时按 `$input` 前缀加进 `REF_PATTERN` 并补 spec 校验。**不为此在 P0 埋半成品。**

### D-P0-4 跨步骤数值比对走 JS 内嵌，不靠 `expect` 引用

因为 F5/F6：`expect` 里的 `{{}}` 不解析也不校验。正确写法是把上游值**插进 JS 源码字符串**（`params.script` 走 `resolveParams`，字符串内嵌引用是被支持的），让 JS 自己比，返回布尔：

```jsonc
{ "tool": "browser_eval",
  "params": { "script": "(() => { const s = getComputedStyle(document.querySelector('h1')); return { sizeMatch: s.fontSize === '{{src-styles.result.h1Size}}' } })()" },
  "expect": { "fields": { "result.sizeMatch": true } } }
```

`true` 是字面量，不需要引用。**这条写进模板注释**——它是本期最容易踩的坑。

### Task 0 — `browser_eval` 扁平化 `[TDD]`

**为什么排第一**：后面所有步骤的引用路径都依赖它。先改形状，后续模板才写得出来。

**Files**
- Modify `apps/windows/src/main/agent-runtime/bridge-browser-tools.ts`
- Modify `.../bridge-browser-tools.test.ts`

**先写失败测试（改现有 `browserEvalPayload` describe）**

| 用例 | 期望 |
|---|---|
| 对象结果 `{hp:7}` | `payload.result` 是对象且 `hp===7`；**没有** `payload.result.value` |
| 标量结果 `42` | `payload.result.value === 42` |
| 标量结果 `'text'` | `payload.result.value === 'text'` |
| 对象结果 + `url` | `payload.result.url` 是页面 URL；顶层 `payload.result.ok === true` |
| 必需字段冲突 | 脚本返回 `{ok:false, x:1}` 时，**外层** `ok` 仍为 `true`（工具本身没失败），内层 `payload.result.ok === false` 被脚本值覆盖 |
| 空白页 | `note` 仍在 `payload.result.note` |
| 非对象结果 `null` / `undefined` | 不炸，`payload.result` 至少含 `{ok:true}` |

**实现**（`browserEvalPayload` 内）

```ts
const isPlainObj = (v: unknown): v is Record<string, unknown> =>
  !!v && typeof v === 'object' && !Array.isArray(v)

return {
  result: {
    ...(isPlainObj(b.result) ? b.result : { ...(b.result === undefined ? {} : { value: b.result }) }),
    ...(url ? { url } : {}),
    ...(b?.targetId ? { targetId: b.targetId } : {}),
    ...(url && isBlankPageUrl(url) ? { note: '当前标签停在空白页…' } : {}),
  },
}
```

> 内层 `ok` 不主动填——脚本自己返回的 `ok` 原样保留；脚本没返回就没有。**不替用户编 `ok:true`**，否则 `payloadIsFailure` 会误判。

**验证**

```bash
cd apps/windows && npx vitest run src/main/agent-runtime/bridge-browser-tools && npx tsc --noEmit
```

|---|---|
| 注册清单 | 14 个工具，含 `browser_set_device` / `browser_requests` / `browser_response_body` / `browser_download` |
| 四个新工具各自命中真实路由 | 报错含 `ROUTE_REACHED`，且**不含** `Not Found`（与现有 `it.each` 同形，加进那个表） |
| `browser_screenshot` 传 `fullPage:true` | 走到 `/screenshot` 而不是 `/act`；body 含 `fullPage:true` |
| `browser_set_device` 缺 `name` 且缺 `width/height` | **本地**就拒（不发起请求），错误文案指明二选一 |
| `browser_set_device` 给 `{width,height}` | 走 `/act` 的 `resize` 分支（body `kind:'resize'`） |
| `browser_download` 缺 `ref` 或 `path` | 本地拒，文案给出 `browser_snapshot` 提示 |

**实现要点**

```ts
// 1) browser_screenshot 加 fullPage（其余保持空参数）
parameters: Type.Object({
  fullPage: Type.Optional(Type.Boolean({ description: '截整页（含折叠区）；复刻取证必须开' })),
}),
execute: wrapExecute('/screenshot', (p) => ({ fullPage: p.fullPage === true })),

// 2) browser_set_device —— 两种模式，二选一
parameters: Type.Object({
  name: Type.Optional(Type.String({ description: 'Playwright 官方设备名，如 "iPhone 14" / "Desktop Chrome"' })),
  width: Type.Optional(Type.Number({ description: '自定义视口宽（与 height 一起用，不改 UA）' })),
  height: Type.Optional(Type.Number()),
}),
execute: async (_id, raw) => {
  const p = raw as { name?: string; width?: number; height?: number }
  const name = typeof p.name === 'string' ? p.name.trim() : ''
  const w = Number(p.width), h = Number(p.height)
  if (name) return wrapExecute('/set/device', () => ({ name }))(_id, {})
  if (w > 0 && h > 0) return wrapExecute('/act', () => ({ kind: 'resize', width: w, height: h }))(_id, {})
  return jsonToolResult({
    ok: false,
    error: '要么给 name（官方设备名），要么给 width + height（自定义视口）。可用设备名如 "iPhone 14" / "Pixel 7" / "Desktop Chrome"。',
  })
},

// 3) browser_requests —— GET + query
// 4) browser_response_body —— POST {url, maxChars?}
// 5) browser_download —— POST {ref, path, timeoutMs?}
```

**`browser_requests` 的参数**：`filter`（URL 子串）与 `clear`（抓完清空，为重页面分段准备）。**不做**按 resourceType 过滤——后端只支持 URL 子串过滤（`pw-tools-core.activity.ts:30`）。要在工具描述里说清："过滤是 URL 子串，不是类型；image/font 请传扩展名或 CDN 路径前缀"。

## 什么时候不该用它   ← 必须放第一节
- 目标站点明确禁止抓取或复现
- 只想看懂技术实现，不重建 → 用 reverse
- 需要后端/数据库/登录态才能跑通的核心流程 → 复刻只能到静态呈现，说清楚

## 四步
1. Map     —— 列出要复刻的页面，源路径 → 本地路由，产物目录 \
2. Observe —— 取证（本节是唯一正本；下面的流水线只是它的自动化版）
3. Build   —— 建工程、逐区块实现
4. Compare —— 同视口、同滚动位置、同状态对比，修最大差异，如实声明剩余差异

## 工具怎么用（本期真实可用的）
| 目的 | 工具 | 注意 |
|---|---|---|
| 打开 | browser_navigate | 先断言 200，非 200 就停 |
| 全页截图 | browser_screenshot({fullPage:true}) | 折叠区只有开 fullPage 才拍得到 |
| 移动端 | browser_set_device({name:"iPhone 14"}) 再截图 | 设备是**状态**，截完记得切回 |
| 自定义视口 | browser_set_device({width,height}) | 不改 UA，只改尺寸 |
| 资源清单 | browser_requests({filter}) | 上限 500 条，重页面先 clear 再分段 |

| 读样式 | browser_eval({script}) | 读 computed style，别猜 |

**四个刻意的写法，都要在 spec 里注释出来**（JSON 不支持注释，写进 `description` 与 `"label"`）：

| 写法 | 为什么 |
|---|---|
| `"__TARGET_URL__"` 占位 | `{{user.x}}` 会被当成 step id 而加载期拒（F7）；本期不加运行时变量 |
| `expect.fields` 里**只有字面量** | `expect` 不走 `resolveParams`、也不做引用校验（F5/F6），写 `{{}}` 会静默按字面量比较 |
| 移动端单独一步，截完立刻切回 | `/screenshot` 不收 device，设备是持久状态（F3）；不切回会让后续步骤全在移动视口里 |
| `reset-desktop` 用 `width/height` 而非 `name:"Desktop Chrome"` | 只改尺寸、不动 UA，避免把桌面站伪装成别的浏览器 |

**验证**

```bash
cd apps/windows && npx vitest run src/plugins/builtin/pipeline   # 确认没碰坏既有校验
# 真机：改写占位符后 pipeline_run web-clone-evidence（rehearsal）
```

## 7. 风险

| 风险 | 缓解 |
|---|---|
| **扁平化打破现有 eval 调用** | 仓内 grep 确认无消费方；测试里加一条"旧调用方拿 `payload.result` 仍能拿到值"的兼容断言 |
| **`browser_requests` 500 条上限** | 工具描述明确写；技能里教"先 `clear` 再按段抓" |
| **设备状态泄漏到后续步骤** | 模板里有显式 `reset-desktop` 步；验收表单列一条 |
| **`expect` 静默比较字面量** | 模板只用字面量；技能里**点名**这个坑（P1 再考虑给 `expect` 接 `resolveParams`） |
| **占位符忘了替换** | `description` 第一句就是"跑之前把 `__TARGET_URL__` 换掉"；`browser_navigate` 会对非法 URL 明确报错 |
| **技能太胖** | 常驻只有名字+描述（~86 tokens）；正文按需 `skill_invoke`。三份文件合计控制在 300 行内 |
| **与 `reverse` 重复** | `clone` 的 references 只讲"怎么取证并重建"；"它为什么这么设计"属于 `reverse`（P1）。交叉引用即可，不复制 |

## 8. 范围外（明确不做）

| 不做 | 理由 |
|---|---|
| agent 节点 / pipeline schema 扩展 | P1 |
| `reverse` 原子 | P1 |
| 并排对比视图 | P2 |
| `create-next-app` / 建工程 / 对比 | 本期只取证；建在 P1 |
| 给 `expect` 接 `resolveParams` | 会改变既有语义，需单独回归；本期用 JS 内嵌绕开 |
| 给 pipeline 加运行时变量（`$input`） | 同样是语义变更；本期用占位符 |
| `bulk_download` | D6 已定不做；非 DOM 资源由 agent 用 `eval` 提 URL + `bash curl` |
| 自动判断"这个站能不能复刻" | 交给技能里的判据由 Agent 判断 |
