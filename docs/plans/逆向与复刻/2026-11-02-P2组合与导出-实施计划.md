## 1. Goal

四件事，按"验证成本"从低到高：

1. **能看**：复刻产物在客户端里并排对照（左源站 / 右本地），不用切浏览器
2. **能带走**：把一次能力固化成「技能包目录 + MCP 配置片段」，拷到别的机器就能用
3. **能串**：`reverse → clone` 的组合样板；先逆向写 `analysis/`，再按它复刻
4. **能读**：时间线上有一张产物卡，能一眼看到跑了什么、剩多少差异、从哪打开

**可验证判据（五条，缺一不算完成）**：

1. 一条已在 P1 跑通的 `web-clone` 产物，在客户端里能打开双栏对照，左右各自可滚动
2. 对照视图对**静态导出**产物有效；非静态导出时明确说明「需自行 `npm run dev`」，不静默空白
3. `capability_export` 产出的目录，拷到另一个工作区的 `skills/` 下能被扫描到（真机验证）
4. `reverse-then-clone` 跑一次，`analysis/` 出现在下游 agent 步的输入里（journal 可查）
5. 时间线产物卡能打开对照视图 / 预览 / 目录，且数据全部来自 run 与 journal，不额外探测

## 3. 设计决策（本期新增）

### D-P2-1 静态导出是预览的前提，写进 spec 而不是注释

`web-clone` 的 `scaffold` 之后加一步（或让 `build` 节点首步写 `next.config.ts`）把 `output: 'export'` 打开，
`check` 步同时断言 `out/index.html` 存在。

- 只对 **Next App Router + 静态可渲染** 成立；用了 SSR / API 路由的站点导出会失败
- 失败时不改回 dev server（设计 §4.6：不引入进程管理器），在 README 里如实写「需自行 `npm run dev`」

### D-P2-2 对照视图 = 新组件，不复用文件预览

`ComparePreviewModal`（`renderer/components/ComparePreview/`）：左右两个 `<webview>`，各自有地址栏只读显示、刷新、缩放（沿用 `WikiSourceDetailDrawer` 的预加载与 zoom 手法）。

- 入参：`{ sourceUrl: string; localUrl: string }`，两个都是 URL，不自带任何"复刻"概念
- 左栏地址来自 spec 的 `provenance.target`（P2 顺带把 `provenance` 接进 run meta，现在 spec 已允许该字段但没读）
- 右栏地址来自 `lumii-local://local/<abs>/out/index.html`
- **不做**同步滚动（两棵 DOM 的滚动高度不同，同步反而误导）

### D-P2-3 `capability_export` 的形态：目录 + 片段，不自动注册

新工具 `capability_export`，两个来源：

```ts
capability_export({
  name: string,                                  // 导出目录名（slug）
  source: { kind: 'skill'; id: string }          // 技能包 → 目录
        | { kind: 'mcp'; id: string },           // MCP server → 配置片段
  dest?: string,                                 // 缺省 {workspace}/exports/<name>
})
```

产出 `{workspace}/exports/<name>/`：

```
SKILL.md                 # kind=skill 时：拷技能目录（含 references/）
mcp-servers.snippet.json # kind=mcp 时：从 ~/.lumii/config/mcp-servers.json 摘一条
README.md                # 粘到哪、怎么用、依赖什么
```

- **不调用 `SkillImporter`、不写插件目录**（设计 §6：插件与主进程同权限，自动生成等于自动生成任意代码执行）
- 权限：`isReadOnly: false`、`needsPermission: true`（会往工作区写目录）

### D-P2-4 产物卡：只读 run 结果，不做第二次探测

新 TimelineCard `pipeline-artifact`，数据来自 `pipeline_run` 的返回 + `journalPath`：

| 字段 | 来源 |
|---|---|
| 步数 / 模式 / 耗时 | `steps`、`note`、`runId` |
| 剩余差异条数 | `report` 步 output 里「剩余差异…N 条」，取不到就显示「见 README」 |
| 预览 | 静态导出存在 → 打开对照；不存在 → 按钮变成「查看 README 说明」 |

**不**在主进程新开一条"扫产物目录"的 IPC——卡片只呈现 run 已经告诉它的事。

### D-P2-5 组合样板：`reverse → clone` 用文件交接，不用内存交接

`bundled-pipelines/reverse-then-clone/spec.json`：

1. `recon`（agent，`assistant`）：跑到 `/reverse` 的等价流程，产出 `projects/<slug>/analysis/{overview,evidence,assets}.md`
2. `clone`（agent）：读 `analysis/` 生成 `docs/research/` 三件套，再按 `web-clone` 的后半段走

**为什么不把一个 agent 步做成 800 轮**：两个节点各自有预算、各自可续跑、失败点可定位；
内存交接（`{{recon.output}}`）只传一段摘要，文件交接才是可复查的产物。

## 6. Task 分解

### Task 0 — 静态导出打通（前置，先做）

**为什么先做**：没有 `out/` 就没有可预览的本地页，后面三个任务都会卡在"没法验收"。

- `web-clone` spec：`scaffold` 后加一步 `bash` 写 `next.config.ts`（`output: 'export'`），或在 `build` 节点提示里要求
- `check` 步改为 `cd projects/<slug> && npm run build && test -f out/index.html`
- 真机重跑一次（可用 `resumeRunId` 续跑 + 单独验证 build 步）

**判据**：`projects/weflow-top/out/index.html` 存在；`lumii-local://local/...` 能载出来。

### Task 1 — 对照视图 `[前端为主]`

1. 先确认 `lumii-local://local/` 对任意 workspace 绝对路径放行（F9）；不放行就在协议层补，不加白名单硬编码
2. `ComparePreviewModal`：左右 webview、只读地址、刷新、缩放、关闭
3. 入口先接到 Task 3 的产物卡上（不先做独立页面）

**测试**：`ComparePreviewModal.test.tsx` —— 渲染两个 webview 且 src 正确；本地页缺失时给文案而不是空白；关闭回调触发。

### Task 2 — `capability_export`

**先写失败测试**（`capability-export.test.ts`）：

| 用例 | 期望 |
|---|---|
| kind=skill | 目标目录有 `SKILL.md`、`references/` 被完整拷贝、`README.md` 非空 |
| kind=skill 且 id 不存在 | `{ ok:false, error }`，不建半个目录 |
| kind=mcp | 产出 `mcp-servers.snippet.json`，内容是原配置里对应条目的**深拷贝**原样 |
| kind=mcp 且 id 不存在 | 报错并列出可用 id |
| 目标已存在 | 拒绝覆盖（除非 `dest` 不同），错误说明如何改用新目录 |

**实现**：纯函数拼目录 + 工具壳；写盘只用 `{workspace}/exports/`。

**真机判据**：导出 → 拷到 `~/.lumii/workspace/skills/` 之外的另一个工作区 → 重启后被扫描到。

### Task 3 — 产物卡

**测试**：给一份 `PipelineRunResult` 夹具，断言：
- 有 artifact/静态导出 → 出现「对照预览」按钮
- 无静态导出 → 按钮变成「查看说明」
- `report` 输出里有「剩余差异 10 条」→ 卡片显示 10；解析不到 → 显示「见 README」

**实现**：注册进 `registry.ts`；点击调 `ComparePreviewModal`。

### Task 4 — `reverse` 的 mobile / desktop references

- `references/mobile.md`：APK/ZIP 结构、manifest/资源定位、加固与脱壳**判定**（不做脱壳）、缺工具时的报法
- `references/desktop.md`：PE/ELF 节区、导入表、签名核验、加壳判定、动态观察的边界
- 两条硬约束沿用 P1：每条工具名必须在 Lumii 里真实存在；缺什么报什么，不自动安装
- `SKILL.md` 里加两行指路（只在判定为移动/桌面目标时才加载）

### Task 5 — `reverse-then-clone` 样板

- 两个 agent 步 + 文件交接（D-P2-5）
- `bundled-specs.test.ts` 加一条：用当前 knownTools / knownAgents 校验新 spec
- 真机跑一次，确认 `analysis/` 出现在下游 prompt（journal 里能看到解析后的 prompt）

### Task 6 — 真机验收 + 文档

五条判据逐条落证据；写 `2026-XX-XX-P2实施总结.md`。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| Next 静态导出对某些站点直接失败 | 如实写进 README；预览按钮降级为「查看说明」，不伪装成可用 |
| `lumii-local://local/` 不放行任意路径 | 先查协议实现；必须放宽时**只放开 workspace 根**，不做全盘 |
| 双 webview 吃内存/抢焦点 | 只允许一个对照窗口；关闭即销毁；不做同步滚动 |
| `capability_export` 把敏感配置带出去 | 只拷单条 server 条目；`env` 里的密钥值原样保留但 README 顶部提示「含凭据，谨慎分享」 |
| 组合样板两个 agent 步都撞预算 | 分别设 `maxTurns`（P1 已支持），失败点可定位、可续跑 |
| 产物卡解析 README 口径漂移 | 优先用 `report` 步 output 的结构化尾行；解析失败就降级成「见 README」 |

## 8. 范围外（明确不做）

| 不做 | 理由 |
|---|---|
| 同步滚动 / 像素差异高亮 | 两棵 DOM 高度不同，同步会误导；相似度判定交给 Agent |
| 自动起 dev server 预览 | 设计 §4.6：不引进程管理器 |
| 把 `.ocskill` 与 `capability_export` 合并 | 一个是分发物、一个是可读目录，语义不同 |
| 自动注册导出的技能 / MCP | 自动生成等价于自动执行任意代码 |
| `forge` 专用 Agent | 设计 §5.4 已否决 |
| EXE/APP **复刻** | P3 |
| 红蓝对攻 | P4 |
