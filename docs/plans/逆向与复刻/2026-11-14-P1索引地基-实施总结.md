## 过程中发现并修掉的问题

### 1. LIKE 降级路径的别名 bug（真实缺陷）

`kindClause()` 硬编码 `i.kind`/`i.root`，但 LIKE 分支的 `FROM lz_items` **没有别名 `i`** →
带 `kind`/`root` 过滤时 SQL 报错 → 被 catch 吞掉 → 静默返回空结果。

**只在 P1 的 root 过滤断言下才暴露**（P0 阶段没这路径）。已修为 `kindClause(options, alias)`，
并补了一条回归断言「降级路径也遵守 root 过滤」。

### 2. 探针的夹具自污染（三处，均为测试问题）

首跑 3 条假失败，根因都是**夹具与断言的环境假设错误**，不是实现问题：

| 现象 | 根因 |
| --- | --- |
| 查「listary」返回全部夹具 | 临时目录名 `lumii-listary-p1-xxx` 含 "listary"，而索引**包含路径**，路径匹配命中 |
| LIKE 降级"搜不到" | 夹具与真实目录混库，`LIMIT 5` 先返回真实文档，夹具被挤出断言窗口 |
| 夹具根自身命中查询 | 扫描器会把根目录当一条条目入库，根名 `fx` 恰好与控制组同名 |

修法：夹具独立子目录 + 路径不含任何被测关键词 + 断言一律用 `root` 过滤而非按名字过滤。

### 3. `node:sqlite` 参数类型

`kindParams()` 返回 `unknown[]` 不合 `SQLInputValue` 联合类型 → 改用 `SQLInputValue[]`。
