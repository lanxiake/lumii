## 顺手修掉的真问题

1. **`orchestrator` 把子 Agent 的产出清空**（`packages/agent-runtime/src/agent/orchestrator.ts`）
   以工具调用收尾的一轮，`message:end` 的 `fullText` 是空串；原代码无条件 `outputText = event.fullText`，
   把之前累积的整段输出抹掉。子 Agent 用 `task_complete` 收尾时父 Agent 拿到空产出——
   流水线 agent 节点在真机上就是 `output: ""`。改为 `if (event.fullText) …`，补 2 条回归测试。
2. **流水线 agent 节点的默认白名单必然撞 `FORBIDDEN_CHILD_TOOLS`**
   `orchestrator` 直接拒 `spawn_agent` / `send_message`。原样透传父工具集 → 真机报
   `allowedTools contains unauthorized tool: send_message`，整步失败。
   新增 `resolvePipelineAgentWhitelist()`：默认与显式白名单**都**扣掉
   `spawn_agent` / `send_message` / `pipeline_run`（最后一个是防递归触发流水线）。
3. **`app-ui-control` 快照读不到富文本输入框**
   `readValue()` 只处理 `input` / `textarea`；对话输入框换成 contenteditable 后，快照永远显示空值，
   验收时误判成「预填没生效」。补 `isContentEditable → textContent`，加 1 条断言。

### 真实站点复刻（`https://weflow.top/`）暴露并修掉的 4 处

4. **`brief` 节点用了只读 Agent 干写文件的活**
   原 spec 写 `agentType: 'builtin:explore'`，而它是 `permissionMode: readOnly`——写不了
   `docs/research/` 三件套，反复重试到 30 轮 maxTurns 被 abort。改成 `assistant`。

5. **`browser_navigate` 把底层已有的 `timeoutMs` 藏起来了**
   `navigateViaPlaywright` 支持 1–120s，工具只透传 `url`，默认 20s。真实站点首次加载
   （含全部子资源）超 20s 就整条挂起。工具与 `/navigate` 路由都补上透传，spec 的 open 步写 60s。

6. **「当前正在执行工具的实例」是单槽不是栈**
   内层工具（子 Agent 的工具）跑完把 ref 置 `undefined`，外层 `pipeline_run` 就丢了归属——
   同一 run 里 `brief` 成功、`build` 却报「无法解析发起流水线的 Agent 实例」。
   `BridgeInstanceFactory` 改成栈：进压、出弹回上一个。

7. **回合预算不可配、且撞上限与「被叫停」无法区分**
   agent 节点一次调用要跑完全程，`assistant` 的 80 轮不够建页。现在：
   `AgentStep.maxTurns` → `spawnAgent.maxTurns` → 子实例定义覆盖；`AgentInstance.abortReason`
   区分 `maxTurns` / `interrupted`，编排层对前者返回点明 `maxTurns=N` 的 error，不再伪装成 aborted。
   `web-clone` 三个 agent 步分别设 120 / 200 / 60。

8. **客户端把自己的启动环境漏给了用户脚本**（两处，都在 `runtime-env.buildScriptEnv`）
   - `NODE_ENV=development` 漏下去 → `next build` 警告「非标准值」并崩在预渲染；
   - `npm_config_local_prefix` 等 `npm_*`/`pnpm_*` 生命周期变量漏下去 → 用户在**自己项目**里跑
     `npm run build`，npm 会认本仓库的 `node_modules/.bin`，报「next 不是内部或外部命令」。
   两处都在源头抹掉（调用方显式传的保留），各补一条单测。

## 遗留

- **无「跑但不录」模式**：spec 写 `record.enabled:false` 时，`mode:record` 已改为「照常执行、
  不录、原因写进 `note`」；但调用方仍只能二选一（彩排 / 录制）。若将来出现「要全量跑、也不要视频」
  的高频诉求，再单独加一个 mode。
- 流水线 `/navigate` 走的仍是 `waitUntil:'load'`；重资源站点靠调大 `timeoutMs` 兜，没有换
  `domcontentloaded`（会改变全站语义，未做）。
- 真实复刻的「像不像」没有量化判据（沿用设计 §4.5：Agent 看像不像，代码查对不对）。
- `apps/windows` 全量 `test:all`：5133 用例 / 9 失败，全部在本期未触碰的模块
  （`artifact-thumbnails` ×6、`artifact-variant` ×1、`design-system.themes` ×1、`ChannelsSection` ×1），
  均在 HEAD 上复现，与 P1 无关。
- `check:wiring` 唯一新增项 `VoiceCallPanel/index.tsx` 仍是既有基线。
- `expect` 不解析 `{{}}`，跨步数值比对只能把上游值拼进 JS 源码（沿用 P0 约定）；
  `web-clone` 的 `brief` 步**不能**引用 `browser_eval` 步的产出——rehearsal 下该步被跳过、产出是 `{}`，
  引用会 `bad_reference`。
