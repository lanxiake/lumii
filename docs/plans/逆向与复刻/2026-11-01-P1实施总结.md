## 顺手修掉的真问题

1. **`orchestrator` 把子 Agent 的产出清空**（`packages/agent-runtime/src/agent/orchestrator.ts`）
   以工具调用收尾的一轮，`message:end` 的 `fullText` 是空串；原代码无条件 `outputText = event.fullText`，
   把之前累积的整段输出抹掉。子 Agent 用 `task_complete` 收尾时父 Agent 拿到空产出——
   流水线 agent 节点在真机上就是 `output: ""`。改为 `if (event.fullText) …`，补 2 条回归测试。
2. **流水线 agent 节点的默认白名单必然撞 `FORBIDDEN_CHILD_TOOLS`**
   `orchestrator` 直接拒 `spawn_agent` / `send_message`。原样透传父工具集 → 真机报
   `allowedTools contains unauthorized tool: send_message`，整步失败。
   新增 `resolvePipelineAgentWhitelist()`：默认与显式白名单**都**扣掉
   `spawn_agent` / `send_message` / `pipeline_run`（最后一个是防递归触发流水线）。
3. **`app-ui-control` 快照读不到富文本输入框**
   `readValue()` 只处理 `input` / `textarea`；对话输入框换成 contenteditable 后，快照永远显示空值，
   验收时误判成「预填没生效」。补 `isContentEditable → textContent`，加 1 条断言。
