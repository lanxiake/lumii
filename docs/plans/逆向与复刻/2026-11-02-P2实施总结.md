## 真机验收暴露并修掉的 4 处

### 1. `fs.cpSync` 在中文源路径上 abort 主进程（最严重）

`capability_export` 导出技能目录时，连续 4 次把整个主进程打挂：

```
length_error was thrown in -fno-exceptions mode with message "basic_string"
Command failed with exit code 3221226505
```

- **根因**：Electron 36.9.5（Node 22.19）里 `fs.cpSync` 的 source 路径含中文时，内部
  C++ 抛 `std::length_error`；Node 是 `-fno-exceptions` 编的 ⇒ 直接 abort，JS 层连 `catch` 的机会都没有。
- **为什么单测看不见**：单测跑在系统 Node 24 上，`cpSync` 正常。最小复现需要
  `electron.exe` + 中文源路径 + `cpSync` 三个条件同时成立（见下方验证记录）。
- **修法**：改用手写递归 `copyDirSync`（`mkdirSync` + `copyFileSync`）。同一坑也出现在
  `pipeline/index.ts` 的 `seedBundledPipelines`，一并换掉。
- **守卫**：`capability-export.test.ts` 加一条断言「导出实现不得出现 `cpSync(`」——
  这个 bug 在纯 Node 上永远复现不出来，只能守源码形态。

验证：手写实现先在 Electron 里单验通过（`cpSync` 换成 `copyDirSync` 后同一目录立即成功），
再上真机导出 `逆向与复刻/reverse`，`diff -r` 除新增 README 外逐字节一致。

### 2. 流水线 agent 节点的实例归属被子 Agent 抹掉（P1 修复被绕过）

`web-clone` 的 `build` 节点报「无法解析发起流水线的 Agent 实例」。

- P1 把 `toolExecutorStack` 从「单槽」改成「栈」，但那只覆盖了 `toolLifecycle` 这条通路；
  `bridge-agent-instance-events.ts` 的 `tool:end` 仍然**无条件** `setCurrentToolExecutorInstanceId(undefined)`。
- 子 Agent（`brief`/`recon` 节点）的内层工具一结束，就把外层 `pipeline_run` 的归属清空。
- **修法**：事件层把实例 id 作为 `owner` 传下去，栈实现只摘自己那条（`lastIndexOf` + `splice`）。
- 两条通路（`toolLifecycle` 与实例事件）现在都写同一个栈，各自 push/pop 一次；
  靠 `lastIndexOf` 只摘自己那条，重复计数不影响「栈顶是谁」。
- 新增回归测试 `工具执行归属（tool:start / tool:end 与实例栈同步）`。

真机验证：`web-clone` 续跑（`resumeRunId=20261102-102819-pw5nw2`）的 `build` 步 646s 通过，
run `20261102-102819-pw5nw2` 最终 `status=ok`，14/14 步。

### 3. 对照视图在 `dom-ready` 前调 `setZoomFactor` ⇒ 整张卡被错误边界打红

```
Uncaught Error: The WebView must be attached to the DOM and the dom-ready event emitted
before this method can be called.
```

- 组件挂载时会立刻跑一次 zoom effect，此时 webview 还没 ready。
- **修法**：加 `domReady` 状态，`dom-ready` 事件之后才调 `setZoomFactor`；刷新按钮同时禁用。
- `ComparePreviewModal.test.tsx` 补一条（也是原计划声称有、但**实际不存在**的 4 条测试的新建）。

### 4. `lumii-local://` 在 `<webview>` 里静默挂起

右栏一片空白：既不报 `did-fail-load`，也不发 `dom-ready`，`getURL()` 返回空串。

- 同一个 URL 在主窗口里 `fetch` 正常（200，28KB）——协议 handler 本身没问题，
  是自定义 scheme 在 webview 的独立进程里加载不动。
- `file://` 在 webview 里正常，且静态导出的 `assetPrefix:'.'` 保证相对资源一起加载。
- **修法**：预览 URL 改用 `file:///<abs>`。真机截图为证：左右两栏都渲染出真实内容，逐像素一致。

### 顺带：`reverse-then-clone` 的 scaffold 与 `analysis/` 目录冲突

`recon` 先把 `projects/<slug>/analysis/` 建出来，`create-next-app` 拒绝在非空目录初始化。

- **修法**：先 scaffold 到 `<slug>-scaffold`，再并入 `<slug>/`。
- 踩到的第二个坑：`` .<slug>-scaffold `` 以点开头，npm 包名不允许。
