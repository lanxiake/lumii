| 项 | 结果 |

| **带窗口启动** + 截图 | ✅ React 挂载、运行时态势（技能 22 / MCP 2/7）、会话侧栏、v0.1.4；截图 `/tmp/lumii-pkg-window.png` |
| 退出 | ✅ `资源清理完成 → app.exit(0)`，无残留进程 |

**实测中发现并修复的两个问题**：

1. **`@ffmpeg-installer/linux-x64` 在产物中静默丢失**（新的 dir 产物里 asar 只有 meta 包、unpacked 空；
   09-23 的旧产物曾碰巧带上）。根因是 AGENTS.md 明文禁止的形态：平台包只由 meta 包的
   optionalDependencies 间接引入，未被 `apps/windows` 显式声明。修复 = 显式声明
   `@ffmpeg-installer/{linux-x64,win32-x64,win32-ia32}` + `asarUnpack` 加 `node_modules/@ffmpeg-installer/**/*`
   （去掉对智能解包的隐式依赖，设计 §3 的可选加固升级为必需）。修复后探针通过。
2. **无头模式语音预热空引用**：`pushVoiceEvent` 直接 `this.win.isDestroyed()`，无头（无窗口、构造传 null）时抛
   `Cannot read properties of null`，预热在 TTS 步骤失败。修复 = 字段允许 null + 守卫（推送变为 no-op）。
   此前「模型未就绪」的失败挡在前面，这个缺口一直没露头。

**观察（不在本次范围）**：`pet:get-mode` No handler（09-20 起偶发，宠物线）；CloakBrowser 四源全败（AGENTS 已载）；
模型须放 `~/.lumii/models/voice/`（实测中先放错一层，已纠正——顺带补齐了本机 VAD 模型）。

**遗留**：无头下真实触发一次 ffmpeg 调用（需 UI 或 agent 侧动作）未做；新增的 win32 ffmpeg 平台包声明
**需要在 Windows 真机上跑一次 `pnpm package:win` + `verify:win-package`** 确认收集与体积护栏。
