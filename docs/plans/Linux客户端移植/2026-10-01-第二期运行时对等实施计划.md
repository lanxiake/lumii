## W1 · ffmpeg 逃生口（先做，最小）

### W1-1 `LUMII_FFMPEG_PATH` + 系统兜底

**改动**：`apps/windows/src/main/screen-record/ffmpeg-runner.ts` 的 `resolvePackagedFfmpegPath()`（:22-30）改为四级解析：

1. `LUMII_FFMPEG_PATH`：设置且 `existsSync` → 用；设置但无效 → `log.warn` 并继续（不静默失败也不硬停）；
2. `@ffmpeg-installer` 包内（现状，`index.js` 抛「Unsupported platform」时捕获继续）；
3. 系统 `ffmpeg`（`resolveCommand('ffmpeg')` 或 PATH 扫描 + `--version` 冒烟）；
4. 都没有 → 现有 `{ok:false, message}` 错误路径。

**测试**：`ffmpeg-runner.test.ts` 复用现有 `setFfmpegRunnerDepsForTest`（:40）注入：四级各自的命中与回退、环境变量无效时的回退。
**验证**：真机 `LUMII_FFMPEG_PATH=$(which ffmpeg 自备)` 跑一次时长解析（`audio-duration.ts` 调用点最轻）。
**文档**：AGENTS.md Linux 章节加一行（随 W5 统一提交）。

## W2 · Python（系统 python3 + 应用 venv）

### W2-1 探测修复：负缓存 TTL + 版本

**改动**：`python-env.ts` —`cachedSystemPython` 负结果改为带时间戳的 TTL 缓存（30s），正结果保持；`verifyPython3` 解析版本号（`Python 3.x.y` → `{cmd, version}`），导出 `detectSystemPythonInfo()` 供 venv 路径校验 ≥3.10（原 `detectSystemPython()` 保持返回命令名的兼容签名）。
**测试**：`python-env.test.ts` 补 TTL 翻转（fake timers）、版本解析、`_resetSystemPythonCache` 兼容。

### W2-2 应用 venv：创建与就绪探测

**新增**：`apps/windows/src/main/python-venv.ts`

- `getPythonVenvDir()` → `~/.lumii/runtimes/python-venv`（复用 `paths.ts` 的 runtime 目录约定）；
- `isPythonVenvReady()`：`venv/bin/python -m pip --version` 冒烟，负结果 TTL；
- `ensurePythonVenv()`：单飞去重；先 `python3 -m venv <dir>`，失败回退 `--without-pip` + `get-pip.py`（下载源与镜像逻辑同 `PYPI_MIRROR` 注入，失败时默认源兜底）→ 校验 pip；临时目录 + rename（沿用 `installBundledPython` 的失败清理模式）；
- `getPythonVenvExe()`、`getPythonVenvPipArgs()`（供 W4-V2 与 modelscope 用）。

**测试**：新 `python-venv.test.ts`（node 环境），mock `execFile`/下载：两条创建路径、单飞、失败清理、就绪探测 TTL。
**真机验证**：本机（无 `python3-venv`）直接跑通创建 → `pip --version`。这是设计 §0 实测 4 的落地复验。

### W2-3 shim 与脚本环境修正

**改动**：`runtime-env.ts` `writeShims()`（:140-164）：

**测试**：`runtime-env.test.ts` 补 shim 生成矩阵（用临时 HOME）。
**验证**：`pnpm dev` 启动后看 `~/.lumii/runtimes/bin/` 无坏 shim。

### W2-4 技能解释器链补末级
