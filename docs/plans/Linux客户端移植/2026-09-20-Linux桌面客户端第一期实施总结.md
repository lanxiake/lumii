## 4. 过程中值得记住的几件事

### 4.1 移植的真实收益：把「只在某个平台刚好成立」的隐式假设逼出来

最典型的是 **git 错误信息随 locale 变化**导致的 index 自愈失效：`vcs-repo.ts` 的
损坏提示表全是英文字符串，而中文 locale 下 git 报的是「坏的签名」——**全部失配**，
用户的 index 一旦损坏就再也无法自愈。它只在 Linux 上暴露，但**根源是跨平台的**
（这段代码一直按 Windows 的 MinGit 行为写：MinGit 对非 UTF-8 locale 回退英文）。

修法是**钉死 git 输出语言**（`LC_ALL: 'C'`）而不是往匹配表加中文串——
后者要为每种 locale 无限追加，前者一次解决所有语言。

同类还有：`spawnSync` 对「命令不存在」**不抛异常**，所以四处 `try/catch` 兜底的回退
**永远没被执行过**（收敛到 `platform/process-kill` 时才暴露）。

### 4.2 「能力矩阵」只有在被真正读到时才算数

T4 冒烟第一次报「`No handler registered` 计数 0」，看着像已屏蔽——**其实是没触发**：
隔离的空数据目录里没有会话，而第三处（`PetSessionSync`）的 effect 开头就 `if (!currentSessionKey) return`。
**那个 0 是「没跑到」，不是「已修复」**。

后来补的两处里，`ChatToolbar` 的 ✧ 按钮是**完全没接矩阵**的（点了是未处理的 Promise 拒绝）。
复核方式改成了 A/B 两轮：判据挡在 `ready` 之后才发 IPC，B 轮临时摘掉判据复现出线上同型日志。

教训：**这类「有前置条件才发」的 IPC，判据要配对看**——要同时确认「那条路径真的跑过」，
只数错误为 0 会把「没触发」读成「已修复」。

### 4.3 我自己犯的错，比代码缺陷更值得记

这一期我推翻过**六次**自己的结论，其中**四次是同一件事：判据读错了地方**。

| 我说过 | 实际 | 错在哪 |
|--------|------|--------|
| 「UI 建的定时任务不会到点触发」 | 触发了 | 依据是「日志里没有 `[scheduleJob]`」——**那条日志只对 `cron` 类型打印，`every` 类型不打** |
| 「密钥环被替换，可能是我 `pkill -9` 造成的」 | 密文本身不是当前实现写的 | 探针**没有自编自解对照**，无法区分「环境不行」与「密文不行」；而且自编会**新建密钥**，那个「✓」什么都没证明 |
| 「助手产出为空（对话不通）」 | 通了，答了「完成」 | 判据只查 `content[]`，而正文在 `contentJson.parts[]` |
| 「Wiki 检索管线在跑但库是空的」 | 证据无效 | `wiki:search` 的字段是 **`keyword` 不是 `query`**，发错不报错、返回空 hits |
| 「定时任务不工作」 | 还没到点 | 查的时候 23:13:59，`nextRunAt` 是 23:15:10——**观察窗口没覆盖预期时刻** |
| 「浏览器控制仍然不通」（第三次同型） | agent 早答了 `LUMIN-BROWSER-7742` | `conversation:messages` 的返回键是 **`items`**（不是 `messages`），且 `contentJson` 是 **JSON 字符串**（不是对象）——判据两处都读空 |
| 「浏览器控制开箱不可用，属环境阻塞」 | 环境确实缺，但**通道可以补** | 把「本机没装」直接当成「做不到」，**没去问「能不能补上」**；补上后实测通过 |

**提炼出的四条判据**（已写进计划相应小节）：

1. **看见「没有」之前，先确认工具本身是活的**——`find -newermt "-3 hours"` 静默失效过一次，
   我差点拿它的空输出当结论；换个写法立刻列出 21 个文件。
2. **判据本身要先拿已知成功的样本试一遍**——否则会得出「应用没答」而实际是「我没看对地方」。
   **这一条我写了却没照做，于是又栽了第三次**：日志里白纸黑字 `fullText="LUMIN-BROWSER-7742"`，
   我的判据却说「助手文本片段=0」。写下来不等于会做。
3. **要断言「X 不存在」时，先列出 X 可能存在的地方**——直接观测（`gdbus` 列密钥环条目）
   强于推断（猜应用名再试）。
4. **「环境不行」和「代码不行」要分开下结论**。这一期至少两次把前者当成了后者的免罪符；
   浏览器控制这次真正的动作是问「缺的东西能不能补」——能补（2.2 MB/s 的可达镜像 + 两个环境变量）。

### 4.4 文档里承诺了、测试里构造了，而真实形态里都不是那样

**其一：文档承诺了、代码里不存在。** `AGENTS.md` 曾写着「也可在浏览器配置里用 `executablePath`
手工指定任意 Chromium 系可执行文件」——而全仓库唯一的赋值点是 `buildWindowsBrowserConfig()` 里的
`executablePath: undefined`，**硬编码**。用户没有任何入口，那句话从一开始就不成立。

它没被更早发现，是因为**没人按它操作过**：读文档的人（包括写它的我）都在看代码，而不是在照着做。
修法不是删掉那句话，而是**把它变成真的**（两个环境变量），并顺手补掉了一个真实缺口。

**其二：测试构造了、生产里不是那样。** 浏览器报错中文化时，我的单测喂的是
`No supported browser found (…)`，而真机跑出来是 **`Error: No supported browser found (…)`**
——生产路径上 `dispatcher.ts` 用 `String(err)` 写进 `body.error`，前缀是必然的。
子串匹配侥幸兼容了，所以测试全绿；但**判据本身没覆盖真实形态**，有人给正则加个 `^` 就会全废。

这次是**真机复核把它抓出来的**，不是我想出来的。修法是让每个用例同时跑「带前缀 / 不带前缀」两种形态，
并锁上「透传时不剥前缀、翻译过才剥」这条区别。

> 一般化的教训有两条，方向相反：
> 文档里「用户可以 X」的句子，**至少被人照着执行过一次**再留；
> 单测里构造的输入，**至少有一种要来自真实路径**——否则测的是我以为的形态，不是它本来的样子。

## 5. 可以交给第二期的

- **无头形态**（D2 路线 A + D3 终端二维码 + systemd）
- **系统 Python + venv**：`pythonSkills` 的判定已在矩阵里就位，缺的只是技能页的置灰挂载点
- **桌宠精灵图重写**：入口屏蔽与 IPC 不注册都已就位，重写时不必先清理半初始化状态
- **浏览器控制的可依赖化**：现已有一条不依赖 root 的可用通道（`LUMII_BROWSER_EXECUTABLE` +
  `LUMII_BROWSER_NO_SANDBOX`），但仍是**用户手工三步**。要真正做到开箱可用，二选一：
  deb `Recommends` 补一个 Chromium 系浏览器（24.04 上意味着默认拉约 200MB 的 snap），
  或让应用自己在首次使用时下载（此时**必须解决镜像选择**——CloakBrowser 现有策略国内四源全灭）。
- **几个小尾巴**：`resolveWindowsClientDataRoot` 名字里的 “Windows” 是历史遗留（改名波及 44 处）。
  ~~`describeUnsupported()` 的 `.ps1` 分支永远走不到~~ **已修**（2026-09-20 晚）：
  `.ps1` 原先在两个平台都返回非空命令，那句「需要先安装 pwsh」从未被执行到；
  现在 `resolveShell()` 会先在 well-known 目录与 PATH 里探测 pwsh，找不到才返回 `null`。
  两侧都有测试守住——探测写错会让**装了 pwsh 的用户**反被挡掉，所以「有 pwsh 时照常走 pwsh」
  这条比「没 pwsh 时报错」那条更要紧。
