## 4. 过程中值得记住的几件事

### 4.1 移植的真实收益：把「只在某个平台刚好成立」的隐式假设逼出来

最典型的是 **git 错误信息随 locale 变化**导致的 index 自愈失效：`vcs-repo.ts` 的
损坏提示表全是英文字符串，而中文 locale 下 git 报的是「坏的签名」——**全部失配**，
用户的 index 一旦损坏就再也无法自愈。它只在 Linux 上暴露，但**根源是跨平台的**
（这段代码一直按 Windows 的 MinGit 行为写：MinGit 对非 UTF-8 locale 回退英文）。

修法是**钉死 git 输出语言**（`LC_ALL: 'C'`）而不是往匹配表加中文串——
后者要为每种 locale 无限追加，前者一次解决所有语言。

同类还有：`spawnSync` 对「命令不存在」**不抛异常**，所以四处 `try/catch` 兜底的回退
**永远没被执行过**（收敛到 `platform/process-kill` 时才暴露）。

### 4.2 「能力矩阵」只有在被真正读到时才算数

T4 冒烟第一次报「`No handler registered` 计数 0」，看着像已屏蔽——**其实是没触发**：
隔离的空数据目录里没有会话，而第三处（`PetSessionSync`）的 effect 开头就 `if (!currentSessionKey) return`。
**那个 0 是「没跑到」，不是「已修复」**。

后来补的两处里，`ChatToolbar` 的 ✧ 按钮是**完全没接矩阵**的（点了是未处理的 Promise 拒绝）。
复核方式改成了 A/B 两轮：判据挡在 `ready` 之后才发 IPC，B 轮临时摘掉判据复现出线上同型日志。

教训：**这类「有前置条件才发」的 IPC，判据要配对看**——要同时确认「那条路径真的跑过」，
只数错误为 0 会把「没触发」读成「已修复」。

### 4.3 我自己犯的错，比代码缺陷更值得记

这一期我推翻过**五次**自己的结论，其中三次是同类错误：**拿间接证据当结论**。

| 我说过 | 实际 | 错在哪 |
|--------|------|--------|
| 「UI 建的定时任务不会到点触发」 | 触发了 | 依据是「日志里没有 `[scheduleJob]`」——**那条日志只对 `cron` 类型打印，`every` 类型不打** |
| 「密钥环被替换，可能是我 `pkill -9` 造成的」 | 密文本身不是当前实现写的 | 探针**没有自编自解对照**，无法区分「环境不行」与「密文不行」；而且自编会**新建密钥**，那个「✓」什么都没证明 |
| 「助手产出为空（对话不通）」 | 通了，答了「完成」 | 判据只查 `content[]`，而正文在 `contentJson.parts[]` |
| 「Wiki 检索管线在跑但库是空的」 | 证据无效 | `wiki:search` 的字段是 **`keyword` 不是 `query`**，发错不报错、返回空 hits |
| 「定时任务不工作」 | 还没到点 | 查的时候 23:13:59，`nextRunAt` 是 23:15:10——**观察窗口没覆盖预期时刻** |

**提炼出的三条判据**（已写进计划相应小节）：

1. **看见「没有」之前，先确认工具本身是活的**——`find -newermt "-3 hours"` 静默失效过一次，
   我差点拿它的空输出当结论；换个写法立刻列出 21 个文件。
2. **判据本身要先拿已知成功的样本试一遍**——否则会得出「应用没答」而实际是「我没看对地方」。
3. **要断言「X 不存在」时，先列出 X 可能存在的地方**——直接观测（`gdbus` 列密钥环条目）
   强于推断（猜应用名再试）。
