## 一、目标与验收

### 1.1 一句话目标

打开一个有 1110 个产物的会话，工作台首屏 = **1 个任务组 + 成品卡 + 一行「中间产物 1107 个 · X GB」**；点卡在右区预览；「只看产出」关掉变工作区文件；切视图/切档**宽度不变**；「清理」先出清单、确认后进 trash、可恢复。

### 1.2 验收判据（全部满足才算完成）

| # | 判据 | 验证方式 |
|---|---|---|
| A1 | 1110 文件回合首屏 DOM 节点 < 60（不含隐藏 pane） | DevTools Elements 计数 / React Profiler |
| A2 | 中间产物折叠行显示「1107 个」，展开后为网格而非 1107 行 | 手工 |
| A3 | 切「工作区/版本」、拨「只看产出」时 `aside.clientWidth` 不变 | 手工 + 单测 |
| A4 | 拖宽时对话区文字不重排（只有左边缘移动） | 手工录屏/逐帧 |
| A5 | 图片/视频/markdown/pptx 四类在 main 内预览；双击开独立窗 | 手工 |
| A6 | 运行任务时进度条显示「阶段 · 已用时」，无百分比；可中断 | 手工 |
| A7 | 清理 10,000 个中间文件：主线程无 >100ms 阻塞；成品 0 删除；trash 可恢复 | 单测 + 手工 |
| A8 | `pnpm typecheck` / `test:all` / `check:wiring` 全绿 | 命令 |

### 1.3 非目标

P1/P2 的全部内容（artifacts 契约、真实缩略图、多选、对比、inspector、通知、跟随、TTL/配额自动清理、设置页、侧车元数据、结果卡）。见两份大纲。

### 3.2 工作台状态

```ts
// hooks/useWorkspacePanels.ts
export type WorkbenchView = 'workspace' | 'vcs'
export type WorkbenchPreset = 'half' | 'wide' | 'full' | 'custom'

interface WorkbenchState {
  open: boolean
  view: WorkbenchView
  /** 只看产出：workspace 视图内的呈现密度开关 */
  onlyArtifacts: boolean
  preset: WorkbenchPreset
  /** 手动拖拽后的像素宽度；preset!=='custom' 时由 preset 推导 */
  customWidth?: number
  /** main 当前打开的产物（工作区相对路径） */
  selectedPath?: string
}
```

持久化（P0 全量走 localStorage，key 带工作区 hash 防串档）：

```ts
const KEY = `lumii.workbench.v2.${hashWorkspace(workspaceDir)}`
type Persisted = Pick<WorkbenchState, 'view'|'onlyArtifacts'|'preset'|'customWidth'>
```

### 3.3 分类规则（唯一来源）

```ts
// src/shared/artifact-rules.ts （main / renderer 共用）
export type ArtifactRole = 'deliverable' | 'intermediate' | 'ephemeral' | 'internal'

export interface ClassifyInput { path: string }   // 工作区相对路径（posix 分隔）
export function classifyArtifact(input: ClassifyInput): ArtifactRole

export type ArtifactKind =
  | 'image' | 'image-set' | 'video' | 'audio' | 'doc' | 'slides'
  | 'sheet' | 'site' | 'code' | 'archive' | 'other'
export function kindOf(path: string): ArtifactKind

/** 工具名 → 用户阶段名；未知返回 undefined（UI 不显示阶段，不猜） */
export function stageOfTool(toolName: string): string | undefined
```

规则（P0 硬编码，P1 移到技能规范后仍由本文件承载）：

| 规则 | 命中 | 角色 |
|---|---|---|
| 路径以 `temp/` 开头 | 是 | `ephemeral` |
| 路径含 `.lumii/`、`.git/`、`node_modules/`、`.cache/` | 是 | `internal` |
| 文件名以 `.lumii-ref`、`.tmp` 结尾 | 是 | `internal` |
| 路径段命中 `parts*/`、`normalized/`、`frames/`、`cut-*` | 是 | `intermediate` |
| 其余 | — | `deliverable` |

**认不出一律 deliverable**（不删）。

### 3.4 产物台账

```ts
// WorkspaceArtifactsPanel/ledger.ts
export interface Artifact {
  path: string                 // 工作区相对
  kind: ArtifactKind
  role: 'deliverable' | 'intermediate'
  status: 'added' | 'modified' | 'deleted'
  sourceTool?: string
  timestamp: number
  turnId: string
}

export interface ArtifactGroup {
  key: string                  // `${turnId}:${dirFirstSegment}`
  label: string                // 前一用户消息首句（≤24 字）或 HH:mm
  timestamp: number
  sourceLabel?: string         // 子 Agent
  deliverables: Artifact[]
  intermediates: Artifact[]    // ≥20 才折叠
  bytes?: number               // 懒加载（见 T7 scan）
}

export interface ArtifactLedger {
  groups: ArtifactGroup[]      // 倒序
  counts: { deliverables: number; intermediates: number; byKind: Partial<Record<ArtifactKind, number>> }
  /** 同一路径在会话内的历史版本（时间正序） */
  versions: Map<string, Array<{ turnId: string; timestamp: number; status: Artifact['status'] }>>
}

export function buildArtifactLedger(
  messages: readonly LedgerMessageLike[],
): ArtifactLedger
```

`LedgerMessageLike` 增加 `readonly text?: string`（renderer 侧由 `content` 的 text 块拼接后传入；纯函数层不依赖 React 类型）。

分组规则：

1. 每个有 `fileChanges` 的 assistant 消息是一个候选组（复用 `buildChangeLedger().turns`）
2. 组键 = `turnId + 产出目录首段`（如 `outputs/pet-demo/…` → `outputs/pet-demo`）；同键跨回合合并，取最新时间
3. 组标签 = 该回合之前最近的 user 消息首行（截断 24 字，去 Markdown 标记）；没有则 `HH:mm`
4. 组内按 `classifyArtifact` 分成品/中间；`internal` 直接丢弃
5. 中间产物 < 20 个 → 按成品处理（避免「3 个也算中间」的过度折叠）

3. 没有 `total` 时只显示阶段 + 计时；**不显示百分比**

**测试**：`stageOfTool` 单测；计时器卸载清理（fake timers）。

### T7 · 手动清理（约 1.5 天）

**T7.1 主进程服务 `src/main/workspace-cleanup.ts`**

```ts
export interface CleanupClassStats { count: number; bytes: number }
export interface CleanupScan {
  workspaceDir: string
  classes: Record<'deliverable'|'intermediate'|'ephemeral'|'internal', CleanupClassStats>
  candidates: Array<{ path: string; role: 'intermediate'|'ephemeral'; bytes: number; mtimeMs: number }> // top 20，按 bytes 降序
  skipped: Array<{ path: string; reason: 'too-recent'|'referenced'|'outside'|'symlink'|'locked' }>
  truncated: boolean   // 达到时间/数量预算
}

export function scanWorkspace(opts?: { dir?: string; budgetMs?: number }): Promise<CleanupScan>
export function runCleanup(opts: { target: 'intermediate'|'ephemeral'|'both'; dryRun: boolean; dir?: string }): Promise<{
  ok: boolean; dryRun: boolean; removed: number; bytes: number; skipped: number; trashId?: string
}>
export function listTrash(): Promise<Array<{ id: string; createdAt: number; bytes: number; files: number }>>
export function restoreTrash(id: string): Promise<{ ok: boolean; restored: number; conflicts: number }>
```

实现要点（每条都要有注释）：

1. **只扫两个根**：`<ws>/outputs`、`<ws>/temp`；其余一律按 deliverable 统计（不遍历 deep）
2. 异步 `fs.promises.opendir` 递归；`budgetMs` 默认 1500，超时返回 `truncated: true`
3. 分类调用 `classifyArtifact`（**同一份规则**）
4. 安全闸（顺序执行）：
   - `path.resolve` 后在 workspace 内（前缀 + 分隔符校验）
   - `lstat` 不是 symlink；不进入 symlink 目录
   - 跳过 `mtime > now - 1h`
   - 「被成品引用」：对 deliverable 中的文本类（html/svg/json/md/js）做同目录相对路径扫描（上限 2MB），命中即跳过（**保守**）
5. 删除：`rename` 到 `<ws>/.lumii/trash/<ts>-<rand>/`（保留相对路径结构）→ 后台 `fs.promises.rm(trashDir,{recursive:true,force:true})`；**严禁 `rmSync`**
6. 日志：`<dataRoot>/logs/cleanup-<YYYYMMDD>.jsonl`，每行一条操作摘要
7. 并发：同一时刻只允许一个 `runCleanup`（模块级 promise 锁）

**T7.2 IPC / preload**

`workspace-ipc.ts` 增 4 通道：`cleanup:scan` / `cleanup:run` / `cleanup:listTrash` / `cleanup:restore`；参数校验（字符串/枚举），错误结构化返回，不抛裸异常。
`preload/api/workspace-api.ts` 增同名方法 + 类型（`CleanupScan` 等放 `src/shared/` 以便两端引用）。

**T7.3 渲染**

- 中间折叠行右侧按钮 → `CleanupDialog`
- Dialog：分类计数 + 前 20 条 + 「将删除 N 个 · 释放 X GB」+ 勾选（默认只勾 intermediate）+ 确认
- 结果 Toast：「已移入回收站，可在 设置 → 存储 恢复」（P0 设置页未做 → 文案改为「7 天内可恢复」，恢复入口 P1 补；或 P0 在 Dialog 内加「查看回收站」列表 + 恢复按钮，二选一，**倾向后者**，成本低）
- `bytes` 懒加载：展开折叠行 / 打开 Dialog 时才 `scan`；结果缓存 30s

**测试 `workspace-cleanup.test.ts`（node env）**

- 临时 workspace 造：成品 1、中间 10、temp 2、`node_modules` 1、`.lumii-ref` 1
- `scan` 统计正确；`candidates` 只含 intermediate/ephemeral
- `runCleanup({dryRun:true})` 不删文件
- `runCleanup()` 后成品仍在；trash 内可找到被删文件；`restoreTrash` 恢复
- 「最近写入」跳过；symlink 跳过；路径逃逸（`../../etc`）拒绝
- 10,000 文件性能冒烟（可选，标记 `slow`）：主线程计时通过 `setImmediate` 心跳检测最大间隔 < 100ms

**验收**：A7；单测全绿。
