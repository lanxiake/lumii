## 一、主题

P0/P1 让产物「可见、可拿」；P2 让产物「可改、可回、可对照」。

一句话：**不重跑整个任务，只改需要改的那一处；改坏了能回到现场。**

## 二、范围（清单）

### A. 局部重做（核心）

| # | 项 | 说明 | 依赖 |
|---|---|---|---|
| A1 | 参数回显 + 变体 | 结果卡上的参数 chip，改完只重跑该结果（换 seed / 换风格两条路） | P1 的 `details.artifacts.meta` |
| A2 | 写作段落级 | 选中段落 → 改写/扩写/精简/换语气；**增量重写该段**，不整篇重跑 | 写作编辑器 + 工具能力 |
| A3 | PPT 单页 | 点某页 → 换版式 / 换图 / 重写要点；先预览再应用（Gamma 式） | pptx 技能 |
| A4 | 图片局部 | 重绘 / 扩图 / 擦除 / 去背景（若已有工具则接动作条，否则后置） | 图像工具 |
| A5 | 视频局部 | 重生成某镜头 / 换参考图（依赖视频 pipeline 拆分能力） | H3 pipeline |

### B. 版本与对照

| # | 项 | 说明 |
|---|---|---|
| B1 | 版本间「显示更改」 | 文档/代码先做；图片做并排对比；PPT 做页级 diff |
| B2 | 产物评分 / 以此为准 | 在版本历史里标「选定」，导出与分享默认用选定版 |
| B3 | 整态 checkpoint | 参考 Replit：恢复文件 + 对话上下文 + 配置/依赖 + 环境；与 git 版本**并列但明确区别**；可 roll forward |
| B4 | 行/页级评论 → 上下文 | v0 式：在某行/某页留评论，作为下一轮指令的一部分（比用户复述强） |

### C. 复用与去重

| # | 项 | 说明 |
|---|---|---|
| C1 | 内容去重 | 同 hash 文件只保留一份（中间产物为主），显示引用计数 |
| C2 | 重跑复用中间产物 | 同参数重跑时复用已生成的帧/切片（需技能配合声明依赖） |

### D. 观察项（不承诺）

| # | 项 | 为什么不是现在 |
|---|---|---|
| D1 | 「任意 pane」工作台（Claude Code 式） | 固定两区已够用；pane 化会显著增加状态与布局复杂度 |

## 三、关键设计点（升级详细计划时要先定的）

1. **局部重做的协议**：工具需要接受「只改 X」的指令——是新增参数（`target: {page:3}`）还是新工具？**不得**用「重跑全部再替换」伪装成局部。
2. **预览再应用**：AI 的修改必须「提议 → 预览 → 应用 → 可回滚」；不能静默覆盖。
3. **checkpoint 的边界**：明确恢复哪些（文件/对话/配置）；**不**恢复数据库/外部服务状态；UI 文案必须写清。
4. **评分/以此为准的存储**：存 `<dataRoot>` 还是产物侧车？会不会与「版本来自 fileChanges」冲突？
5. **评论作为上下文**：评论存在哪（消息 part？侧车？），下一轮怎么拼进 prompt，超长怎么截断。
6. **去重安全**：硬链接/复制？跨设备同步怎么办？被成品引用的中间文件不能去重。

## 四、验收口径（粗）

- 改一张图的风格：只有该图重跑，耗时与消耗符合预期，其他产物不动
- 改写文档一段：其余段落字节不变（可 diff 验证）
- 重写 PPT 第 3 页：其余页不变，可预览后应用
- 版本对照：能看出两版差异并选定一版
- checkpoint：恢复到某一轮后，文件与对话都回到当时；明确提示未恢复的内容
- 去重后：中间产物占用显著下降，成品可打开，引用计数正确

## 五、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 伪局部重做 | 工具其实重跑全部，用户以为只改一处（时间/费用翻倍） | 契约里要求工具回传「实际改动范围」，UI 展示 |
| 覆盖用户手改 | 局部重做覆盖了用户在预览里的手动编辑 | 应用前 diff + 冲突提示 |
| checkpoint 误导 | 用户以为环境也回滚了 | 明确文案 + 二次确认 |
| 去重破坏引用 | 中间文件被成品引用 | 引用扫描 + 保守跳过 |
| 评论上下文污染 | 评论进入下一轮导致 prompt 漂移 | 限定作用域 + 可关闭 |
