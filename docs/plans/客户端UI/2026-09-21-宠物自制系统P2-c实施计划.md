# 宠物自制系统 P2-c 实施计划（闲置感知：打盹与睡着）

设计见 [`../../design/客户端UI/2026-09-20-虚拟人精灵图渲染后端设计.md`](../../design/客户端UI/2026-09-20-虚拟人精灵图渲染后端设计.md) §8（P2：多宠物同屏、好感度/状态系统、键鼠联动）。

来源是 P2-b 计划 §一 那张表：Electron 自带两个**安全的**全局信号，光标位置已用于注视，
**系统闲置**留给本片——用户离开 → 宠物静下来；回来 → 醒来。

## 一、先定一件事：用 Electron 自带的 `powerMonitor`，不引任何新东西

不引 native 钩子、不读键鼠事件，理由与 P2-b §一 完全相同（一个聊天应用不该有能力看到用户输入）。

| 信号 | API | 能表达什么 | 看不到什么 |
| --- | --- | --- | --- |
| 系统闲置时长 | `powerMonitor.getSystemIdleTime()` → 整数**秒** | 用户离开多久了 | 用户输入了什么 |
| 闲置状态（查询） | `powerMonitor.getSystemIdleState(threshold)` → `active` / `idle` / `locked` / `unknown` | 按阈值一档判定；`locked` 能认锁屏 | 同上 |

**两个都是查询，Electron 没有「用户闲置了」的事件**，所以只能轮询。要点：

- **1Hz**（1000ms）。阈值是分钟级的，1Hz 不是为了分辨率，是为了**醒来跟手**：用户一动，
  最多 1 秒后宠物就该醒。成本可忽略——一次同步调用 + 一次整数比较。
- **状态没变就不发 IPC**（与 P2-b 光标轮询同一约定）。1Hz 轮询全年只在三次状态切换时发消息。
- **只在宠物模式且开关打开时轮询**，退出即停（同一套启停约定，见 `pet-cursor-tracker`）。

## 二、目标与边界

| # | 内容 |
| --- | --- |
| W1 | pet-core：`idleStage(idleSec, opts)` 纯函数——秒数 → `awake` / `drowsy` / `asleep` |
| W2 | 主进程：宠物模式期间 1Hz 轮询闲置，**状态变化时**推给宠物窗口 |
| W3 | 渲染层：按阶段切表情 + 停/恢复随机动作调度（**不进 `petStateMachine`**） |
| W4 | 设置项开关（默认开） |

**不做什么**

- ✗ 锁屏/系统睡眠的专门分支：`locked` 直接按 `asleep` 处理，不另立一套逻辑
- ✗ 好感度、多宠物同屏 → P2 其余部分
- ✗ Live2D 后端的专门适配：它走同一套 `setExpression`，不需要分支

## 三、关键设计决策

### 3.1 两个阈值，外加免费得到的迟滞

- **打盹**：闲置 ≥ 60s。半眯眼，随机动作频率降低（×3）。
- **睡着**：闲置 ≥ 300s。闭眼，**随机动作调度全停**（呼吸继续）。
- **醒来**：闲置秒数 < 打盹阈值。**没有单独的醒来阈值**——任何一次输入都会把秒数
  直接归零，而「用户动了」这件事本身就是阈值。

**为什么不是"到点直接睡"**：宠物「慢慢困了」才像活的；5 分钟一到立刻瘫倒，像是被断了电。

**为什么不额外写迟滞逻辑**：有输入时闲置秒数归零，而两档之间差着几分钟——
睡着（300s）→ 醒来只要「有过一次输入」，再睡回去又要 300s。阈值附近不可能来回抖。
迟滞是这两条规则免费带来的，不需要状态机。

> 初版这里写的是「醒来阈值 3s」，实现时发现那是个**多余的第三阈值**：
> 纯函数只吃两个阈值（`idleStage(idleSec, {drowsySec, asleepSec})`），
> 秒数归零自然就醒了。多一个 3s 的常数只会多一处要维护、要解释的东西。

### 3.2 状态放编排器的一个正交布尔，不进 `petStateMachine`

`petStateMachine` 是**对话**生命周期（idle / listening / thinking / speaking），
「用户离开」是**环境**状态，两者正交——硬塞进去会让两个维度互相干扰。
照抄 P2-a `setPicked` 那条先例（同样只用一个标记暂停待机调度）。

### 3.3 睡着时**保留呼吸**，停的是随机动作

程序化原语（bob / breathe）继续跑：一只睡着但仍在起伏的宠物，正是「它在呼吸」的证据；
把帧冻住反而不像活着。要停的是**编排器的随机动作调度**（`interactionActive` 用的同一处闸门）。

### 3.4 「睡着」用已有表情表达，不新增动作组

demo 模型现成就有两档：`sleepy`（半眯，`eye_sleepy`）与 `calm`（闭眼，`eye_shut`）——
打盹与睡着分别用它们。**不凭空造「睡觉」动作组**（与 P1-c / P2-a 同一条原则）；
模型没有对应表情时就只停动作，脸上不演（对照表见 §七）。

### 3.5 醒来要有「被吵醒」的反馈

从 `asleep` 醒来时切一次现有表情（`shocked` 或 `joy`），随后回到中性；
模型声明了约定组就再播一个动作，没声明就只切表情。

### 3.6 与注视的关系：不用特殊处理

睡着的前提是**用户没动鼠标**（闲置秒数归零即醒），所以「睡着时该不该看光标」这个问题
在物理上不会出现；醒来后注视自然恢复。两片功能不需要互相知道。

### 3.7 开关默认开，但必须能关

「它睡着了」可能被误读成程序卡死；也有人就是不想要宠物自作主张。给开关，默认开。

## 五、验收

**单测**（pet-core）

- 阈值边界：59 → `awake`、60 → `drowsy`、299 → `drowsy`、300 → `asleep`
- 醒来：从 `asleep` 的秒数回到 0/2 → `awake`
- 非法输入（负数 / NaN / Infinity）→ `awake`（**不能产生"永远睡着"**）
- 单调：秒数增大时阶段只进不退（`awake` ≤ `drowsy` ≤ `asleep`）

**手测**（真实客户端）

> **用哪个宠物测，两条判据用的不是同一个模型**（这一节是实测反馈补的，与 P2-b §七 同源）：
>
> | 判据 | 用哪个模型 | 为什么 |
> | --- | --- | --- |
> | 表情：打盹半眯 / 睡着闭眼 / 醒来反馈 | **`demo_pixel_cat`** | 唯一同时有 `sleepy`(`eye_sleepy`) 与 `calm`/`闭眼`(`eye_shut`) 两档的 sprite 模型，部件名清晰可查 |
> | 动作：随机动作停掉 | **`mao_pro`** | **demo 两兄弟根本没有装饰随机组**（`idleMotionFallbackGroup` 与 `idleMotionRandomGroups` 都没配，`$unnamed` 组不存在）——对着它们验这条是**空过** |
>
> 换 `real_dog` 只会「停动作」，脸上什么都不演（§七）。

阈值默认 60s/300s。手测可用环境变量压到秒级（走的是同一条生产代码路径）：

```bash
pnpm dev:stop
LUMII_PET_IDLE_DROWSY_SEC=3 LUMII_PET_IDLE_ASLEEP_SEC=8 pnpm dev:start
```

1. 进入打盹 → 表情变半眯（`demo_pixel_cat` → `eye_sleepy`），随机动作变少
2. 继续不动 → 睡着 → 闭眼（→ `eye_shut`）+ 不再出现随机动作（呼吸仍在）
3. 动一下鼠标 → **1 秒内**醒来：切回睁眼并播一次反馈
4. 关掉设置项 → 无论闲置多久都不睡
5. 退出宠物模式 → 主进程停止轮询（不再有 IPC 流量）

### 5.1 怎么量（2026-09-21 实测）

**判据落在日志上，而不是截图上**：截图只能证明「脸变了」，日志能证明**切到的是哪一张脸**。
主进程与渲染进程的 `console` 都进同一份 `~/.lumii/logs/app/mtbot-<日期>.log`：

- 阶段迁移：`[pet-idle-watcher] 闲置 8s → asleep（原 drowsy）`
- 编排器意图：`[PetOrchestrator] [setExpression] orchestrator → renderer index=9 name=sleepy`
- 渲染器落地（sprite 才有部件名）：`[SpritePetRenderer] [setExpression] index=9 → eye_sleepy`
- 随机动作：`[PetOrchestrator] [playRandomIdleNow] 装饰待机组="$unnamed" count=6`

→ [`verify/pet-sprite/check-idle-sleep.mjs`](../../../verify/pet-sprite/check-idle-sleep.mjs)：
`node verify/pet-sprite/check-idle-sleep.mjs [--model mao_pro]`。它进宠物模式、制造输入保持清醒、
停在某处等打盹与睡着、最后再制造一次输入等它醒，按判据打分并写进
`docs/test/pet-sprite/evidence/check-idle-sleep-result.json`。

| 判据 | `demo_pixel_cat` | `mao_pro` |
| --- | --- | --- |
| 闲置到阈值即打盹（阈值 3s） | ✅ 3.7~3.9s | ✅ 3.8s |
| 打盹切的表情 | `sleepy`(9) → `eye_sleepy` | `tired`(9) |
| 再久一档即睡着（阈值 8s） | ✅ 再 5.0s | ✅ 再 5.0s |
| 睡着的表情 | `闭眼`(1) → `eye_shut` | `闭眼`(2) |
| 打盹与睡着是两张不同的脸 | ✅ 9 vs 1 | ✅ 9 vs 2 |
| 有输入即醒 | ✅ 0.5~0.7s | ✅ 0.5s |
| 醒来反馈 | `shocked`(5) | `shocked`(10) |
| 反馈后回默认 | ✅ `neutral`(0) | ✅ `neutral`(0) |
| 醒着时有随机动作（正对照） | 不适用（无装饰组） | ✅ 40s 内 3 次 |
| 睡着后无随机动作 | 不适用 | ✅ 16s 内 0 次 |

**A/B 对照（开关）**：把 `enableIdleAwareness` 置 false 后重启，**同一套 3s/8s 阈值**下
静置 25s：watcher 在跑（日志有「已启动闲置轮询」），但**一条阶段迁移都没有**；
打开时同一段闲置是 3.8s 打盹、再 5s 睡着。第 4 条据此判定通过。

### 5.2 这轮实测抓到的东西

**两个真缺陷（已修）**

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| 进宠物模式时若**用户已经闲置很久**，宠物永远不睡 | CLI/智能体拉起宠物模式（全程没有输入）时该直接睡着，实际一直醒着 | 初始阶段是在窗口页面加载完**之前**发的，`webContents.send` 直接丢掉；而主进程**只在阶段变化时**推，下一次变化要等用户回来再离开。补一条 `getIdleStage` 查询通道，渲染层挂载时主动问一次 |
| **跨后端换模型后表情与随机动作全没了** | `demo_pixel_cat`(sprite) → `mao_pro`(live2d) 之后画面还在动，但切表情、随机动作全失效，**一声不响** | 编排器把渲染器存在构造函数里；跨后端会销毁旧实例建新的，而 `handleModelLoaded` 只 `setModelConfig` 复用旧编排器 → 此后所有调用打在**已销毁**的渲染器上。改成「渲染器换实例就重建编排器」 |

> 第二个是**相邻缺陷**，不是本片引入的（同后端热切换不受影响，所以一直没暴露）；
> 但它是验本片「睡着后随机动作停掉」的拦路虎——正对照第一次跑就红，
> 一查日志发现 `playRandomIdleNow` 在醒着时也是 0 次。

**一个工具事实（已固化进 `verify/pet-sprite/lib/pet-frame.mjs`）**

`SetCursorPos`（`Cursor.Position = …`）**不更新系统闲置计时**：实测闲置从 663063ms
一路涨到 663516ms，一点没归零；`mouse_event` 一调就归零到 422ms。
所以「摆光标位置」与「假装用户动了」是两件事，验证脚本必须用后者。
第一版脚本用前者保持清醒，结果宠物在脚本「抖光标」期间照样睡死了。

**一条判据的空过风险**

「睡着后不再有随机动作」在 demo 两兄弟上是**永远为真**的（它们本就不播随机动作）。
脚本因此加了正对照：先证明醒着时会播，睡着的 0 次才算数；模型没有装饰组时明确标「不适用」，
**而不是拿一条恒真断言冒充验证**。

## 七、能力对照表（哪些模型演得出「睡着」）

**这一节是实测反馈补的**（与 P2-b §七 同源）：模型之间的表情集差别很大，不标注就会出现
「按说明试了但没反应」——因为那个模型根本没有这一张脸（或根本没有那一组动作）。

数据取自 `apps/windows/resources/pet-models/registry.json`、各模型 `manifest.json`
与 2026-09-21 的实测日志。**表情名是编排器按候选表探测出来的实际结果**，不是推测。

| 模型 | 打盹（实际取到） | 睡着（实际取到） | 随机动作 | 说明 |
| --- | --- | --- | --- | --- |
| **`demo_pixel_cat`** | ✅ `sleepy`(9) → `eye_sleepy` | ✅ `闭眼`(1) → `eye_shut` | ❌ 无 | ✅ **验表情就用它**（§五 判据 1~3） |
| **`demo_hires_girl`** | 同上 | 同上 | ❌ 无 | ✅ 只是画风不同 |
| **`mao_pro`** | ✅ `tired`(9) | ✅ `闭眼`(2) | ✅ `$unnamed` 6 个 | ⚠️ Live2D；**唯一能验「随机动作停掉」的模型** |
| `real_dog` | ❌ 无 | ❌ 无 | ❌ 无 | ⚠️ `emotionMap` 是空的：只能停动作，脸上没反应 |
| `ug_official` | ❌ 无「困」这一类 | ❌ 无 | ❌ 无 | ⚠️ 九个表情里最接近的是 `desk`（伏案） |
| `xiaomai` | ❌ 只有 1 张脸 | ❌ | ❌ | ❌ 且 Cubism 2 当前渲染不了（P0-b 已知问题） |

**「随机动作」这一列决定了一条判据能不能验**：编排器的装饰随机池只看
`idleMotionRandomGroups` 或 `idleMotionFallbackGroup`（回退到 `$unnamed`）。
**demo 两兄弟两个都没配、`$unnamed` 组也不存在**，所以它们从头到尾不播随机动作——
对着它们验「睡着后不再有随机动作」是**空过**（`check-idle-sleep.mjs` 会据此标「不适用」，
并配一条正对照，见 §5.2）。

**表情名候选表**（`PetOrchestrator` 里，按序探测 `emotionMap`，第一个命中的生效）：

- 打盹：`sleepy` / `困` / `打瞌睡` / `drowsy` / `tired`
- 睡着：`闭眼` / `睡着` / `sleep` / `calm`
- 醒来反馈：`shocked` / `惊讶` / `surprise` / `surprised` / `joy` / `开心`

`tired` 排在打盹候选最后，是因为它在 demo 里指的是「无语/冷漠」（index 7 = `eye_half`）——
只有当模型没有更明确的「困」脸时才轮到它（mao_pro 就是这种）。
`闭眼` 排在 `calm` 前，是因为万一某个模型里 `calm` 指的是「平静」，中文名不会歧义。

**判断一个新模型能不能演「睡着」，看 `emotionMap` 里有没有困/睡这一档**；没有也能用，
只是退化成「只会停动作的宠物」——那不是缺陷，是那类模型确实没有这张脸。

**阈值**（60s / 300s）是按桌面软件手感取的，可用环境变量覆盖
（`LUMII_PET_IDLE_DROWSY_SEC` / `LUMII_PET_IDLE_ASLEEP_SEC`，手测与验证脚本用）。
