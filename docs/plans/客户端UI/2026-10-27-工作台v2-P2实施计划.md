## 一、目标、范围与验收

### 1.1 一句话目标

P0/P1 让产物「看得见、拿得走」；P2 让产物「**只改该改的那一处、改坏了能回现场、两版能对照**」。

三条硬规则贯穿全阶段：

1. **只改作用域**——文档只替换选中区间、PPT 只改目标页、变体只新增一份；不得用「整篇/整任务重跑再覆盖」伪装局部。
2. **预览后应用**——AI 的修改先成为候选稿（candidate），用户看到差异并确认后才写盘；冲突（文件被别人改过）必须阻止，不静默覆盖。
3. **可回滚**——每次应用前留「改前内容」；每个恢复动作前留备份；删除只进回收站。

### 1.3 非目标（P3 / 有条件再做）

- **图像局部编辑**（inpaint / outpaint / 擦除 / 去背景 / 超分）与**视频单镜头重生成**：本机没有任何对应工具（见 §2.1），P2 只做「变体」。
- **PPT 换版式 / 换图**：P2 只做单页**文本**重写；版式与图片替换需要额外的 OOXML 操作与视觉校验。
- **docx / xlsx 内联编辑**：P2 文档编辑只覆盖 Markdown（`.md`）；docx/xlsx 继续走技能 + Agent 通道。
- **完整环境 checkpoint**：不恢复配置、依赖、环境变量、数据库、外部服务；只回工作区文件 + 对话分支。
- **自动逐回合 checkpoint**：全量二进制快照会成为新的磁盘膨胀源（本机单会话最多 4985 个文件），P2 只在用户显式恢复时按需取内容。
- **自动去重**、**重跑复用中间产物（C2）**、**产物评分**、画布 / 任意 pane / 外部应用插入。

### 2.5 AG-UI 对齐（P2 扩展）

P1 已按「事件 → 状态 → 卡片」建模；P2 **不新增 Agent 事件、不加 SSE**，只补以下几类本地状态：

| P2 动作 | AG-UI 家族 | 落法 |
|---|---|---|
| 编辑提议（candidate / diff） | `CUSTOM`（本地） | 只存于 workbench UI state + 主进程编辑存储；不进消息、不进 agent 状态 |
| 应用编辑（文件已写） | `STATE_DELTA` | 对受影响卡片的 `timestamp/versions` 发本地 delta；不重算全会话台账 |
| checkpoint 恢复 | 用户动作 + 新会话 | 文件回退是本地操作；「从此轮分支」复用现有 fork，之后用户发消息才产生 `RUN_STARTED` |
| 评论 | 用户消息的一部分 | 拼成普通 user 文本；不新增 part 类型 |
| 版本对照 / 固化 | `CUSTOM`（派生结果） | 只更新检查器，不改消息正文 |

四条 P1 硬规则继续成立：Agent 权威 / UI 本地；snapshot + delta；卡片即状态视图；人机回路是卡片交互。**禁止**为了让本地编辑出现在 rail 而伪造 assistant 消息。

## 三、关键决策

| # | 决策 | 结论 | 理由（含否决项） |
|---|---|---|---|
| D1 | 局部修改由谁执行 | **主进程本地编辑为默认，Agent 为逃生通道**：文档区间、PPT 单页文本、图片变体由主进程直接完成；需要多步推理或超出作用域时，回退为「带上下文的消息」交给 Agent，并明确提示可能更慢/更贵 | 本地单轮调用能保证「只改这一处」且不重启回合；全交给 Agent 无法证明局部性（P2 大纲风险 #1） |
| D2 | 预览-应用协议 | **候选稿 + `baseHash` + 原子替换 + 改前副本**；应用前内容变了就拒绝并提示 | 直接覆盖会吃掉用户在预览期间的手改（大纲风险 #2）；原子写避免半截文件 |
| D3 | 版本来源 | 版本模型扩为 `turn`（fileChanges）/ `local`（工作台编辑、手工保存）；`versionId` 带命名空间；`pin` 是**版本的固化标记**，不是独立版本 | `fileChanges` 仍是 Agent 回合的唯一来源；本地编辑不该写假 assistant 消息（会污染回放、上下文与台账）；把固化当版本会让同一内容在历史里出现两次 |
| D4 | 版本内容从哪来 | 文本/代码：**`agent:end` 时把本轮成品文本复制到 `<ws>/.lumii/versions/turn-<messageId>/`（精确副本）**；VCS Git blob + messageId→commit 索引作为回退；本地编辑：编辑存储的 before/after；媒体/Office：只有固化或本地编辑才有内容，否则 `content.available=false` 并说明 | 实测 VCS 快照可能早于本轮最后一次 `file_write`（工具循环里多次 message:end），且快照队列可能被前一个任务堵住；只靠 git 会拿到「回合中途」的文本。仍不新增「每回合全量二进制快照」——只存成品文本、≤50 个/回合 |
| D5 | 「以此为准」 | **不是指针，而是立即固化内容**（复制到 `.lumii/pins/<id>/`）；无内容的旧版不可固化 | 只存指针无法在文件被覆盖后导出旧版，属于假承诺 |
| D6 | checkpoint 边界 | 只回**本会话**在该轮之后改动/新增的文件：文本用 `revertFile` 按路径回退，新增文件进回收站；媒体仅在存在固化/编辑副本时恢复；对话用 `forkConversation` 分支，**不截断原会话**；不恢复配置/依赖/环境/数据库 | 整仓 `rollbackTo` 会连带回退其它会话与用户手改；`deleteMessagesAfter` 有同毫秒漏删，且破坏性太强 |
| D7 | 评论存储 | `<ws>/.lumii/comments/<conversationId>.json`；锚点支持文本区间与 PPT 页；发送时拼成普通 user 文本，**预填不自动发送**；不新增消息 part / DB 表 | 评论是工作台草稿，发出去才属于对话；新 part 会牵动回放、压缩与渠道 |
| D8 | 内容去重 | **手动、仅中间产物、硬链接、引用跳过、默认关**；失败回退（先入回收站再链接） | 自动去重会破坏引用与正在复用的素材；硬链接是同卷唯一不改变路径的方案 |
| D9 | 图片能力边界 | P2 只做「参数回显 + 同源变体」（同 prompt/模型/尺寸，指令可追加）；**不提供 seed / 局部重绘 / 扩图 / 去背景**；没有声明元数据的图不显示「变体」 | 本机 schema 与上游请求体都没有这些字段，做了就是假按钮 |
| D10 | PPT 范围 | P2 只做**单页文本重写**（标题/要点）；换版式、换图后置；预览补页列表与单页跳转 | `replace.py`/`add_slide.py` 只能按页改文本或追加页，版式/图片替换没有安全入口；预览库已有单页 API |
| D11 | 文档范围 | P2 只覆盖 Markdown；`.txt/.docx/.xlsx` 不做内联编辑 | 只有 Markdown 有编辑态与保存链路；强行做 docx 会引入往返转换与版式损坏 |
| D12 | LLM 通道 | 新增 `main/single-turn-llm.ts`，复用 `bridge.resolveSelectionChatStream()`；非流式、90s、按 requestId 取消；**只记长度与耗时，不记正文** | `callLLM` 会把完整 prompt/输出写日志，编辑场景是用户正文；与划词隐私口径保持一致 |
| D13 | AG-UI 映射 | 提议 = 本地 `CUSTOM`；应用 = 卡片 `STATE_DELTA`；checkpoint = 用户动作 + 现有 fork；评论 = 普通 user 消息。不新增事件类型 | 不把 UI 本地编辑伪装成 Agent 状态，避免回放时「消息里没有却出现版本」 |
| D14 | 存储落点与保留 | 编辑/固化/评论/编辑索引都放 `<ws>/.lumii/`；编辑未应用 24h 清理；已应用编辑 30 天/1GB（超限按最老优先删内容副本、保留 meta，版本标「内容已清理」），回合文本副本 30 天/500MB，固化软上限 2GB（超限拒绝新增，不自动删），设置页可见可清；VCS 对象库维持现有 `gc` 策略 | 与缩略图/回收站同一类「工作区派生数据」；不进入清理候选，不会被 TTL 误删 |

### 4.1 编辑作用域与请求

新增 `apps/windows/src/shared/artifact-edit-types.ts`：

```ts
export type ArtifactEditAction =
  | 'rewrite' | 'expand' | 'shorten' | 'tone'   // 文档
  | 'slide-title' | 'slide-bullets'              // PPT
  | 'variant'                                    // 图片

export type EditScope =
  | { type: 'text-range'; start: number; end: number }        // UTF-16 偏移，基于 baseHash 对应的内容
  | { type: 'slide'; index: number }                          // 0-based
  | { type: 'image-variant' }

export interface ArtifactEditRequest {
  editId: string              // 渲染层生成（requestId）
  sessionKey: string
  path: string                // 工作区相对路径（posix）
  baseHash?: string           // 文本必填（渲染层按磁盘内容算 sha256）；PPT 可省略，由主进程 propose 时计算并保存
  scope: EditScope
  action: ArtifactEditAction
  instruction?: string        // 可选附加要求（≤500 字）
  tone?: 'formal' | 'casual' | 'confident'
}

export interface ArtifactEditProposal {
  ok: true
  editId: string
  candidatePath: string       // 工作区相对路径：.lumii/edits/<editId>/candidate.<ext>
  changedScope: EditScope
  diff?: TextDiffResult        // 文本类返回；二进制类不返回
  warnings?: string[]          // 例如「仅替换选中范围」「模型返回过长已拒绝」
}

export interface ArtifactEditApplyResult {
  ok: true
  versionId: string           // local:<editId>
  appliedAt: number
  backupPath: string          // 改前副本（工作区相对）
}
```

**作用域校验**：`path` 必须经现有路径归一（参考 `artifact-export.ts` 的 `resolveExportFiles`）后位于工作区内；`text-range` 必须落在当前内容长度内且 `start < end`；`slide.index` 必须在页数内。

**文本偏移的基准必须是磁盘内容**：发起编辑前，渲染层把编辑器全文的 sha256 与磁盘内容比对；不一致（有未保存修改）时先保存或提示保存，避免「缓冲区偏移」套到「磁盘内容」上导致改错位置。

### 4.2 编辑存储布局与 apply 语义

```
<ws>/.lumii/edits/
  index.jsonl                    # 一行一条（只追加；读取时按 editId 去重）
  <editId>/
    meta.json                    # 请求、动作、目标路径、状态、时间、来源
    before.<ext>                 # 应用前的完整内容（撤销 / 上一版内容）
    candidate.<ext>              # 候选稿 = 应用后的内容（预览用；apply 后保留作该版内容）
```

- **propose** 只写 candidate 与 before，不改目标文件。
- **apply** 校验 `baseHash`（重新读目标文件算 sha256）→ 原子写（同目录临时文件 + `rename`）→ 把 meta 标为 `applied` 并记录 `versionId`。
- **discard** 删除 candidate（before 可留到清理）。
- **undo**（A5）：先校验当前文件 sha256 == 该次编辑的 `candidate` 内容（否则说明之后又被改过，拒绝并提示）；通过后把 `before` 写回，作为一次新的 `local` 版本（保留线性历史，不删除已发生的版本）。
- **未应用候选 24h 清理**；已应用编辑按 D14 保留。
- 候选稿与 before 都归 `internal`，**不进 rail、不进清理候选**；预览通过 `files:read-preview-by-path`（工作区内路径允许）。

### 4.3 版本模型与内容可用性

`artifact:history` 返回结构升级（保持向后兼容字段）：

```ts
export type ArtifactVersionSource = 'turn' | 'local'

export interface ArtifactVersionInfo {
  versionId: string            // turn:<messageId> | local:<editId>
  source: ArtifactVersionSource
  turnId?: string              // source=turn 时用于「回到消息」
  timestamp: number
  status: 'added' | 'modified' | 'deleted' | 'edited'
  /** 该版是否已固化（以此为准）；固化不是新版本 */
  pinned?: { pinId: string; at: number }
  content:
    | { available: true; kind: 'git' | 'store'; approximate?: boolean }
    | { available: false; reason: string }
}
```

**`artifact:history` 只做可用性推断，不读 blob**（否则一个文件 50 个版本就是 50 次 `git show`，把列表拖到秒级）；真正的内容读取发生在 `artifact:versionDiff` / 版本预览时，读失败返回 `{ok:false, reason}`。可用性推断：有固化副本、有本地编辑 candidate、或有 turn 索引 oid（且路径被 VCS 跟踪）即标 `available:true`，否则 `false`。

内容解析优先级：

| 来源 | 解析 | 备注 |
|---|---|---|
| 已固化（任意来源） | 固化副本（`<ws>/.lumii/pins/<pinId>/`） | 精确；优先于 Git 快照 |
| `turn`（文本/代码） | **优先** `<ws>/.lumii/versions/turn-<messageId>/<path>`（agent:end 精确副本）；没有则 `messageId → oid` 索引 → `git show <oid>:<path>` 回退 | 副本 `kind:'store'`、精确；git 回退在提交合并时标 `approximate:true` |
| `turn`（媒体/Office/被 VCS 排除） | 无内容 | `reason: '该版本的原始文件未被保留（VCS 不含二进制）'` |
| `local` | 编辑存储的 `candidate`（该版内容；变体则指向新文件）；撤销/上一版用 `before` | 精确 |

`status='deleted'` 的版本没有可读内容：`git show <oid>:<path>` 会失败。解析时改用该版**前一版**的内容（或删除提交的父提交），并在 UI 标「已删除 · 内容为删除前」。没有前一版则 `content.available=false`。

**messageId → oid 索引**：`maybeSnapshot` 增加 `messageId`，快照返回后追加 `<ws>/.mtbot-vcs/turn-index.jsonl`：

```json
{"conversationId":"…","runId":"…","messageId":"…","oid":"…","at":1761…,"coalesced":0}
```

- 无变更（`commit` 返回 `null`）也记一条 `oid:null`，表示「该回合没有产生新快照」。
- 读取时取「该消息及之前最近的非空 oid」。
- **不改 commit trailer 的既有语义**；索引是增量文件，VCS 插件关闭时不写、读端降级。
- 索引只追加（万条约 1MB），随 `.mtbot-vcs` 一起存在；重建 VCS 时一并丢弃（内容可取性降级，不影响消息与版本记录）。

### 4.4 文本 diff 与版本对照

- 抽出 `apps/windows/src/shared/text-diff.ts`（`structuredPatch` + 512KB 上限 + `insertions/deletions/hunks`），`plugins/builtin/vcs/vcs-diff.ts` 改为 re-export（保持现有调用方不变）。

```ts
export interface TextDiffResult extends FileDiffResult {
  /** 任一侧超过 512KB 时为 true（调用方应先判大小再计算） */
  truncated?: boolean
}
```
- 新 IPC `artifact:versionDiff({ sessionKey, path, fromVersionId, toVersionId })`：
  - 解析两版内容（§4.3）→ 任一侧不可取：`{ ok:false, reason }`；
  - 文本：返回 hunks（≤512KB，超出标 `truncated`）；
  - 图片/视频：返回 `{ ok:false, reason:'该类版本不支持文本 diff' }`，由 UI 引导到并排预览（仅当两版内容都可用）。
- 新 IPC `artifact:versionContent({ sessionKey, path, versionId })`：文本 ≤2MB 直接返回内容（只读预览）；二进制物化到 `<ws>/.lumii/exports/<id>/` 走 `lumii-local` 预览；内容不可取时返回原因。版本行同时提供「预览此版」与「显示更改」。
- 版本列表按时间正序；「当前版」= 最后一版且非 `deleted`。本地编辑插入后同样参与排序。

### 4.5 固化（以此为准）

- `artifact:pinVersion({ sessionKey, path, versionId })` → `{ ok, pinId, bytes }`
  - 内容可用才允许；布局 `<ws>/.lumii/pins/<pinId>/<basename>`；
  - 单文件 ≤200MB；索引 `<ws>/.lumii/pins/index.json`：`{ pinId, sessionKey, path, versionId, bytes, at }`；总量软上限 2GB，超过时**拒绝新固化**并提示清理（不自动删）；
  - 同一 `(sessionKey, path)` 只保留一个选定；新选定替换旧索引项（旧文件保留到清理）。
- `artifact:export` 扩展可选 `versionId`：**只允许单路径**（多路径批量仍导出当前文件）；先用 pin 内容（或按 §4.3 解析）**物化到临时文件**，再走现有 zip/copy/save；完成后清理临时文件。
- `artifact:unpin({ pinId })`：只删索引项，文件留给清理（可恢复式删除）。

### 4.6 checkpoint（恢复到这一轮）

```ts
export interface CheckpointPlan {
  anchor: { turnId: string; timestamp: number }
  files: Array<{
    path: string
    action: 'restore' | 'trash' | 'skip'
    reason?: string             // skip 原因
    content?: 'git' | 'store'   // restore 来源
  }>
  textCommitOid: string | null  // 锚点轮及之前最近一个非空快照；无则 null
  canRestoreConversation: boolean
}
```

`textCommitOid` 为 `null` 时（VCS 关闭、或锚点前从未有文本快照）：文本文件全部标 `skip`（原因「没有可用的文本快照」），只处理可回收的新增/媒体文件；`canRestoreConversation` 仍可为 true。

- 计划来源：`listFileChangeTurns(sessionKey)` 中锚点之后的全部 `fileChanges`（按路径聚合，**同时保留首次状态与最后状态**：首次 `added` ⇒ 锚点时不存在，走回收站；首次 `modified/deleted` ⇒ 走回退）。
- **本地编辑也计入**：编辑索引中锚点之后的 `local` 记录，若路径不在上面的 `fileChanges` 里，用**该路径第一条 local 编辑的 `before`** 作为恢复内容；变体等新增路径进回收站。这样「改一版后再恢复到该轮」不会漏掉工作台自己的修改。
- **跨会话保护**：对每个文本路径查 VCS 中「锚点之后最后一次改动该路径的提交」；若其 trailer 的 `conversationId` 是**其它会话**，该路径标 `skip`（原因「其它会话在之后修改过该文件」），不回退、不删除。**例外**：该路径在锚点后有本会话的 `local` 编辑时，以 local 编辑为准（本会话确实改过，不应被 VCS 的提交归属误判）。二进制不在 VCS，改查 `client_files` 的最近归属：`conversation_id` 不是本会话则 `skip`。查不到归属时保留 restore/trash，但 UI 提示「共用工作区，可能与其它会话的改动重叠」。
- 应用步骤：
  1. `vcs.commit({ author:'user', message:'恢复前自动备份' })`（有变更才产生 oid，作为撤销点）；
  2. **回合后新增的文件（文本或二进制）**：`trashPaths`（可恢复），不走 `revertFile`；
  3. 回合后**修改/删除的文本**：`revertFile(textCommitOid, path)`（目标版本无该文件则说明在锚点前不存在，按新增处理）；
  4. 回合后修改/删除的**二进制**：有 pin/编辑副本才覆盖，否则 `skip` 并列出；
  5. 可选 `forkConversation({ uptoMessageId: turnId })` 创建分支（默认勾选）；返回 `newSessionKey`，由渲染层调用 `switchSession` 切换；
  6. `vcs.commit({ message:'已恢复到 <turn>' })`；
  7. 审计 `<ws>/.lumii/checkpoints/<id>.json`（备份 oid、trash 批次、跳过项）：**动手前**先写 `status:'applying'`，完成后改 `done`；启动时发现 `applying` 的未完成记录要提示用户（可撤销到备份 oid / 查看清单），不留半截状态无人知。
- 撤销：按备份 oid 逐路径 `revertFile`，并 `restoreTrash` 记录的批次；不改对话（分支保留，用户自行切回）。

### 4.8 去重

```ts
export interface DedupePlan {
  groups: Array<{
    hash: string
    size: number
    keep: string
    duplicates: string[]
    /** 去重后共享同一内容的路径数（= fs.stat.nlink，用于 UI 显示「引用计数」） */
    links: number
  }>
  totalFiles: number
  reclaimableBytes: number
  skipped: Array<{ path: string; reason: string }>
  truncated: boolean
}
```

- 范围：`classifyArtifact` 判为 `intermediate` 的文件、`size ≥ 64KB`、`mtime` 早于 24h；不碰 deliverable/ephemeral/internal。**不能直接用 `scanWorkspace().candidates`**（它只返回体积前 20）；把 `collectWorkspaceFiles` + 分类抽成 `listWorkspaceFiles({dir, budgetMs})` 供去重使用。
- 每组保留 **mtime 最早**的一份（相同则按路径字典序），其余为重复项；结果确定、可复跑。
- 引用跳过：复用 `collectReferencedNames`（成品文本引用）。
- 执行：每个重复项 → 写 journal（原路径/临时路径/hash）→ `rename` 到 `<ws>/.lumii/tmp/dedupe-<ts>/`（临时，不进回收站）→ `fs.link(keep, duplicate)` → 校验内容 hash → **成功后删除临时副本并清 journal**；失败则把临时副本放回原路径。回滚 = 从 `keep` 复制回原路径（内容一致）。
- **崩溃恢复**：启动时读 journal；原路径缺失且临时副本存在 → 放回；两者都在 → 删临时副本；journal 清理先于 `.lumii/tmp` 的 24h 清理执行。
- 审计：`trigger: 'dedupe'`；设置页显示可回收字节与结果。

## 八、风险与回滚

## 十一、与 P2 大纲的偏差（明确不做 / 降级）

| 大纲项 | P2 实际 | 原因 |
|---|---|---|
| A1 换 seed | 不做 | 工具 schema、RightAPI/RightCodes 请求体均无 seed；只做同 prompt/同模型/同尺寸变体 |
| A1「只改该结果」 | 变体=同源**新文件**，不是同路径新版本 | 生图固定写 `outputs/<日期>/<uuid>`；同路径覆盖会破坏「每次生成都可回溯」 |
| A4 图片局部（重绘/扩图/擦除/去背景） | 不做 | 无任何内置工具；`image:process` 是占位；ComfyUI 默认关闭且产出不落工作区 |
| A5 视频单镜头 | 不做 | 依赖视频 pipeline 拆分能力，当前没有 |
| A3 PPT 换版式/换图 | 只做单页文本（标题/要点） | 现有脚本只支持按页改文本/追加页；版式与图片替换缺少安全入口 |
| A3 PPT 页缩略图（视觉） | 只做页标题列表 + 单页跳转 | `pptx-preview` 无离屏缩略图接口；逐页渲染截图成本高，留 P3 |
| B1 图片并排对照历史版本 | 仅两版内容都可用时（固化/本地编辑/当前） | 二进制历史内容未被保留（VCS 排除） |
| B1 PPT 页级 diff | 仅两版内容都可用时 | 同上 |
| B2 产物评分 | 不做；只做「以此为准」固化 | 评分没有消费方；固化才是可验证的承诺 |
