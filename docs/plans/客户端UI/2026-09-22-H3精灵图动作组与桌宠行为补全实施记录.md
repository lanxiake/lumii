## 一、起因

用户报「宠物还不会自己走动和爬墙，我没看到这些动作」。

查下来**不是功能坏了，是素材缺组**：客户端 `PetOrchestrator.resolveAmbientGroup` 找不到动作组时
**静默回落到基础待机**——日志里每一次 `[setAmbientActivity] → 组 "(基础待机)"` 就是一次缺失，
表现为「一边平移一边播呼吸」，看起来像在滑行。

仓库里其实有**两套「九个动作」规范**（交互那套 `Idle/Talk/Jump/Wave/Nod/Shake/Picked/Land/PlayBall`、
行为那套 `Idle/Walk/Sit/Talk/Fall/Picked/Jump/Climb/Crawl`），团子当时只有前者的一部分。
两套都要装。

另外用户明确要求：**走 / 攀爬 / 爬行要侧身**（"走路的图片记得是左右侧身哦，不是正面的"），
其余保持正面。坐下按参考素材定，见 §六。

## 二、方法：两段式

H3 的 `first_frame` 是**机位标定**，且循环闭合靠 FL2VA（同一张图同时接 `first_frame` 和 `last_frame`）。
于是「用正面立绘直接生成侧身循环」会在末帧被**强制拉回正面**，循环里出现"转过去→被拉回来"的鬼畜。

所以非正面姿势走两段：

```
正面立绘 ──pose(I2VA，尾帧自由)──▶ 姿势拼条 ──pose-pick──▶ 挑一帧
   └─▶ stage-frame --keep-scale ──▶ staged/<角色>-<姿势>.png
        └─▶ sheet(FL2VA，首帧=该姿势) ──▶ 8 格动作表 ──▶ install-pet ──▶ 客户端
```

⚠ 两条路的 `freeEnd` **别接反**：循环必须接 `last_frame`，姿势图必须**不接**。
接反任一条都**静默**毁掉整轮，而出图看着完全正常。

## 五、换机器继续

**素材已入库**（见 `10733daa`），所以 `git clone` 之后**直接能重装**，不用重跑生成：

| 位置 | 是什么 |
| --- | --- |
| `verify/pet-sprite/sources/pet-motion/`（**入库，24MB**） | 7 个首帧 `staged/` + 13 张 8 格动作表。`install-pet --dir <本目录>` 的输入 |
| `verify/pet-sprite/characters/` + `apps/windows/bundled-skills/…/pet-sprite-h3/` | 工具与技能（**入库**） |
| ComfyUI 用户库里那三条工作流 | **随服务器走**，不随机器走（在本机 `~/.claude.json` 里配地址） |

入库的理由是**这批东西不是"一条命令能重建"的那类**——对比 `verify/pet-sprite/review/assets/`
那条排除（那些确实一条命令能重建）：这里每张表是一次 5 分钟的模型生成，而且挑帧是人工判断。
放在 `verify/` 下，不进安装包。

**仍然只在机器上、不在仓库里的**：

| 路径 | 大小 | 要带吗 | 说明 |
| --- | --- | --- | --- |
| `~/.lumii/pet-models/demo_cartoon_cat/` | 16M | 可选 | 装好的成品。不带也行——`install-pet` 能重建 |
| `~/.lumii/pet-models/registry.json` | <1K | 可选 | 客户端 install 时自己写。⚠ 它**每进程只读一次** |
| `~/.lumii/workspace/outputs/pet-motion/tuanzi-pose-*/` | ~110M | 不用 | 旧 `gen` 路径的 56 帧 dump，只有 `f0050.png` 被引用 |
| 各首帧的**姿势拼条** | — | 不用 | ⚠ 但**要改挑帧就得重跑 `pose` 命令**——拼条本身没入库，只有挑完的结果在 `staged/` 里 |

重装（**客户端必须正在运行**——这一步经 `/pet/asset` 控制口走技能链，只有它写用户目录）：

```bash
node verify/pet-sprite/characters/install-pet.mjs --id demo_cartoon_cat \
  --dir verify/pet-sprite/sources/pet-motion --canvas 560x448 --bg 00ccff
.\scripts\stop-dev.ps1 ; .\scripts\start-dev.ps1 -Force     # registry 每进程只读一次，点 UI 开关不算重启
```

⚠ **`--canvas` 别照抄 560**，它是量出来的（见 SKILL.md 第五节）。换角色、加动作都要重新量：

```bash
node verify/pet-sprite/characters/sheet-canvas.mjs \
  --dir verify/pet-sprite/sources/pet-motion --char tuanzi --canvas 560x448
```

**额外验证过的一条**：`git fsck --connectivity-only` 退出码 0、只有 dangling 对象、无缺失
（仓库里有 31 个孤儿 `.idx`，是历次 repack 的残留，git 会告警但能正常读写）。

## 六、未完成 / 已知取舍

1. **`sit` 是正面、`walk` 是侧身，客户端没有转身过渡** → 从走到坐会**瞬间翻面**。
   参考素材（Shimeji）同样如此、也没有过渡，所以按参考来了。
   真要改：`POSES` 里加一条 `from: 'side'` 的侧身坐姿，代价是坐着的猫一直侧对着你。
2. **`fall` 的循环里角色仍会上下漂 ~104px**（模型"下落＝画面里要动"的先验改不掉，改措辞实测无效）。
   靠**头顶留足余量**装下（`--baseline` 0.856 → 0.95，余量 125 → 167px），**不是消除了漂移**。
   ⚠ 想再压它时注意：**头一旦被裁到 0，真实位移就被截断了**，量出来的漂移是**下界**——
   "再换个更狠的措辞"这个方向本身不可证伪，别在这上面迭代。
3. **`crawl` / `fall` 的组解析这一轮没实测到**（爬行要爬到屏幕上边缘、下落要把它扔下去）。
   组都装好了、机制同一套、`walk`/`climb`/`sit` 都验过，但严格说这两条是推断。
4. **宠物窗口的实时画面没能自动截图取证**：`lumii-ui screenshot --target pet` 抓到的是**全黑**
   （透明窗口 + WebGL 画布，`capturePage` 抓不到）。要像素级证据得用
   `scripts/lumii-cdp.mjs`，而它要求客户端带 `--remoteDebuggingPort` 启动，`start-dev.ps1` 没这个口子。
   本轮的视觉验证是**把图集里的帧拼成对照图**看的（`verify/pet-sprite` 下没有现成脚本，当时是临时 node -e）。
5. **图集 4480×5824（26M 像素，RGBA ≈ 104MB）**——14 组 8 帧的代价。再往上加动作要留意。

## 七、这一路的坑（都已修，细节在 SKILL.md）

只列**方法学之外**的、属于本次交付的：

- **画布宽度连错四版**：`421 × 宽高比` → 错（忽略"组内最高"才是分母）；只按包围盒算 → 偏小
  （客户端按**重心**对齐，两侧余量要分开算）；按最小 16 倍数取 → **装完爬行距左边只剩 1px**。
  最终 `560×448`，工具已按四条一并实现。
- **`stage-frame --keep-scale` 保的是"像素"不是"比例"**：对整幅帧等价，对**拼条裁出来的格**
  会再缩 0.667 倍——爬行的猫比走路那格**连头都小**。**这是看出来的不是算出来的**。
- **`fall` 不能用 `displacement`**（"may rise, drop, or crouch within the frame" 会让模型照做，
  角色升出格线、头顶信息丢失），也不能用 `static`（"does not leave the ground" 与"在空中"矛盾）
  → 新增第四类 `suspended`。⚠ 同一个句子在不同动作上对错不同（`static` 对 `sit` 是对的），
  **逐个看，别按类名套**。
- **归因写错过一次并已更正**：`accc3d02` 说"改措辞之后不再升出格线"，实测三次底边漂移
  149 / 131 / 104px，**没变小**，过关的是余量。更正见 `cf91c658`。
  ⚠ 那次的教训值得留着：头被裁到 0 之后**漂移量是下界**，"再试一次更狠的"不可证伪；
  要断言措辞有效得用**同一批抽样帧**做 A/B。
