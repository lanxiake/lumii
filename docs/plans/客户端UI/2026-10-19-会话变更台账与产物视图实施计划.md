# 会话变更台账与产物视图实施计划（2026-10-19）

## 背景与诊断

文件编辑、批量生成短剧素材时，变更散落在每轮对话底部，或全部挤在最后一张变更卡片里；
Agent 通过 bash / 脚本 / MCP 写出的文件甚至完全不出现在卡片中。

根因是变更卡片同时用了两道过滤：

1. 写文件工具在 `tool:end` 登记的归属白名单；
2. 回合开始/结束的全工作区快照 diff。

只有**同时命中两边**的路径才会显示。bash 写入不在白名单，被快照忽略的目录（`uploads/**`
的图片视频、根级 `projects/`、`tmp/` 等）不进 diff，任一条件缺失都会让文件消失；
快照超时/失败还会让整张卡片消失。

## P0（已完成，2026-10-19）

- `FileChangeEntry` 增加 `confidence?: "exact" | "unattributed"` 与 `sourceTool?`。
- 按工具语义登记写入路径（`file_move` 收 source+destination，`file_copy` 只收 destination）。
- `tool:start` 记录写目标写入前是否存在；回合结束时：
  - 登记路径在 diff 内 → exact，用 diff 状态；
  - 登记路径不在 diff（被快照忽略）→ `stat` + 写入前存在性合成 added/modified/deleted；
  - 快照失败 → 用起点 hash 兜底比对，卡片不再整体消失。
- ~~diff 内没人登记的路径 → unattributed，不再丢弃~~ →
  2026-10-19 修订：workspace 被所有会话共用，无证据的 diff 路径会串台；
  已改为 **exact-only**（见下方「归属修订」），无证据路径直接丢弃。

## P1（本轮）

### 目标

在工作台新增「变更」Tab，作为**会话级**变更台账，并提供批量产物的网格视图，
解决「文件太多、位置太散」的问题。

### 数据来源

不做新表：会话消息里已经持久化了每轮的 `fileChanges`（`assistant_parts.content_json`），
实时事件 `agent:turn:file-changes` 也会更新内存消息。台账直接从当前会话消息派生，
历史与实时共用一条路径。

### 纯函数（ledger.ts）

- `buildChangeLedger(messages)`：
  - 每轮 assistant 消息的 `fileChanges` 聚成一组，按时间倒序；
  - 全会话按路径去重，取**最新一轮**的状态统计总数；
  - 统计 added / modified / deleted；历史数据里的 unattributed 条目在此层过滤；
  - 媒体条目（图片/视频/音频）按所在目录分批，排除 deleted；
- `filterTurns(turns, filter, query)`：状态筛选 + 路径子串搜索；
- `mediaUrl(absPath)`：`lumii-local://media/?path=…`。

### UI（WorkspaceChangesPanel）

- 概要：`N 个文件 · 新增 x · 修改 y · 删除 z`。
- 视图切换：列表 / 产物。
- 列表：按轮分组（时间、文件数、子 Agent 标签），行内展示 A/M/D、扩展名、路径、
  来源工具；点击行内预览，行尾按钮「在文件中定位」。
- 产物：按目录分批的网格；图片用 `lumii-local` 懒加载缩略图，视频/音频用扩展名卡片；
  点击打开同一个 `FilePreviewModal`。
- 搜索框 + 状态筛选（全部/新增/修改/删除）。
- 长列表用 `content-visibility: auto` 降低渲染成本，不引入虚拟列表。

### 接线

- `WorkspaceWorkbenchArea` 从消息派生 ledger，传给面板并作为 Tab 角标数量。
- `useWorkspacePanels` 暴露 `workspaceDir` / `toAbsolutePath`，供缩略图与预览使用。

## 归属修订：exact-only（2026-10-19）

### 问题

workspace 被所有会话共用，回合快照 diff 会把并发会话/后台进程写入的文件算进当前回合；
原实现把这些无主路径标为 `unattributed` 展示，用户在卡片里看到大量对话中未提到的文件。

### 方案

`resolveTurnFileChanges` 改为 **exact-only**：只保留本会话有证据的路径，其余 diff 直接丢弃。

- 写文件工具（`file_write`/`file_edit`/`file_move`/`file_copy` 等）继续在 `tool:start` 登记；
- 生图/语音/截图等工具从结果里的 `details.filePath` 登记；
- `bash` / `execute_skill` / `skill_invoke` 用**命令文本 + 输出文本**作为证据
  （`collectToolEvidence`，上限 500,000 字符）：
  - 完整相对路径命中（右边界 token 校验，避免 `a.ts` 命中 `a.tsx`）；
  - 目录级命中：命令点名某个目录时，该目录下本轮新增的产物整批归属；
  - 路径归一化：`\`→`/`、折叠重复斜杠、忽略大小写；
  - 读类工具（`file_read`/`list_dir`/`grep` 等）不产生证据。
- 历史消息里的 `unattributed` 条目在渲染层（回合卡片、台账）过滤；
  `confidence` 字段保留只为兼容旧数据。

### 测试

- `turn-touched-paths.test.ts`：仅保留实例登记路径、bash 命令点名文件/目录、
  目录前缀不误伤、Windows 分隔符与大小写、bash 输出证据、读类工具无证据、
  `file_copy` 不误报源文件、`file_move` 双路径；
- 回合卡片与台账：旧 `unattributed` 数据被过滤；全为未归属时卡片不渲染、轮次不显示。
- `pnpm typecheck` 全包通过；`apps/windows` 全量 3970 passed，
  仅 3 个既有环境失败（本机未部署 `wechat-mcp.exe`、Edge TTS 403）。
