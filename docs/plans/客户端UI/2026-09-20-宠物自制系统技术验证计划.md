## 一、Goal

用 4 个**独立可失败**的验证点，确认「AI 生成静态部件 + 运行时程序化动画」这条主路径能否支撑用户自制宠物；每个验证点失败时都有明确的退路，能独立止损。

**一句话目标**：在投入任何产品实现之前，用最小成本回答「这条路走不走得通、走不通退到哪」。

## 二、Architecture

```
验证产物分层（决定了什么留下来、什么扔掉）

spike（一次性实验）          →  verify/ 目录，跑完即弃，不进主干
  验证点 A/B/C/D 的脚本          用真实素材跑，产出结论截图/数据

沉淀（验证通过才做）          →  packages/pet-asset/（工具链）+ packages/pet-core/（原语）
  固定实现、TDD 覆盖              从 spike 提炼，是后续产品实现的地基

结论                          →  docs/test/pet-sprite/验证报告.md
  四个验证点的判据结果 + 选型建议
```

**关键分离**：spike 与沉淀分开。spike 允许写脏代码、允许硬编码、允许失败；只有验证通过的结论才提炼成 `packages/pet-asset` 下的 TDD 代码。这样即使某个验证点失败，也不会留下半成品代码污染主干。

## 三、Tech Stack

**使用**：

| 用途 | 选型 | 说明 |
| --- | --- | --- |
| 图像处理 | `sharp@0.34.5`（**已在 `apps/windows` 依赖中**） | 抠底、切片、缩放、拼图集 |
| 运行时渲染 | `pixi.js@6.5.10`（已有） | 复用现有 PIXI Application |
| 素材生产（验证阶段） | Node 脚本程序化生成占位素材 | 不依赖任何外部素材，结果可复现 |
| 素材生产（验证点 D） | 客户端 `image_generate` 工具 | 唯一产生真实费用的验证点 |

**不引入**：

- ✗ 任何游戏引擎（Phaser / Cocos 等）
- ✗ 任何动画库（GSAP / Anime.js 等）
- ✗ 任何图集打包运行时（图集为构建期产物）
- ✗ 任何新的图像处理依赖（`sharp` 已够用）

## 四、Global Constraints

1. **验证脚本进 `verify/`，不进主干**。跑完即弃，不提交到 `packages/` 或 `apps/`。
2. **零模型调用除非明确标注**。验证点 A/B/C 必须可离线复现；只有 D 允许调用生图模型，且必须**先经用户确认**再执行。
3. **清单是数据不是代码**。`params` 只接受数值，禁止表达式、函数字符串、模板语法。此约束由 `validate` 强制，且必须有测试覆盖。
4. **不改现有渲染链路**。验证期间 `PetOrchestrator` / `PetCanvas` / Live2D 后端**一行不动**；运行时渲染验证用独立 HTML 页面（复用 `demos/` 惯例），避免干扰现有宠物模式。
5. **每个验证点独立可失败**。任何一个失败不得阻塞其余验证点；失败即记录退路，继续下一个。
6. **不写用户 workspace**。验证产物落在仓库内 `verify/` 与 `docs/test/pet-sprite/`。
7. **TDD 只约束沉淀代码**。`packages/pet-asset` 下的工具链先写失败测试再实现；spike 脚本不受此约束。

## 六、Task 分解

### T1 — 验证素材生成（阻塞全部后续）

**做什么**：写 `gen-fixtures.mjs`，程序化生成验证所需素材，保证结果可复现、不依赖外部图片。

产物：
- `char-magenta.png` — 角色部件图，纯品红底（模拟 AI 生图输出的不透明底）
- `sheet-4x4.png` — 4×4 网格切片源图（模拟手绘图集）
- `parts/` — 分离的眼/嘴部件（用于分层合成验证）

**关键设计**：品红底色**故意选与角色色接近但有可测差异的值**，用来验证抠底算法的容差边界，而不是只测「纯色 vs 纯色」的理想情况。

**改哪些文件**：`verify/pet-sprite/gen-fixtures.mjs`

**验证命令**：
```bash
node verify/pet-sprite/gen-fixtures.mjs
# 预期：生成 6 个 PNG，控制台打印尺寸与路径
```

---

### T2 — 验证点 A：抠底与切片（依赖 T1）

**做什么**：用 `sharp` 实现并验证三条图像处理路径。

| 子项 | 判据 |
| --- | --- |
| A1 抠底 | 品红底被完全移除，角色边缘无残留色晕、无误伤的半透明区域 |
| A2 网格切片 | 4×4 图切出 16 张等大帧，尺寸精确、无偏移 |
| A3 锚点对齐 | 分离部件按锚点拼回，**像素级对齐**（允许偏移 ≤ 1px，且需为偶数对齐） |

**改哪些文件**：`verify/pet-sprite/check-cutout.mjs`

**验证命令**：
```bash
node verify/pet-sprite/check-cutout.mjs
# 预期：三项全 PASS，输出对齐误差数据 + 对比图到 docs/test/pet-sprite/evidence/
```

**失败退路**：抠底边缘色晕无法消除 → 放弃生成线，转纯手工素材（带 alpha 的 PNG）。**不阻塞 B/C/D**。

---

### T3 — 验证点 B：程序化原语（依赖 T1）

**做什么**：实现 5 个原语并断言其在时间轴上的取值。此任务同时是**沉淀代码的 TDD 起点**——先写测试再实现。

原语与判据：

| 原语 | 参数 | 断言 |
| --- | --- | --- |
| `bob` | 振幅 px | t=0 与 t=周期 归零；峰值 = 振幅；连续无跳变 |
| `breathe` | 缩放倍率 | 缩放中心在锚点（脚底），非图像中心；范围 [1, 倍率] |
| `sway` | 角度 | 以锚点为轴心；正负对称 |
| `blink` | 平均间隔 ms | 间隔在期望区间内随机；单次眨眼时长固定；不连续两次眨眼 |
| `nod` | 角度 | 同 sway，用于点头语义 |

**关键设计**：所有原语接收**归一化时间 t**（秒）而非帧号，输出变换量。纯函数，无副作用——这是能单测的前提。

**改哪些文件**：`packages/pet-core/src/render/procedural-motion.ts`（沉淀）+ `verify/pet-sprite/check-procedural.mjs`（可视化抽查）

**验证命令**：
```bash
cd packages/pet-core && npx vitest run src/render/procedural-motion.test.ts
node verify/pet-sprite/check-procedural.mjs   # 输出一段动画序列帧供肉眼抽查
```

**失败退路**：原语效果「像一张图在滑动」→ 原语降级为辅助，主表现力回到帧动画（说明生成线需要 AI 产帧能力，即验证点 D 变成必需项）。

---

### T4 — 验证点 C：运行时合成（依赖 T2、T3）

**做什么**：独立 HTML 页面同时渲染四类内容，验证它们能否无冲突共存。

| 共存维度 | 验证内容 |
| --- | --- |
| base 帧序列 | 图集帧按 fps 播放 |
| face 覆盖层 | 眼部/嘴部覆盖在 base 上，按锚点定位 |
| 程序化原语 | 对整体施加 bob/breathe/sway |
| 嘴型切档 | `setMouthOpen(0~1)` → 档位切换（模拟口型驱动） |

**判据**：
- 覆盖层**像素级对齐**，缩放时不错位（验证原点设置正确）
- 原语作用于整体时，覆盖层跟随（验证层级正确）
- 连续播放 60s 无抖动、无掉帧、无内存增长
- `pixelArt: true` 时 `nearest` 采样，缩放不糊

**关键风险点**：覆盖层与 base 必须共用**同一原点坐标系**。PIXI 中子 `Sprite` 默认以自身左上角为原点，若不给覆盖层设置 `anchor` 并用容器统一变换，缩小时会分离。这是本验证点最可能暴露的问题。

**改哪些文件**：`verify/pet-sprite/check-composite.html`

**验证命令**：
```bash
# 用项目已有的静态服务方式打开（或直接 file:// 打开）
# 目视验收 + 浏览器 Performance 面板记录 60s
```

**失败退路**：覆盖层无法稳定对齐 → 简化分层，退回整体帧方案（即设计文档 §4.2 方案 A）。

---

### T5 — 图集打包与清单校验（依赖 T2）

**做什么**：实现 `pack` 与 `validate` 两个子命令，并用**对抗性用例**验证校验强度。

**`validate` 必须拦截的输入**（每条都要有对应测试）：

| 非法输入 | 期望 |
| --- | --- |
| `params` 中含字符串表达式（如 `"sin(t)"`） | 拒绝，并指出违规字段 |
| `params` 值为函数/对象 | 拒绝 |
| 帧引用不存在的图集条目 | 拒绝 |
| 声明的图集文件不存在 | 拒绝 |
| 空 animations / 动画组名为空 | 拒绝 |

**改哪些文件**：`packages/pet-asset/src/validate.ts` + `validate.test.ts`（先写测试）、`verify/pet-sprite/check-validate.mjs`

**验证命令**：
```bash
cd packages/pet-asset && npx vitest run
cd apps/windows && npx tsc --noEmit    # 新增包后必须重跑类型检查
```

**失败退路**：无（本任务无技术不确定性，属于必做的基础设施）。

---

### T6 — 验证点 D：图生图参考链（依赖 T2；**需要用户确认后执行**）

⚠️ **本任务产生真实生图费用。**

**做什么**：以上一帧为参考生成下一帧，验证角色一致性是否随帧数衰减。

步骤：
1. 用 `image_generate` 生成第 1 帧（品红底，明确姿态与角色描述）
2. 以第 1 帧为 `referenceImagePaths` 生成第 2 帧（同角色，姿态微调）
3. 以第 2 帧为参考生成第 3 帧
4. 三帧并排 + 与第 1 帧叠加对比

**判据**：
- 第 3 帧与第 1 帧**肉眼可辨为同一角色**（体型、五官布局、配色一致）
- 三帧在抠底+对齐后能连续播放且不「跳」（帧间位移在合理范围内）

**成本控制**：只生成 3 帧即可得出结论，不做批量。若第 3 帧已明显漂移，立即停止。

**失败退路**：放弃 AI 生成帧序列，仅生成静态部件（回到主路径，不影响 A/B/C 的结论）。

---

## 十之二、追加实验 — 直出图集

**触发**：用户在 T6 执行期间提出「可以让生图模型直接产出目标格式，现在的生图模型很厉害」。

**做法**：一次生成 2×2 图集（站立 / 挥手 / 坐下 / 跳跃，四格均为纯品红底）。

**结果**：S1 不越界 ✓ / S4 角色一致 93.3% ✓ / S5 抠底可用 ✓；S2 格子对齐 ✗ / S3 尺度一致 ✗（软要求）。

**判定：可用，但需逐格归一化。** 软要求不达标不影响可用性 —— 精灵流水线本就要求逐格抠底 + 按共同地线对齐（该步骤已在 A3 验证，误差 0px）。

**意义**：一致性由单次生成天然保证，且成本为链式的 1/N。**这是后续素材生产的推荐路线。**
