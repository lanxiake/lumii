块引用的循环风险
需限制
A 文档嵌入 B 的段落，B 又嵌入 A 的段落时，渲染会递归。第一版必须禁止跨文档的二级嵌入，或在检测到环时降级为普通引用。
这个模型的取舍
适合：设定集、人物小传、反复引用的世界观段落。
代价：“在正文里改还是改源文”的语义必须明确；同步、冲突、循环都要处理。
建议：第一版不做；等稳定引用跑通、用户明确要求“正文里直接改设定”时再上。

失效时怎么回退

1. 精确锚点命中 → 直接定位
2. 锚点偏移 → 上下文匹配
3. 仍然失败 → 展示引用时快照，并标记“来源已改动”
三种模型的稳定性
同一份数据
轻量稳定引用高
能定位到句；失效有快照兜底。需要维护锚点与刷新动作。
块级 transclusion中
能同步源文；但同步冲突、循环、编辑语义都要额外设计。
文件级引用低
实现最简单；无法定位段落，也无法判断来源是否还相关。

建议的落地顺序

1文件级 @ 引用（已有基础）先保证“能把文件放进上下文”
2轻量稳定引用 + 快照正文里能精确引用一句话，并能回退
3块级 transclusion等用户明确需要在正文里改设定再做
如果源文改了，引用会自动更新吗？
Lumii
轻量稳定引用不会自动改正文。它会先尝试重新定位锚点：位置没变就只标记“来源已改动”；位置变了就提示刷新；找不到就展示引用时的快照。
那和我直接在正文里嵌入一段有什么区别？
Lumii
嵌入是“这一段就是源文的一部分”，源文改了正文跟着变；引用是“我在这里提到了它”，源文改了正文不变，只提示你去确认。前者适合设定集，后者适合叙事正文。
