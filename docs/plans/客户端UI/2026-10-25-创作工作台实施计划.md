> 创建：2026-10-25 · 状态：**已实施**（T1–T9 全部落地，真机冒烟通过；见 §八 实施记录）

**先读这一段**：本期只做设计 §四 的 **P1** —— **新增 `app_panel` 工具，让 Agent 自己决定
"要不要开面板、开哪个模式"**，渲染层忠实执行。UI 不做任何启发式判断（不问扩展名、不问文件大小）。

P2（卡内网格）、P3（右栏板式）、P4（中栏模式）**都不在本期**，各自"什么时候才做"写在设计 §四 对应段落。

## 一、目标

用户说"把第二章打开我改改"，稿子出现在右栏、可编辑可保存；说"看看结果就行"，
就只在对话里用 `a2ui` 显示——**这个分叉由模型判断，不由 UI 猜**。

做完之后：

1. Agent 调 `app_panel { mode:'doc', path:'卷二/第二章.md' }` → 右栏打开该文件；
2. 右栏多一个「文档」Tab，与文件/变更/版本并列，宽度独立记忆；
3. 模式清单唯一（`APP_PANEL_MODES`），工具 schema 从中生成，渲染层按它校验，写错要报错不回落。

**不做**（设计 §七）：卡片横向并排、中栏换模式、独立创作空间、小说 Binder、时间轴编辑器。
**也不做**：让 UI 根据文件类型自动开面板。

---

## 二、为什么是"Agent 控制"而不是"UI 自动"

| 信息 | 谁能看到 |
|---|---|
| 用户说"通读一遍"还是"改第三段" | 只有模型 |
| 用户在改稿还是只是看看结果 | 只有模型 |
| 文件是 `.md` | UI 也能看到 —— **但这就够了？不够** |

只有一个 `.md` 文件，用户可能是"打开我要改"也可能是"贴出来给我看看"，
两者都合理。按扩展名自动开面板，等于把意图判断降级成文件名判断，
猜错的代价是**用户正在读的对话被一块面板挤走**。

已有的同款先例（这是延伸，不是新机制）：

- `app_goto` —— Agent 决定去哪一页；
- `a2ui_guide` 的 `selection_guide` —— Agent 决定用 Chart 还是 DataTable；
- `skill_invoke` —— Agent 决定调哪个技能。

## 三、任务分解

### T1 · 模式清单（唯一真相源）

**新增** `src/shared/app-panel-modes.ts`

```ts
/** 右栏面板可用的呈现模式。工具 schema、渲染层校验、错误码提示都从这里衍生。 */
export const APP_PANEL_MODES = ['doc'] as const
export type AppPanelMode = typeof APP_PANEL_MODES[number]

/** 每个模式写给模型看的用途说明（也是唯一的文档来源） */
export const APP_PANEL_MODE_HINTS: Record<AppPanelMode, string> = {
  doc: '可翻可改的 markdown 稿件。用户说"打开这篇/改这段/通读一遍"时用。',
}

export function isAppPanelMode(v: unknown): v is AppPanelMode {
  return typeof v === 'string' && (APP_PANEL_MODES as readonly string[]).includes(v)
}
```

- 放 `src/shared/` 而不是 `src/main/`：主进程（工具 schema）和渲染层（Tab 校验）都要读。
- **不放在** `plugins/api/`：面板是宿主能力，不给插件注册新模式（设计 §九）。

**验收**：`app-panel-modes.test.ts`——`isAppPanelMode('doc')` 为真、`'auto'`/`''`/`null` 为假；
`APP_PANEL_MODE_HINTS` 的键集合必须等于 `APP_PANEL_MODES`（防止加模式忘了写说明）。

### T2 · `app_panel` 工具

**新增** `src/main/agent-runtime/bridge-app-panel-tools.ts`，照 `bridge-app-ui-tools.ts` 的结构写。

```ts
const APP_PANEL_DESCRIPTION = `在右侧面板打开内容给用户阅读/编辑。
只在用户需要**持续看或改**时用；只是想让用户看到结果，用 a2ui（图表/表格/图片在对话里就行）。
模式：
${APP_PANEL_MODES.map((m) => `- ${m}：${APP_PANEL_MODE_HINTS[m]}`).join('\n')}
不给 mode 或给了不存在的 mode 会失败，失败码里列出可用模式。`

name: 'app_panel'
parameters: Type.Object({
  mode: Type.String({ description: `呈现模式：${APP_PANEL_MODES.join(' | ')}` }),
  path: Type.Optional(Type.String({ description: '工作区相对路径或绝对路径（doc 模式必填）' })),
})
```

三个检查，**全部显式返回错误，不回落**：

| 条件 | 返回 |
|---|---|
| 模式不在清单 | `{ok:false, error:'unknown_mode', available: APP_PANEL_MODES}` |
| `doc` 但没给 path / 文件不存在 | `{ok:false, error:'file_not_found'}` |
| 受 `privacy.allowAgentAppUiControl` 关掉 | `{ok:false, error:'disabled'}` |

**通路**（与 `app_goto` 同一条，不是新机制）：

```
工具 execute → win.webContents.send('app-ui:panel', { mode, path })
            → App.tsx 写进 runtime store（顶层一次性意图）
            → ChatPage 消费 → useWorkspacePanels.openDoc(path) → 右栏切到「文档」
```

- **不进 `ChatMessageActionsContext`**：那条链是"消息行 → 页面"，这里是"主进程 → 页面"，
  混进去会牵连 `ChatMessage` 的 memo 契约（现有风险已由 `ChatMessageActionsContext.tsx` 文件头说明）。
- 用完即清：`ChatPage` 消费后 `setPendingPanel(null)`（同 `pendingPetHandoff` 的纪律）。

**注册**：在 `bridge-tool-registrar.ts` 里跟 `registerAppUiTools` 并排调用。

**验收**：
- `bridge-app-panel-tools.test.ts`——四类参数各一组（合法 / 未知模式 / 缺 path / 被关闭），
  断言返回形状与**不回落**（失败时 `ok !== true`）；
- `host-tool-prompt-coverage.test.ts` 的工具名扫描能扫到 `app_panel`（该测试扫宿主源码，
  新文件放对位置即自动纳入）。

### T7 · ChatPage 消费意图

**文件**：`src/renderer/pages/ChatPage/ChatPage.tsx`

在 `useWorkspacePanels()` 解构里取 `openDoc`，再加一个 effect：

```tsx
useEffect(() => {
  if (!pendingPanel) return
  const req = pendingPanel
  setPendingPanel(null)          // 先清再执行：失败也不重试
  if (req.mode === 'doc' && req.path) openDoc(req.path)
}, [pendingPanel, openDoc])
```

- **先清再执行**：与 `pendingPetHandoff` 同一条纪律（失败不无限重试）。

1. 打开一个含 `.md` 的工作区会话；

8. 把 `privacy.allowAgentAppUiControl` 关掉 → `app_panel` 返回 `disabled`，面板不开。

## 六、风险

| 风险 | 发生率 | 缓解 |
|---|---|---|
| **模型滥用面板**（每篇都开） | 中 | 工具描述明写"只在需要持续看/改时用"；§5.2 第 3 步专测这个；若仍滥用，在提示词分组里加一行反例 |
| **模型从不调工具**（只会贴 markdown） | 中 | §5.2 第 2 步专测；不行就在提示词里给一个正例 |
| 未知模式静默回落 | 低 | 设计上就禁止（T2 明确返回 `unknown_mode`）；单测守住 |
| `docEnabled` 传错导致空白 Tab | 中 | `docPath` 为空即不显示 Tab；T5 补单测 |
| 编辑器与 Agent 同时写同一文件 | 低 | 保存前比 mtime，不一致提示覆盖；本期只做提示，不做合并 |
| 760px 下 md-editor 双栏太挤 | 中 | `FilePreviewModal` 的 embedded 已自适应；实测太挤就用它现成的「预览/源码」单栏切换 |
| 与 `app_goto` 语义重叠、模型分不清 | 中 | 描述里划清：`app_goto` = 换页面；`app_panel` = 当前页开面板。若仍混，考虑合并成一个带 `target` 的工具 |

## 七、后续模式（写在这里防止被遗忘）

每加一个模式 = `APP_PANEL_MODES` 加一项 + `WorkspaceWorkbenchArea` 加一个分支 + 一条单测。
**不要一次把四种模式都铺开**——三个没有调用方的分支就是三份要维护的代码。

| 模式 | 触发条件 | 数据来源 |
|---|---|---|
| `candidates` | 用户说"给我几个标题/生成 4 张挑一张" | 卡片内网格（设计 §四 P2） |
| `board` | 用户说"分镜/清单/矩阵"，多行结构化内容 | 分镜 markdown 表或 `DataTable` |
| `compare` | 用户说"这版和上版比 / A 和 B 比" | 两次产出（`vcs-diff.ts` 的 `structuredPatch` 可用） |

其余后置项（内联建议块、中栏模式、小说 Binder）见设计文档 §七 与 §十。

## 八、实施记录（2026-10-25）

T1–T9 全部落地，`tsc --noEmit` 无错，全量 vitest **4283 passed / 0 failed**，
`docs/test/lumii-cli/chat/run-timeline-cards.mjs` 回归 PASS。

### 8.1 落点与计划的三处偏差

| 计划 | 实际 | 原因 |
|---|---|---|
| `controller.ts` 加 `panel(input)` 并供工具调用 | 控制器确有 `panel()`，但工具注册时**直接传 `{panel}` 最小接口**，没有走 `createAppUiController` 的实例 | `registerAll()` 原本每次都新建一个 controller；改成建一份复用给 `app_ui` 与 `app_panel`，两边的 `getWindow` / `readSettingsJson` 只写一次 |
| 事件载荷是 `{mode, path}` 原样 | 工具层把 path **统一成绝对路径 + 正斜杠**再发 | 渲染层（FileTree / FilePreviewModal）全按 `/` 处理；让主进程做一次归一，比每个消费方各转一次可靠 |
| `App.tsx` 直接写入 store | 先用 `isAppPanelMode()` 过一道 | 前端不信任事件载荷：非法模式不进 store，`ChatPage` 就不必再判 |

### 8.2 真机冒烟结果（8 条全过）

|---|---|---|
| 1 | 说「把 X.md 打开，我要改」 | 模型调 `app_panel{mode:'doc'}`，右栏宽 760 并渲染该文件 |
| 2 | 模型第一次猜 `mode:'open'` | 返回 `{ok:false,error:'unknown_mode',available:['doc']}`，模型自行改对后成功——**不回落这条真的起作用了** |
| 3 | 说「给我看看这篇的内容就行」 | **只** `file_read` + 贴正文，面板没开（核心验收） |

| 5 | 拖到最大宽（1160） | 对话柱 280，`chat-container` 无横向溢出 |
| 6 | 右键 `.md` →「在文档 Tab 打开」 | 切到文档并渲染 |
| 7 | 关工作台再开 | 文档 Tab 仍在，仍是上次那份 |

### 8.3 实施中发现并修掉的两件事

- **Esc 会误关整个工作台**：`WorkspaceWorkbench` 的 Esc 只检查 `[data-file-preview-open]`，
  但 `variant='embedded'` 不渲染这个标记。在文档 Tab 按 Esc 本想退出编辑，结果面板整块关掉。
  修法：`visibleTab === 'doc'` 时同样放行，交给嵌入的预览自己处理（退出编辑 → 回文件页）。
- **`WorkbenchTab` 联合扩了一个成员后，`visibleTab` 需覆盖两个失效条件**（vcs 插件停用 + 无 docPath），
  否则"文档 Tab 不可用却留在 doc"会渲染一块空白。已改成两级回退。
