# 微信 MCP 设计改进计划

> 状态：**执行中** ｜ 领域：`渠道与CLI`
> 关联：[`微信聊天记录接入PoC验证计划`](./2026-10-06-微信聊天记录接入PoC验证计划.md)、
> 代码落点 `apps/windows/resources/wechat-mcp/`、测试套件 `docs/test/lumii-cli/wechat-mcp/`

## 0. 目标

在**已站住的安全底座**（前置校验 / dry-run 默认 / 双印证目标校验 / 发送后读库确认 / 严格名字解析 / 搜索兜底定位）之上，
补齐**能力缺口**、**可靠性**与**性能**，让常用微信操作**准确、稳定、快速**。

**已完成（2026-10-07，作为基线）**：6 个工具 `list_sessions`/`read_history`/`poll_new`/`check_env`/`send_text`/`send_file`；
server 更名 `wechat-local` 与渠道 `weixin` 严格区分；工具 description 带「何时用/别用」；WM 套件 11/11 通过。

**非目标（本轮先不做）**：更换 OCR 引擎（RapidOCR 等）；Qt 无障碍网关（注入类）；微信语音消息（按住录音，无法自动化）。

## 1. P0 —— 决定「能不能稳定用」

| 步 | 项 | 做法 | 判据 |
|---|---|---|---|
| **P0-1** | **进程内截图（提速）** | 用 ctypes GDI（`BitBlt` + `GetDIBits`）在 Python 内直接抓窗口位图并手写 PNG，**去掉每次截图 spawn PowerShell** | 同一次发送的截图耗时明细可见下降；发送总耗时不升；WM 套件全绿 |
| **P0-2** | **会话定位原语** | `list_sessions(query=...)` 返回候选（name+talker），让 Agent **在发送前就能拿到确切名字**；`resolve_talker` 保持严格 | 新用例 WM-12：按关键词能定位到目标会话；错词返回空候选而非乱匹配 |
| **P0-3** | **结构化错误码** | 所有工具返回加 `error_code`：`env_not_ready` / `target_not_found` / `target_ambiguous` / `input_not_landed` / `send_not_confirmed` / `attachment_missing` | 新用例 WM-13：各失败路径返回**预期 error_code**（而非只有中文句子） |
| **P0-4** | **并发互斥** | 加**跨进程文件锁**（`msvcrt.locking` on a lock file），一次只允许一个 UI 操作；拿不到锁即返回 `busy` | 新用例 WM-14：并发两次 `send_text`，一个成功、另一个返回 `busy` 且**不产生副作用** |

## 2. P1 —— 决定「好不好用」

| 步 | 项 | 做法 | 判据 |
|---|---|---|---|
| **P1-1** | 消息检索 | `search_messages(keyword, talker?, since?, until?, limit?)`（优先走 `message_fts`，退化 LIKE） | 能检索到已知历史消息；带时间范围过滤正确 |
| **P1-2** | 未读/待回视图 | `list_unread()`：读 `session.db` 的 `unread_count` + 各会话「最后一条不是我发的」 | 与微信 UI 未读一致（抽样核对） |
| **P1-3** | 失败现场 | 返回值带**最后一次截图路径**；异常栈落 `WORK/fail-*.log` | 人为制造一次失败，能从返回里找到截图并肉眼确认状态 |
| **P1-4** | 量化指标 | 每次操作记 `{op, ms, ok, error_code}` 到 `WORK/metrics.jsonl`；`devcli stats` 汇总 | smoke：发送 P50/P90 耗时、成功率可读出 |
| **P1-5** | 发送走审批（草稿） | 与客户端审批闭环对接（或至少群聊/首次发送前二次确认） | 设计对齐后再实施 |

## 4. 执行约定

- **小步快跑**：每步独立可验收，改完即跑对应用例（或整条 WM 套件），**红了就停**。
- **安全不回退**：任何改动不得削弱「双印证 + 读库确认 + 严格解析」；宁可拒绝，不许盲发。
- **每步留证据**：套件证据写 `wechat-mcp-evidence.jsonl`；性能数字进报告。
- **改 py 后必须重载 MCP server**（客户端 MCP 面板「配置文件 → 保存并重连」），否则跑的还是旧代码。

| **已知观察** | ⚠️ | **`grab_png` 抓的是「窗口所在屏幕区域」**（`GetDC(None)`+按 rect `BitBlt`），被压在微信之上的窗口会污染 OCR。实测：微信前台 8 行 / 被遮挡后 0 行；`PrintWindow(PW_RENDERFULLCONTENT)` 可抗遮挡（返回码 1、内容正确）。**当前发送路径已把微信置前台并复核 `foreground`，故正常流程不受影响**；仅当有**置顶不透明窗口**压住时才可能串味。另外微信宽窗右侧存在固定栏，其 OCR 文本会进入 `chat_text`（跨会话恒定，不破坏判据，但属噪声）。改抓图法会使 OCR 像素与现网略有差异，有回归风险，暂不改 |
