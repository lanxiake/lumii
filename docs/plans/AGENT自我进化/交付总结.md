## 三、核心问题解答

### 问题 1：Agent 有什么用？

**3 个实际应用场景：**

#### 场景 1：能力自动提升
```
用户多次请求生成 React 组件
→ Agent 发现代码质量满意度低
→ 自我反思：缺少 TypeScript 类型定义
→ 生成学习目标：学习 TS 最佳实践
→ 请求用户批准 → 执行学习
→ 下次生成带完整类型的代码
```

#### 场景 2：主动提醒和帮助
```
Agent 观察用户行为模式
→ 发现：每天 9:00 查看日程
→ 生成目标：8:50 提前准备摘要
→ 请求批准 → 用户同意
→ 每天自动执行
```

#### 场景 3：能力边界透明化
```
用户：分析复杂数据集
Agent：检测难度超过能力边界
→ 诚实告知：当前能力 0.6/1.0
→ 尝试执行并记录结果
→ 根据反馈更新能力评估
→ 生成针对性提升目标
```

**对比传统 AI：**

| 维度 | 传统 AI | 自主进化 Agent |
|------|---------|---------------|
| 能力 | 固定不变 | 持续进化 |
| 评估 | 无法自评 | 实时评分 |
| 学习 | 需人工调优 | 自主学习 |
| 透明度 | 黑盒 | 可观测 |

## 七、核心算法总结

### P0 算法

| 算法 | 公式 | 用途 |
|------|------|------|
| 满意度评分 | `0.35×task + 0.30×feedback + 0.20×efficiency + 0.15×knowledge` | 评估表现 |
| ε-greedy | `ε=0.15` | Prompt 探索 |
| UCB1 | `score + c × √(ln(N)/n)` | Prompt 选择 |

### P1 算法

| 算法 | 公式 | 用途 |
|------|------|------|
| Elo Rating | `newLevel = level + K×(actual - expected)` | 能力追踪 |
| Logistic | `1/(1 + e^(-10×(level - difficulty)))` | 预期表现 |
| 置信度 | `1 - e^(-testCount/20)` | 评估可信度 |

### P2 算法（计划中）

| 算法 | 用途 |
|------|------|
| Learning-to-Rank | 记忆排序优化 |
| Thompson Sampling | 工具选择优化 |
| Shapley Value | 层级贡献归因 |
