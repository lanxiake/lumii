## D2 · 4 条预置任务迁移

### 改动（`apps/windows/src/main/seed-cron-jobs.ts`）

1. `SEED_JOBS` 中 4 条的 `agentId` 改为 `'chronicler'`（新装直接正确）：
   `seed-morning-briefing` / `seed-daily-report` / `seed-weekly-review` / `seed-focus-check`
2. 新增迁移函数 `migrateWorkReportsToChronicler(db)`（在 `ensureSeedCronJobsSeeded` 顶部与现有迁移并排调用）：

```ts
/**
 * 工作简报类任务转正：执行者 assistant → chronicler。
 * 仅迁移「未被用户改过」的行（agent_id 仍为 'assistant'）；改过/删过的不碰。
 */
function migrateWorkReportsToChronicler(db: DatabaseAdapter): void {
  const jobIds = ['seed-morning-briefing', 'seed-daily-report', 'seed-weekly-review', 'seed-focus-check'] as const
  for (const id of jobIds) {
    try {
      const r = db.prepare(`UPDATE local_cron_jobs SET agent_id = 'chronicler'
                            WHERE id = ? AND agent_id = 'assistant'`).run(id)
      if (r.changes > 0) log.info(`[migrateWorkReportsToChronicler] ${id} → chronicler`)
    } catch (err) { log.error(`[migrateWorkReportsToChronicler] ${id} 失败:`, err) }
  }
}
```

- 注意：`task_text` / `system_prompt` / 调度 / 开关一律不动（口径不变的实现方式）。
- `DEFAULT_AGENT_ID`（`'assistant'`）常量保留——news-pipeline 在 D3 前仍用它。

### 验收

- [ ] 新库首启后 4 条任务 `agent_id='chronicler'`（查 `local_cron_jobs`）
- [ ] 老库升级后同样迁移；把其中一条手工改成别的 agent 后重启**不被覆盖**
- [ ] `cron run seed-daily-report`（手动）产出与迁移前一致（对比一条历史 summary 的段落结构：今天完成 / 进行中 / 明天优先）
- [ ] 产出消息 `agent_id='chronicler'`（A1 的查库法：`SELECT agent_id FROM messages WHERE conversation_id='cron:seed-daily-report'`）

## D3 · info-curator 定义 + news-pipeline 迁移

### 1. 定义（「灵栖情报」）

`INFO_CURATOR_DEF`：

- `id: 'info-curator'`、`name: '灵栖情报'`、`sourceType: 'system'`、`selectable: true`、`isActive: true`
- `systemPrompt`（`prompts.ts` 新条目）：角色——按用户偏好策展资讯；
  - 每次运行**先读偏好**（`profile_memory` / `memory_search`，如订阅领域、反感类型、时段）；
  - 按偏好筛选与去重；**不编造条目**（沿用现有口径）；
  - 把本次筛选依据写入 `memory_manage`（供下轮与用户查阅）。
- `tools` 白名单：`web_search/web_fetch/bing_search`、`dashboard_feed_write`、`memory_search/memory_read/memory_manage/profile_memory`、`wiki_search`、`skill_list/skill_search/skill_invoke`、`todo_write`
  （无 bash / 无文件写）

### 2. `news-pipeline` 迁移（`seed-cron-jobs.ts`）

1. `SEED_JOBS` 中 `news-pipeline` 的 `agentId` 改为 `'info-curator'`；
2. `NEWS_PIPELINE_SYSTEM_PROMPT` 升级（**保留原有选条/摘要/综述口径逐字不变**，只在首尾加两步）：
   - 首：「0. 先读用户偏好（`profile_memory` / `memory_search`）：关注的领域、反感的内容类型；按偏好调整选题侧重。」
   - 尾：「4. 完成后把本次的筛选依据（侧重什么、排除了什么及原因）用 `memory_manage` 记一条。」
3. 新增迁移 `migrateNewsPipelineToInfoCurator(db)`：
   - `agent_id='assistant'` → 改 `'info-curator'`（其他值不动）；
   - `system_prompt` 仅在命中旧文本特征（不含「先读用户偏好」的现有 version）时升级为新文案——仿 `migrateSystemPromptsForWorkReports` 的特征匹配模式，**用户手改过的 system_prompt 不覆盖**。

### 验收

- [ ] `cron run news-pipeline` 由 info-curator 执行，概览页资讯卡正常写入（`dashboard_feed_items` 有新条目）
- [ ] 在会话里说「以后少推论文」→ 其记忆出现该偏好 → 下一轮产出体现（人工判断，一轮即可）
- [ ] 用户改过 system_prompt 的库不被迁移覆盖（构造一条改过的行验证）
