## A1 · cron 产出归属修正

**问题**：cron 任务驱动任意 Agent 执行后，会话消息落库与记忆写入都标 `assistant`（`bridge.ts` 的 CronScheduler 注入处硬编码）。多 Agent 产出会污染 L1 的满意度评分与能力画像——满意度是 Prompt 进化与人格 EMA 的输入，错误输入比不接更糟。

**改动**：

1. `apps/windows/src/main/agent-runtime/cron-scheduler.ts`
   - `driveAgent(job, row, agentId, startedAt)`：两处 `this.deps.saveMessage?.({ conversationId, role, text })`（约 `:889-898`）补 `agentId`；`driveAgent` 已持有解析后的 agentId（`runLocalCronJob` 的 `job.agent_id ?? DEFAULT_AGENT_ID` 分支）。
   - 全文件 grep `addMemory?.`：调用点同样补 `agentId`。
2. `apps/windows/src/main/agent-runtime/bridge.ts`（`initializeCronScheduler` 注入，约 `:1129-1151`）
   ```ts
   saveMessage: (params) => {
     this._conversationRepo?.saveMessage({
       conversationId: params.conversationId,
       agentId: params.agentId ?? 'assistant',   // ← 由 params 透传
       role: params.role,
       contentJson: { type: 'text', text: params.text },
     })
   },
   addMemory: (content, agentId) => {
     this._memoryManager?.addMemory({
       agentId: agentId ?? 'assistant',
       userId: 'local-user', category: 'project', content,
     })
   },
   ```
3. `CronSchedulerDeps` 类型（cron-scheduler.ts 顶部接口）同步扩参：
   `saveMessage?: (params: { conversationId: string; role: 'user' | 'assistant'; text: string; agentId?: string }) => void`
   `addMemory?: (content: string, agentId?: string) => void`

**测试**：
- 单测：`cron-scheduler` 相关既有测试的 mock deps 补断言（saveMessage 收到的 agentId === job.agent_id）。
- 手工查库：`cron run <id>` 后 `SELECT agent_id FROM messages WHERE conversation_id='cron:<id>'` 与 job 的 `agent_id` 一致。

**验收**：查库一致；`run-autonomous-life-e2e.mjs` 23 例仍绿。

## A3 · `evolution:` 会话泛化（3 处精确匹配）

**问题**：多 Agent 的自主会话将是 `evolution:<agentId>`，但现有三处守卫是精确匹配 `evolution:main`，漏改会导致误删会话 / 心跳被自主会话卡死。

**改动**（实施时 grep `EVOLUTION_CONVERSATION_ID` 复核无遗漏）：

| # | 位置 | 现状 | 改为 |
|---|---|---|---|
| 1 | `conversation-commands.ts:293`（删除守卫） | `sessionKey === EVOLUTION_CONVERSATION_ID` | `isEvolutionConversationId(sessionKey)` |
| 2 | `conversation-commands.ts:582`（`resolveConversationChannel`） | `conversationId === EVOLUTION_CONVERSATION_ID` | `isEvolutionConversationId(conversationId)` |
| 3 | `bridge.ts:1223`（`hasActiveUserTurn` SQL） | `AND conversation_id != 'evolution:main'` | `AND conversation_id NOT LIKE 'evolution:%'` |

- helper 落点：`packages/agent-runtime/src/autonomous/config.ts` 增
  ```ts
  export const EVOLUTION_CONVERSATION_PREFIX = 'evolution:';
  export function isEvolutionConversationId(id: string): boolean {
    return id === EVOLUTION_CONVERSATION_ID || id.startsWith(EVOLUTION_CONVERSATION_PREFIX);
  }
  ```
- 渲染层无需改动：#2 修正后 `channel === 'evolution'` 的既有过滤（ChatPage 自动恢复、侧栏分组）自动覆盖所有 `evolution:*` 会话。
- ChatSidebar「进入自主进化」固定入口（`index.tsx:397-404`）继续指向 `evolution:main`；多 Agent 会话会作为普通会话出现在「系统」tab。

**测试**：单测覆盖 `isEvolutionConversationId`（`evolution:main` / `evolution:code-dev` / `evolution:` 前缀边界——`evolutionary:x` 不算）。

**验收**：手工创建一个 `evolution:code-dev` 会话 → 删除被拒；启动自动恢复不会切到任何 `evolution:*` 会话。

## A2 · tick 多 Agent 遍历（核心重构）

**问题**：`evolution-tick.ts:25` 硬编码 `EVOLUTION_AGENT_ID = 'assistant'`；所有副作用回调（落独白 / 执行目标 / 反思 / 日记 / 规划）都绑定 assistant 与 `evolution:main`（bridge 注入处写死）。

**设计**：`handleEvolutionTick` 从「单 Agent 执行」改为「遍历自主 Agent 列表，逐个执行」；每个 Agent 独立 try/catch，互不影响；返回汇总字符串（写入 `local_cron_runs.summary`，定时任务页可见）。

**改动 1 · `evolution-tick.ts`**

```ts
export interface EvolutionTickDeps {
  // ...现有字段
  /** 参与本次 tick 的 agentId 列表（bridge 读取 app.json autonomousAgents） */
  listAutonomousAgentIds?: () => string[]          // 缺省 ['assistant']
  // 所有回调的 agentId 化：
  appendEvolutionMessage: (agentId: string, text: string) => void
  executeGoal: (goal: ApprovedGoalSignal, agentId: string, selfCheckBias?: boolean) => Promise<string>
  sendOutreach: (goal: ApprovedGoalSignal, agentId: string) => Promise<string>
  reflect: (agentId: string) => Promise<string>
  writeDiary: (agentId: string) => Promise<string>
  plan?: (agentId: string) => Promise<string | null>
}

export async function handleEvolutionTick(deps: EvolutionTickDeps): Promise<string> {
  // 前置保持：driveConflictGoal（assistant 专属，全局一次）
  // 全局门保持：isAutonomousEnabled / hasActiveUserTurn（任一 agent 的 tick 都被用户回合全局阻塞，保持现语义）
  const ids = deps.listAutonomousAgentIds?.() ?? ['assistant']
  const results: string[] = []
  for (const agentId of ids) {
    try { results.push(`${agentId}=${await runTickForAgent(deps, agentId)}`) }
    catch (err) { results.push(`${agentId}=error: ${msg(err)}`) }
  }
  return results.join('; ')
}
```

- `runTickForAgent(deps, agentId)` = 现有 `handleEvolutionTick` 主体（从 `collectTickSignals(getDb(), agentId, now)` 开始），回调统一带 `agentId`。
- `recordTokenUsage` / `TOKEN_COST` 保持现状（表带 agent 维度则透传，实施时核对 `tick-signals.ts` 的 token 表结构）。

**改动 2 · `bridge.ts`（`runEvolutionTick` 闭包，`:1209` 起）**

- `listAutonomousAgentIds: () => ['assistant', ...readAutonomousAgents().filter(id => id !== 'assistant')]`（A4 落地后接 app.json；先落地时可硬编码 `['assistant']` 保持行为不变）。
- 会话 ID 解析：`evolutionConversationIdFor(agentId) = agentId === 'assistant' ? EVOLUTION_CONVERSATION_ID : \`evolution:${agentId}\``；`ensureConversationExists(convId, \`${name} · 自主会话\`)`。
- `appendEvolutionMessage(agentId, text)` / `executeGoal(goal, agentId, ...)` / `sendOutreach(goal, agentId)` / `reflect(agentId)` / `writeDiary(agentId)` / `plan(agentId)` 全部按 agentId 取会话 ID 与定义。
- `executeGoal` 的 `baseDef`：`definitionStore.get('assistant')` → `definitionStore.get(agentId)`；`finalizeGoal` / `recordMoodEvent` / `persistLearningOutcome` / `recordProactiveAction` 若签名未含 agentId，一并扩参（对应表均带 `agent_id`）。
- `reflect(agentId)`：`reflectAutonomous(agentId, 'scheduled')`；日记读写（`hasWrittenDiaryToday` / `writeDiary`）按其实现核对 per-agent 键。

**测试**：
- `evolution-tick.test.ts` 更新：① 单 agent 保持旧断言；② 两 agent：一个 idle 一个 execute，汇总串正确；③ 第一个 agent 抛错时第二个仍执行。
- 回归：life-e2e 23 例。

**验收**：`cron run autonomous-tick`（companion 指令路径）summary 含 `assistant=idle: liveness-ok`；A4 打开第二个 agent 后 summary 含两条。

## A5 · 失败可见性

**问题**：`executeGoal`（`bridge.ts:1284-1345`）只在成功时落会话与通知；失败（`!ok`）时目标被标 failed，但会话里没有任何记录，用户无从知晓。

**改动**（均在 `bridge.ts` 的 `executeGoal` 内）：

- `!ok` 分支同样 `saveMessage` 到该 agent 的 evolution 会话：
  `{ role: 'user', text: \`目标未完成：${goal.description}\` }` + `{ role: 'assistant', text: output.slice(0, 500) || '（无输出）' }`；
- `!ok` 分支发系统通知（复用 `config.showCronNotification`，文案「目标未完成：…」，点击跳该 agent 会话）；
- 成功路径行为不变。

**验收**：构造一个必然失败的目标（如读取不存在文件）→ 会话有失败记录 + 收到通知。
