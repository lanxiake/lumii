## 一、背景：功能很多，用户发现不了

用户原话概括：客户端功能很多，但呈现给用户的很少；用户看不懂那些功能，看懂了也不知道怎么用；藏在设置与后台的功能没人主动介绍。目标：由**「灵栖维护」Agent 主导**，帮用户发现功能、学会使用、并用到自己的工作/生活/学习里。

**现状盘点（2026-09-13 工作区核实）**

| 类别 | 事实 | 位置 |
|---|---|---|
| 功能面 | 设置 Hub 9 个 Tab；设置页 11 个分类；主路由仅 3 页，侧栏只留「概览」+ 会话列表 | `SettingsHub/types.ts:48`、`SettingsPage.tsx`、`Router.tsx` |
| 已有引导 | 首启仅选工作空间向导；输入框 24 条**静态随机**轮播 tips；输入框帮助面板；云同步三步卡先例 | `WorkspaceWizard.tsx`、`useRotatingTip.ts`、`CloudSyncSection/index.tsx:151` |
| 用户指南 | 6 章 + 20 张功能截图；`docs/guide/*.md` → `pnpm sync:guides` → `resources/user-guides/`；读取 IPC 链路齐备 | `scripts/sync-user-guides.mjs`、`main/user-guides/*` |
| 指南入口 | 唯一 UI 消费者是资料库的 WikiHelpDrawer（仅 wiki 手册）；**桌面版指南应用内无任何入口** | `WikiHelpDrawer.tsx:72` |
| 维护官 | 职责已含「用户指南同步」；已具备 `app_goto` / `app_goto_and_screenshot` 等带路工具与截图标注能力 | 手册 SKILL.md §1.3、`definitions.ts:221-229`、`app-ui-control/annotate.ts` |
| 空白 | 无功能使用统计、无蒙层/引导 UI 组件、无通知中心与未读角标、无全局命令面板 | 全库检索无命中 |

**关键洞察**：维护官本来就管「用户指南同步」，又已具备界面带路工具——**改造它做向导最顺**。缺的核心是一个**结构化的功能目录**：作为问答、主动推荐、未来功能地图的共同数据源。

## 二、产品决策（拍板）

1. **向导会话优先**：用户随时问「这个功能怎么用 / 有啥用」，维护官基于产品知识回答；主动推荐作为第二层随后接上。
2. **主动推荐 = 本地使用统计 + 会话轻提醒**：纯本地记录功能使用情况（不上传），发现没用过/用得浅的功能后，由维护官在会话里发轻提醒；**不发系统通知弹窗**。
3. **演示 = 带路式**：维护官把界面导航到对应位置 + 带标注截图告诉用户点哪里，**动手由用户**（指引流程中不代操作）。
4. **新手期更主动**：刚使用的用户不知道有哪些功能，需要多推荐、多引导——推荐节奏按使用龄分阶段（见默认值表），前期密、后期疏。
5. **会话内推荐**：新开会话给 3 个「为你推荐」使用场景（内容任务 + 功能使用场景，如「写一份研究报告」「设置资讯定时推送」「接入消息渠道，离开电脑也能用」）；进行中会话给 ≤3 条「下一步」功能建议。
6. **询问组件优化**（`ask_user_question`）：多选 Tab 呈现、单选完成选择后**自动进入下一题**（多选除外）；**AI 给出它推荐的答案并解释为什么**；整体降低用户心智负担。

**默认值（设计给定，可调）**

| 项 | 值 |
|---|---|
| 开关 `onboarding.enabled` | 默认开（新装与老用户一致）；关闭 = 停收集 + 停推荐，向导问答入口始终可用 |
| 轻提醒节奏（按使用龄） | **新手期（首启 <7 天）每天 ≤1 条**；成长期（8–30 天）每 3 天 ≤1 条；稳定期（30 天+）每周 ≤1 条 |
| 静默时段 | 沿用既有 `quietHours` 设置（`autonomous/settings.ts:16-19`），命中则闭嘴 |
| 启用宽限 | 老用户启用后 48h 内不推（避免功能上线即打扰）；新手期不设额外宽限（当天即可收到第一条） |
| 候选规则 | priority 降序取第一个「从未使用（count=0）且未推过」的功能；无候选则不发 |
| 新会话推荐 | 每次新开会话展示 3 个场景卡（内容任务 + 功能使用场景）；新手期优先功能场景 |
| 会话中下一步 | 每轮至多 3 条建议；仅在约定时机出现（见 §3.6），可忽略、不打扰 |

## 三、总体设计

```
用户侧            渲染层埋点（视图 / Hub Tab / 设置分类 / 少量动作）
                        │ IPC
主进程             onboarding-service ── runtime_state: onboarding.usage（本地 sqlite）
                        │
cron: onboarding-nudge（自有，24h 一次；enabled 跟随开关）
                        │ 魔法指令 __onboarding_nudge__
                   nudge 判定（纯函数：开关/静默/频控/宽限/候选）
                        │ 组模板消息（零 LLM 消耗）
                   onboarding:guide 会话 ← 用户点入口也进这里（静态开场 + 问题 chips）
                        ▲
用户提问 ───────────────┘  维护官 → feature_catalog / feature_usage 工具
                                   → app_goto + app_goto_and_screenshot 带路演示
```

### 3.1 功能目录（新资产，单一事实源）

`docs/guide/feature-catalog.json`，随既有 `sync:guides` 管线分发到 `resources/user-guides/`，随安装包走。

```json
{
  "version": 1,
  "features": [
    {
      "id": "channels.weixin",
      "name": "微信渠道",
      "summary": "把微信接入 Lumii，在微信里直接使唤助手",
      "location": { "view": "settings", "category": "channels" },
      "entryPoints": ["设置 → 渠道接入 → 微信"],
      "steps": ["打开「设置 → 渠道接入」", "选择微信并扫码登录", "在微信里给助手发一条消息验证"],
      "scenes": ["生活", "工作"],
      "guideAnchor": "Lumii-Desktop-User-Guide.md#渠道接入",
      "detectKey": "settings.channels",
      "priority": 5,
      "related": ["channels.wecom", "cron"],
      "scenarioPrompts": ["设置消息渠道，离开电脑也能在微信里使唤助手"]
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 稳定标识（不可改名）；推荐去重、已推集合的键 |
| `name` / `summary` | 展示名 / 一句话作用 |
| `location` | app_goto 目标（`view` + 可选 `category`），带路演示直接吃它 |
| `entryPoints` / `steps` | 人话入口与操作步骤 |
| `scenes` | 适用场景（工作 / 生活 / 学习），供个性化建议 |
| `guideAnchor` | 指南锚点（指向 `docs/guide/` 章节） |
| `detectKey` | 使用统计里对应的事件键 |
| `priority` | 推荐优先级（数字越大越先推） |
| `related`（可选） | 关联功能 id 列表——会话中「下一步」建议的边（用过 A 推 B） |
| `scenarioPrompts`（可选） | 场景卡示例话术（新开会话「为你推荐」用，需可直接当用户消息发送） |

- **首批约 30 条**：9 Hub Tab + 11 设置分类 + 主路由/侧栏核心能力（聊天、Dashboard 资讯、语音通话、录屏、宠物模式、自主进化）。初稿依据 `docs/guide/Lumii-Desktop-User-Guide.md` 起草，完成后交用户审阅。
- **维护流程**：维护官「用户指南同步」职责升级为「指南 + 目录同步」；功能变更时改 `docs/guide/` → 跑 `sync:guides` → 校验 manifest。
- **防过期**：完整性单测对照 `SETTINGS_HUB_TABS`（`SettingsHub/types.ts:48`）与设置页分类常量——新增 Tab/分类不补条目即测试失败。

### 3.2 维护官改造

- **提示词**（`packages/agent-runtime/src/agent/builtin/prompts.ts:75-91`）：WHEN_TO_USE / PROMPT 增「产品向导」域——回答前先查功能目录；演示走带路（`app_goto` → `app_goto_and_screenshot`，让用户自己点）；结合个人记忆/场景记忆给「对你的工作/生活有什么用」的建议；不代操作。
- **手册**（`bundled-skills/系统维护/system-keeper-handbook/SKILL.md`）：新增「产品向导」章节（带路操作序、目录维护流程、回答口径）。
- **工具**（新增两个只读工具，交互档与自主档都放行——自主档无 bash/file_read，读不到文件，必须走工具）：
  - `feature_catalog(action: list|get|search, featureId?, query?, scene?)` → 条目（含 location/steps/guideAnchor/detectKey）
  - `feature_usage(action: unused|summary, days?)` → 未用/浅用功能清单
  - 均为 `isReadOnly`、不需要审批；不做成通用文件读取（打包/开发路径不一致，且结构化返回防模型乱解析、可联查使用状态）。
- **协作提示**：`agent-collaboration-section.ts` 加一句——「产品使用 / 功能怎么用」的问题可委托灵栖维护。

### 3.3 使用统计（本地）

- **存储**：`runtime_state` 键 `onboarding.usage`（sqlite KV，免迁移；与 `autonomous.enabled` 同模式）。纯本地——云同步是白名单文件导出（profile/wiki 等），实施时复核确认不含该表。
- **事件**（渲染层埋点 → IPC → 主进程 500ms 防抖写库）：
  - `view.<view>`：`App.tsx` 视图切换
  - `hub.<tab>` / `settings.<category>`：`SettingsHubModal` 切 Tab / 设置分类
  - 浅用动作首批 3 个：建定时任务 / 装技能 / 资料库导入
- **存量回填**（一次性，仅便宜信号）：渠道已配置、语音、已有定时任务、已装技能、资料库非空、云同步已配、ACP 已绑 → 直接标记已用，避免给老用户误推。
- **联动语义**：开关关闭 = 停止收集 + 停止推荐（一档，简单一致；后续如需"只静默不停止"再议）。

### 3.4 主动推荐（轻提醒）

- **触发路径：自有 cron + 魔法指令，不挂自主进化心跳**。已核实：自主进化默认关闭，且关闭时 `autonomous-tick` 会被暂停（`autonomous-cron-linkage.ts:4-5`）——挂心跳会让默认用户永远收不到。新 job `onboarding-nudge`（`every` 24h）仿 companion 范式（`local-companion-handler.ts:87-95` 魔法指令 + 独立开关联动），在定时任务页可见、可暂停。
- **判定（纯函数）**：开关开 ∧ 非静默时段 ∧ 通过**分阶段节奏**（新手期每天 ≤1 / 成长期每 3 天 ≤1 / 稳定期每周 ≤1，见 §二）∧ 老用户启用 ≥48h ∧ 候选 = priority 最高且 count=0 且未推过。
- **消息形态**：模板组文案（**零 LLM token**），例：
  > 你还没用过「资料库」——把你的资料丢进来，我能自动整理归档，之后随问随取。想试试的话回复「带我看看」，我直接带你打开它。
- **落点**：`onboarding:guide` 会话（`ensureConversationExists` + `saveMessage` + `pushSavedMessage`）；记 `onboarding.nudge`（lastAt + 已推集合）防重复。
- **建议项（可去掉）**：推送时若主窗口可见，用应用内 Toast（`ui/Toast`，actionLabel「去看看」→ 打开会话）提升可察觉度——仍无系统通知。轻提醒无未读角标（当前无角标设施，见 §八）。

### 3.5 入口与开关

- **设置页**：general 分类加「新手指引」Card（开关 + 「开始导览」按钮 + 一句说明）。
- **聊天**：`ChatPage/components/EmptyState` 加常驻卡片「不知道从哪开始？让向导带你逛逛」。
- **会话**：统一进 `onboarding:guide`「新手指引 · 灵栖维护」——静态开场语 + 几个问题 chips（**点 chip 才发消息**，避免每次打开都烧 token）。
- **指南阅读**（片 7）：WikiHelpDrawer 泛化为通用 GuideDrawer，桌面版指南补上应用内入口（复用既有 `app:guides:list/read` IPC）。

### 3.6 会话内推荐（新开会话 + 进行中）

- **新开会话**：空状态从现状（48 条静态场景随机抽 6 个，`EmptyState/index.tsx`）升级为**「为你推荐」3 个**——内容任务（沿用既有场景库）+ **功能使用场景**（目录驱动，如「设置资讯的定时推送」「接入消息渠道，离开电脑也能用」）。新手期（首启 <7 天）优先混入功能场景卡。
- **进行中会话**：本轮回复结束后给**至多 3 条「下一步」建议**（chips，可忽略不打扰）：① 本轮命中某功能（工具调用 / 关键词）→ 推荐目录里的 `related` 关联功能；② 否则推荐与当前话题场景匹配、且你**未使用**的功能。点击直接带入对话（如「带我了解定时任务」）。
- **生成方式**：先做**规则驱动（零 LLM 成本）**——目录字段 + 使用统计 + 工具/关键词命中；「LLM 逐轮生成」留作后续评估（见 §七）。
- **出现纪律**：仅在「会话首轮结束 / 发生工具调用」后出现；同一建议在会话内不重复；可手动关闭。

### 3.7 询问组件优化（ask_user_question）

现状（2026-09-13 核实）：`AskUserModal` 已有的能力——多问题 Tab、单选/多选、选项描述与 preview、Other 自由填写、补充说明、倒计时；工具 schema 支持 1-4 问、每问 2-4 选项（`ask-user-question-tool.ts`）。不足：**无自动前进**（逐题手动切换 + 末尾手动「提交回答」）、**无 AI 推荐与理由**，心智负担偏高。

优化目标：

1. **单选自动前进**：点选某选项后约 300ms 视觉反馈即切到下一题；最后一题选择后自动提交。**多选不自动前进**（需明确确认，避免误提交）。
2. **AI 推荐 + 理由**：选项 schema 增 `recommended?: boolean` 与 `recommendReason?: string`；Modal 对推荐项展示「推荐」徽章 + 一句理由；工具描述与提示词口径要求 Agent **尽量给出推荐并解释为什么**（可解释性直接降低选择负担）。
3. **一键采用**：当所有问题都有推荐项时，提供「全部采用推荐」快捷提交；保留手动翻页与「拒绝回答」。
4. 受益范围不限于新手指引：维护官结构化确认、委托确认等**所有 Agent 提问场景**。

改动点：`packages/agent-runtime/src/tools/built-in/ask-user-question-tool.ts`（schema + 描述口径）、`renderer/components/AskUserModal/AskUserModal.tsx` + `module.css`；超时/拒绝/`Other`/`preview` 语义保持不变。

## 八、风险与开放问题

1. **存量用户回填覆盖有限**：只覆盖便宜信号，部分已用功能可能被误推 → 靠 priority 排序 + 已推集合缓解；实施时复核回填清单。
2. **轻提醒可察觉度**：无未读角标，会话消息可能被埋没 → 建议项 Toast；若仍不够，再评估角标（单独立项）。
3. **关开关 = 停收集** 的语义需在设置文案里说明（否则用户困惑「为什么向导不知道我用过什么」）。
4. **目录维护成本**：靠完整性单测强制 + 维护官职责覆盖；实施后观察一轮真实功能变更是否顺滑。
5. **`onboarding:guide` 会话的守卫覆盖**：转移/清空/删除/侧栏分组各处需核对（参照 `evolution:*` 的处置清单），避免新会话类型漏网。
6. **cron 治理联动**：新 job 的 managedBy 语义与「删除会重建」名单需同步更新（`cron-job-meta.ts` + 相关测试）。
