## 二、首轮实测与归因（2026-09-24）

### 2.1 两处「够不到」让原始数字不可用

| 现象 | 证据 | 处理 |

| **renderer 整条主链被判不可达** | `knip --debug` 里插件给出的 entry 是裸文件名 `apps/windows/main.tsx` / `early-splash.ts`（glob 落空）；正确的 html entry 在上一行 | 在 `knip.jsonc` 显式补 `src/renderer/main.tsx`、`early-splash.ts`。修后 unused files **282 → 9** |

> renderer 那条是 **knip 6.38.0 electron-vite 插件的 bug**：`getHtmlScriptEntries()` 单独调用（喂绝对路径或仓库相对路径）返回正确结果，所以丢在插件→knip 内部那一步。值得上游报 issue。

### 2.3 那 1453 条不是同一种东西

按**引用形态**（import/export 语句本身，非「名字出现过」）全量归类：

| 类别 | 条数 | 占比 | 判据 | 处置 |
| --- | --- | --- | --- | --- |
| B 仅文件内使用 | 705 | 48.5% | 符号在自己文件里被用，只是没人 import | `export` 关键字多余，K5 |
| C 从别处 import | 267 | 18.4% | 有人 import，但来源是另一个模块 | barrel 那层多余，K5 |
| D 冗余再导出 | 287 | 19.8% | 只在 barrel 的 `export ... from` 里出现 | K5 |
| **A 真死** | **95** | **6.5%** | 全仓库无人 import，自己文件里也只有声明 | **K2** |
| E 假阳 | 2 | 0.1% | 有人正是从这个模块 import | 忽略 |

> **一条自我纠正**：最初用「全仓库搜符号名」当判据，得到 46% 假阳——**那个数是错的**。文本判据只看名字出现，不看从哪个模块来（`getScreenRecordService` 在别处出现，但人家 import 的是 `./accessor` 而非被标记的 barrel）。换成按 import/export 语句归类后假阳只剩 2 条。**knip 判定本身可信**，是我的判据粗。

真死 95 条的分布：`src/main 41 / src/renderer 24 / packages/* 16 / src/shared 14`，其中函数/常量 72 条。已手工抽查 6 条（`createSecureSandbox`、`createTrustedSandbox`、`SKILL_EXECUTE_EVENT`、`CHANNEL_LIST_TOOL`、`readCache`、`resolveSharedCacheDir`）——**每条全仓只出现一次，就是它自己的声明**。

> **推论**：本仓任何一次 `pnpm add` 都会顺手抬 pi-ai 的 zod peer。将来要加依赖时，要么锁 zod，要么接受并单独验证。

### 4.2 K1 —— 依赖声明（**最高优先，防打包崩溃**）

58 条 unlisted 按风险分四组。**这一阶段真正的风险不在 package.json 本身，而在它会翻转 `electron-vite` 的外部化决策。**

取证（2026-09-24，`out/main/index.js` 今天 18:35 构建、配置 09-23 未变）：

```
@anthropic-ai   2 次   ← external 模块会以字符串出现（探针自校验通过）
isolated-vm     8 次
better-sqlite3  8 次
earendil        0 次   ← pi-ai / pi-agent-core / typebox 现在是【被内联打包】的
```

而 `electron.vite.config.ts:230` 的注释写「pi-ai / pi-agent-core 已通过 externalizeDepsPlugin（默认规则）外部化」——**这句是错的**：它们没在 `apps/windows/package.json` 里，插件不会外部化它们。同一文件 177 行的设计意图是反的：「只外部化 electron，其他依赖内联打包，避免 pnpm 传递依赖无法被 electron-builder 正确打包」。

| 组 | 内容 | 改法 | 为何安全 |
| --- | --- | --- | --- |
| K1-1 | `packages/browser-control` 的 `ws`（4 处） | 补进该包 dependencies | 不影响 apps/windows 的外部化集合 |
| K1-2 | 根 `scripts/` 用的 `@xenova/transformers`/`sharp`/`sherpa-onnx-node`/`isomorphic-git` | 补进**根** devDependencies | 根不参与 electron-builder |
| K1-3 | `apps/windows` 的 `pi-agent-core`/`pi-ai`/`typebox`（27 处） | **声明 + 同步加进 `externalizeDepsPlugin.exclude`** | 保持内联（行为不变），去掉对 `.npmrc` hoist 的隐性依赖 |
| K1-4 | `tar`（skill-exporter）/ `isolated-vm`（skill-sandbox） | **先取证**：是否真装、是否 optional | `isolated-vm` 已在 `external` 正则里但不在 `onlyBuiltDependencies`，疑似未构建 |

**退出条件**：`knip --include unlisted` 归零或每条都有书面豁免理由；`pnpm typecheck` + `test:all` 全绿；`git diff pnpm-lock.yaml` 只有预期改动。

### 4.3 K2 —— 真死代码 95 条

**分批删，每批一次门禁**（`pnpm typecheck` + 相关包测试）。顺序按「确定度」从高到低：

1. **K2-1 测试缝**：`_forTest` / `reset*ForTests` / `_reset*` 前缀的，无人调用的测试专用导出。最安全。
2. **K2-2 协议常量**：`SKILL_EXECUTE_EVENT`、`SKILL_RESULT_METHOD`、`CHANNEL_LIST_TOOL`、`CHANNEL_SEND_TOOL` 等。**删前必须确认不是协议预留**——它们名字像协议面，删错等于改契约。
3. **K2-3 需决策项**：`createSecureSandbox` / `createTrustedSandbox`（`skill-sandbox.ts`）。安全相关，见 §6。
4. **K2-4 其余**：含 23 条类型导出。

**退出条件**：95 条逐条有归宿（删除 / 保留并写理由）；保留的进 knip 的 `ignoreExportsUsedInFile` 或 JSDoc 标记，不留无声豁免。

### 4.4 K3 —— 坏导入与死文件

**K3-1 是本轮最有价值的一条**：`packages/agent-runtime/src/compact/*.test.ts` 等 5 处写 `import type { AgentMessage } from "../types.js"`，而 `src/types` 是**目录**。两个工具链都看不见它：

- `packages/agent-runtime/tsconfig.json` 的 `exclude` 含 `src/**/*.test.ts` → tsc 不看测试文件
- 是 `import type` → vite/esbuild 直接擦除，运行时不解析

**退出条件**：7 条 unresolved 归零；`kernel/index.ts` 删除后 `pnpm -r typecheck` + agent-runtime 测试全绿。

### 4.5 K4 —— 棘轮

接进 `pnpm verify`，但**分级**而不是一刀切：

| 类型 | 级别 | 理由 |
| --- | --- | --- |
| `files` / `unresolved` / `unlisted` / `dependencies` / `devDependencies` | `error` | 清完即零，防新增 |
| `exports` / `types` | `warn` | K5 未做前不许拦；否则 CI 必红 |

另设 `--max-issues` 预算兜底（数字在 K4 时按当时的真实存量定，不预设）。

### 4.6 K5 —— 批量 fix（⛔ 待批）

`exports`/`types` 是 knip 标注 🔧 可自动修的类型，`knip --fix` 能处理 B/C/D 三类共 1259 条。**但必须先解决两件事**：

1. knip **看不见运行时字符串访问**——`window.electronAPI.x()`、CDP `evaluate('...')`、`resources/app-ui-cli` 的设计表字符串调用。守卫 ⑥ 类就是为此存在的。所以 fix 之后必须 `pnpm verify` 全绿 + 至少一次 `dev:restart` 冒烟。
2. 先小范围试点（例如 renderer 的 `components/ui/index.ts` 一个 barrel），确认 diff 可读、无副作用，再扩大。
