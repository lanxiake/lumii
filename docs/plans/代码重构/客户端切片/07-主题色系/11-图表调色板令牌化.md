## 一、目标

图表类组件里的调色板目前是 TS 常量数组，换主题不变色。本片把它们改成 CSS 变量字符串。

**这片有一个必须讲清楚的技术前提**——见 §二。

## 二、技术前提：recharts 的颜色 prop 能收 `var()`，`fontSize` 不能

第 7 片实施时留下的印象是"recharts 只认数字，读不到 CSS 变量"（`UsageChart/index.tsx:30-31` 的注释这么写）。2026-09-20 复核**这个结论只对 `fontSize` 成立，对颜色不成立**：

| prop 类型 | 能否收 `var()` | 依据 |
|---|---|---|
| `fill` / `stroke` / `color` | **能** | recharts 2.15.4 的类型定义里，`CartesianGrid` 是 `AcceptedSvgProps = Omit<SVGProps<SVGRectElement>,'offset'>`；`XAxis/YAxis` 的 `stroke` 来自 `PresentationAttributes`——都是 `string`，直接透传给 SVG |
| `tick={{ fill: '...' }}` | **能** | `tick?: SVGProps<SVGTextElement> \| ...`，`fill` 是 `string` |
| `axisTickFontSize` / `fontSize` | **不能** | `SVGProps<SVGTextElement>['fontSize']` 虽允许 `number \| string`，但 recharts 的 `Text`/`CartesianAxis` 内部对 `fontSize` 做**数值运算**（计算文本宽高做布局与截断），传字符串会变成 `NaN` |

**仓库内的活证据**（同一个文件里两种写法并存，恰好证明了这条边界）：

```tsx
// pages/DashboardPage/components/UsageChart/index.tsx
:268  <CartesianGrid stroke="var(--mt-border-hairline)" />          // ← 颜色：var() 可用
:271  tick={{ fill: 'var(--mt-fg-4)' }}                             // ← 颜色：var() 可用
:293  cursor={{ fill: 'color-mix(in srgb, var(--mt-accent-500) 6%, transparent)' }}  // ← 连 color-mix 都行
:30   // recharts 只认数字，读不到 CSS 变量 —— 这条注释针对 fontSize，被误读成了颜色
```

**结论**：本片**不需要** `getComputedStyle` 读值，也不需要重渲染时序改造——直接把调色板数组里的 `'#ef4444'` 换成 `'var(--mt-error)'` 即可。这是本片风险评级为"中"而不是"高"的根本原因。

## 四、任务拆分

### 4.1 调色板数组改令牌字符串

`UsageChart` 的 8 色调色板（`PALETTE`）、`COLOR.cost`、`PerformanceDiagnostics` 的四个色表、A2UI `Chart` 的 10 色板——全部改成 `var(--mt-*)` 字符串数组。

**改哪一组令牌**：优先复用已有的语义 / tone 令牌，能复用就不新增：

| 原色 | → 令牌 |
|---|---|
| 调色板里的语义位（成功 / 警告 / 错误） | `--mt-success` / `--mt-warning` / `--mt-error` |
| 分类位（1..n 无固定语义） | `--mt-tone-a` / `--mt-tone-b` / `--mt-tone-c` / `--mt-tone-d` + `--mt-accent-400/500` + `--mt-violet` + `--mt-sky-400/500` |
| 花费线绿 | `--mt-success` |

> `--mt-tone-a..d` 第 7 片已在三主题块显式定义（此前深色块缺失）→ 本片可以直接用，不必再补。

### 4.2 `LumiiLogo` 改用 `--mt-grad-brand`

```tsx
// 前：background: 'linear-gradient(180deg, #7dd3fc 0%, #38bdf8 35%, #2563eb 100%)'
// 后：background: 'var(--mt-grad-brand)'
```

**前提确认**：`--mt-grad-brand` 是 `linear-gradient(180deg, #7dd3fc 0%, #38bdf8 35%, #2563eb 100%)`（`design-system.css:69`），**逐值一致**，改完零视觉差异。它在 `:root` 全局固定区定义 → 三主题同值，Logo 不随主题变色（符合品牌常量语义）。

### 4.3 色相环边界：调色板跨主题要"仍然可区分"

改完之后，light 主题的 8 色调色板会是 light 主题的 8 个令牌值。需要**确认相邻色相的区分度**——`--mt-tone-a..d` 在三主题块下是刻意选过对比的（第 7 片登记），但 `tone + accent + violet + sky` 拼成 8 色后可能有两色过近。

**验证方法**：三主题各截一张 `DashboardPage` 的使用图（`UsageChart` 所在的概览页），肉眼确认 8 条线 / 8 个色块可区分；若不可区分，调整 `tone-*` 的取值或改用 `--mt-accent-300..700` 拉开明度。

## 五、验证

1. `pnpm typecheck` + `pnpm test:all`（基线 298 / 2716 passed / 0 failed）。
2. `probe-theme-colors.mjs` 三主题数值：本片改动**会**带来数值变化（图表面积占比不小），判据是"变化可解释"而非"零差异"。
3. **逐图目视**：概览页（UsageChart）、设置页（PerformanceDiagnostics）、A2UI 演示（Chart / MathVisualizer）三主题各截一张，确认：

   - 色相可区分（4.3）
   - 无色块与背景对比度过低（尤其 eye-care 的暖底上）
4. **`fontSize` 不被误伤**：抽查 `UsageChart/index.tsx:30-39` 的数字型字号逻辑未动。

## 六、明确不做

- **不动 `fontSize` 相关代码**——它是另一个问题（需要 `getComputedStyle('--app-font-scale')`，仓库已有正确实现，第 7 片刚确认）。
- **不动 `WindowEdgeGlow` 的 canvas 渐变**（[12 片](./12-canvas与宠物色层收敛.md)）——它走 `readToken()` 而非 recharts prop，路径不同。
- **不动 pet 的 canvas 烟花**（[12 片](./12-canvas与宠物色层收敛.md)）。
- **不统一 A2UI 嵌入内容的调色板**——`A2UIRenderer.module.css` / `IframeArtifact.module.css` 服务沙箱 iframe，外部上下文不继承令牌。
