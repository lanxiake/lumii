## 一、为什么要拆成 7 片

第 7 片（契约层）解决的是**结构性病灶**：页面级 token 覆写、RGB 变体不随主题走、令牌名覆盖面对不齐。做完之后，"改令牌"这条路径是通的。

但**绕过令牌的颜色**还大量存在。2026-09-20 全量实测基线：

| 指标 | 数量 | 说明 |
|---|---|---|
| `var(--x, #hex)` 字面 fallback | **737 处 / 80 文件** | 令牌已定义，fallback 已死 |
| 裸 `#hex`（不含令牌定义文件） | **906 处 / 96 文件** | 令牌定义文件的 175 处不计 |
| `rgba()/rgb()` 数字写法 | **541 处** | 其中 `rgba(255,255,255,α)` 161 / `rgba(0,0,0,α)` 78 |
| 合计待清理 | **约 1850 处 / 136 文件** | |

一刀切不现实：这 1850 处的**风险差异极大**——有的删掉即等价（零风险），有的改错会让某个主题下的文字消失（高风险）。因此按**风险递增**切 7 刀，每刀都能独立提交、独立回滚、独立验证。

## 三、四类不做的

第 7 片的「明确不做」在本批继续成立，并且**本批做完了也不会碰它们**：

1. **品牌常量**——渠道图标色（微信绿 / 企微蓝 / 飞书蓝 / QQ 蓝）、工具品牌色（Cursor / Claude / Codex）、`Logo` 渐变、`--mt-sky-*`（08 片实测确认它是品牌色阶）。主题化会破坏品牌一致性。
2. **启动前素材**——`early-splash.ts`、`index.html` 的首帧底色。早于样式表求值，且需与 `index.html:10` 保持一致避免闪白。
3. **崩溃兜底 / 独立窗口**——`main.tsx` 崩溃 UI（主题可能未加载）、`file-preview` 独立窗、`pet/` 浮层（**不跟主窗主题是刻意的**，12 片已在代码里写明理由）。
4. **第三方定制**——hljs/GitHub 两套语法高亮、MDEditor 变量覆写层、Excel/PDF 预览的 `:global()` 覆盖。这些是被动映射，改了反而破坏第三方语义。
5. **设计刻度色阶**——`--mt-slate-*`、`--mt-accent-50/100/200/800/900/950`。只在全局固定区、不随主题变是**正确的**（第 1 片已定为"设计系统的词汇表"）。

## 四、共同判据（每片都适用）

1. **改前后零视觉差异是本批的总目标**——本批全部是"同一颜色的另一种写法"。任何一片若在主题截图对比中出现差异，都要先解释清楚再放行。
2. **验证方法**：`scripts/probe-theme-colors.mjs`（整图平均色 / 亮度 / 暖度）逐主题截图对比，三主题数值必须与改动前完全一致。
3. **测试基线**：`cd apps/windows && pnpm test:all`——2026-09-20 实测 298 文件 / 2716 passed / 0 failed，基线已清零（见 `AGENTS.md`）。改了任何文件后必须跑全量，因为 vitest 不做类型检查，`pnpm typecheck` 也要单独跑。
4. **改令牌相关必跑守卫测试**：`renderer/styles/design-system.themes.test.ts`。

## 五、建议执行顺序与理由

**08 → 09 → 10 → 11 → 13 → 12 → 14**

- 08 最前面：它把"令牌契约"钉死，后面所有片才有稳定的判据（比如 09 要按"fallback 是否等于令牌值"分类，契约不完整就没法自动判定）。
- 09 在 10 前面：09 是机械的纯删除（737 处），删完之后 10 面对的才是真正需要判断语义的硬编码，视野干净得多。
- 11 在 13/12 前面：11 有仓内先例（recharts 收 `var()` 已在 `UsageChart` 里验证过），风险明确；12 涉及 canvas 取色与宠物窗，改造面更大。
- 14 最后：唯一需要先出设计再动手的一片。
