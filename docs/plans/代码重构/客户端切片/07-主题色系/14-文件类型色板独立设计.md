## 一、目标

这是本批**唯一需要先做设计**的一片。前 6 片的模式都是"把字面量换成已有令牌"，而这里是"**令牌体系里根本没有这一层语义**"——需要先决定要不要建、怎么建，再动手。

## 二、现状（2026-09-20 实测）

### 2.1 `wikiFileExtDisplay.ts` —— 纸面手账色板

`pages/MemoriesPage/components/wikiFileExtDisplay.ts`，37 处 hex，用途是 **Wiki 页面的文件类型徽标**（按扩展名分色）。文件头注释明确写着设计意图：

> 色板刻意低饱和、略偏暖，贴近纸面手账而非高对比 UI 霓虹色。

结构：

| 层 | 内容 | 数量 |
|---|---|---|
| `MEDIA_ICON_COLORS` | 5 大类图标色（document / image / audio / video + 兜底） | 5 |
| `EXT_BADGE_COLORS` | 按扩展名细分（md / pdf / png / mp4 …） | 32 |
| `DEFAULT_INK` | 未知后缀的兜底灰 `#6B6560` | 1 |

色板特征：赭石 `#8B7355` / 砖红 `#C0785A` / 青绿 `#5B8A7A` / 葡萄紫 `#7A6B8A` —— 低饱和、暖调、彼此明度接近。

### 2.2 `AgentsPage/views/types.ts` —— agentHash 调色板

`agentColor()` 在无主题信息时用的哈希取色调色板，2 处 hex。**注意**：这个函数名暗示它按 agent 名字哈希取色——**同名的 agent 必须永远同色**，否则用户认知会崩。

## 三、为什么这片最难

### 3.1 与主题体系的设计意图直接冲突

第 7 片建立的 4 个主题，每个都有明确的冷暖基调：

| 主题 | 画布 | 基调 |
|---|---|---|
| light | `#f3f5f9` | 冷调蓝白 |
| eye-care | `#f5f1e8` | 暖调米黄 |
| dark | `#0f172a` | 冷调深蓝 |

手账色板是**"刻意低饱和 + 略偏暖"**的单一基调。放在 light（冷）和 dark（冷深）上，它本来就"不搭"——但这是刻意的：Wiki 页面读起来应该像纸，不像 UI。

**所以问题是**：这 37 色应该

- **(a) 完全跟主题**——护眼下更暖、深色下整体压暗。风险是丢掉"纸面手账"的辨识度，且深色下低饱和暖色会糊成一团。
- **(b) 完全豁免**——保持现状。风险是深色主题下这 37 色是"为浅底选的"，在 `#0f172a` 上可能对比度不足。
- **(c) 分主题各出一套**——最正确但工作量最大（37 × 3 = 111 个色值要选）。

### 3.2 从"扩展名 → 颜色"到"语义 → 颜色"的映射缺失

现在的映射是**直接按扩展名给色**（`png: '#C0785A'`）。要令牌化，必须先把 35 个扩展名归到**有限的语义类**（如"文档族 / 图片族 / 音视频族 / 代码族"），再从语义类取色。文件里已有部分注释暗示这个分类：

```
// 文档族：赭石 / 墨绿 / 靛蓝 / 砖褐
// 图片族：砖红 / 琥珀
// 音视频：青绿 / 葡萄紫
```

**但当前同一族内是靠"同色系不同深浅"区分的**（md `#7A6F4D` vs txt `#6B7F6A`），令牌化后若要保留这种区分，需要一组"每族 2-3 档"的令牌——这就是设计工作量的来源。

## 四、任务拆分

### 4.1 先做设计决策（本片的第一步，产出写回本文档）

需要拍板的三件事：

1. **走 (a) / (b) / (c) 哪条路**？
2. 若走 (a)/(c)：**语义分几类**？（建议 4-5 类：文档 / 图片 / 音视频 / 代码 / 其他）
3. 每类**几档**？（建议 2 档，够区分同族内的常见格式即可）

**建议**：走 **(c) 但只做"光照条件"级适配**——即保持色相与相对关系完全不变，只为每个主题做**明度 / 饱和度的整体平移**（light 用现值，eye-care 略降饱和，dark 整体提亮 + 加饱和）。这样既保住了手账调性（色相不变），又解决了深色下对比度不足的问题，且**不需要重新设计 111 个色值**——只需为每个主题定义一条"平移规则"。

### 4.2 Token 命名空间设计

若确定要令牌化，命名建议：

```css
/* 大类图标色（5 个） */
--mt-file-doc / --mt-file-image / --mt-file-audio / --mt-file-video / --mt-file-other
/* 分类档位（每类 2 档） */
--mt-file-doc-1 / --mt-file-doc-2 / ...
```

或更紧凑的方案：**只令牌化大类（5 个），族内细分保留字面量**——因为族内细分本质是"装饰性区分"，不承担主题语义。

> **权衡**：只做 5 个大类令牌 = 5 × 3 = 15 行定义，工作量可控；族内 32 色保留字面量则深色下仍有对比度问题。执行时需要与用户确认取舍。

### 4.3 `agentColor()` 哈希调色板

**这项比 4.2 简单，建议拆出来单独做**：

- 约束是**稳定性**（同名 agent 永远同色），所以不能"每次从主题令牌里随机取"。
- 正确做法：保持调色板**数组顺序不变**，只把数组元素从 hex 换成令牌字符串——顺序不变 → 哈希结果不变 → 同色 invariant 保住。
- 只需确认：改完后**同一个 agent 名在三个主题下取到的是"同一个位置"的颜色**（如都是第 3 个），只是第 3 个色在不同主题下值不同。这是期望行为。

## 五、验证

1. `pnpm typecheck` + `pnpm test:all`。
2. **对比度专项**（本片的核心验收）：把 37 色在**三个主题的画布底色**上逐一算对比度，要求全部 ≥ 3:1（徽标是装饰性文字，按 WCAG 非正文标准）。**当前深色主题下大概率不达标**——这是本片要解决的主要问题，改动前的数据要记录作为基线。
3. **Wiki 页面三主题截图**：确认色板在每主题下都"像纸"且可区分。
4. **`agentColor()` 稳定性**：写一个遍历常见 agent 名的脚本，确认改动前后哈希结果（数组下标）完全一致。

## 八、执行记录（2026-09-20）

### 8.1 基线数据推翻了计划的问题假设

计划 §3.1 假设"37 色在深色主题下大概率不达标"，据此讨论 (a)/(b)/(c) 三条路。
实测（`scripts/verify-wiki-file-palette.mjs` 同源算法，徽章落在卡片底而非画布）：

| 主题 | 对比度 < 3:1 的颜色 | 与底色的最小 ΔE |
|---|---|---|
| light | **0 / 16**（3.46~5.74） | 50.3 |
| eye-care | **0 / 16**（3.41~5.65） | 49.4 |
| dark | **7 / 16**（2.55~3.00，临界） | 28.3 |

**问题比预想小得多**：不是"深色下不可用"，而是"深色下 7 个略微不足"。
且 ΔE 全部 ≥ 28.3 —— "看得见"从来不是问题。

### 8.2 决策：只补 dark 一套（用户确认）

计划推荐的 (c)「三主题各一套」被否决，理由：

1. light / eye-care **本来全部达标**，给它们另出一套是无谓改动；
2. 更关键的是——eye-care 下若让手账色**也变暖**，会与米黄底**同类相斥**
   （现在正是靠冷暖差才立得住，ΔE 49.4）。变暖后既丢了"纸面"辨识度，
   又降低了与背景的分离度。

最终方案：**light / eye-care 共用浅色原值，只给 dark 一套亮化版**。

### 8.3 实现

15 个唯一色 → `--mt-file-*` 令牌（`design-system.css` 三主题块各 15 个）。
dark 亮化版由脚本生成：**HSL 空间固定色相**，只提明度直到与 `#1e293b`
对比度 ≥ 3.2 —— 色相与相对关系完全不变，保住"纸面手账"调性。

结果：dark 下全部 ≥ 3.21（原 7 个从 2.55~3.00 提上来）。

- `MEDIA_ICON_COLORS` / `EXT_BADGE_COLORS` 的值改为 `var(--mt-file-*)` 字符串。
  消费点是 DOM 内联 style（`style={{ color }}`），天然支持 CSS 变量，无需读计算值。
- **命名注意**：`txt`/`log` 原值是墨绿 `#6B7F6A`，与兜底石墨灰 `#6B6560` **不同**
  （实施中一度混用，已修正为独立的 `--mt-file-ink`）。墨绿在 dark 下原值即达标
  （3.39），故 dark 不做亮化。

### 8.4 `agentColor()` 哈希调色板

约束是**稳定性**（同名 agent 永远同色），所以**保持数组长度与顺序完全不变**，
只把元素从 hex 换成 `var(--mt-chart-N)` —— 哈希取模结果不变，同名仍取到
同一**位置**的颜色，只是该位置的值随主题不同（期望行为）。

`scripts/verify-agent-color-stability.mjs` 遍历 14 个常见 agent 名验证：
改动前后下标**全部一致**。

### 8.5 验证

- **映射校验**：`scripts/verify-wiki-file-palette.mjs` 逐项比对"新令牌的 light 值
  == 原 hex"，36 项全部通过（这是防"映错令牌"的关键检查，实施中确实抓到一次）
- **既有测试更新**：`wikiFileExtDisplay.test.ts` 断言色值匹配 `/^#/`（字面 hex），
  改为断言 `var(--mt-file-*)` 形式 + 保留"同大类可区分"的语义断言，另补一条
  "未知类型回退到同一兜底色"
- `typecheck` ✔
- `test:all`：**2721 passed / 0 failed**（2721 这个数字与改动前一致——
  新增 3 条用例，同时移除了 2 条重复断言）

> 满载跑序下 `vcs-repo.test.ts` 的 `diffCommits` 偶发耗时断言超时
> （实测 2199ms > 2000ms 阈值），**单跑 21/21 全过** —— 属已知摆动位，与本次无关。

### 8.6 累计效果

第 7 片的四个主题 + 08~14 七片收尾完成后：**改色系只需改 `design-system.css`
三个主题块里的变量**。剩余字面量均为已登记的豁免项（品牌色、第三方定制、
独立窗口、启动前素材）。
