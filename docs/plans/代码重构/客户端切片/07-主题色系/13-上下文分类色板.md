## 一、目标

`ContextUsageCard` 是上下文占用的可视化卡片，把 token 消耗按**8 个来源**分色展示：系统提示 / 工具 / 技能 / MCP / 子 Agent / 记忆 / 动态上下文 / 对话历史。

8 个颜色目前是硬编码 hex。本片让它们随主题变，同时**保持 8 色之间的可区分度**——这是本片唯一的难点。

## 三、任务拆分

### 3.1 令牌选择：优先复用，尽量不新增

**方案 A（推荐）：复用 `--mt-tone-*` + 语义令牌凑够 8 色，零新增令牌。**

```
系统提示    → var(--mt-fg-3)          （中性灰，语义准确）
工具        → var(--mt-violet)
技能        → var(--mt-warning)
MCP         → var(--mt-tone-d)        （橙色，原 #f97316 的邻近色）
子 Agent    → var(--mt-sky-500)
记忆        → var(--mt-success)
动态上下文  → var(--mt-tone-b)        （青绿，正好对应原 #14b8a6）
对话历史    → var(--mt-accent-500)
```

**方案 B：新增一组 `--mt-ctx-*` 令牌（8 个 × 3 主题块 = 24 行）。**

优点：语义精确、后续可独立调；缺点：新增 8 个令牌要三块同步（08 片守卫测试会校验），且这 8 色**只在这一次要用**，复用价值存疑。

**建议执行时先做方案 A**，只有在三主题下发现可区分度不够时才升级到方案 B。

### 3.2 可区分度验证（本片的真正难点）

8 色在**浅色画布**上的可区分度，与在**深色画布**上的可区分度是两回事。尤其：

- 方案 A 里 `--mt-tone-b`（青绿）与 `--mt-sky-500`（天蓝）在浅色底上可能偏近。
- `--mt-warning`（黄）与 `--mt-tone-d`（橙）在**护眼主题的暖底**上会进一步靠近（护眼主题的 tone-d 是 `#b5473b` 砖红，warning 是 `#b5751d` 赭黄，都有相当分量的红）。

**验证方法**：三主题各截一张 `ContextUsageCard`，把 8 个色块并排截图放大，逐一确认相邻色相不混淆。若护眼主题下不达标 → 走方案 B，为护眼块单独选色。

### 3.3 实现方式

`ContextUsageCard` 的颜色用法需要先确认是"DOM 元素的内联 style"还是"传给图表库"。两种情况的写法：

- **DOM 内联 style**（如 `style={{ background: color }}`）→ 直接写 `'var(--mt-violet)'` 即可，DOM 天然支持。
- **传给 recharts / SVG** → 同样直接写字符串（见 [11 片 §二](./11-图表调色板令牌化.md) 的实证）。

**两种情况都不需要 `getComputedStyle`**，除非要拿去算派生值（如按透明度生成浅色底）。若确有派生需求，用 `color-mix(in srgb, var(--mt-violet) 12%, transparent)` 而非读值计算。

## 四、验证

1. `pnpm typecheck` + `pnpm test:all`（基线 298 / 2716 passed / 0 failed）。
2. **可区分度目视**（§3.2）——这是本片的主要验收项，不是可选项。
3. 三主题截图，确认 8 色都随主题变且都清晰可辨。
4. 数值抽查：卡片内的百分比数字与色块的对比度达标（护眼暖底上尤其要看 `--mt-warning` 系）。

## 五、明确不做

- **不改卡片的结构 / 布局 / 文案**——本片只碰颜色。
- **不改 Wiki 文件类型色板**（[14 片](./14-文件类型色板独立设计.md)）——那是 35 项、需要独立设计。
- **不改 `ContextUsageCard.module.css`**——该文件只有 2 处硬编码，若颜色全部移到 TS 侧常量，CSS 侧无需改动；若发现 CSS 里也有该组色，一并处理。
