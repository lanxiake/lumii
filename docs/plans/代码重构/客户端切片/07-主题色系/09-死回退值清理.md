## 一、目标

清理 **737 处 / 80 文件**的 `var(--x, <字面量>)` fallback。这类写法的存在理由是"令牌万一没定义时的兜底"，但：

- `design-system.css` 与 `tokens.css` 已在 `styles/global.css` 全局 `@import`，**这 737 处的 `--x` 全部有定义** → fallback 永不生效，是死代码。
- 更糟的是**它会误导**：改令牌的人看见 `var(--mt-fg-1, #1a202c)` 会以为 `#1a202c` 是相关值，实际上是几轮前的旧色。
- 它还**掩盖主题缺失**：某个主题漏定义变量时，页面不会暴露问题，而是静默用 fallback 显示错误颜色（第 7 片守卫测试要解决的就是这个，但只覆盖了主题块，覆盖不到使用处）。

## 二、现状与分类（2026-09-20 实测）

按 **fallback 值 vs 令牌当前值** 的关系，737 处分成三类：

| 类 | 定义 | 数量 | 处置 |
|---|---|---|---|
| **A · 冗余** | fallback 值 == 令牌在某主题下的值 | 约 150 处 / 21 种变量 | **直接删 fallback**（零视觉变更，可证明） |
| **B · 陈旧** | fallback 值 ≠ 令牌任何主题下的值 | 约 587 处 / 168 种变量 | **逐种变量核对后删**（见 §3.2） |
| **C · 悬空** | 变量名全仓无定义 | 2 处 | 变量名本身要修（见 §3.3） |

## 三、任务拆分

### 3.1 建立"可删清单"（先证据后动手）

写一个一次性核对脚本，对全部 737 处做机械判定：

```
输入：全仓 var(--x, <字面量>) 出现列表
      令牌定义表（: 每个 --x 在 :root / dark / light / eye-care 下的值，含 var() 解开）
输出：三张清单
  ✓ 可删：字面量 ∈ 该变量的值集合（含解 var() 链后的实值）
  ? 待查：字面量 ∉ 值集合（人工判断是否曾是该变量的旧值）
  ✗ 悬空：--x 全仓无定义（按 C 类单列）
```

**关键**：`--mt-*` 的值可能是 `var()` 引用（如 `--text-secondary: var(--mt-fg-3)`），必须解开链条再比对，不能只看字符串。

### 3.2 按清单执行删除

- **✓ 可删**（预计 ~150 处）：脚本替换 `var(--x, #hex)` → `var(--x)`，一次提交。
- **? 待查**（预计 ~580 处）：按变量聚合成表（变量名 / fallback 值 / 次数 / 涉及文件），**人工逐个判断**：
  - 若字面量是旧版令牌值（能从 git 历史或第 7 片的变更记录找到来源）→ 删。
  - 若是刻意写的"不随主题变的固有色"（如深色遮罩上的白字）→ **不删**，改为语义令牌（转 [10 片](./10-语义色与中性色收敛.md)）。
  - 判断不清的**保留并登记**，不猜。

### 3.3 修两处悬空变量

- `ToolsPage.module.css:229`：`--mt-danger-500` → `var(--mt-error, #d9534f)` 去掉整个中间层，或直接 `var(--mt-error)`（若无视觉差异）。
- `NewsPreferencesPanel.module.css:75`：`--mt-bg-hover` 本身**就是第 1 片补的旧别名**（`tokens.css:307` 里 `--bg-hover: var(--mt-bg-tertiary)`），此处写的是 `--mt-bg-hover`（多了 `mt-` 前缀）→ 改成 `var(--mt-bg-tertiary)`。**这是个真实的样式失效 bug，修完会有视觉变化**（该面板的 hover 背景色会开始生效）——需单独登记。

### 3.4 补守卫测试

在 `design-system.themes.test.ts` 增加一条：**扫描渲染层 CSS，断言不存在 `var(--mt-xxx, #hex)` 形式**（除非在豁免清单里）。

> **为什么要这条**：本片删完之后，新写的代码仍可能加回 fallback。这条守卫把"令牌必须有定义"从约定变成强制——若某处真的需要 fallback，那说明令牌契约有洞，应该去 [08 片](./08-主题令牌契约.md) 补令牌，而不是在使用处打补丁。
>
> **⚠️ 执行前必须先跑通全量**：这条测试会让本片成为"要么全清完、要么测试红"的 all-or-nothing 门禁。如果 §3.2 的"待查"里有大量保留项，需要给豁免清单一个明确的落点（建议放测试文件顶部的常量数组，注明每条的保留理由）。

## 五、明确不做

- **不动 `var(--mt-*, var(--other-token))` 形式**（fallback 是另一个变量而非字面量）——这类可能是有意的降级链，本片只处理字面量 fallback。

## 七、执行记录（2026-09-20）

### 7.1 范围收窄：只做颜色 fallback

计划里的"737 处"经精确审计**不成立**，原因是统计方法有缺陷：

- 用 `[^()]*` 正则抓 fallback，漏掉所有含括号的写法（`var(--x, rgba(...))`、嵌套 `var()`），
  又会把 `var(--a, var(--b, #hex))` 的**内层**重复计数（`--text-secondary ← #94a3b8` 28× 其实
  是外层 fallback 的内层半边）。**`var()` 的解析必须用括号配对**，正则做不到。
- 737 这个数把非颜色 fallback 也算进来了，而实际构成是：颜色字面量约 1051 处、
  转引另一个变量约 220 处、长度/时间/数字/字体/缓动约 380 处。**近七成不是颜色。**

经与用户确认，本片**只做颜色字面 fallback**（与主题工作直接相关、等价性易证）；
非颜色 fallback 归后续切片。

### 7.2 实际产出

| 项 | 数量 |

删除器按两条规则工作：`var(--x, #hex)` → `var(--x)`；`var(--a, var(--b, #hex))` → `var(--a, var(--b))`。
守卫测试固化同样规则（排除两个令牌**定义**文件 `design-system.css` / `tokens.css`——
它们定义里的字面值是合法内容，不是在"使用处打补丁"）。

### 7.3 等价性论证（本片的核心命题）

"删 fallback 零视觉变更"不靠截图，靠两条 CSS 层论证：

1. **fallback 不可达**：`global.css` 由 `main.tsx:15` 无条件导入（file-preview 独立窗
   同样走 `main.tsx` 懒加载），令牌在所有渲染入口都已就位；实测全仓 1051 处引用的
   变量**无一未定义**（C 类 = 0）→ fallback 分支永远不会被触发。
2. **删的是死代码**：`rgba(var(--x-rgb), α)` 这类在令牌缺失时是**整条声明失效**，
   使用处写不了字面 fallback（`r,g,b` 三元组拆不开），故从来不是有意的兜底。

⚠️ **像素探针证明不了这个命题**。实测同版本连跑两次，含动画/计时/图表的页面
（对话页、概览页）差异像素就有 12–14%、单通道最大差 200+——噪声与"改动差异"同量级。
该工具只能发现大幅变化，已在其文件头标注局限。

### 7.4 顺带发现的既有缺口（**本片不修，登记给 10 片**）

`--primary`（`SearchToolsSection/index.tsx:128` 内联 style）——全仓无定义且**无 fallback**，
颜色声明直接失效。属 [10 片](./10-语义色与中性色收敛.md) 范围。

> 另有约 20 个"无定义"变量经逐个核实是**运行时注入**（`setProperty` / 内联 style 对象 /
> 局部 CSS 声明），合法，不必处理。判定方法：同时检查 CSS 声明、`.setProperty(`、
> 内联 style 对象键三类赋值点。
