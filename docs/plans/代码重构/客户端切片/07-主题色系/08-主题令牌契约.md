## 一、目标

第 7 片把"CSS `var()` 这条取色路径"对齐了，但取色还有另外两条路径：**`getComputedStyle` 运行时读取**和 **canvas 绘制**。本片把三条路径的契约一起补齐，让后面 09–14 片的改动有稳定判据。

按此目标，最终交付两件事（原计划的第三件经实测改判，见 §2.3）：

1. **RGB 三元组契约**：保证每个 `rgba(var(--mt-xxx-rgb), α)` 在首帧和三个主题下都有值。
2. **守卫测试扩展**：把契约变成自动校验——新增变量漏补某一块、或引用了没有兜底的三元组，测试直接红。

## 二、现状与缺口（证据均为 file:line）

### 2.1 RGB 三元组的两个缺口

| # | 缺口 | 证据 |
|---|---|---|
| 1 | **`:root` 缺 `--mt-surface-rgb`** | `tokens.css` 的 `:root` 块只定义 5 个三元组，`--mt-surface-rgb` **只在三个主题块里定义**、`:root` 没有 → 首帧无值 |
| 2 | **eye-care 缺 3 个语义色三元组** | `[data-theme="eye-care"]` 只有 `--mt-surface-rgb` / `--mt-accent-rgb` / `--mt-fg-rgb`，缺 `--mt-success-rgb` / `--mt-warning-rgb` / `--mt-error-rgb` |

> **原计划第三项「删掉 `:root` 与三主题块重复的 success/warning/error」已被推翻**：实测 `tokens.css` 的 `[data-theme="dark"]` 与 `[data-theme="light"]` **都没有**重复定义这三个（只有在 `:root` 才有），所以不存在冗余。
>
> 更关键的是，原计划 §3.1 写的"eye-care 补暖调三元组 `79,122,58` 等，对应其 `--mt-success #4f7a3a`"**基于一个错误前提**——实测 `design-system.css` 的三个主题块里**都没有** `--mt-success/warning/error` 定义（三主题块只覆盖 `--mt-violet` / `--mt-tone-*` / `--mt-shine` / `--mt-mesh`），语义色三主题**共用全局固定区的值**（`design-system.css:47-58`）。
>
> 因此 eye-care 的语义色三元组按**与全局固定区一致**处理，否则会造出"`--mt-success` 是 `#22c55e` 但 `--mt-success-rgb` 是 `79,122,58`"的自相矛盾。
>
> （"深色应该用亮色还是压深色"是独立的体系问题，与"令牌写在哪个块里"无关。深色画布 `#0f172a` 上 `#22c55e` 对比度约 8:1，是可用的。）

### 2.2 一个真实的先帧缺陷

`components/ui/Tooltip/Tooltip.module.css:11/55`：

```css
background-color: rgba(var(--mt-surface-rgb), 0.96);
```

无 fallback。而 `--mt-surface-rgb` 在 `:root` 无定义（缺口 1）→ **首帧（`ThemeContext` 给 `<html>` 加上 `data-theme` 之前）这条声明失效，Tooltip 背景变透明**。

这类写法的危险在于：`rgba(var(--mt-x-rgb), α)` 在令牌未定义时是**整条声明失效**（不像普通颜色属性那样回退到某个颜色），而使用处没法写字面 fallback——因为三元组 `r, g, b` 拆不开，没法整个塞进 `rgba()` 的参数位。所以"被引用的三元组至少要在 `:root` 有定义"是硬要求。

这个缺陷在肉眼上极难察觉（首帧只有几十毫秒），但它恰好说明"`:root` 必须有兜底"不是洁癖而是真需求。

### 2.3 `--mt-sky-*` 的改判：不是缺口，是品牌色阶

原计划写"`--mt-sky-300/400/500` 三主题都不覆盖 → 换主题不变色，是漏了"，要补进三个主题块。**实测推翻了这个判断**：

| 事实 | 证据 |
|---|---|
| **零消费者** | 全仓没有任何 `var(--mt-sky-*)` 引用（grep 全量确认） |
| **它是品牌色阶** | 三个值被 Logo 渐变以字面量使用：`LumiiLogo.tsx` 的 `180deg,#7dd3fc,#38bdf8,#2563eb` 即 sky-300 → sky-400 → accent-600；`design-system.css:69` 的 `--mt-grad-brand` 同 |
| **也是浅色主题的底噪来源** | light 的 `--mt-shine` 用 `rgba(14,165,233,…)`（= sky-500）、`--mt-mesh` 用 `rgba(14,165,233,…)` |

**结论：三主题共用同一组值才正确**——Logo 品牌渐变不该跟着主题变色。所以本片**不动 `--mt-sky-*`**，并在守卫测试里为它写一条显式断言（见 §3.3），防止下轮又被误判成缺口。

> 同类还有 `--mt-slate-*`（约 170 处使用）与 `--mt-accent-50/100/200/800/900/950`——同样只在全局固定区、无主题覆盖。第 1 片已把这类登记为"设计刻度，属设计系统的词汇表，删不删是产品决策"，口径保持一致：**本次不动**。

## 三、任务拆分

### 3.1 `--mt-*-rgb` 定义归位（`styles/tokens.css`）

- **`:root` 补齐 6 个**，全部按**深色值**（`design-system.css:163-164` 明确写着"深色主题（产品原生，默认）"，与该块共用 `:root` 选择器）：
  ```css
  --mt-surface-rgb: 30, 41, 59;     /* #1e293b */
  --mt-accent-rgb:  59, 130, 246;   /* #3b82f6 */
  --mt-fg-rgb:      248, 250, 252;  /* #f8fafc */
  --mt-success-rgb: 34, 197, 94;
  --mt-warning-rgb: 245, 158, 11;
  --mt-error-rgb:   239, 68, 68;
  ```
- **三个主题块各自显式声明 6 个**（dark / light / eye-care），名字集合完全一致（守卫测试校验）。
- **eye-care 的语义色三元组与全局固定区同值**（`34,197,94` / `245,158,11` / `239,68,68`），理由见 §2.1 的说明；只有 `surface` / `accent` / `fg` 三个是暖调专属值。
- 文件头注释补上"六个三元组都必须在 `:root` 有定义"的理由。

### 3.2 ~~`--mt-sky-*` 补进三个主题块~~ —— 经实测取消

见 §2.3。本片不修改 `--mt-sky-*`。

### 3.3 守卫测试扩展（`styles/design-system.themes.test.ts`）

现有 3 个 describe 块（三块变量名集合一致 / tokens.css 变体块一致 / `--mt-accent-*` 只在 styles/ 定义）。**已新增 2 条**：

1. **RGB 三元组三主题一致**：断言 tokens.css 三个 `[data-theme]` 块内 `--mt-*-rgb` 的**名字集合完全一致**。
2. **引用必有定义**：扫渲染层所有 CSS/TSX（排除 `styles/`），收集 `rgba(var(--mt-*-rgb)` 形式的引用名，断言每个名字在 **`tokens.css` 的 `:root` 定义里存在**。

第 2 条在本片实施时**先跑红**，报的就是 `--mt-surface-rgb` missing（即 §2.2 的 Tooltip 缺陷），修复后转绿——测试的有效性已被实证。

> 注意：`tokens.css` 自身在映射层用了一批 `rgba(var(--mt-accent-rgb), …)`（`--color-accent-soft` 等），但那些处于**运行时**兜底位置（有 `data-theme` 时由主题块覆盖），不需要 `:root` 兜底。该测试排除了 `styles/` 目录；`--mt-warning-rgb` 的 `:root` 兜底由本片 §3.1 一并补齐。

### 3.4 顺带修正两处结论错误

1. 第 7 片 §六 第 6 条的说明写"深色块没有 tone 变量时落到 `:root` 全局固定区的亮色值"。经复核，全局固定区（`design-system.css:13-161`）与深色块（`:163-164` 的 `:root, [data-theme="dark"]`）**共用 `:root` 选择器**，深色块靠后者胜出，故落点是深色块。**深色下视觉无变化**（深色块值就是亮色值），但推理路径要改。已在第 7 片文档就地更正。
2. 本片原 §2.1 的"`:root` 与三主题块重复定义"、§3.1 的"eye-care 暖调语义三元组"两处判断，均基于未核实的假设，已按实测改写（见 §2.1）。

## 五、明确不做

- **不动 `--mt-sky-*`**——它是品牌色阶（Logo 渐变 / 浅色底噪的来源），三主题共用才正确。理由见 §2.3。
- **不动 `--mt-slate-*` / `--mt-accent-50..200` 等设计刻度色阶**——与第 1 片口径一致（"属设计系统的词汇表，删不删是产品决策"）。全仓约 170 处使用，但都不需要随主题变。
- **不动 `:root` 全局固定区里已有的 accent 色阶**（`design-system.css:16-26`）——它们服务 `readToken()`，且第 7 片刚校过。
- **不重构 `--color-*` 映射层**——那是 `tokens.css` 的独立话题，本片只碰 `*-rgb` 相关的约 20 行。
- **不给 pet 窗口补 `data-theme`**——宠物窗不跟主窗主题是刻意的，见 [12 片](./12-canvas与宠物色层收敛.md)。
