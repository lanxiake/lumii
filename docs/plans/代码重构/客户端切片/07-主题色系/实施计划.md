# 第 7 片 · 主题色系 — 实施计划

> 创建：2026-09-20 · 状态：**规划中**（待实施）
> 范围：`apps/windows/src/renderer` 主题机制 + 设计令牌 + 颜色常量收敛
> 上位文档：[客户端切片计划](../README.md)
> 起因：用户反馈「亮色主题饱和度偏低，看着发淡」+「新增护眼主题，并把前端所有主题色相关样式统一，以后换色系只需改配套变量」

---

## 一、目标

1. **亮色提饱和**：现有 `[data-theme="light"]` 的强调色与底噪光斑提饱和，去掉"发淡"感；对比度按 WCAG ≥ 4.5:1 校核，不靠肉眼舒服为准。
2. **新增护眼主题**：第四档独立主题 `eye-care`（暖色浅色），与现有冷调浅色并存，不动现有浅色。
3. **换色系只改变量**：清理掉会让"改变量不生效"的结构性病灶，并加守卫测试防回归。这是本片的核心价值——第 7 片做完后，后续换任何色系都是在 `design-system.css` 三个主题块里改值。

## 二、现状与根因（证据均为 file:line）

## 三、任务拆分

### 3.1 主题机制支持第三态

| 文件 | 改动 |

### 3.2 护眼主题块 + 亮色提饱和（`styles/design-system.css`）

新增 `[data-theme="eye-care"]` 块，紧跟 `[data-theme="light"]`（:288 之后），**按浅色块相同的变量顺序与分组**覆盖同一组变量：表面层级 → 毛玻璃 → 内嵌表面 → violet → shine/mesh → code-bg → diff → tone-a..d → 前景 → 边框 → 阴影。

配色（已按 WCAG 校核：主/次文字 ≥ 4.5:1，三级 ≥ 3:1）：

| 组 | 值 |
|---|---|
| 画布 / 卡片 / 填充 | `#f5f1e8` / `#fffdf7` / `#ece5d6` |
| 内嵌次级 / 三级 | `#faf6ec` / `#ece5d6` |
| 主 / 次 / 三级 / 禁用文字 | `#2f2a22` / `#5c5346` / `#8a7f6b` / `#a99f8c` |
| 强调色 300/400/500/600/700 | `#e0b56a` / `#cf9c4a` / `#b8863b` / `#9c6f2c` / `#7f5820` |
| 语义色 success/warning/error/info | `#4f7a3a` / `#b5751d` / `#b5473b` / `#a06a2c` |
| 边框（标准/浅/深/hairline） | `rgba(93, 78, 55, .14/.10/.20/.10)` |
| 阴影 | 暖灰褐 `rgba(87, 71, 45, …)` |
| mesh 底噪光斑 | 琥珀 / 暖橙 / 青苔三色低强度 |

**新增语义 token `--mt-fg-on-accent`**（"强调色底上的文字"）：light `#ffffff` / dark `#ffffff` / eye-care `#fffdf7`。现有的 `--mt-fg-inverse` 是"主题主文字的取反"，light 下是浅色、dark 下是深色，拿来当按钮白字在 light 主题下会出错，故单独加这一个（三个主题块都要有，守卫测试会校验）。

浅色主题提饱和（同色阶联动，保持色相）：
- `--mt-accent-500: #3b82f6 → #2f7bf6`
- `--mt-accent-400: #60a5fa → #4f94f8`、`--mt-accent-600: #2563eb → #1e63e9`
- `--mt-mesh` 透明度 `0.09/0.07/0.05 → 0.12/0.10/0.07`
- `--mt-tone-a..d` 同步提饱和

> 视觉变更需逐项登记（本片 §六），交付时说明。

## 四、验证

1. `cd apps/windows && pnpm typecheck`——类型干净（vitest 不做类型检查，类型改动后必须跑）。
2. `pnpm test:all`——改了 `src/main/app-ui-control/**`，按 AGENTS.md 必须跑全量。**基线注意**：`src/main/model-thinking.integration.test.ts` 有 4 个既有失败（2026-09-20 实测，与样式无关，已定位为直连发送链路回归，另行处理）。
3. `scripts/start-dev.ps1`（改主进程后**必须** stop → start，HMR 不覆盖主进程），然后实测：
   - `lumii-ui settings set theme.mode <light|eye-care|dark>` 逐主题截图，用 `node scripts/probe-theme-colors.mjs` 统计整图色彩：
     - 期望 light 亮度 ~239 / 暖度 **-9**（冷），eye-care 亮度 ~238 / 暖度 **+14**（暖），dark 亮度 ~47（2026-09-20 实测值）。
     - 判据：护眼与浅色亮度接近而冷暖相反，才是"同亮度暖色系"；若护眼亮度明显更低说明底色压太暗。
   - `lumii-ui goto --view settings --category appearance` → `screenshot` 应出现 4 个 `role=radio`（浅色/护眼/深色/跟随系统）；`click --ref <护眼>` 后 `settings get theme.mode` 返回 `eye-care`。
   - 标题栏按钮循环：连点三次应走 浅色→护眼→深色→浅色，按钮 `title` 随当前态变化（实测已通过）。
   - 概览页标题渐变随强调色变（验证 3.4 的局部覆写清理生效）。
4. 抽查 5 组 `color: white` 改动点（Button / Modal / Toast / Badge / TitleBar），确认护眼主题下仍是清晰的暖白字。

> #6 说明：改动前深色块没有 tone 变量，随后加载的 `[data-theme="light"]` 块（非 `:root`，不命中深色）**不生效**，实际落到 `:root` 全局固定区的亮色值（#38bdf8/#2dd4bf/#60a5fa/#fb923c）。补齐时按"深色用亮色"显式写入同一组值，故深色下视觉**无变化**，只是从此有据可依、换肤不再漏。
