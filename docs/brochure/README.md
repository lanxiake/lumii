# 微信 MCP 工具集 · 产品手册

> 状态：已确认（2026-10-14）· 面向**使用者与推介**，不是设计文档。
> 设计与实现见 [`../design/渠道与CLI/`](../design/渠道与CLI/)。
> 每份说明书里的数字都是 **2026-10-14 在本机真机上跑这套 exe 的原始输出**，不是估算。

四件套都是 **stdio MCP server**：装进你已经在用的 AI 客户端（Claude Code / Cursor / Claude Desktop /
Codex / Gemini CLI / VS Code / Zed / Cline / Warp 等十余家，一键勾选），
然后**用大白话问**，AI 自己决定调哪个工具。

它们解决的是同一类问题：**你电脑上那份微信，除了你自己手点，谁也读不动。**
微信不开任何口子，聊天记录是加密的，文件、图片、语音散在几十个目录里，
撤回的东西转瞬即逝。这四件套把这份数据变成 AI 能用的接口——**不改微信、不注入、不外传**。

## 一句话选型

| 你想干的事 | 用哪个 | 它给你什么 |
|---|---|---|
| 「帮我看看/回一下微信」 | **wechat-mcp**（本机微信助手） | 读会话历史、搜消息、看图听语音、**以你本人身份发消息**、蒸馏你的说话风格 |
| 「把这段聊天记录导出来发人」 | **wechat-export-mcp**（记录面） | 单个自包含 HTML／Markdown，图片内嵌，双击就像翻微信 |
| 「导出来给 AI 分析」 | **wechat-export-mcp**（记录面） | **JSON**，附 `stats` 统计报表与独立的 `stats.json`；还能**只说"提到某某的那些"**，含全库搜 |
| 「群里发的文件我全要存下来」 | **wechat-export-mcp**（文件面） | 列文件消息、**趁没过期**归档到本地、报告下不动的；顺带答"微信怎么这么占地方" |
| 「我有哪些客户、谁很久没联系了」 | **wechat-crm-mcp**（客户分析） | 通讯录、群成员、互动排行、沉默分层，**加**读正文/按范围搜/客户简报——**从"该看谁"到"他在说什么"一个产品闭环**，只给事实不下结论 |
| 「他刚才撤回的那句到底是什么」 | **wechat-recall-mcp**（撤回防护） | 常驻守护事前留档，撤回后**连原文一起**翻出来 |

**会打包一起用**：记录面与文件面在**同一个产品、同一套目录结构**里（附件与归档共用 `files/`）；
撤回防护和文件面互补——一个留**文字**，一个留**文件本体**。

### 从实测量级先感受一下它们处理的是什么规模

| 本机实测（2026-10-14） | 数字 |
|---|---|
| 通讯录联系人 | **2712**（其中 35 个群） |
| 真正产生过互动的联系人 | **171** —— 其余约 **2540 人从没说过话** |
| 有未读的会话 | **132** |
| 账号目录总量 | **1.47 GB**（其中聊天记录本体只有 **67 MB**） |
| 文件消息 | **157** 条，其中 **9 条已过期、3 条同名不同版本** |
| 视频消息 | **48** 条，**只有 8 条**本机有文件 |
| 近 30 天我发出的消息 | **3886** 条（其中我发出 **1119** 条） |
| 撤回防护已归档 | **4713** 条 / 71 个会话 / 1.9 MB |

**这张表本身就是这四件套存在的理由**：这些数字**微信一个都不告诉你**。

## 共同的三条底线

这三条是四件套每一件都成立的，也是它们和"外挂"的分界线：

1. **零注入**。读取靠 SQLCipher4 直读本机库，密钥**从微信进程内存只读扫描**取得——
   不打补丁、不挂钩子、不改微信的任何数据或组件。写操作（只有 wechat-mcp 有）走
   **模拟真人操作**：窗口消息投递 + UI Automation 读数，不碰剪贴板、不抢前台。
   > 这不是保守，是**对现实的判断**：微信 4.x 客户端带 **VMProtect 加固 + Detours 钩子**
   > （社区扫描工具 `wcprobe` 自己就是这套机制）。跟这种客户端玩注入，
   > ①和反调试器硬碰、②有你被它反制的一天、③把用户账号置于风险中。
2. **全本地、不外传**。图片在本机解密、语音在本机转写（SILK → Paraformer，**音频不出机器**）、
   画像在本机存 Markdown。有效期校验本身也是离线的。
   （**唯一的外传风险在你自己选的模型**：把聊天内容交给云端 LLM
   就等于外传——这一条由你的客户端决定，我们不替你打包票。）
3. **失败自带原因，绝不装作成功**。任何失败都是同一个形状：
   `{"ok": false, "detail", "error_code", "stage", "suggestion"}`，
   并且区分「名字没对上」（`target_not_found`，给你相近候选）和「真没有数据」——
   这两件事长得一模一样，混起来就是让人把"没找到"当成事实。

还有一条产品的脾气：**宁可说"我做不到"，也不编**。文件过期了就说救不回来，
视频没下载过就说本机没有，群昵称查不到就说这个群没设过，
`read_image` 拿到的是缩略图就**明说 `variant: "thumb"`**。
读不到内容时编一段画面，被当成最严重的那类 bug。

**五条值得单独说的结论**：

1. **同类工具几乎都不发消息。** 读取是"解一个数据库"，发送是"让一个真人账户真的把话发出去"——
   后者必须驱动真实的微信客户端。这四件套里的 wechat-mcp 是**这条路上唯一一件**，
   而且它的做法（窗口消息投递 + 失败自带原因 + 五道校验）比"注入 hook"难得多也稳得多。
2. **这个生态正在萎缩，而不是扩张。** 腾讯曾一次性 DMCA 投诉 **30+ 个仓库**；
   `PyWxDump` 2025-10 收到律师函后删库；`wx_key` 删库并留了个讽刺 README；
   `WeChatMsg` 官方版停在 3.x 且自述不再更新；`wxauto` 被反馈不支持 4.0。
   ——**"越狱式"路线的共同结局**。这四件套选的是**换一条路走**（不注入、不逆向客户端），
   而不是在这条路上跑得更快。
3. **企业级方案管不到个人微信。** 企微会话存档只覆盖**企业微信体系内**的沟通
   （含企微窗口里与客户个人微信的对话），**个人微信本身完全不在范围内**；
   而且原生只给**加密数据接口**，"开了存档却查不到"是行业里最常见的坑。
   **个人微信这一侧，市面上基本是空的**——尤其是"谁很久没联系了"这类**按人**的视图，
   查到的方案**全是企微 SCRM**。
4. **有几件事，横向比下来没人做。** 我们查过市面上的工具后确认：
   **没有一个**做"文件级清单 + 过期标注 + 按会话归档"；
   **没有一个**把"图片缺密钥（能修）"和"原图本地根本没有（没救了）"分开报；
   **没有查到**"自包含单文件导出"作为卖点（媒体普遍是**落盘到旁边的 `_files` 目录**，
   单独把 HTML 发出去会掉图）。
   这不证明我们做得对，只说明**这几件事上我们是唯一的选择**。
5. **"本地读取类 MCP"是当下被点名的攻击面。** 学术与厂商安全研究都在讲同一件事：
   MCP server 以用户权限在本机运行，工具描述本身会被模型当指令读，
   于是"摄入 → 采集 → 外泄"可以链式完成。所以这四件套的三条底线不是保守，
   是**这个位置上唯一站得住的姿势**：只读、全本地、工具描述里不藏任何"该做什么"的策略。

## 风险与合规（必读，不埋末尾）

前面讲的都是"能做什么"。这一节讲**代价**，而且是主动写出来的——**不写等于骗人**。

### 1. 微信的协议明确禁止这类自动化

《腾讯微信软件许可及服务协议》**8.2.1.6** 的原文禁止：

> 通过非腾讯开发、授权的第三方软件、插件、外挂、系统等……**进行自动化操作**，
> 对本软件及其组件、模块、界面、数据等进行**访问、读取或控制**。

微信安全中心的《针对在微信使用"外挂"行为的打击公告》则把
**"微信机器人（定时群发、自动回复、自动聊天）"与"群控"直接列为外挂**。

**说白一点**：这四件套做的事——读取本地数据、以你的身份发送消息——**落在上面这段禁令的字面范围内**。
使用它们**可能违反你与腾讯的协议**。这是使用者的判断，我们不替你打包票。

### 2. 我们不会写"零封号风险"

社区里"零封号"式的宣传已经被反复戳穿，写它等于自毁信誉。能给的只有**归因**，不是保证：

| 做法 | 社区公开反馈 |
|---|---|
| **DLL 注入 / Hook**（如 WeChatFerry 一派） | 2025-09 的封号风暴中"**几乎无一幸免**"，有统计称封号率 **>80%** |
| **网页协议**（itchat 一类） | 只有老号能登，扫码有风险 |
| **UI 自动化**（wxauto / WePush 一派，**我们在这里**） | 公开的封号反馈**显著少**；微信"面对的就是一个正常客户端" |
| 反方观点 | "只要登录账号就都是 hook，都必定会封号，只是时间问题" |

还有一条反直觉的说法（腾讯云开发者社区）：**"本地电脑运行为封号率最高环境"**。

腾讯官方**没有**公开对个人号 Bot 的处罚阶梯，社区里也没有可验证的个案编号——
所以**任何给你"保证不封"的说法，都是编的**。

### 3. 已知的高风险行为（照这个清单自查）

- **群发 / 批量发送**（`send_batch` 就是干这个的——用它之前想清楚）
- **高频、固定间隔的发送**（"秒回、24 小时在线、毫秒级固定间隔"是被点名的机器特征）
- **主动加好友**（社区封号归因里，"有加好友动作就触发检测"是被提到最多的一条）
- **新号 / 小号**上跑自动化

**建议：用小号或测试号先行。** 这是你能做的最有效的一件事。

### 4. 有一条线我们不碰，也不该有人碰

2024-12，市场监管总局通报的典型案例里，**北京尘锋**因"私域流量聚合管理软件"被罚 **10 万**——
认定的行为是：**破解读取微信核心数据库 + 上传聊天消息与通讯录 + 控制微信自动批量加好友**。
另有**某教培机构批量导出客户手机号触发风控，整个企业账号被冻结 72 小时**。

**"破解 + 上传 + 代操作加好友"这三件事，这四件套一件都不做**：只读本机、不外传、不加好友。
——这不是谦虚，这是**那条罚单画出来的线**。

### 5. 隐私要分两层说，别含糊

| 层 | 这四件套挡得住吗 |
|---|---|
| **第三方 LLM 厂商**（把你的聊天记录拿去训练/人工审核） | ✅ **挡得住**——图片在本机解密、语音在本机转写、画像存本地 Markdown，工具本身**不发出任何内容** |
| **腾讯** | ❌ **挡不住**。你的消息本来就要过腾讯的服务器才能送达 |
| **你自己接入的云端模型** | ❌ **由你的客户端决定**。你在 Claude / ChatGPT 里问"帮我回一下微信"，那段上下文就送出去了——**这一层我们不替你决定，但必须告诉你它存在** |

云端侧的真实代价有据可查：有研究统计，**六家主流厂商的隐私政策全部默认用消费者对话做训练**；
有的厂商人工审核员可访问对话片段；有的对话曾在诉讼中被要求提交，
且**不享有律师-当事人保密特权**。

### 6. 版本能力边界（本机实测，不含糊）

- 本机微信 **4.1.15.13**，落在**已真机验证**的范围内（`4.1.15`），
  密钥扫描、解密、读取、发送**今天全部实测通过**。
  公开讨论里有说法称"微信 4.1.x 纯内存扫描已失效"——**与本机实测不符**，
  所以我们写自己的测量结果，不转述别人的结论。
- 版本**不在验证范围内**时：不是静默出错，而是**每条工具结果都挂一句警告**
  （"这版没验过，读到的内容可能是错的，先抽查几条与界面核对"）。这是刻意的——
  密钥扫描依赖固定内存偏移，换版本最怕的不是报错，是**静默给错东西**。
- **微信必须正在运行且登录**。密钥只在进程内存里；而且**微信刚启动、没打开过任何会话时可能取不到**——
  点开一个会话等几秒就好。这条写进了错误提示，不是让你自己猜。

## 怎么拿到

目前走**双击 exe** 这条路（npm 社区分发已于 2026-10-13 废弃）：

1. 拿到对应产品的 `wechat-*.exe`，**双击**。
2. 向导先讲清楚它是什么，再用**方向键勾选**要装到哪些 AI 客户端（不用打字）。
3. 它把 exe 的真实路径写进客户端配置、把技能包拷进技能目录。
4. **重启客户端**，用大白话开问。

exe 在**构建时**钉死一个到期日（默认构建日 + 365 天），到期后每次调用返回
`{"ok": false, "error_code": "expired", ...}` 并写明怎么办；
`--expiry-status` 随时可查。不需要任何授权密钥。

**装完别移动、别删这个 exe**——客户端配置里存的就是它当前的位置。想换地方，在新位置再双击一次。

## 前提与适用面

- **Windows + 微信 4.x**，且微信**已登录、在运行**（读的是你本机这份数据）。
- 只支持**你自己的账号**——读不了别人的。
- 微信版本未被验证过时**直接拒答**（fail-closed，而不是猜着读）。
- 有一条**只有你能做**的补救：大多数图片和视频**没在微信里点开过就不在磁盘上**
  （实测 48 条视频消息只有 8 条能定位）。**在微信里点开一次，之后再搜/再导就有了。**

> ⚠️ 这四件套处理的是**你和他人的聊天内容**。请只用于你自己账号、你自己机器上的自用与
> 小范围场景；是否把内容交给云端模型，由你评估。
