## 对方撤回了？原文我这里还有

**【事前留档】** 后台守护自动保存消息，撤回发生前就已经存好了
**【原文完整】** 文字原文、引用内容、图片和文件信息都在
**【不改微信】** 不装插件、不打补丁、不拦截撤回，微信该怎么用还怎么用
**【自己误删也能找】** 删除和撤回同一套判定，手滑删掉的也能查
**【体积很小】** 4713 条消息只占 1.9 MB，长期开着也不心疼

## 你是不是也这样？

- 群里有人发了条重要通知，**你还没看就撤回了**，只剩一行灰字；
- 客户说了个价格，**转头就撤回改口**，你想核对却无从查起；
- 自己手滑删了一条消息，**想找回来却没有任何办法**；
- 网上搜「查看撤回消息」，要么是骗人的，要么要装改微信的插件，**装完就被强制下线**。

---

## 为什么别的工具查不到撤回？

微信撤回是**真的删除**：实测 114 条撤回通知，原消息要么整行被删，要么被原地改写成系统消息，
撤回通知里**根本不带原消息的内容**。

所以任何「事后去库里翻」的工具都注定查不到——东西已经不在了。

**唯一可行的办法：在撤回发生之前，先自己存一份。** 本产品就是这么做的。

## 核心卖点

### 卖点 1：撤回前就存好了，事后一问就有

```
你：XX 群里最近有人撤回消息吗？
AI：有 2 条：14:32 王五撤回了一条文字，14:50 赵六删除了一条……
你：第一条原文是什么？
AI：（完整原文 + 引用内容 + 附件信息）
```

按会话内的消息编号精确取回，**同一秒发了好几条也不会取错**。

### 卖点 2：两种撤回机制都能识别，不误报

| 类型 | 意思 |
|---|---|
| `deleted` | 整条消息从库里消失了 |
| `recalled` | 消息被改写成「撤回了一条消息」 |
| `changed` | 内容发生了其他变化 |

只判「消息没了」会漏掉「被改写」，只判「内容变了」会漏掉「整行删除」，实测两种都存在，所以两种都判。
不同消息恰好用了同一个编号时也不会误报（有专门的测试覆盖）。

### 卖点 3：不是「防撤回插件」，没有改客户端的风险

| 做法 | 公开反馈 |
|---|---|
| 防撤回补丁（修改微信客户端） | 「上午装补丁，下午被强制下线，重新登录还要签承诺书」 |
| 「微商版」微信（含防撤回，约 38 元/月） | 不到 24 小时收到官方警告 |
| **本产品** | **不改微信、不拦截撤回**，只是自己抄了一份 |

微信那边该撤回还是撤回，对方看到的提示也照旧。本产品只是让你手里多一份记录。

### 卖点 4：守护稳定，挂了会自己爬起来

- **自动重启**：意外崩溃后自动重启（等待时间从 5 秒逐步拉长到最多 300 秒），并记录日志；
- **不会双开**：再启动一个会自动识别「已经有一个在运行」并退出，避免两个进程抢着写库；
- **优雅停止**：`--stop` 通知守护自己收尾退出，记下停机时间，而不是硬杀进程；
- **每 24 小时全量对账一次**：接住那些落库较晚的消息；
- **开机自启**：一条命令装好，重启电脑后自动运行。

### 卖点 5：哪段时间没覆盖到，如实告诉你

关机、休眠、守护没运行的时段会被记成「缺口」，`archive_gap` 一查就知道。
**不假装全覆盖**——哪段时间的撤回查不到，工具会明说。

### 卖点 6：能证明自己在干活

```
你：守护在跑吗？有没有漏记的时段？
AI：已归档 4713 条，覆盖 71 个会话，归档库 1.9 MB，缺口 0 个。
```

本机实测把归档库和微信当前数据逐条比对：**4713 条完全一致，0 条被改，0 条被删**——
既证明守护确实在持续留档，也证明判定没有乱报（这段时间确实没人撤回）。

## 功能清单（5 个只读工具）

| 工具 | 做什么 |
|---|---|
| `daemon_status` | 守护是否在运行、已归档多少条、归档库多大、有没有缺口、是否已开机自启、日志在哪 |
| `health_check` | 一句话判断能不能用、哪坏了：`status`（healthy/warning/critical）+ 逐项检查（守护/数据增长/缺口/磁盘）+ **修复建议** |
| `list_recalls` | 列出被撤回 / 删除的消息，可按会话、时间段筛选 |
| `read_recall` | 取某一条被撤回消息的完整原文 |
| `archive_gap` | 列出没有覆盖到的时段 |

**守护命令**

```powershell
wechat-recall-mcp.exe --install-autostart   # 开机自启 + 立刻后台拉起（双击安装时默认已开）
wechat-recall-mcp.exe --status              # 查看状态
wechat-recall-mcp.exe --stop                # 停止守护（保留自启）
wechat-recall-mcp.exe --uninstall-autostart # 取消开机自启
```

## 三步上手

1. 双击 `wechat-recall-mcp.exe`，方向键勾选要装到的 AI 客户端。
2. 问到「要不要开后台守护」时**直接回车**（默认就是开）——守护当场在后台跑起来，开机也会自动启动。
3. 重启 AI 客户端，之后有人撤回时问 AI：「刚才撤回的是什么？」

> 撤回防护和其他三款不同：**守护开起来之前发生的撤回，是查不到的**。所以安装时默认就把守护开好，
> 装完那一刻起就开始留档，不用等下次开机。

## 常见问题

**Q：装之前别人撤回的消息能查到吗？**
A：查不到。这是唯一「过了就没了」的地方，所以安装时默认就开启守护和开机自启，装完立刻开始留档。

**Q：关机、休眠的时候呢？**
A：那段时间漏掉的补不回来，工具会如实记成缺口。

**Q：能阻止对方撤回吗？**
A：不能，也不该。本产品不改微信的任何行为，只是提前存了一份。

**Q：发出来几秒就撤回的消息也能存到吗？**
A：守护默认每 30 秒扫描一次（可用 `--interval` 调短）。如果一条消息恰好在两次扫描之间发出又撤回，可能来不及存下。

**Q：归档库会不会越来越大？**
A：会缓慢增长，但很小（实测每条约 400 字节）。默认永不删除；想控制体积可以给守护加 `--retain-days N`，
代价是 N 天前的消息被清理后，那些消息再被撤回就查不到了——这个取舍由你决定。

**Q：被撤回的文件本身能找回吗？**
A：本产品保存的是文字原文和附件信息，**不保存文件本体**。想把文件存下来，请搭配 [微信导出与文件归档](wechat-export-mcp.md)。

**Q：留档能当证据吗？**
A：归档库是你本机的一份文件，可以被修改，不能替代公证。需要法律效力请自行做公证或哈希固化。
