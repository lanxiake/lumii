# spences10/wiki0 设计解构与 Lumii 参考

## 结论

`wiki0` 的核心选择是“Markdown 为真相源，SQLite 为可随时丢弃并重建的本地索引/缓存”。这是本批项目中最直接可迁移到 Lumii Wiki 的存储边界：文件可移植、可人工编辑，SQLite 负责 FTS、chunk、反链和图查询。其价值不在 MCP 工具数量，而在把索引陈旧、来源指纹和人工审核写成可验证的产品语义。

## 调研边界与已验证证据

本解构基于 `872d0da2910a147f6990b20d3926a243aa59e6ba`。证据文件与 MIT 许可见 [源码/README.md](源码/README.md)。以下“已验证”对应 `schema.sql`、`indexer.ts`、`search.ts`、`sync.ts` 与相关 Vitest；“建议”不等同于 Lumii 已实现能力。

## 已验证：存储、索引与检索数据流

```text
Markdown 页面（frontmatter + body + [[link]]）
        |
        v
index_wiki() 全量读取、解析和事务重建
        |
        +-> pages / page_links / page_chunks / facts
        +-> fts_pages / fts_page_chunks
        +-> wiki_meta（schema、包版本、时间）/ wiki_events
        |
        v
search_wiki_chunks() -> FTS5 BM25 -> 页面、标题、heading、行范围、snippet
backlinks_for_page() / graph_wiki() -> page_links
```

- `schema.sql` 将 `pages`、`page_links`、`page_chunks`、`facts`、`wiki_meta`、`wiki_events` 与两张 FTS5 虚表分开。chunk 记录路径、标题、heading、行范围、页面状态/标签/优先级，便于在检索结果中定位原文。
- `indexer.ts` 的 schema 版本为 4；索引时清空并重建 FTS 和页面派生记录，在事务内插入页面、解析的 wikilink 和按标题切分的 chunk，并在 meta 写入索引时间、schema 与包版本。`index_status()` 会识别缺失、页面变化、schema/包版本变化等陈旧原因。
- `search.ts` 使用 FTS5 `bm25()` 与 `snippet()`；先严格转义纯文本查询，空结果再尝试放宽词项。chunk 结果会检查索引状态并给出陈旧 warning；反链从 `page_links` 查询。
- `sync.ts` 将外部文档写为 `sources/synced` 页面，可在选项允许时派生 facts；生成的候选页面文本明确标注“Needs human review before becoming a stable wiki page”。
- `indexer.test.ts`、`search.test.ts`、`sync.test.ts` 证明这些不是纯 README 设想，而有对应行为测试。

## 对 Lumii 的建议

1. P0 采用“页面源数据 + 可重建 FTS/链接索引”边界。若 Markdown 写入文件，文件为真相源；若先落 SQLite，页面表为真相源，FTS 和 link 表仍必须可重建。两者不能同时含糊地称为真相源。
2. P0 为搜索结果保存并展示 `pageId/path/title/heading/line-range/snippet`，使 Agent 与用户能返回原文位置；索引版本与最后构建时间应可诊断。
3. P0 对 `[[wikilink]]` 保存 raw text、目标、alias、embed 与 resolved/unresolved 状态，反链仅查询该派生关系表。
4. P1 将导入/AI 编译输出置为候选状态，维护来源指纹与审核动作；审核通过后才提升为稳定页面。

## 不可直接采用项与风险

- 不直接引入 `node:sqlite`、Node >=24.15 或整个 MCP/CLI/Svelte 应用；Lumii 需沿用现有 SQLite 和 Electron IPC 边界。
- 全量重建在小型个人库易于保证正确性，但大库须测量耗时并增加增量策略；无论如何保留全量恢复路径。
- `fts5` 默认 tokenizer 的中文召回效果未经此项目验证，必须以 Lumii 中文与中英混合样本测试。
- 其 `facts` 是可派生的辅助表；不要允许 AI 将推断事实写回用户原始页面。

## 分阶段采用

| 阶段 | 范围 |
| --- | --- |
| P0 | 明确真相源、wiki 页面/链接/chunk 表、FTS5、反链、索引状态与全量重建 |
| P1 | 导入来源指纹、候选页面、人工审核与事件日志 |
| P2 | facts 及受控的图查询；只保留可追溯来源的事实 |
| 不纳入 | MCP/CLI/Svelte UI、强绑定 Node 24 的实现 |
