# siyuan-note/siyuan 设计解构与 Lumii 参考

## 结论

思源笔记是面向个人知识管理的完整块级文档系统。其最重要的设计启示不是 `.sy` 文件格式，而是严格区分持久内容、可重建索引、历史与缓存；把引用定位到块级；并通过内核 API 统一维护落盘、索引、加密和历史。对 Lumii 而言，它是 Wiki 产品边界、可追溯关系与数据安全的参考，而非可直接嵌入的技术方案。

## 调研边界与已验证证据

基于 HEAD `afa823b6b4e4f183511e0bc0a3be93caa94c7c97`，许可为 AGPLv3，详见 [源码/README.md](源码/README.md)。已验证结论来自 `docs/WORKSPACE.md`、`docs/SY-FORMAT.md`、`kernel/filesys/tree.go`、`kernel/sql/index_queue.go`、`kernel/sql/block_ref.go`、`kernel/search/find.go` 和对应 Go 测试；Lumii 建议为独立推导。

## 已验证：工作区、引用与索引数据流

```text
编辑器/API
   |
   v
内核解析块树 -> .sy JSON 树（持久源数据） -> 文件/加密写入
   |                                      |
   +-> 索引队列 --------------------------+
                   |
                   v
          temp/ 下 SQLite 索引和缓存
                   |
        搜索、块引用、反链、面包屑、历史/同步
```

- `docs/WORKSPACE.md` 明确工作区 `data/` 保存笔记本、`.sy` 文档和资源；`temp/` 下的 `siyuan.db`、`blocktree.db` 等为可重建索引/缓存，`history/` 与 `repo/` 独立处理历史/同步。文档还明确目录层级是文档层级的一部分，文件名等于文档 root ID。
- 同一文档说明普通笔记本内容可直接读取，但加密笔记本内容、资源和索引由解锁后的 kernel 管理，并明确建议修改数据时优先走 HTTP API/MCP/CLI，避免直接文件写入造成索引、引用和面包屑陈旧。
- `tree.go` 的 `WriteTree` 从 AST 生成 JSON，比较缓存/磁盘避免重复写；加密文档通过密钥租约、加密数据与受控写入落盘，并在路径 ID 与树 root ID 不一致时对加密文件 fail-closed。
- `block_ref.go` 与引用查询文件实现块引用的持久化与查询路径；README 也将块级引用和双向链接列为产品能力。关系由稳定块 ID 表达，而非仅依赖页面标题匹配。
- `index_queue.go` 表明索引更新被放入专门的队列/数据层；`find.go` 是搜索入口。该设计避免让 UI 直接读写派生索引。

## 对 Lumii 的建议

1. P0 明确三类数据：用户原文/页面为持久真相源，FTS/link/chunk 为可重建派生数据，历史/操作日志为独立审计数据。重建索引绝不可删除原文。
2. P0 先提供页面级 Wiki 链接，P1 再引入稳定的 chunk ID 和“精确段落引用”，使 Agent 回答可以回到来源片段而不是只回到整页。
3. P0 所有写入、索引刷新与导入都经 repository 和 Electron IPC，renderer 不直接操纵数据库或文件；失败时保留页面源数据并标记索引待修复。
4. P1 将编辑历史、恢复和冲突显示为产品能力。AI 的引用、摘要和关系必须指向原始页面/chunk 与生成操作记录。
5. P2 才评估加密知识库。先定义密钥生命周期、备份、索引隔离和 Windows 恢复路径，不能只对 Markdown 文件做表面加密。

## 不可直接采用项与风险

- 不复制 `.sy` 格式、Go kernel、块编辑器或其完整同步栈；Lumii 的数据模型、Electron 生命周期和产品范围不同。
- AGPLv3 是强 copyleft 许可证，未经法务与架构评估不得复用代码、复制实现或将其作为内嵌依赖。
- 思源的块级模型、属性视图、插件、同步、加密和多端构建相互耦合，直接移植会远超 Lumii 当前 Wiki MVP。
- 目录即层级在直接文件操作时容易造成孤儿节点；若 Lumii 选择文件真相源，必须将移动/重命名设计为原子操作并提供一致性检查。
- README 说明不支持第三方同步盘，提示“直接同步文件”有损坏风险；Lumii 必须独立定义并测试同步/备份策略。

## 分阶段采用

| 阶段 | 范围 |
| --- | --- |
| P0 | 真相源与派生索引分离、页面链接、统一写入边界、索引重建与故障状态 |
| P1 | chunk 标识/精确引用、反链、编辑历史、AI 操作审计 |
| P2 | 加密库和高级关系浏览，前提是备份与恢复测试完成 |
| 不纳入 | `.sy`/Go kernel、整套同步与块编辑器、AGPL 代码复用 |
