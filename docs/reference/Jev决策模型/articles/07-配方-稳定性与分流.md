# 07 · 配方：稳定性与分流

> 覆盖官方路线「**判断稳定性与分流**」的三篇：
> `01 自一致性 Noul`、`02 自一致性 Choice`、`18 基于置信度的分类`。
>
> 这三篇回答同一个问题：**同一个判断重复跑，会不会翻？翻的时候怎么办？**

---

## 7.0 这三篇在问什么

官方对这条路线的一句话概括：

> **重复运行、保留完整分布、把不确定样本交给后续策略。**

⚠️ **先记住最重的一条免责声明**（出现在 Choice 篇的图注里）：

> `* Haiku t=0: 100% repeatability does not imply correctness.
> This experiment does not measure accuracy.`
>
> **这些指标描述的是可重复性以及应用执行动作的频率，而不是动作是否正确。**

—— **自一致性高 ≠ 更准。** 这两件事在这三篇里被反复强调。

---

## 7.1 自一致性：Noul（`01_自一致性Noul`）

**设置**：一份车险理赔上跑 **14 个 Noul × 15 次重复**。

对比对象：TypeSafe vs 四个 LLM（含推理模型），全部用同一套评分细则。

### 状态里的四处"临界判断"

`CLAIM`（保单 `AP-77413`）：

| 事实 | 临界点 |
| --- | --- |
| 免赔额 `deductible: 500.00`、单次限额 `per_incident_limit: 10000.00` | — |
| 排除项含 `"track/competitive driving"`、`"drivers not listed on the policy"` | 事故发生在**停车场静止状态**（赛道日相关但未在赛道上） |
| `"police_report_required_over": 2000.00` | 索赔 `amount_claimed: 3250.00`，**无警方报告** |
| line_items 含 `rental car (6 days) 300.00` | **保单无 rental_reimbursement** |
| 自动分诊备注："Approved. Pay full amount $3,250" | **未经人工审核即全额批准、未扣免赔额** |

### 14 个 Noul

```
covered / exclusion / on_circuit / deductible / docs_sufficient / within_limit /
within_window / reported_timely / rental_eligible / fraud_flag / human_review /
manual_review / line_items_sum / subrogation
```

**关键设计**：问题措辞保证**「答是 = 要检查的事为真」**，
这样各模型的概率与 TypeSafe 的 noul 度量的是**同一件事**。

### 成本 / 速度对照（15 次平均）

| 条件 | 延迟 | 成本 | 速度比 | 成本比 |
| --- | --- | --- | --- | --- |
| **typesafe_noul** | **111ms** | **$0.000043** | **1.0x** | **1.0x** |
| `claude-haiku-4-5` t=0 | 1780ms | $0.001798 | 16.0x | 42.2x |
| `claude-haiku-4-5` t=default | 1644ms | $0.001798 | 14.8x | 42.2x |
| `claude-haiku-4-5` yes/no t=0 | 1485ms | $0.001650 | 13.4x | 38.8x |
| `gpt-5.4-mini` t=0 | 1405ms | $0.001089 | 12.7x | 25.6x |
| `gpt-5.4-mini` t=default | 1177ms | $0.001179 | 10.6x | 27.7x |
| `gpt-5.4-mini` yes/no t=0 | 1113ms | $0.000950 | 10.0x | 22.3x |
| `gpt-5.5-reasoning` | 11125ms | $0.033157 | 100.2x | **778.9x** |
| `claude-opus-4-8-reasoning` | 13886ms | $0.034275 | 125.0x | **805.1x** |

**一次 14 问量表调用：TypeSafe 111ms / $0.000043，LLM 各条件 1.1–13.9 秒。**

> ⚠️ 官方声明：**成本用的是历史价格假设（含 TypeSafe `speed_latest` 费率），
> 不是经核实的 jev-latest 价格，也不是当前计费。**

### 一致性

| 指标 | 值 |
| --- | --- |
| TypeSafe **逐问题概率标准差均值** | **0.0102** |
| | **低于此处所有 LLM 概率条件** |

**逐问题波动分布**（热力图）：

- `covered` 分布 **0.43–0.53**——**跨越 0.5 决策阈值**
- `exclusion` 分布 **0.53–0.62**
- **其余 13 个问题始终在阈值同一侧**
- 官方总结：**事实性问题稳定，判断型问题**（`exclusion`、`rental_eligible`、
  `fraud_flag`、`manual_review`）**在样本间移动或模型间不一致**

### 不确定区间

```python
NOUL_UNCERTAINTY_LOW  = 0.30
NOUL_UNCERTAINTY_HIGH = 0.70

def noul_decision_with_uncertainty(probability: float) -> str:
    if probability < NOUL_UNCERTAINTY_LOW:  return "no"
    if probability > NOUL_UNCERTAINTY_HIGH: return "yes"
    return "uncertain"      # 含边界：0.30 与 0.70 都算 uncertain
```

**uncertain → 转人工**，同时**底层 noul 值保持可见**。

### ⚠️ 四条边界（官方明确）

1. **价格是历史假设**，不是当前计费。
2. **每次查询带一个会变化的一次性 `uid` 字段**——
   > **这一设置无法把对无关字段的敏感性与"在完全相同请求上本来就会出现的波动"区分开。**
3. **claude-haiku-4-5 尽管有 "ONLY a JSON object" 指令，
   仍几乎把每个回复包在 ```json 围栏里**，严格 `json.loads` 会拒绝；
   辅助函数剥掉围栏，仍解析不了的记为解析失败（**计入数量但不参与打分**）。
4. **uncertain 区间 0.30–0.70 仅为示例**：
   > 既不是校准后的保证，也不是优化过的阈值；
   > 生产边界应从**带标注样本**、以及**错误决策与审核的成本**出发来设定。
   >
   > 审核区间吸收了 0.5 附近波动，但**靠近外侧边界的值仍可能在 uncertain 与是/否之间移动**；
   > **模型并不会因此变得更确定，越过了该区间的自动决策也并未被证明是正确的。**

**⚠️ 未做显著性检验。**

## 7.2 自一致性：Choice（`02_自一致性Choice`）

**设置**：一条**刻意"骑墙"**的用户帖子，跑 **8 个 Choice × 15 次重复**。

### 帖子内容（四个互相冲突的信号）

`P-88213`：账号 38 天、**前科 1 次**、210 粉丝、公开回复、
社区 `r/gamedebates`、正文含侮辱 + `discord.gg` 链接 + 结尾 "I'll end your whole channel"、
`has_link: True`、**4 条举报**（harassment / spam / threat）。

### 8 个 Choice 问题

| 键 | 标签集 |
| --- | --- |
| `category` | None / Harass / Hate / Violence / Spam / Sexual |
| `primary_risk` | Harassment / Violence / LinkAbuse / AccountHistory / LowRisk |
| `target` | None / Person / Group / Platform |
| `action` | Allow / Warn / Remove / Strike / Escalate |
| `queue` | Auto / General / Threat / Spam / TSLead |
| `link_handling` | Allow / RmLink / Brigade / Escalate |
| `review_path` | Auto / Human / Senior / Legal |
| `severity` | None / Low / Medium / High |

### 弃权机制

```python
MIN_CHOICE_PROBABILITY = 0.60

def choice_decision_with_uncertainty(values, labels):
    if any(value < 0 or value > 1 for value in values):   # 非法概率视为解析失败
        return None
    return label if max(probabilities) >= MIN_CHOICE_PROBABILITY else "uncertain"
```

**注意边界**：`>= 0.60` **取最高标签**（等于 0.60 时不算弃权）。

### 实测

**① LLM 在多次运行间确实会翻**

| 条件 | 平均概率标准差 | 最大标准差 | ×TypeSafe |
| --- | --- | --- | --- |
| `claude-haiku-4-5` t=0 | **0.0012** | 0.0221 | **0.12x** |
| `claude-haiku-4-5` t=default | 0.0516 | 0.3150 | 5.29x |
| `gpt-5.4-mini` t=0 | 0.0312 | 0.0905 | 3.20x |
| `gpt-5.4-mini` t=default | 0.0543 | 0.2303 | 5.56x |
| `gpt-5.5-reasoning` | 0.0305 | 0.1047 | 3.12x |
| `claude-opus-4-8-reasoning` | 0.0245 | 0.0693 | 2.52x |
| **typesafe_choice** | **0.0098** | **0.0515** | **1.00x** |

> TypeSafe 平均概率波动**低于六个 LLM 分布条件中的五个**
> ——唯一更低的是 **temperature 0 的 Haiku**。

**② 翻在哪几个问题上**

引入弃权前，TypeSafe 在 8 个问题中**有 2 个翻转**：

| 问题 | 翻转情况 |
| --- | --- |
| `primary_risk` | **Harassment 11 次 / Violence 4 次** |
| `link_handling` | **RmLink 8 次 / Brigade 7 次** |

**明确的问题稳定**：`target` 全读 Person，`severity` 全读 High。

**引入 0.60 阈值后，这两行全程 `uncertain`。** ← 这就是弃权机制的价值。

**③ 决策一致性表**

| 条件 | raw agree | policy agree | uncertain | automatic | conflicts |
| --- | --- | --- | --- | --- | --- |
| `claude-haiku-4-5` t=0 | **100.0%** | 100.0% | 0.0% | 100.0% | 0 |
| `claude-haiku-4-5` t=default | 87.5% | 86.7% | 0.8% | 98.3% | 2 |
| `gpt-5.4-mini` t=0 | 99.2% | 87.5% | 12.5% | 87.5% | 0 |
| `gpt-5.4-mini` t=default | 90.8% | 84.2% | 22.5% | 77.5% | 2 |
| `gpt-5.5-reasoning` | 90.0% | 93.3% | 30.8% | 69.2% | 1 |
| `claude-opus-4-8-reasoning` | 92.5% | 94.2% | 33.3% | 66.7% | 0 |
| **typesafe_choice** | **90.8%** | **99.2%** | **25.8%** | **74.2%** | **0** |

> **同一 0.60 规则下，TypeSafe 一致性从 90.8% 升至 99.2%，
> 代价是 25.8% 弃权、74.2% 自动。**

### ⚠️ 三条边界

1. **Haiku t=0 的 100% 一致 + 零弃权不代表更优**（页面图注原文已引于 7.0）。
2. **单选（single-pick）LLM 条件没有概率估计**，
   其人工 one-hot 向量**无法度量不确定性**，被**排除在一致性图表和表格之外**。
3. **弃权不会让模型变确定**：
   > 接近 0.60 的概率仍可能在具体标签与 uncertain 之间移动；
   > `raw agree` 列报告的仍是**原始模型输出**。

**⚠️ 未做准确性测量，只测可重复性。**

## 7.3 关于不确定性的一个通用工程结论

这两篇合起来给出了一条可以直接用的经验：

> **温度 0 并不消除不确定性。** LLM 在 `temperature=0` 下，
> 主观判断问题上**仍会与自己不一致**（`gpt-5.4-mini` t=0 平均标准差 0.0312）。
>
> **而"翻在哪些问题上"本身是可观测的**——
> TypeSafe 的 8 个问题里，**只有 2 个翻**，
> 且这两行恰好就是"骑墙"帖子设计出来要踩的那两个（主风险类别、外链处置）。
>
> 所以：**弃权机制的价值不在于让答案更准，而在于把"模型自己也不确定"的位置标出来。**
> 那两行从"11:4 的随机翻转"变成"全程 uncertain"，**正是分流该做的事**。

## 7.4 基于置信度的分类（`18_基于置信度的分类`）

**核心**：**读答案自身的 `confidence`，高就报细粒度标签，低就回退到宽标签。**

> **宽标签由窄标签直接推导，无需第二次调用。**

### 分类体系（不涉及模型）

```
444 个四位 SIC 代码 → 按前两位分组成 75 个 major group → 按固定区间映射到 10 个 division
```

```python
DIVISIONS = [
    (1, 9,   "agriculture, forestry and fishing"),
    (10, 14, "mining"),
    (15, 17, "construction"),
    (20, 39, "manufacturing"),
    (40, 49, "transportation, communications and utilities"),
    (50, 51, "wholesale trade"),
    (52, 59, "retail trade"),
    (60, 67, "finance, insurance and real estate"),
    (70, 89, "services"),
    (91, 99, "public administration"),
]
```

**选项描述怎么生成**：

```python
MAX_NAMED = 8
def describe(group):
    umbrella = INDUSTRIES.get(f"{group}00")
    inside = [INDUSTRIES[c] for c in GROUPS[group] if c != f"{group}00"][:MAX_NAMED]
    return f"{umbrella} — includes: {listed}"
```

> 75 个组里 **42 个带伞形标题**，其余没有。

### 全套做法就四行

```python
CONFIDENT = 0.9

def classify(filing: dict) -> dict:
    answer = ask(filing["id"], filing["text"])
    sure = answer["confidence"] >= CONFIDENT
    return {
        "level": "group" if sure else "division",
        "label": answer["group"] if sure else division(answer["group"]),
        "confidence": answer["confidence"],
        "group": answer["group"],
    }
```

> **每份文档只一次请求；没把握的答案向上返回一层，而不是丢弃。**

### 实测（60 份 10-K，`jev-1.12`）

数据：`filings.jsonl` 60 份 10-K，裁剪到 Item 1 "Business"，
年份 1993–2024，篇幅 **700–2,200 词**，**平均 1,438 词**。

**置信度阈值 0.9 把 60 份正好对半分开（30 sure / 30 unsure）。**

| 策略 | 结果 |
| --- | --- |
| 每次都被迫报一个 group | **39/60** 对 |
| ├ 其中 **30 个有把握的** | **27/30（90%）** |
| └ 其中 **30 个没把握的** | **12/30（40%）** |
| **不确定时允许答粗（回退到 division）** | **48/60 有用答案** |

> **没把握的那一半从 40% 提到 70%。**

**样例**：

| filing | conf | 结果 |
| --- | --- | --- |
| `310158_1996` | 1.00 | group 28（chemicals & allied products） |
| `33416_1998` | 1.00 | group 63（life insurance; accident & health insurance） |
| `352541_1996` | 1.00 | group 49（electric, gas & sanitary utilities） |
| `1372167_2013` | **0.22** | division manufacturing（group 38） |
| `1398633_2009` | **0.23** | division wholesale trade |
| `46653_1999` | **0.29** | division services |

**困难案例的成因可顺文本读出**（官方注明）：两个开发阶段公司描述"**打算开展的**业务"、
一个卖掉了两个业务板块之一。

### 三条关键洞察

**① 困难案例与简单案例看起来毫无差别**

> **区分它们通常正是成本所在**（再来一个模型、额外调用、人工审核）——
> 而 Choice 的 `confidence` **一个数字就区分开**。

**② 读 `confidence` 而不是获胜者自身的概率**

> 获胜者 0.45 而第二名 0.44（**分散**）与获胜者 0.45 而其余稀薄散开，
> 是**两种情形**，`confidence` 把它们区分开。

**③ Choice 的容量**

> **Choice 在大约 240 个选项以内都能可靠工作**，75 远在范围之内。

> （与 `api` 页写的硬上限 **255** 一致，但这里是官方给的"可靠工作"经验值。）

### ⚠️ 三条边界

1. **标签是自行申报的**——编制者一次性选定，
   公司卖掉代码所指业务却保留代码时会过时。
2. **这 60 份是筛选过的**（只保留文本本身能支撑所带代码的），
   因此**数字衡量的是这套做法本身，而非 EDGAR 元数据的现状**。
3. **若大类太粗、无法据此行动，`unsure` 分支就是交人工处理的地方。**

## 7.5 三篇的共性提炼

| 教训 | 出处 |
| --- | --- |
| **可重复性 ≠ 正确性**——这两件事必须分开报 | 7.0 |
| **temperature=0 不消除不确定性**（LLM 在主观问题上仍会翻） | 7.1 / 7.2 |
| **"翻在哪些问题上"本身是可观测的**——这正是该分流的位置 | 7.2 |
| **弃权不会让模型变确定**，只是把不确定标出来 | 7.1 / 7.2 |
| **回退到宽标签是免费的**（窄标签直接推导，无需第二次调用） | 7.4 |
| **读 `confidence` 而非获胜者概率**——分布形态携带信息 | 7.4 |
| **阈值必须是示例值而非默认值**——生产阈值要从标注数据 + 错误成本来定 | 全篇 |
| **所有对照都没做显著性检验** | 全篇 |
