# 01 · 认识 Jev 与适用边界

> 来源：课程第 1 章导读、`introduction`、`introduction/coding-agents`、
> `introduction/machine-learning-primer`、`concepts/system-one`、`concepts/use-case-map`、`models`。

---

## 1.1 它是什么

**Jev 是 TypeSafe 的旗舰模型，也是首个 "System One" 模型。**

- **System One 模型**是一类专为「做出软件可直接使用的快速结构化决策」而构建的 AI 模型：
  评估一个 `state`，返回**类型化的答案和概率**。
- 名称源自丹尼尔·卡尼曼《思考，快与慢》——系统 1 快速而直观，系统 2 更慢、更审慎。
  这里强调的是**快速、聚焦的判断**。

与 LLM 的**相同点**：都能理解自然语言输入。
与 LLM 的**不同点**：Jev **返回类型化决策和概率，而非生成的文本**。

它**不做**这些事：

- 不撰写回复
- 不产出代码
- **不生成对其推理过程的解释**

答案空间由**原语**定义（见 [02-接口与三原语](02-接口与三原语.md)）：

| 原语 | 问题 | 示例答案空间 | 示例输出 |
| --- | --- | --- | --- |
| `Choice` | 哪个团队应当处理这张工单？ | billing, technical, account | `choice: "billing"` |
| `Score` | 这位客户有多不满？ | 0 = 平静, 1 = 不满, 2 = 非常不满 | `score: 1.4` |
| `Noul` | 这条消息是否要求退款？ | 真或假 | `noul: 0.95` |

> 官方标注：**这些只是示例性的配置和数值，不是 API 实测。**

**输入端限制**（写死的事实）：Jev 目前**只接受文本**——可以评估字符串、JSON 对象和文本数组。
**图像、音频和视频尚不受支持。** 非文本输入（图像/音频/视频/二进制）必须先预处理为文本或结构化字段。

## 1.2 为什么需要它：两类任务的错位

课程第 1 章用一条工单讲清了动机：

```
工单：「充电器冒烟，刚买两天」

生成式路径
  工单 + prompt → "这可能涉及安全问题，请转人工……"
  → 解析文本 / 校验 JSON → 代码决定后续动作

有限选项路径
  工单 + Choice{安全问题, 退款, 普通咨询}
  → 概率分布 {安全问题: 0.93, 退款: 0.05, 普通咨询: 0.02}
  → 代码检查策略 → 转人工处理
```

官方在这里给了一段很关键的自我限定，值得原文记住：

> 这组概率**只是结构示意，不是 API 实测**。例子要表达的是：模型回答"属于哪类"和
> 应用决定"接下来做什么"是**两个步骤**；涉及安全的动作仍要走既定人工流程。

而 `introduction` 页把这个错位说得更直接：

> LLM 为生成人类阅读的文本而设计；需要供代码消费的判断时产生错位
> （强迫文本系统输出结构化决策再解析回来）。

Jev 的回应是：**无文本生成、无需解析**，直接返回类型化值和概率分布，代码据此分支/排序/路由。

官方还提到一个常被忽略的性质：**增加问题几乎不改变响应时间，也不会造成上下文腐化
（context-rot）**——因为每个问题是相互独立评估的，不是串成一条推理链。

### 读图时要留意的分界

课程特意强调：类型化输出**能让程序更容易检查答案范围**，
但**是否准确、概率是否可信，仍要通过目标数据评测**；
代码策略**也不能因为收到高概率就省略授权与安全校验**。

## 1.3 与相邻技术的区别

官方给了一张对比表（第 1 章）：

| 方法 | 常见输出 | 更适合的任务 | 需要注意 |
| --- | --- | --- | --- |
| 生成式 LLM | 自由文本，也可受格式约束 | 解释、写作、开放式推理 | 生成结果仍需校验；**JSON 约束不等于概率校准** |
| 固定标签分类器 | 训练标签上的类别或分数 | 标签集合长期固定、可积累标注数据 | 新标签通常需要重训或额外设计 |
| NLI / reranker | 蕴含关系或相关性分数 | 文本蕴含、候选排序 | 分数语义由模型与训练任务决定 |
| **Jev 类类型化决策接口** | 请求中定义的类型化答案与分布 | 同一任务需要明确问题、选项和**可读概率** | 分布质量和延迟**仍须在目标数据上测量** |

关键区别不是"谁更聪明"，而是**答案空间是每次请求里现定义的**——Jev 不训练你的标签集。

## 1.4 三种后训练路线：RLHF / RLVR / RLCD

`introduction/machine-learning-primer` 页交代了 Jev 的训练来路，这段能解释"为什么它不一样"：

| 方法 | 目标产物 | 特点 |
| --- | --- | --- |
| **RLHF**（人类反馈强化学习） | 聊天机器人 | 训练生成人们偏好的响应；曾训练 InstructGPT/ChatGPT |
| **RLVR**（可验证奖励强化学习） | 推理模型 | 擅长数学，但**更慢更贵** |
| **RLCD**（面向校准决策的强化学习） | **返回决策和校准概率而非文本** | Jev 走的这条 |

官方对 RLHF 的批评值得记下来：它**奖励谄媚和听起来自信的幻觉**；
偏好优化会导致 **mode dropping**（降低其他可能输出的概率），
是 GAN 里 **mode collapse** 的较温和版本。

> 立场：RLHF 仍是会话模型的好选择；**生产自动化需要不同的训练目标**——
> 受约束决策 + 校准不确定性。

**校准的确切含义**（对校准良好的模型的**多次**预测）：

```
概率 0.2 的结果应约 20% 发生
概率 0.8 的结果应约 80% 发生
概率 1.0 的结果应 100% 发生
```

> **这些比率描述一组预测，不保证单个答案。**

配套概念是 **Machine Native Intelligence（机器原生智能）**——
官方列出的机器接口属性：结构化、可靠性、可观测性、可测试性、速度、一致性、低成本。
他们的预期是「大规模 AI 自动化接近 99% 机器对机器 + 1% 人类交互」。

**一个必须明确的边界**（`introduction/coding-agents` 页）：

> Jev **不是** Claude Code、Cursor、opencode、Copilot 等工具背后 LLM 的即插即用替代品。
> 它不生成文本、不写代码、不对话。
> **没有任何 `model:"jev-latest"` 设置能把编码智能体变成 Jev 驱动。**

正确的分工是：**让编码智能体照常写代码，由它调用的应用去调 Jev 做判定。**

## 1.5 什么时候该用

`introduction/coding-agents` 给了四条明确信号：

- 要**路由到固定目的地**，且想知道置信度
- 要按**评分标准**（紧急程度 / 质量 / 风险）打分并据以分支
- 要**检查某陈述对某文档 / 消息 / 记录是否成立**
- 要**替换「让 LLM 返回 JSON」这类脆弱提示词**为类型化调用

`use-case-map` 把任务形态归成十类（可作为头脑风暴清单）：
**分类 · 检测 · 评分 · 路由 · 搜索 · 检索 · 排序 · 核验 · ML 特征提取 · 结构化数据提取**。

其中与工程直接相关的几个：**模型路由**（决定每个提示词由哪个 LLM 接收、估计难度与风险、升级）、
**LLM 防护栏**（对每个输入/输出/工具调用施加语义检查、检测越狱与注入）、
**语义代码检查**（lint、CI 运行）、**特征提取**（从自然语言提取概率特征训练下游模型）。

官方给出的性能期待：**大多数查询约 100 毫秒**，目标是让「智能 / 速度 / 成本」之比**超过 100 倍**。

## 1.6 什么时候不该用

来自课程第 1 章与 `model-jaggedness/jev-1.13`：

| 任务 | 为什么不该用 |
| --- | --- |
| **长篇生成、开放式问答、创作** | Jev 明确没训练文本生成；串联 Choice 强行生成"效果差且非常慢" |
| **计数** | 见 [08-短板](08-短板与评测校准.md)：把计数单元交给正则/解析器，模型帮不上忙 |
| **算术与数值比较** | 不是计算器；强烈建议任何数学逻辑都在代码中实现 |
| **日期先后比较** | 把日期当文本读，不是有先后顺序的量 |
| **需要多跳间接推理** | 官方明说多层间接引用会损失准确率 |
| **代码能精确计算的问题** | 官方禁令之一：**别向模型询问代码可以精确计算的问题** |

还有一条容易被忽略的**语言限制**（`models` 页）：

> Jev 的主要训练语言是英语，其他语言（**包括中日韩文字**）可以处理
> **但效果不一**；在用于非英语工作负载之前，请先在自己的内容上测试，
> 并在路由时密切关注 `Confidence`。

---

## 1.7 本章要记住的三句话

1. **Jev 是"判断题机器"，不是"作文机器"**——它返回类型化答案和概率，不返回文本。
2. **模型回答"属于哪类"，代码决定"接下来做什么"**——这两步永远分开。
3. **高概率不等于已授权**——涉及安全的动作仍必须走既定流程。
