## 你将搞清楚的问题

- **Jev 到底是什么？** 为什么它既不是 Agent 框架，也不是"只会输出 JSON 的 LLM"——它不做生成、不做推理链，只回答"是/哪个/多严重"并给概率。
- **为什么"选最大概率"经常是错的？** 官方给的反例里，`非紧急` 是最大概率类别，最优动作却是"转人工"。
- **`state` 里到底该放什么？** 为什么官方明说"无关细节越多准确率越低"（context rot），以及怎么用 Noul 先过滤。
- **Noul 调好的阈值能直接搬到 Choice 上吗？** 不能——官方实测 `P(退款)=0.72`、`P(非退款)=0.47`，和是 1.19。
- **"工具太多，全塞进上下文"这个问题，官方怎么解的？** 182 个技能的名册，只往系统提示词注入**一行**，且**名册本身不变**（前缀缓存不失效）。错误加载从 16.8% 降到 7.3%。
- **同一个判断问 LLM 和问 Jev 差多少？** 14 个 Noul：Jev 111ms / $0.000043，haiku 1.4–1.8s，推理模型 11–14s。
- **13 个问题打包成一次调用会引入噪声吗？** 不会——均值和标准差与逐条调用完全一致，便宜 12.2 倍、快 10.0 倍。
- **Jev 的已知短板有哪些？** 9 条官方清单，其中"计数不可靠""日期当文本读"两条会直接坑到工程项目。
- **prompt injection 对 Jev 有没有用？** 有。类型化选项**不构成权限边界**。

## 一句话备忘

- **它回答你写下的问题，不是你想问的问题**——criteria 要写全，边界情况要写进去
- **代码掌握控制权**：权限、阈值、顺序、副作用都在代码里
- **别 argmax，看期望损失**
- **保留完整分布**：`[0.51,0.49]` ≠ `[0.99,0.01]`
- **Noul ≠ 1 − not Noul**，阈值不能跨原语搬
- **先确定性后模型**：字符串/正则/解析器能做的先做掉
- **计数、算术、日期比较放代码里**
